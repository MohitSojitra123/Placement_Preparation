# 🟢 Part 1 — C# Fundamentals (Q1–50)

### Q1. What is C#?
C# (C-Sharp) is a modern, object-oriented, type-safe programming language made by Microsoft. You use it to build web APIs, desktop apps, games (Unity), mobile apps and cloud services.
```csharp
Console.WriteLine("Hello, World!");
```

### Q2. What is .NET?
.NET is a free, open-source platform (runtime + libraries + tools) used to build and run apps. It gives you ready-made things like collections, file handling, HTTP, database access, and a runtime that executes your code.

### Q3. What is the difference between C# and .NET?
- **C#** = the *language* you write code in.
- **.NET** = the *platform* that compiles/runs the code and provides libraries.

Analogy: C# is English (language), .NET is the country with roads, schools and rules where English is used. .NET also supports F# and VB.NET.

### Q4. What is CLR?
**Common Language Runtime** is the engine of .NET. It runs your code and gives: memory management (garbage collection), type safety, exception handling, security and JIT compilation (IL → machine code).

### Q5. What is CTS?
**Common Type System** defines how types (int, string, class, interface) are declared and used so all .NET languages understand each other. Example: C# `int` = VB `Integer` = `System.Int32`.

### Q6. What is CLS?
**Common Language Specification** is a *subset* of CTS rules. If your library follows CLS, every .NET language can use it. Example: avoid public members that differ only by case (`Name` and `name`), because VB is case-insensitive.

### Q7. What is managed code?
Code that runs under the control of the CLR (which handles memory, security, exceptions). All normal C# code is managed.
```csharp
var list = new List<int>(); // you never free this memory; GC does
```

### Q8. What is unmanaged code?
Code that runs outside the CLR (C/C++ DLLs, Windows API). You must handle memory yourself. C# can call it with P/Invoke.
```csharp
[DllImport("user32.dll")]
static extern int MessageBox(IntPtr h, string text, string caption, int type);
```

### Q9. What is an assembly in .NET?
A compiled unit of code (`.dll` or `.exe`) that contains IL code, metadata, and a manifest (name, version). It is the smallest unit of deployment and versioning.

### Q10. What is the difference between .dll and .exe?
- **.exe** – has an entry point (`Main`) and can run on its own.
- **.dll** – a library of reusable code; it cannot run itself, other apps load it.

Example: `MyApi.exe` (your app) uses `Newtonsoft.Json.dll`.

### Q11. What are value types in C#?
Types that store the **actual data directly** (usually on the stack). Examples: `int, double, bool, char, decimal, struct, enum, DateTime`.
```csharp
int a = 10;
int b = a;  // copy
b = 20;     // a is still 10
```

### Q12. What are reference types in C#?
Types where the variable stores a **reference (address)** to the object on the heap. Examples: `class, string, array, interface, delegate, object`.
```csharp
var u1 = new User { Name = "Ali" };
var u2 = u1;      // same object
u2.Name = "Sara"; // u1.Name is also "Sara"
```

### Q13. What is the difference between value type and reference type?
| Point | Value type | Reference type |
|---|---|---|
| Stores | Actual value | Address to object |
| Memory | Stack (usually) | Heap |
| Copy | Copies value | Copies reference |
| Default | 0 / false | null |
| Examples | int, struct | class, string |

### Q14. What is boxing?
Converting a **value type to `object`** (or interface). The value is wrapped and copied to the heap — it costs performance.
```csharp
int x = 5;
object o = x; // boxing
```

### Q15. What is unboxing?
Getting the value type back from `object`. Needs an explicit cast and the correct type, otherwise `InvalidCastException`.
```csharp
object o = 5;
int x = (int)o; // unboxing
```

### Q16. What is implicit conversion?
Automatic conversion by the compiler when there is **no data loss**.
```csharp
int i = 100;
long l = i;     // int → long, safe
double d = i;
```

### Q17. What is explicit conversion?
Manual conversion (cast) needed when data may be **lost**.
```csharp
double d = 9.78;
int i = (int)d; // 9, decimal part lost
```

### Q18. What is the difference between Parse() and TryParse()?
- `Parse` throws an exception if the text is invalid.
- `TryParse` returns `false` and never throws — better for user input.
```csharp
if (int.TryParse(input, out int age)) Console.WriteLine(age);
else Console.WriteLine("Invalid number");
```

### Q19. What is the difference between Convert.ToInt32() and int.Parse()?
- `int.Parse(null)` → throws `ArgumentNullException`.
- `Convert.ToInt32(null)` → returns `0`.
- Both throw `FormatException` for `"abc"`. `Convert` also converts from other types (double, bool, etc.).

### Q20. What is nullable value type?
A value type that can also hold `null`, written `int?`. Useful for optional database columns.
```csharp
int? age = null;
if (age.HasValue) Console.WriteLine(age.Value);
```

### Q21. What is Nullable<T>?
The generic struct behind `int?`. `int?` is just shorthand for `Nullable<int>`. It has `HasValue`, `Value`, and `GetValueOrDefault()`.

### Q22. What is the difference between null, 0, and string.Empty?
- `null` → no object/reference at all.
- `0` → a real number value zero.
- `string.Empty` (`""`) → a real string object with zero characters.
```csharp
string a = null;          // a.Length → NullReferenceException
string b = string.Empty;  // b.Length → 0
```

### Q23. What is var in C#?
Implicitly typed local variable. The compiler decides the type at **compile time**; the type is fixed after that.
```csharp
var name = "Ali";  // string
var count = 10;    // int
```

### Q24. What is dynamic?
A type whose checking happens at **runtime**, not compile time. Used for COM interop, reflection, JSON with unknown shape.
```csharp
dynamic x = 10;
x = "hello"; // allowed
```

### Q25. Difference between var and dynamic?
| var | dynamic |
|---|---|
| Type fixed at compile time | Type resolved at runtime |
| Must be initialized | No need |
| IntelliSense works | No IntelliSense |
| Errors caught at compile time | Errors at runtime |

### Q26. What is const?
A compile-time constant. Value must be known at compile time and never changes. It is implicitly static.
```csharp
public const double Pi = 3.14159;
```

### Q27. What is readonly?
A field that can be assigned only at declaration or inside the constructor (runtime value).
```csharp
public class Order {
    public readonly DateTime CreatedAt;
    public Order() { CreatedAt = DateTime.UtcNow; }
}
```

### Q28. Difference between const and readonly?
| const | readonly |
|---|---|
| Compile-time value | Runtime value (constructor) |
| Implicitly static | Instance or static |
| Only primitives/strings | Any type |
| Value copied into callers | Value read at runtime |

### Q29. What are access modifiers in C#?
Keywords controlling who can access a type/member: `public, private, protected, internal, protected internal, private protected, file`.

### Q30. Difference between public, private, protected, and internal?
- **public** – everywhere.
- **private** – only inside the same class.
- **protected** – same class + child classes.
- **internal** – same assembly (project) only.
```csharp
public class Account {
    private decimal _balance;        // hidden
    protected int Id;                // children can use
    internal string BranchCode;      // same project
    public string Owner;             // everyone
}
```

### Q31. What is a class?
A blueprint that defines data (fields/properties) and behavior (methods).
```csharp
public class Product { public string Name { get; set; } public decimal Price { get; set; } }
```

### Q32. What is an object?
A real instance of a class created in memory using `new`.
```csharp
var p = new Product { Name = "Laptop", Price = 50000 };
```

### Q33. What is a constructor?
A special method with the class name, no return type, run automatically when an object is created. Used to initialize data.

### Q34. What is a default constructor?
A constructor with no parameters. The compiler gives one automatically **only if** you write no constructors.
```csharp
public class User { public User() { } }
```

### Q35. What is a parameterized constructor?
A constructor that takes parameters to set initial values.
```csharp
public class User {
    public string Name;
    public User(string name) { Name = name; }
}
var u = new User("Ali");
```

### Q36. Can a class have multiple constructors?
Yes — with different parameter lists (constructor overloading).

### Q37. What is constructor overloading?
Multiple constructors in the same class with different parameters.
```csharp
public class Employee {
    public Employee() { }
    public Employee(string name) { }
    public Employee(string name, int age) { }
}
```

### Q38. What is inheritance?
A child class reuses members of a parent class (IS-A relationship).
```csharp
public class Animal { public void Eat() { } }
public class Dog : Animal { public void Bark() { } }
```

### Q39. What is encapsulation?
Hiding internal data and exposing it only via controlled members (properties/methods).
```csharp
public class BankAccount {
    private decimal _balance;
    public void Deposit(decimal amt) { if (amt > 0) _balance += amt; }
    public decimal GetBalance() => _balance;
}
```

### Q40. What is abstraction?
Showing only *what* an object does and hiding *how*. Done with abstract classes and interfaces. Example: you call `payment.Pay()` without knowing if it uses UPI or card.

### Q41. What is polymorphism?
"Many forms" — the same method call behaves differently depending on the object. Two kinds: compile-time (overloading) and runtime (overriding).
```csharp
Shape s = new Circle();
s.Draw(); // Circle's Draw runs
```

### Q42. What is method overloading?
Same method name, different parameters, in the same class (compile-time polymorphism).
```csharp
int Add(int a, int b) => a + b;
double Add(double a, double b) => a + b;
```

### Q43. What is method overriding?
A child class gives a new implementation of a parent's `virtual`/`abstract` method (runtime polymorphism).
```csharp
public class Base { public virtual string Hi() => "Base"; }
public class Child : Base { public override string Hi() => "Child"; }
```

### Q44. Difference between overload and override?
| Overload | Override |
|---|---|
| Same class | Parent–child classes |
| Different parameters | Same signature |
| Compile time | Runtime |
| No special keyword | `virtual` + `override` |

### Q45. What is the virtual keyword?
Marks a parent method as *can be overridden* by children. Without `virtual` it cannot be overridden.

### Q46. What is the override keyword?
Used in the child class to replace a `virtual`, `abstract` or `override` method of the parent.

### Q47. What is the abstract keyword?
- **abstract class**: cannot be instantiated; may contain abstract (no body) and normal methods.
- **abstract method**: no body; children **must** implement it.
```csharp
public abstract class Payment { public abstract void Pay(decimal amt); }
public class UpiPayment : Payment { public override void Pay(decimal amt) { /* UPI */ } }
```

### Q48. What is an interface?
A contract that lists members a class must implement. It defines *what*, not *how*. Names start with `I`.
```csharp
public interface IEmailService { void Send(string to, string body); }
```

### Q49. Difference between abstract class and interface?
| Abstract class | Interface |
|---|---|
| Can have fields, constructors | No fields/constructors |
| Single inheritance only | Multiple allowed |
| Shared base code + contract | Pure contract (default methods possible) |
| Use for IS-A with shared code | Use for CAN-DO capability |

### Q50. Can a class implement multiple interfaces?
Yes. C# disallows multiple *class* inheritance, but allows many interfaces.
```csharp
public class Report : IPrintable, IExportable { /* implement both */ }
```

# 🟢 Part 2 — C# OOP, Collections & Advanced Basics (Q51–100)

### Q51. What is the difference between composition and inheritance?
- **Inheritance** = IS-A (`Dog` is an `Animal`).
- **Composition** = HAS-A (`Car` has an `Engine`).

Prefer composition: it is more flexible and less tightly coupled.
```csharp
public class Car { private readonly Engine _engine = new(); public void Start() => _engine.Run(); }
```

### Q52. What is method hiding?
When a child defines a method with the **same name as a non-virtual parent method**, it hides the parent's version (it does not override it).

### Q53. What is the new keyword in method hiding?
`new` tells the compiler "I hide the parent method on purpose" and removes the warning.
```csharp
public class A { public void Show() => Console.WriteLine("A"); }
public class B : A { public new void Show() => Console.WriteLine("B"); }
A obj = new B(); obj.Show(); // prints "A" (hiding), with override it would print "B"
```

### Q54. What is a sealed class?
A class that **cannot be inherited**. Used for security/performance. `string` is sealed.
```csharp
public sealed class JwtHelper { }
```

### Q55. What is a sealed method?
An overridden method that further children cannot override again.
```csharp
public sealed override void Pay() { }
```

### Q56. Can an abstract class have a constructor?
Yes. It cannot be called with `new`, but it runs when a child object is created, to initialize base data.

### Q57. Can an interface contain properties?
Yes — declared without implementation.
```csharp
public interface IUser { string Name { get; set; } }
```

### Q58. Can an interface contain method implementations?
Yes, since C# 8 (**default interface methods**), but it's used rarely — mostly to add a method to an existing interface without breaking implementers.
```csharp
public interface ILogger { void Log(string m); void Info(string m) => Log("INFO: " + m); }
```

### Q59. What are properties in C#?
Members that expose a field with `get`/`set` accessors; they allow validation and encapsulation.
```csharp
private int _age;
public int Age { get => _age; set { if (value >= 0) _age = value; } }
```

### Q60. Difference between field and property?
- **Field**: a raw variable in a class (usually private).
- **Property**: controlled access (get/set), supports validation, works with data binding, serialization and interfaces.

### Q61. What is an auto-implemented property?
Shortcut where the compiler creates the hidden field.
```csharp
public string Name { get; set; }
```

### Q62. What is an init-only property?
A property that can be set only during object initialization, then it becomes read-only (C# 9). Good for immutable DTOs.
```csharp
public class UserDto { public string Name { get; init; } }
var u = new UserDto { Name = "Ali" }; // u.Name = "x"; → compile error
```

### Q63. What is a static class?
A class that only has static members, cannot be instantiated or inherited. Used for helpers/extension methods.
```csharp
public static class MathHelper { public static int Square(int x) => x * x; }
```

### Q64. What is a static method?
A method that belongs to the class, not to an object. Call it with the class name.
```csharp
int r = MathHelper.Square(5);
```

### Q65. Can a static class be inherited?
No. A static class is implicitly sealed and abstract.

### Q66. What is a namespace?
A container that groups related types and avoids name conflicts.
```csharp
namespace MyApp.Services { public class UserService { } }
```

### Q67. What is exception handling?
Handling runtime errors in a controlled way so the application does not crash, using `try`, `catch`, `finally`, `throw`.

### Q68. Difference between throw and throw ex?
- `throw;` keeps the **original stack trace** (recommended).
- `throw ex;` **resets** the stack trace so you lose where the error began.
```csharp
try { Process(); }
catch (Exception ex) { _logger.LogError(ex, "failed"); throw; } // correct
```

### Q69. What is try-catch-finally?
- `try` – risky code.
- `catch` – handle error.
- `finally` – always runs (cleanup such as closing a file/connection).
```csharp
try { conn.Open(); }
catch (SqlException ex) { Log(ex); }
finally { conn.Close(); }
```

### Q70. Can finally execute if an exception occurs?
Yes, `finally` runs whether an exception occurs or not (even with `return`). It will not run only if the process is killed (e.g., `Environment.FailFast`, power failure).

### Q71. What is a custom exception?
Your own exception class for business errors.
```csharp
public class InsufficientBalanceException : Exception {
    public InsufficientBalanceException(string msg) : base(msg) { }
}
throw new InsufficientBalanceException("Not enough money");
```

### Q72. What is Exception base class?
`System.Exception` is the parent of all exceptions. Useful members: `Message`, `StackTrace`, `InnerException`.

### Q73. What is IEnumerable<T>?
The simplest collection interface; lets you loop with `foreach`. Read-only forward iteration. Supports LINQ-to-Objects (in memory).

### Q74. What is ICollection<T>?
Extends `IEnumerable<T>` and adds `Count`, `Add`, `Remove`, `Contains`, `Clear`.

### Q75. What is IList<T>?
Extends `ICollection<T>` and adds **index access** (`list[0]`), `Insert`, `RemoveAt`, `IndexOf`.

### Q76. Difference between IEnumerable, ICollection, and IList?
| Interface | Adds |
|---|---|
| IEnumerable | Iterate only |
| ICollection | Count, Add, Remove |
| IList | Index, Insert, RemoveAt |

Rule: return the **least powerful** type the caller needs (e.g., `IEnumerable<T>` for read-only).

### Q77. What is List<T>?
A dynamic array that grows automatically. Most commonly used collection.
```csharp
var names = new List<string> { "Ali", "Sara" };
names.Add("John");
```

### Q78. What is Dictionary<TKey,TValue>?
Stores key-value pairs with very fast lookup (O(1) average). Keys must be unique.
```csharp
var stock = new Dictionary<string,int> { ["Pen"] = 10 };
if (stock.TryGetValue("Pen", out var qty)) Console.WriteLine(qty);
```

### Q79. Difference between List and Dictionary?
- **List**: ordered by index; searching by value is O(n).
- **Dictionary**: lookup by key is O(1); no index; keys unique.
Use Dictionary when you search by ID/key a lot.

### Q80. What is HashSet?
A collection of **unique** items with fast `Contains`. Duplicates are ignored.
```csharp
var emails = new HashSet<string> { "a@x.com" };
bool added = emails.Add("a@x.com"); // false
```

### Q81. Difference between HashSet and List?
HashSet: unique, no order/index, `Contains` O(1). List: allows duplicates, indexed, `Contains` O(n).

### Q82. What is Queue?
FIFO (First In First Out). `Enqueue` / `Dequeue`. Example: print jobs, background job queue.
```csharp
var q = new Queue<string>(); q.Enqueue("Job1"); var next = q.Dequeue();
```

### Q83. What is Stack?
LIFO (Last In First Out). `Push` / `Pop`. Example: undo feature, browser back button.
```csharp
var s = new Stack<int>(); s.Push(1); s.Push(2); s.Pop(); // 2
```

### Q84. What is LinkedList<T>?
Doubly linked list; fast insert/remove in the middle (if you have the node), slow index access. Rarely used in business apps.

### Q85. What is IQueryable<T>?
An interface for **building queries that are translated to another language (like SQL)** and executed by the data source. EF Core `DbSet<T>` is an `IQueryable<T>`.

### Q86. Difference between IEnumerable and IQueryable?
| IEnumerable | IQueryable |
|---|---|
| In-memory | Database/remote |
| Filtering happens in C# after loading data | Filter converted to SQL `WHERE` |
| Uses delegates (`Func`) | Uses expression trees (`Expression<Func>`) |

```csharp
IQueryable<User> q = db.Users.Where(u => u.IsActive); // SQL WHERE
IEnumerable<User> e = db.Users.AsEnumerable().Where(u => u.IsActive); // loads all first (bad)
```

### Q87. What is LINQ?
**Language Integrated Query** — a uniform way to query collections, databases, XML using C# syntax.
```csharp
var adults = users.Where(u => u.Age >= 18).OrderBy(u => u.Name).ToList();
```

### Q88. What are LINQ extension methods?
Methods like `Where, Select, OrderBy, GroupBy` defined as extension methods on `IEnumerable<T>`/`IQueryable<T>` in `System.Linq`. They let you chain operations.

### Q89. Difference between Where() and Select()?
- `Where` **filters** rows (same type, fewer items).
- `Select` **transforms/projects** each item into something else.
```csharp
var names = users.Where(u => u.IsActive).Select(u => u.Name);
```

### Q90. Difference between First() and FirstOrDefault()?
- `First()` throws `InvalidOperationException` if nothing found.
- `FirstOrDefault()` returns `null`/default.
Use `FirstOrDefault` when "not found" is a normal case.

### Q91. Difference between Single() and SingleOrDefault()?
- `Single()` expects **exactly one** match; throws if 0 or more than 1.
- `SingleOrDefault()` allows 0 (returns default) but throws if more than 1.
Use for unique values like `Id` or unique email.

### Q92. Difference between Any() and Count()?
- `Any()` returns true/false and stops at the first match (fast).
- `Count()` counts all items.
```csharp
if (users.Any(u => u.Email == email)) { } // better than Count() > 0
```

### Q93. What is deferred execution in LINQ?
The query is **not executed when written**; it runs when you enumerate it (`foreach`, `ToList`, `Count`).
```csharp
var q = users.Where(u => u.Age > 18); // nothing runs yet
users.Add(new User { Age = 30 });
var list = q.ToList(); // runs now, includes the new user
```

### Q94. What is immediate execution in LINQ?
Methods that run the query right away: `ToList, ToArray, Count, Sum, First, Any, ToDictionary`.

### Q95. What does ToList() do in LINQ?
Executes the query and stores the result in a `List<T>` in memory (a snapshot). In EF Core it sends the SQL to the database.

### Q96. What is SelectMany()?
Flattens a collection of collections into a single sequence.
```csharp
var allOrders = customers.SelectMany(c => c.Orders); // all orders of all customers
```

### Q97. What is OrderBy()?
Sorts ascending. Use `OrderByDescending`, and `ThenBy` for a second sorting key.
```csharp
var sorted = users.OrderBy(u => u.LastName).ThenBy(u => u.FirstName);
```

### Q98. What is GroupBy()?
Groups items by a key (like SQL `GROUP BY`).
```csharp
var byCity = users.GroupBy(u => u.City)
                  .Select(g => new { City = g.Key, Total = g.Count() });
```

### Q99. What is Join() in LINQ?
Combines two collections on a matching key (like SQL `INNER JOIN`).
```csharp
var result = from o in orders
             join c in customers on o.CustomerId equals c.Id
             select new { c.Name, o.Total };
```

### Q100. Write a LINQ query to find duplicate records.
```csharp
var duplicates = users
    .GroupBy(u => u.Email)
    .Where(g => g.Count() > 1)
    .Select(g => new { Email = g.Key, Count = g.Count() })
    .ToList();
```
For full duplicate rows: `.Where(g => g.Count() > 1).SelectMany(g => g)`.

# 🟡 Part 3 — ASP.NET Core Fundamentals (Q101–150)

### Q101. What is ASP.NET Core?
A free, open-source, cross-platform, high-performance framework for building web apps, REST APIs, and microservices with C#.

### Q102. What are the advantages of ASP.NET Core?
Cross-platform (Windows/Linux/macOS), very fast (Kestrel), built-in Dependency Injection, modular middleware pipeline, cloud/Docker friendly, unified MVC + Web API, built-in configuration and logging, open source.

### Q103. Difference between ASP.NET Framework and ASP.NET Core?
| ASP.NET Framework | ASP.NET Core |
|---|---|
| Windows only | Cross-platform |
| IIS only | Kestrel (+IIS/Nginx) |
| Heavy, `System.Web` | Lightweight, modular |
| DI needs third-party | DI built in |
| Slower | Much faster |
| MVC and Web API separate | Unified |

### Q104. Is ASP.NET Core cross-platform?
Yes. The same API can run on Windows, Linux (Docker), and macOS.

### Q105. What is Kestrel?
The default built-in, cross-platform web server of ASP.NET Core.

### Q106. What is the role of Kestrel in ASP.NET Core?
It receives HTTP requests, passes them to the middleware pipeline, and sends back responses. In production it often sits **behind** a reverse proxy (Nginx, IIS, Azure App Service) for extra security/load balancing.

### Q107. What is Program.cs?
The entry point of the app. It builds the host, registers services, configures the middleware pipeline and runs the app.
```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();
var app = builder.Build();
app.MapControllers();
app.Run();
```

### Q108. What is Startup.cs?
In older versions (.NET Core 2.x–5) it had `ConfigureServices` (register services) and `Configure` (middleware pipeline).

### Q109. Why is Startup.cs not required in newer ASP.NET Core versions?
From .NET 6 the **minimal hosting model** merged everything into `Program.cs` with top-level statements — less boilerplate. (You can still use Startup if you want.)

### Q110. What is WebApplicationBuilder?
The object used to configure the app *before* it is built: services (`builder.Services`), configuration (`builder.Configuration`), logging, environment.

### Q111. What is WebApplication?
The built app (`builder.Build()`) used to add middleware (`app.UseXxx`) and map endpoints (`app.MapControllers()`), then run it.

### Q112. What is the purpose of appsettings.json?
Stores configuration (connection strings, logging levels, JWT settings, feature flags) outside code so you can change values without recompiling.
```json
{ "ConnectionStrings": { "Default": "Server=.;Database=AppDb;Trusted_Connection=True;" },
  "Jwt": { "Issuer": "MyApi", "ExpiryMinutes": 30 } }
```

### Q113. What is appsettings.Development.json?
Environment-specific overrides that load only when `ASPNETCORE_ENVIRONMENT=Development` (e.g., local DB, verbose logging). Values override `appsettings.json`.

### Q114. How do you read configuration values in ASP.NET Core?
```csharp
var cs = builder.Configuration.GetConnectionString("Default");
var issuer = builder.Configuration["Jwt:Issuer"];
var minutes = builder.Configuration.GetValue<int>("Jwt:ExpiryMinutes");
```

### Q115. What is IConfiguration?
The interface that gives access to config values from all sources (JSON files, environment variables, user secrets, command line, Key Vault). Inject it anywhere.
```csharp
public class MyService(IConfiguration config) { string x = config["Jwt:Issuer"]; }
```

### Q116. What is the Options pattern?
Binding a section of configuration to a **strongly-typed class**, instead of reading magic strings.
```csharp
public class JwtSettings { public string Issuer { get; set; } public int ExpiryMinutes { get; set; } }
builder.Services.Configure<JwtSettings>(builder.Configuration.GetSection("Jwt"));
```

### Q117. What is IOptions<T>?
Injects the strongly-typed settings.
```csharp
public class TokenService(IOptions<JwtSettings> options) { var s = options.Value; }
```
Variants: `IOptionsSnapshot<T>` (reloads per request), `IOptionsMonitor<T>` (live change notifications).

### Q118. What is environment configuration?
Running the same code with different settings per environment (Development, Staging, Production).

### Q119. What are ASP.NET Core environments?
Named modes: **Development, Staging, Production** (custom names allowed), controlled by `ASPNETCORE_ENVIRONMENT`.

### Q120. What is Development environment?
For local coding: detailed error pages, Swagger enabled, local DB, verbose logging.
```csharp
if (app.Environment.IsDevelopment()) { app.UseSwagger(); app.UseSwaggerUI(); }
```

### Q121. What is Production environment?
Live environment: generic error messages, no stack traces to clients, HTTPS, real DB, secrets from vault, minimal logging. Default if nothing is set.

### Q122. What is launchSettings.json?
Used only during development (VS / `dotnet run`). Defines profiles, URLs, ports and environment variables. It is **not deployed**.

### Q123. What is wwwroot?
The folder for **static files** (HTML, CSS, JS, images) served directly when `app.UseStaticFiles()` is enabled. Mostly used in MVC/Razor apps.

### Q124. What is a Web API?
A service that exposes functionality over HTTP so other apps (React, mobile, other services) can call it and exchange data, usually JSON.

### Q125. What is ASP.NET Core Web API?
The framework feature to build HTTP APIs with controllers (or Minimal APIs), routing, model binding, validation and formatters.

### Q126. What is MVC?
**Model–View–Controller** pattern: Model (data), View (UI), Controller (handles request, picks view). Used for server-rendered web pages.

### Q127. Difference between MVC and Web API?
| MVC | Web API |
|---|---|
| Returns HTML views | Returns data (JSON/XML) |
| Inherits `Controller` | Inherits `ControllerBase` |
| For browsers | For any client |

### Q128. What is a Controller?
A class that receives HTTP requests, calls business logic and returns a response.

### Q129. What is an API Controller?
A controller marked with `[ApiController]`, inheriting `ControllerBase`, designed for HTTP APIs.
```csharp
[ApiController]
[Route("api/[controller]")]
public class UsersController : ControllerBase { }
```

### Q130. What does [ApiController] do?
Enables API conveniences: automatic **400 on invalid model**, automatic **binding source inference** (`[FromBody]` for complex types), required attribute routing, and **ProblemDetails** error responses.

### Q131. What is routing?
Matching an incoming URL + HTTP method to the correct action method.

### Q132. What is attribute routing?
Defining routes with attributes directly on controllers/actions.
```csharp
[HttpGet("api/users/{id}")]
public IActionResult Get(int id) => Ok();
```

### Q133. What is conventional routing?
Routes defined centrally using a pattern, mainly for MVC.
```csharp
app.MapControllerRoute(name: "default", pattern: "{controller=Home}/{action=Index}/{id?}");
```

### Q134. Difference between attribute routing and conventional routing?
Attribute: route next to the action, flexible, **recommended for APIs**. Conventional: one global pattern, good for MVC pages.

### Q135. What is [Route]?
Sets the URL template for a controller or action. `[controller]` is replaced by the class name without "Controller".
```csharp
[Route("api/[controller]")] // → api/users
```

### Q136. What is [HttpGet]?
Maps the action to HTTP GET (read data).
```csharp
[HttpGet("{id}")] public IActionResult GetById(int id) => Ok();
```

### Q137. What is [HttpPost]?
Maps to POST — create a new resource.

### Q138. What is [HttpPut]?
Maps to PUT — replace/update a whole resource.

### Q139. What is [HttpPatch]?
Maps to PATCH — partially update a resource (only some fields).

### Q140. What is [HttpDelete]?
Maps to DELETE — remove a resource.

### Q141. Difference between PUT and PATCH?
- **PUT**: send the **complete** object; replaces it. Idempotent.
- **PATCH**: send **only changed fields**.
Example: update only a user's phone → PATCH `{ "phone": "999" }`.

### Q142. What is ActionResult?
The base class of action results (`OkResult`, `NotFoundResult`…). `ActionResult` can represent any HTTP result without typed data.

### Q143. What is IActionResult?
Interface for any action result. Flexible — you can return different results (Ok, NotFound, BadRequest) from one method.

### Q144. What is ActionResult<T>?
Lets you return **either** a typed value `T` **or** an `ActionResult`; helps Swagger infer the response type.
```csharp
[HttpGet("{id}")]
public ActionResult<UserDto> Get(int id) {
    var u = _svc.Find(id);
    if (u == null) return NotFound();
    return u;  // implicit conversion
}
```

### Q145. Difference between IActionResult and ActionResult<T>?
`IActionResult` – no compile-time type, Swagger needs `[ProducesResponseType]`. `ActionResult<T>` – strongly typed, auto documentation, can return the object directly.

### Q146. What is model binding?
ASP.NET Core automatically maps request data (route, query, body, headers, form) to action parameters.
```csharp
[HttpPost] public IActionResult Create(CreateUserDto dto) { } // JSON → dto
```

### Q147. What is model validation?
Checking bound data against rules (Data Annotations/FluentValidation) before using it. Result is stored in `ModelState`.

### Q148. What is [FromBody]?
Reads data from the HTTP **body** (JSON). One per action.
```csharp
public IActionResult Create([FromBody] UserDto dto)
```

### Q149. What is [FromRoute]?
Reads from the **URL path**.
```csharp
[HttpGet("{id}")] public IActionResult Get([FromRoute] int id)
```

### Q150. What is [FromQuery]?
Reads from the **query string**: `/api/users?page=2&size=10`.
```csharp
public IActionResult List([FromQuery] int page = 1, [FromQuery] int size = 10)
```

# 🟡 Part 4 — RESTful API Concepts (Q151–200)

### Q151. What is REST?
An architectural **style** for designing networked APIs using HTTP, where everything is a **resource** identified by a URL and operated on with standard HTTP methods.

### Q152. What does REST stand for?
**RE**presentational **S**tate **T**ransfer.

### Q153. What are REST architectural principles?
1. Client–Server separation
2. Stateless
3. Cacheable
4. Uniform interface (resources, standard methods)
5. Layered system
6. Code on demand (optional)

### Q154. What is a RESTful API?
An API that follows REST principles: resource URLs (`/api/users/5`), correct HTTP verbs, proper status codes, stateless calls, JSON representation.

### Q155. Difference between REST API and Web API?
**Web API** = any API over HTTP. **REST API** = a Web API that follows REST rules. ASP.NET Core Web API is the *tool*; REST is the *style* you apply with it.

### Q156. What is a resource in REST?
Any "thing" the API exposes: user, order, product. Use **nouns** in URLs.
`GET /api/orders/42` ✅  `GET /api/getOrder?id=42` ❌

### Q157. What is statelessness in REST?
The server stores **no client session** between requests. Each request carries everything needed (e.g., JWT token in header).

### Q158. Why should REST APIs be stateless?
Easier to scale (any server can handle any request), simpler, more reliable, easier caching and load balancing.

### Q159. What is an HTTP request?
A message from client to server: **method + URL + headers + optional body**.
```
POST /api/users HTTP/1.1
Content-Type: application/json
{ "name": "Ali" }
```

### Q160. What is an HTTP response?
Server's reply: **status code + headers + optional body**.
```
HTTP/1.1 201 Created
Location: /api/users/5
{ "id": 5, "name": "Ali" }
```

### Q161. What is an HTTP method?
A verb that tells the server what action to do: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS.

### Q162. Explain GET.
Reads data. **Safe** (no change) and **idempotent**. No body. Cacheable. `GET /api/users/5`.

### Q163. Explain POST.
Creates a resource or triggers an action. **Not idempotent** — sending twice may create two records. Returns `201 Created`.

### Q164. Explain PUT.
Replaces an entire resource at a known URL. **Idempotent**. `PUT /api/users/5` with full body.

### Q165. Explain PATCH.
Partially updates a resource. Not guaranteed idempotent. `PATCH /api/users/5` `{ "phone": "123" }`.

### Q166. Explain DELETE.
Removes a resource. **Idempotent** (deleting again leaves same state). Returns `204` (or `200`).

### Q167. What is HEAD?
Like GET but returns **only headers, no body**. Used to check if a resource exists or its size/last-modified.

### Q168. What is OPTIONS?
Asks the server which methods/headers are allowed. Browsers use it for **CORS preflight** requests.

### Q169. Which HTTP method is idempotent?
GET, PUT, DELETE, HEAD, OPTIONS. (POST and PATCH are generally not.) *Idempotent* = calling many times gives the same final server state as calling once.

### Q170. Is POST idempotent?
No. Two identical POSTs can create two records (that's why payment APIs use an **Idempotency-Key** header).

### Q171. Is PUT idempotent?
Yes. Sending the same full object repeatedly results in the same state.

### Q172. Is DELETE idempotent?
Yes. The first call deletes; later calls change nothing (may return 404, but state is the same).

### Q173. What is an HTTP status code?
A 3-digit number telling the result of a request: 1xx info, 2xx success, 3xx redirect, 4xx client error, 5xx server error.

### Q174. Explain status code 200.
**OK** — request succeeded, response contains data (GET/PUT/PATCH).

### Q175. Explain status code 201.
**Created** — new resource created. Include a `Location` header.

### Q176. Explain status code 202.
**Accepted** — request accepted but processing is not finished (async/background job).

### Q177. Explain status code 204.
**No Content** — success with no response body (typical for DELETE/PUT).

### Q178. Explain status code 400.
**Bad Request** — client sent invalid/malformed data (bad JSON, missing field).

### Q179. Explain status code 401.
**Unauthorized** — not authenticated: no token, expired or invalid token.

### Q180. Explain status code 403.
**Forbidden** — authenticated but **not allowed** (e.g., a normal user calls an Admin API).

### Q181. Explain status code 404.
**Not Found** — resource/URL does not exist.

### Q182. Explain status code 405.
**Method Not Allowed** — URL exists but the HTTP method isn't supported (e.g., DELETE on a GET-only route).

### Q183. Explain status code 409.
**Conflict** — request conflicts with current state, e.g., duplicate email or concurrency conflict.

### Q184. Explain status code 422.
**Unprocessable Entity** — JSON is well-formed but fails business/validation rules (e.g., age = -5).

### Q185. Explain status code 429.
**Too Many Requests** — rate limit exceeded; often sends `Retry-After`.

### Q186. Explain status code 500.
**Internal Server Error** — unexpected server bug (unhandled exception). Never expose the stack trace to clients.

### Q187. Difference between 401 and 403?
- **401** = "Who are you?" (not logged in / bad token).
- **403** = "I know you, but you can't do this" (no permission).

### Q188. Difference between 400 and 422?
- **400** = request is malformed/can't be parsed.
- **422** = request is well-formed but semantically invalid. (Many APIs, including ASP.NET Core's default, use 400 for both.)

### Q189. When should an API return 201?
After a successful **POST that creates** a resource, with a `Location` header or the created object.

### Q190. When should an API return 204?
When the operation succeeded and there is nothing to return — typically DELETE or PUT.

### Q191. What is content negotiation?
Client and server agree on the response format using `Accept` header (JSON, XML). If unsupported → `406 Not Acceptable`.

### Q192. What is JSON?
JavaScript Object Notation — lightweight text format of key/value pairs.
```json
{ "id": 1, "name": "Ali", "roles": ["Admin","User"] }
```

### Q193. Why is JSON commonly used in REST APIs?
Small, human-readable, language-independent, natively supported by JavaScript/React/mobile, easy to parse.

### Q194. What are HTTP headers?
Key-value metadata sent with requests/responses: `Authorization`, `Content-Type`, `Accept`, `Cache-Control`, `Location`.

### Q195. What is the Content-Type header?
Tells the receiver the format of the **body being sent**: `Content-Type: application/json`.

### Q196. What is the Accept header?
Tells the server which format the client **wants back**: `Accept: application/json`.

### Q197. Difference between Content-Type and Accept?
Content-Type = "what I am sending". Accept = "what I want to receive".

### Q198. What is API versioning?
Managing changes to an API by exposing multiple versions (v1, v2) at the same time.

### Q199. Why is API versioning required?
To make **breaking changes** (rename field, change response) without breaking existing mobile apps/clients.

### Q200. What are different API versioning strategies?
1. **URL path**: `/api/v1/users` (most common)
2. **Query string**: `/api/users?api-version=1.0`
3. **Header**: `X-Api-Version: 1.0`
4. **Media type**: `Accept: application/vnd.myapi.v1+json`

```csharp
builder.Services.AddApiVersioning(o => { o.DefaultApiVersion = new ApiVersion(1,0); o.AssumeDefaultVersionWhenUnspecified = true; });
```

# 🟡 Part 5 — Controllers, Routing & Request/Response (Q201–250)

### Q201. How do you create a REST API controller?
```csharp
[ApiController]
[Route("api/[controller]")]
public class UsersController : ControllerBase
{
    private readonly IUserService _service;
    public UsersController(IUserService service) => _service = service;
}
```

### Q202. How do you create a GET API?
```csharp
[HttpGet]
public async Task<ActionResult<IEnumerable<UserDto>>> GetAll() => Ok(await _service.GetAllAsync());
```

### Q203. How do you create a POST API?
```csharp
[HttpPost]
public async Task<ActionResult<UserDto>> Create(CreateUserDto dto)
{
    var user = await _service.CreateAsync(dto);
    return CreatedAtAction(nameof(GetById), new { id = user.Id }, user);
}
```

### Q204. How do you create a PUT API?
```csharp
[HttpPut("{id:int}")]
public async Task<IActionResult> Update(int id, UpdateUserDto dto)
{
    var ok = await _service.UpdateAsync(id, dto);
    return ok ? NoContent() : NotFound();
}
```

### Q205. How do you create a DELETE API?
```csharp
[HttpDelete("{id:int}")]
public async Task<IActionResult> Delete(int id)
    => await _service.DeleteAsync(id) ? NoContent() : NotFound();
```

### Q206. How do you pass an ID through the URL?
Use a route parameter: `GET /api/users/5`.
```csharp
[HttpGet("{id:int}")] public IActionResult GetById(int id) => Ok();
```

### Q207. How do you pass parameters through query string?
`GET /api/users?name=ali&page=2`
```csharp
[HttpGet] public IActionResult Search([FromQuery] string? name, [FromQuery] int page = 1) => Ok();
```

### Q208. How do you receive JSON request body?
Use a DTO parameter (with `[FromBody]` optional under `[ApiController]`).
```csharp
[HttpPost] public IActionResult Create([FromBody] CreateUserDto dto) => Ok(dto);
```
Client must send `Content-Type: application/json`.

### Q209. How does model binding work?
ASP.NET Core checks value providers in order (form → route → query; body for complex types), converts text to .NET types and fills your parameter/DTO. Failures go to `ModelState`.

### Q210. What is DTO?
**Data Transfer Object** — a simple class used only to carry data between client and API (no business logic).
```csharp
public record UserDto(int Id, string Name, string Email);
```

### Q211. Why should DTOs be used in Web APIs?
Security (hide password hash), control the shape of data, avoid over-posting, decouple DB from API contract, enable versioning, smaller payloads.

### Q212. Difference between Entity Model and DTO?
- **Entity**: maps to a DB table (`User` with `PasswordHash`, navigation properties).
- **DTO**: what the API exposes/accepts (`UserDto`). Entities are internal, DTOs are public contract.

### Q213. What is Request DTO?
Data coming **into** the API.
```csharp
public class CreateUserDto { [Required] public string Name { get; set; } [EmailAddress] public string Email { get; set; } public string Password { get; set; } }
```

### Q214. What is Response DTO?
Data going **out** of the API (no sensitive fields).
```csharp
public class UserResponseDto { public int Id { get; set; } public string Name { get; set; } public string Email { get; set; } }
```

### Q215. Why should database entities not always be returned directly?
They may expose sensitive columns (password hash), cause **circular reference** JSON errors, tie the API to DB structure, load too much data, and allow lazy-loading surprises.

### Q216. What is over-posting?
Client sends extra fields that you did not intend to be set, e.g. `"isAdmin": true`, and model binding writes them into your entity (**mass assignment**).

### Q217. How can DTOs prevent over-posting?
DTO contains only allowed fields. Even if client sends `isAdmin`, it is ignored because the DTO has no such property.
```csharp
var user = new User { Name = dto.Name, Email = dto.Email, IsAdmin = false };
```

### Q218. What is object mapping?
Copying data from one object type to another (Entity ↔ DTO).

### Q219. How can you manually map Entity to DTO?
```csharp
var dto = new UserDto(user.Id, user.Name, user.Email);
// or with projection in EF Core
var list = await _db.Users.Select(u => new UserDto(u.Id, u.Name, u.Email)).ToListAsync();
```

### Q220. What is AutoMapper?
A library that maps objects automatically by matching property names.
```csharp
public class MapProfile : Profile { public MapProfile() => CreateMap<User, UserDto>().ReverseMap(); }
var dto = _mapper.Map<UserDto>(user);
```

### Q221. What are the advantages of AutoMapper?
Less repetitive code, central mapping rules, supports projection (`ProjectTo`), flattening and custom rules.

### Q222. What are the disadvantages of AutoMapper?
Hidden "magic", errors appear at runtime, harder debugging, slight performance cost, can hide wrong mappings. Many teams prefer manual mapping or Mapperly (source generator).

### Q223. How do you return a NotFound() response?
```csharp
var user = await _service.GetAsync(id);
if (user is null) return NotFound(); // 404
```

### Q224. How do you return a BadRequest() response?
```csharp
if (dto.Age < 0) return BadRequest("Age cannot be negative"); // 400
```

### Q225. How do you return CreatedAtAction()?
Returns 201 with a `Location` header pointing to the GET action.
```csharp
return CreatedAtAction(nameof(GetById), new { id = user.Id }, user);
```

### Q226. What is CreatedAtRoute()?
Same as above but uses a **named route** instead of an action name.
```csharp
[HttpGet("{id}", Name = "GetUser")] ...
return CreatedAtRoute("GetUser", new { id = user.Id }, user);
```

### Q227. Difference between Ok() and Created()?
`Ok()` → 200, for success of read/update. `Created()` → 201, a new resource was made and has a URI.

### Q228. How do you return a custom HTTP status code?
```csharp
return StatusCode(StatusCodes.Status418ImATeapot, new { message = "custom" });
return StatusCode(503, "Service unavailable");
```

### Q229. How do you return JSON from an API?
Return an object — `[ApiController]` formats it as JSON automatically.
```csharp
return Ok(new { Id = 1, Name = "Ali" });
```

### Q230. What happens if a controller returns an object?
The framework wraps it in `ObjectResult` with status 200 and serializes it using the output formatter based on `Accept` (JSON by default). Returning `null` gives `204`.

### Q231. What is serialization?
Converting a .NET object to text (JSON/XML) to send or store.
```csharp
string json = JsonSerializer.Serialize(user);
```

### Q232. What is deserialization?
Converting JSON text back to a .NET object.
```csharp
var user = JsonSerializer.Deserialize<User>(json);
```

### Q233. What is System.Text.Json?
Microsoft's built-in, fast, low-memory JSON library — the default in ASP.NET Core.

### Q234. Difference between System.Text.Json and Newtonsoft.Json?
| System.Text.Json | Newtonsoft.Json |
|---|---|
| Built in, faster | NuGet package, richer features |
| Strict by default | Very flexible |
| Fewer features (improving) | Better for complex/legacy scenarios |

### Q235. How do you configure JSON serialization?
```csharp
builder.Services.AddControllers().AddJsonOptions(o =>
{
    o.JsonSerializerOptions.PropertyNamingPolicy = JsonNamingPolicy.CamelCase;
    o.JsonSerializerOptions.DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull;
    o.JsonSerializerOptions.ReferenceHandler = ReferenceHandler.IgnoreCycles;
});
```

### Q236. How do you ignore a property during serialization?
```csharp
public class User { public string Name { get; set; } [JsonIgnore] public string PasswordHash { get; set; } }
```

### Q237. What is camelCase JSON?
Property names start lowercase: `userName` instead of `UserName`. It is the JavaScript/React convention.

### Q238. How do you configure camelCase?
ASP.NET Core Web API uses camelCase by default. To set explicitly: `PropertyNamingPolicy = JsonNamingPolicy.CamelCase` (see Q235).

### Q239. What is null value handling?
Deciding whether `null` properties appear in JSON.
```csharp
o.JsonSerializerOptions.DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull; // omit nulls
```

### Q240. What is model state?
`ModelState` is a dictionary holding binding/validation results and error messages for the request.

### Q241. What is ModelState.IsValid?
`true` if all validation rules passed.
```csharp
if (!ModelState.IsValid) return BadRequest(ModelState);
```

### Q242. What happens when [ApiController] detects invalid model state?
It **automatically returns 400** with a `ValidationProblemDetails` JSON; your action code does not even run.

### Q243. How do you customize validation errors?
```csharp
builder.Services.Configure<ApiBehaviorOptions>(o =>
{
    o.InvalidModelStateResponseFactory = ctx =>
    {
        var errors = ctx.ModelState.Where(x => x.Value!.Errors.Any())
            .ToDictionary(k => k.Key, v => v.Value!.Errors.Select(e => e.ErrorMessage));
        return new BadRequestObjectResult(new { success = false, errors });
    };
});
```

### Q244. What is [Required]?
Field must be present/non-null (for strings, non-empty by default).
```csharp
[Required(ErrorMessage = "Name is required")] public string Name { get; set; }
```

### Q245. What is [StringLength]?
Limits text length.
```csharp
[StringLength(50, MinimumLength = 2)] public string Name { get; set; }
```

### Q246. What is [Range]?
Limits numeric/date range.
```csharp
[Range(18, 60)] public int Age { get; set; }
```

### Q247. What is [EmailAddress]?
Validates email format.
```csharp
[EmailAddress] public string Email { get; set; }
```

### Q248. What is [RegularExpression]?
Validates against a regex.
```csharp
[RegularExpression(@"^\d{10}$", ErrorMessage = "Phone must be 10 digits")] public string Phone { get; set; }
```

### Q249. How do you create custom validation attributes?
```csharp
public class NoSpacesAttribute : ValidationAttribute
{
    protected override ValidationResult? IsValid(object? value, ValidationContext ctx)
        => value is string s && s.Contains(' ') ? new ValidationResult("Spaces not allowed") : ValidationResult.Success;
}
// usage: [NoSpaces] public string UserName { get; set; }
```

### Q250. How do you validate a complex request DTO?
Use nested DTOs with annotations (nested objects are validated), implement `IValidatableObject`, or use **FluentValidation**.
```csharp
public class OrderDto : IValidatableObject
{
    [Required] public List<OrderItemDto> Items { get; set; } = new();
    public IEnumerable<ValidationResult> Validate(ValidationContext c)
    {
        if (!Items.Any()) yield return new ValidationResult("At least one item required", new[] { nameof(Items) });
    }
}
// FluentValidation
public class CreateUserValidator : AbstractValidator<CreateUserDto>
{
    public CreateUserValidator() { RuleFor(x => x.Email).NotEmpty().EmailAddress(); RuleFor(x => x.Password).MinimumLength(8); }
}
```

# 🟠 Part 6 — Dependency Injection & Services (Q251–300)

### Q251. What is Dependency Injection?
A technique where a class **receives** the objects it needs (dependencies) from outside instead of creating them with `new`.
```csharp
public class OrderService(IEmailSender email) { /* email injected */ }
```

### Q252. Why is Dependency Injection used in ASP.NET Core?
Loose coupling, easy unit testing (mock dependencies), central object lifetime management, cleaner code, easy to swap implementations.

### Q253. What is IoC?
**Inversion of Control** — the framework (not your class) controls object creation and flow. DI is one way to achieve IoC.

### Q254. Difference between IoC and DI?
IoC is the **principle** (control is inverted). DI is a **pattern** implementing it (dependencies are injected).

### Q255. What are the benefits of DI?
Testability, maintainability, flexibility, reusability, follows SOLID (Dependency Inversion).

### Q256. What is constructor injection?
Dependencies passed via constructor. **Recommended.**
```csharp
public class UsersController(IUserService svc) : ControllerBase { }
```

### Q257. What is property injection?
Dependencies set through public properties. Not supported by the built-in container (needs Autofac etc.). Dependencies may be missing/null.

### Q258. What is method injection?
Dependency passed as a method parameter. In ASP.NET Core: `[FromServices]` in actions.
```csharp
public IActionResult Get([FromServices] IUserService svc) => Ok();
```

### Q259. Which DI approach is recommended in ASP.NET Core?
**Constructor injection** — dependencies are explicit, required and immutable (`readonly`).

### Q260. What is IServiceCollection?
The list where you **register** services at startup: `builder.Services`.

### Q261. What is IServiceProvider?
The built container that **resolves** (creates) registered services at runtime.
```csharp
var svc = provider.GetRequiredService<IUserService>();
```

### Q262. What is AddTransient()?
A **new instance every time** it is requested. For lightweight, stateless services.

### Q263. What is AddScoped()?
**One instance per HTTP request**. Same instance shared within a request. Most common for services/repositories/DbContext.

### Q264. What is AddSingleton()?
**One instance for the entire application lifetime**. Must be thread-safe. For caches, configuration, HttpClient factories.

### Q265. Difference between Transient, Scoped, and Singleton?
| Lifetime | Created | Example |
|---|---|---|
| Transient | Every injection | Small helper/validator |
| Scoped | Once per request | DbContext, UserService |
| Singleton | Once per app | In-memory cache, config |

### Q266. Which lifetime is normally used for DbContext?
**Scoped** (`AddDbContext` registers it as scoped by default).

### Q267. Why is DbContext usually scoped?
It is **not thread-safe**, tracks entities for a unit of work, and holds a DB connection. One per request keeps data isolated and disposes it at the end.

### Q268. What happens if a Singleton depends on a Scoped service?
It's the **captive dependency** problem: the scoped service gets captured and lives forever, causing stale data/thread-safety bugs. In Development, scope validation throws `InvalidOperationException: Cannot consume scoped service from singleton`. Fix: use `IServiceScopeFactory` inside the singleton.

### Q269. What is service registration?
Telling the container which interface maps to which class and with what lifetime.

### Q270. How do you register an interface and implementation?
```csharp
builder.Services.AddScoped<IUserService, UserService>();
builder.Services.AddScoped<IUserRepository, UserRepository>();
```

### Q271. How do you inject a service into a controller?
Add it to the constructor.
```csharp
public class UsersController : ControllerBase
{
    private readonly IUserService _svc;
    public UsersController(IUserService svc) { _svc = svc; }
}
```

### Q272. Why should business logic not be written directly inside controllers?
Controllers should only handle HTTP (read request, call service, return response). Logic in controllers is hard to test, reuse and maintain ("fat controller").

### Q273. What is the Service Layer?
A layer holding **business rules**, between controller and repository.
```csharp
public async Task<UserDto> RegisterAsync(CreateUserDto dto)
{
    if (await _repo.EmailExistsAsync(dto.Email)) throw new ConflictException("Email exists");
    ...
}
```

### Q274. What is Repository Pattern?
A class that hides data-access details behind an interface, so the rest of the app doesn't know whether data comes from SQL, Mongo or a file.
```csharp
public interface IUserRepository { Task<User?> GetByIdAsync(int id); Task AddAsync(User u); }
```

### Q275. What is Unit of Work?
A pattern that groups multiple repository operations into **one transaction** and commits them together with a single `SaveChanges`. EF Core `DbContext` already *is* a Unit of Work.

### Q276. Is Repository Pattern mandatory with EF Core?
No. `DbContext` already acts as repository + unit of work. Use repositories only if you want testability/abstraction or complex query reuse; otherwise it can be over-engineering.

### Q277. What is a generic repository?
One reusable repository for any entity.
```csharp
public interface IRepository<T> where T : class { Task<T?> GetByIdAsync(int id); Task<IEnumerable<T>> GetAllAsync(); Task AddAsync(T e); void Remove(T e); }
```

### Q278. What are disadvantages of generic repository?
Leaky abstraction, hides EF features (Include, projection), encourages loading full entities, can't express entity-specific queries well, extra layer with little value over `DbContext`.

### Q279. What is Clean Architecture?
Layered design where dependencies point **inward**: Domain (entities) ← Application (use cases, interfaces) ← Infrastructure (EF, email) ← API/UI. Business rules don't depend on frameworks or DB.

### Q280. What is separation of concerns?
Each part of the code has one responsibility: controller → HTTP, service → business logic, repository → data access.

### Q281. What is SOLID?
Five design principles: **S**ingle Responsibility, **O**pen/Closed, **L**iskov Substitution, **I**nterface Segregation, **D**ependency Inversion.

### Q282. Explain Single Responsibility Principle.
A class should have **one reason to change**. `InvoiceService` calculates invoices; `InvoicePdfGenerator` makes PDFs; `EmailSender` sends mails — not all in one class.

### Q283. Explain Open/Closed Principle.
Open for extension, closed for modification. Add new behavior by adding new classes, not editing old ones.
```csharp
public interface IDiscount { decimal Apply(decimal p); }
public class FestivalDiscount : IDiscount { public decimal Apply(decimal p) => p * 0.9m; }
```

### Q284. Explain Liskov Substitution Principle.
A child class must be usable wherever the parent is expected without breaking behavior. Bad: `Penguin : Bird` with `Fly()` that throws.

### Q285. Explain Interface Segregation Principle.
Many small specific interfaces are better than one big one. Don't force a class to implement methods it doesn't use (`IPrinter`, `IScanner` instead of `IMultiFunctionDevice`).

### Q286. Explain Dependency Inversion Principle.
High-level modules should depend on **abstractions**, not concrete classes.
```csharp
// ❌ var mail = new SmtpMailer();
// ✅ constructor receives IMailer
```

### Q287. How does DI support SOLID?
Mostly **D** (inject abstractions), also helps **O** (swap implementations), **S** (small focused classes), **L/I** (interface-based design).

### Q288. What is tight coupling?
A class directly depends on a concrete class (`new SqlUserRepo()`). Hard to change or test.

### Q289. What is loose coupling?
A class depends on interfaces, so implementations can change without touching it.

### Q290. How do you unit test a service using DI?
Pass fake/mock dependencies to the constructor.
```csharp
var repo = new Mock<IUserRepository>();
repo.Setup(r => r.GetByIdAsync(1)).ReturnsAsync(new User { Id = 1 });
var svc = new UserService(repo.Object);
var result = await svc.GetAsync(1);
Assert.NotNull(result);
```

### Q291. What is mocking?
Creating fake objects that imitate real dependencies so you can test a class in isolation (no real DB/email).

### Q292. What is Moq?
A popular .NET mocking library. `new Mock<IEmailService>()`, `Setup`, `Returns`, `Verify`.
```csharp
mock.Verify(m => m.Send(It.IsAny<string>(), It.IsAny<string>()), Times.Once);
```

### Q293. What is an abstraction?
An interface/abstract class describing *what* something does, hiding *how*. e.g. `IPaymentGateway`.

### Q294. Why should controllers depend on interfaces?
So they can use any implementation, be unit-tested with mocks, and follow Dependency Inversion.

### Q295. What happens when a dependency is not registered?
The app fails when it tries to create the class — for controllers, the request fails with a 500 error (`InvalidOperationException`).

### Q296. What exception occurs when DI cannot resolve a service?
`System.InvalidOperationException: Unable to resolve service for type 'IUserService' while attempting to activate 'UsersController'.`
Fix: `builder.Services.AddScoped<IUserService, UserService>();`

### Q297. How do you register multiple implementations of one interface?
```csharp
builder.Services.AddScoped<INotifier, EmailNotifier>();
builder.Services.AddScoped<INotifier, SmsNotifier>();
// inject IEnumerable<INotifier> to get all
public class AlertService(IEnumerable<INotifier> notifiers) { }
```
Injecting a single `INotifier` gives the **last** registered one.

### Q298. How do you select a specific implementation?
Use a factory/delegate, a resolver class, or keyed services.
```csharp
builder.Services.AddScoped<Func<string, INotifier>>(sp => key => key switch
{
    "email" => sp.GetRequiredService<EmailNotifier>(),
    "sms"   => sp.GetRequiredService<SmsNotifier>(),
    _ => throw new ArgumentException()
});
```

### Q299. What is keyed service registration?
Built into .NET 8: register and inject services by a **key**.
```csharp
builder.Services.AddKeyedScoped<INotifier, EmailNotifier>("email");
builder.Services.AddKeyedScoped<INotifier, SmsNotifier>("sms");
public class AlertService([FromKeyedServices("email")] INotifier notifier) { }
```

### Q300. Explain the complete request flow through Controller → Service → Repository → Database.
1. Client sends `POST /api/users` (JSON).
2. Kestrel → middleware pipeline (HTTPS, CORS, Auth, exception handling).
3. Routing picks `UsersController.Create`; model binding builds the DTO; validation runs.
4. **Controller** calls `_service.CreateAsync(dto)`.
5. **Service** applies business rules (duplicate check, hash password), maps DTO → Entity.
6. **Repository** adds the entity via EF Core.
7. `SaveChangesAsync()` generates SQL `INSERT` and executes in the **Database**.
8. Result goes back up: Repository → Service (maps Entity → DTO) → Controller returns `201 Created`.
9. Response passes back through middleware to the client as JSON.

```csharp
// Controller
[HttpPost] public async Task<IActionResult> Create(CreateUserDto dto) { var u = await _svc.CreateAsync(dto); return CreatedAtAction(nameof(Get), new { id = u.Id }, u); }
// Service
public async Task<UserDto> CreateAsync(CreateUserDto dto) { var e = new User{ Name = dto.Name, Email = dto.Email }; await _repo.AddAsync(e); await _repo.SaveAsync(); return new UserDto(e.Id, e.Name, e.Email); }
// Repository
public async Task AddAsync(User u) => await _db.Users.AddAsync(u);
public Task SaveAsync() => _db.SaveChangesAsync();
```

# 🟠 Part 7 — EF Core & Database (Q301–350)

### Q301. What is Entity Framework Core?
A lightweight, open-source, cross-platform **ORM** from Microsoft. You work with C# classes and LINQ; EF Core generates SQL.

### Q302. What is ORM?
**Object-Relational Mapper** — maps database tables to C# classes and rows to objects, so you avoid writing raw SQL for everyday work.

### Q303. Why use EF Core?
Less boilerplate, LINQ queries with compile-time checking, migrations, change tracking, supports many databases (SQL Server, PostgreSQL, MySQL, SQLite), protects from SQL injection by default.

### Q304. What is DbContext?
The main class that represents a **session with the database**: queries, tracks changes, saves data.
```csharp
public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options) { }
    public DbSet<User> Users => Set<User>();
}
```

### Q305. What is DbSet?
A property on DbContext representing a **table**. `db.Users` = Users table.

### Q306. How do you configure DbContext?
```csharp
builder.Services.AddDbContext<AppDbContext>(o =>
    o.UseSqlServer(builder.Configuration.GetConnectionString("Default")));
```

### Q307. What is a connection string?
Text containing information to connect to a database: server, database, credentials.
`Server=localhost;Database=AppDb;User Id=sa;Password=***;TrustServerCertificate=True;`

### Q308. Where should the connection string be stored?
Not in code. Use `appsettings.json` for non-secret dev values; **User Secrets** (local), **environment variables**, **Azure Key Vault / AWS Secrets Manager** for production.

### Q309. Why should passwords not be hardcoded in source code?
Source code goes to Git and many people can see it; leaked credentials = database breach. Rotating a hardcoded password needs redeployment.

### Q310. What is Code First?
Write C# entity classes first; EF Core creates/updates the database through migrations. Best for new projects.

### Q311. What is Database First?
Database already exists; EF generates classes from it (`dotnet ef dbcontext scaffold`).
```bash
dotnet ef dbcontext scaffold "Server=.;Database=Shop;Trusted_Connection=True;" Microsoft.EntityFrameworkCore.SqlServer
```

### Q312. Difference between Code First and Database First?
| Code First | Database First |
|---|---|
| Classes → DB | DB → classes |
| Migrations manage schema | DBA manages schema |
| New projects | Legacy databases |

### Q313. What is migration?
A versioned C# file describing a schema change (create table, add column) that EF can apply or roll back.

### Q314. Why are migrations used?
To keep the database schema in sync with your model, track history in source control, and deploy schema changes safely across environments.

### Q315. How do you create a migration?
```bash
dotnet ef migrations add AddUserTable
```
(Package Manager Console: `Add-Migration AddUserTable`)

### Q316. How do you apply a migration?
```bash
dotnet ef database update
```
Or in code: `await db.Database.MigrateAsync();`

### Q317. How do you remove the last migration?
```bash
dotnet ef migrations remove
```
Works only if it has not been applied to the DB (otherwise run `database update <PreviousMigration>` first).

### Q318. What is EnsureCreated()?
Creates the database and tables from the model if the DB doesn't exist. Quick for demos/tests.

### Q319. Difference between EnsureCreated() and migrations?
`EnsureCreated` does **not** use migrations, can't update an existing schema, and can't be mixed with migrations. Use **migrations** in real applications.

### Q320. What is entity configuration?
Defining how a class maps to a table: key, column types, lengths, relations, indexes — via Data Annotations or Fluent API.

### Q321. What is Fluent API?
Configuring the model in code, inside `OnModelCreating`, using method chaining.
```csharp
protected override void OnModelCreating(ModelBuilder mb)
{
    mb.Entity<User>().Property(u => u.Email).IsRequired().HasMaxLength(200);
}
```

### Q322. What are data annotations?
Attributes on the entity class for configuration.
```csharp
public class User { [Key] public int Id { get; set; } [Required, MaxLength(200)] public string Email { get; set; } }
```

### Q323. Difference between Fluent API and Data Annotations?
Annotations: simple, on the class, limited. Fluent API: more powerful (composite keys, delete behavior, indexes), keeps entities clean, **takes priority** over annotations.

### Q324. What is a primary key?
A column (or set) that **uniquely identifies** each row; cannot be null. EF treats `Id` or `ClassNameId` as PK by convention.

### Q325. What is a foreign key?
A column that references the primary key of another table to link rows. `Order.UserId` → `User.Id`.

### Q326. What is a composite primary key?
A key made of two or more columns, e.g., `UserRole(UserId, RoleId)`.
```csharp
mb.Entity<UserRole>().HasKey(ur => new { ur.UserId, ur.RoleId });
```

### Q327. What is a navigation property?
A property that references related entity(ies), letting you traverse relationships.
```csharp
public class Order { public int UserId { get; set; } public User User { get; set; } }
public class User { public List<Order> Orders { get; set; } = new(); }
```

### Q328. What is one-to-one relationship?
One row in A relates to exactly one row in B. Example: `User` ↔ `UserProfile`.
```csharp
mb.Entity<User>().HasOne(u => u.Profile).WithOne(p => p.User).HasForeignKey<UserProfile>(p => p.UserId);
```

### Q329. What is one-to-many relationship?
One row in A relates to many in B. Example: one `Customer` has many `Orders`.
```csharp
mb.Entity<Customer>().HasMany(c => c.Orders).WithOne(o => o.Customer).HasForeignKey(o => o.CustomerId);
```

### Q330. What is many-to-many relationship?
Many rows in A relate to many in B via a join table. Example: `User` ↔ `Role` through `UserRole`.
```csharp
mb.Entity<UserRole>().HasKey(x => new { x.UserId, x.RoleId });
mb.Entity<UserRole>().HasOne(x => x.User).WithMany(u => u.UserRoles).HasForeignKey(x => x.UserId);
mb.Entity<UserRole>().HasOne(x => x.Role).WithMany(r => r.UserRoles).HasForeignKey(x => x.RoleId);
```

### Q331. How do you configure relationships in EF Core?
By **convention** (navigation + FK property names), with **Data Annotations** (`[ForeignKey]`), or with **Fluent API** (`HasOne/WithMany/HasForeignKey/OnDelete`) — Fluent API is most explicit.

### Q332. What is cascade delete?
When a parent row is deleted, its dependent child rows are **automatically deleted**. Deleting an `Order` deletes its `OrderItems`.

### Q333. What is DeleteBehavior.Cascade?
EF/DB deletes dependents when principal is deleted. Default for **required** relationships.
```csharp
.OnDelete(DeleteBehavior.Cascade)
```

### Q334. What is DeleteBehavior.Restrict?
Prevents deleting the parent if children exist (throws an exception). Safe for important data.
```csharp
.OnDelete(DeleteBehavior.Restrict)
```

### Q335. What is DeleteBehavior.NoAction?
EF does nothing; the **database** enforces the FK and rejects the delete if children exist (similar result to Restrict, but enforced only by DB).

### Q336. When should cascade delete be avoided?
When children are independent/valuable (Users shouldn't vanish if a Role is deleted), or when multiple cascade paths exist (SQL Server error "may cause cycles"), and for audit/financial data (prefer soft delete).

### Q337. How do you prevent deleting Users when deleting a Role?
Make the relation between `UserRole`→`User` not cascade from Role. The Role→UserRole can cascade, but **UserRole→User must not delete User** (it never does — User is the principal, UserRole is the dependent). If `User` has a direct `RoleId` FK, use `Restrict`:
```csharp
mb.Entity<User>().HasOne(u => u.Role).WithMany(r => r.Users)
  .HasForeignKey(u => u.RoleId).OnDelete(DeleteBehavior.Restrict);
```

### Q338. How do you delete related UserRole records when a Role is deleted?
Cascade only the join table:
```csharp
mb.Entity<UserRole>().HasOne(ur => ur.Role).WithMany(r => r.UserRoles)
  .HasForeignKey(ur => ur.RoleId).OnDelete(DeleteBehavior.Cascade);
mb.Entity<UserRole>().HasOne(ur => ur.User).WithMany(u => u.UserRoles)
  .HasForeignKey(ur => ur.UserId).OnDelete(DeleteBehavior.Cascade);
```
Deleting a Role removes only its `UserRole` rows; **Users remain**. (Deleting a User removes that user's UserRole rows too.) Or delete manually in a transaction (see Q498).

### Q339. What is eager loading?
Load related data **together** in the same query using `Include`.
```csharp
var users = await db.Users.Include(u => u.Orders).ToListAsync();
```

### Q340. What is lazy loading?
Related data loads **automatically when first accessed** (needs proxies package + virtual navigation properties). Can cause N+1 queries — avoid in APIs.

### Q341. What is explicit loading?
You manually load related data later.
```csharp
await db.Entry(user).Collection(u => u.Orders).LoadAsync();
```

### Q342. Difference between Include and ThenInclude?
`Include` loads the first-level related entity; `ThenInclude` goes one level deeper.
```csharp
db.Users.Include(u => u.UserRoles).ThenInclude(ur => ur.Role);
```

### Q343. What is tracking in EF Core?
EF remembers loaded entities and their original values (change tracker) so `SaveChanges` can detect modifications and generate UPDATE statements.

### Q344. What is AsNoTracking()?
Tells EF **not to track** results — faster and uses less memory for read-only queries.
```csharp
var list = await db.Users.AsNoTracking().ToListAsync();
```

### Q345. When should AsNoTracking() be used?
For read-only GET endpoints, reports, large lists. Do **not** use it when you plan to modify and save the same entities.

### Q346. What is SaveChanges()?
Sends all pending inserts/updates/deletes tracked by the context to the DB in one transaction. Returns number of affected rows.

### Q347. What is SaveChangesAsync()?
Async version — frees the thread while waiting for DB.
```csharp
await db.SaveChangesAsync();
```

### Q348. Difference between synchronous and asynchronous database operations?
Sync blocks the thread until DB responds. Async releases the thread so the server handles more requests → better scalability under load. Always use async in APIs.

### Q349. What is concurrency in EF Core?
Two users changing the same row at the same time, which can cause lost updates.

### Q350. What is optimistic concurrency?
Assume conflicts are rare; detect them at save time using a **concurrency token** (e.g., `RowVersion`). If the row changed since read, EF throws `DbUpdateConcurrencyException`.
```csharp
public class Product { public int Id { get; set; } [Timestamp] public byte[] RowVersion { get; set; } }
try { await db.SaveChangesAsync(); }
catch (DbUpdateConcurrencyException) { return Conflict("Record was modified by another user"); }
```

# 🔴 Part 8 — EF Core Practical & Performance (Q351–400)

### Q351. Write an EF Core query to retrieve all users.
```csharp
var users = await _db.Users.AsNoTracking().ToListAsync();
```

### Q352. Write an EF Core query to retrieve a user by ID.
```csharp
var user = await _db.Users.AsNoTracking().FirstOrDefaultAsync(u => u.Id == id);
```

### Q353. Write an EF Core query to retrieve users by role.
```csharp
var admins = await _db.Users
    .Where(u => u.UserRoles.Any(ur => ur.Role.Name == "Admin"))
    .Select(u => new UserDto(u.Id, u.Name, u.Email))
    .ToListAsync();
```

### Q354. How do you insert a record using EF Core?
```csharp
_db.Users.Add(new User { Name = "Ali", Email = "ali@x.com" });
await _db.SaveChangesAsync();
```

### Q355. How do you update a record using EF Core?
```csharp
var user = await _db.Users.FindAsync(id);
if (user is null) return NotFound();
user.Name = dto.Name;
await _db.SaveChangesAsync();
// bulk (EF 7+)
await _db.Users.Where(u => u.IsActive == false).ExecuteUpdateAsync(s => s.SetProperty(u => u.Status, "Inactive"));
```

### Q356. How do you delete a record using EF Core?
```csharp
var user = await _db.Users.FindAsync(id);
if (user != null) { _db.Users.Remove(user); await _db.SaveChangesAsync(); }
// or without loading (EF 7+)
await _db.Users.Where(u => u.Id == id).ExecuteDeleteAsync();
```

### Q357. How do you delete all records using EF Core?
```csharp
await _db.Users.ExecuteDeleteAsync();             // EF 7+, single SQL DELETE
// older: _db.Users.RemoveRange(_db.Users); await _db.SaveChangesAsync();  (loads everything — slow)
```

### Q358. How do you check whether a record exists?
```csharp
bool exists = await _db.Users.AnyAsync(u => u.Email == email);
```

### Q359. Difference between FindAsync() and FirstOrDefaultAsync()?
- `FindAsync(id)`: searches by **primary key**, checks the **change tracker (cache) first** — may skip DB.
- `FirstOrDefaultAsync(predicate)`: always queries DB, any condition, supports `Include`, `AsNoTracking`.

### Q360. Difference between AnyAsync() and CountAsync()?
`AnyAsync` → SQL `EXISTS`, stops at first match (fast). `CountAsync` → `COUNT(*)`, scans all matches. Use `AnyAsync` to check existence.

### Q361. What is projection in EF Core?
Selecting only the columns you need (usually into a DTO) with `Select`.
```csharp
var names = await _db.Users.Select(u => new { u.Id, u.Name }).ToListAsync();
```

### Q362. Why use Select() instead of retrieving complete entities?
Smaller SQL (`SELECT Id, Name`), less memory, faster, no tracking overhead, no sensitive columns leaked.

### Q363. What is the N+1 query problem?
1 query to fetch N parents + N extra queries (one per parent) to fetch children → 1+N database calls.
```csharp
var users = await _db.Users.ToListAsync();               // 1 query
foreach (var u in users) Console.WriteLine(u.Orders.Count); // +N queries with lazy loading
```

### Q364. How can you solve the N+1 query problem?
Use `Include`, projection with `Select`, or `AsSplitQuery`.
```csharp
var users = await _db.Users.Include(u => u.Orders).ToListAsync();
var data = await _db.Users.Select(u => new { u.Name, OrderCount = u.Orders.Count }).ToListAsync();
```

### Q365. What is query execution?
The moment EF translates LINQ to SQL, sends it to the DB and materializes results.

### Q366. When does an EF Core LINQ query execute?
On enumeration or an immediate operator: `ToList/ToListAsync`, `First*`, `Single*`, `Count`, `Any`, `Sum`, `foreach`. Building `Where/Select/OrderBy` doesn't run it.

### Q367. Why should ToList() not be called too early?
It pulls **all rows into memory** first; later `Where/Skip/Take` then run in C#, not SQL.
```csharp
// ❌ loads entire table
db.Users.ToList().Where(u => u.IsActive).Take(10);
// ✅ SQL does the filtering
await db.Users.Where(u => u.IsActive).Take(10).ToListAsync();
```

### Q368. What is client-side evaluation?
Part of the query runs in C# memory after data is loaded because EF couldn't translate it to SQL. Can be slow; EF Core 3+ throws an error for most cases instead of silently doing it.

### Q369. What is server-side evaluation?
The whole query is translated to SQL and run in the database. This is what you want.

### Q370. How do you optimize a slow EF Core query?
`AsNoTracking`, project with `Select`, add **indexes**, filter early, **paginate**, avoid N+1, avoid `ToList` early, use `AsSplitQuery` for big includes, check the generated SQL/execution plan, use compiled queries/caching if needed.

### Q371. How do database indexes improve API performance?
An index is like a book's index: DB finds rows without scanning the whole table (O(log n) vs O(n)). Add indexes on columns used in `WHERE`, `JOIN`, `ORDER BY`. Trade-off: slower writes and more storage.

### Q372. What is a unique index?
An index that **forbids duplicate values** in a column (or combination). Perfect for email/username.

### Q373. How do you create a unique index using EF Core?
```csharp
mb.Entity<User>().HasIndex(u => u.Email).IsUnique();
```
Then run a migration.

### Q374. How do you handle duplicate email records?
1. Check first: `AnyAsync(u => u.Email == email)` → return `409 Conflict`.
2. Enforce with a **unique index** (the real protection against race conditions).
3. Catch `DbUpdateException` as a safety net.

### Q375. What happens if you insert duplicate values into a unique column?
The DB rejects the insert with a unique-constraint error (SQL Server 2601/2627); EF throws `DbUpdateException` wrapping `SqlException`.

### Q376. How do you handle DbUpdateException?
```csharp
try { await _db.SaveChangesAsync(); }
catch (DbUpdateException ex) when (ex.InnerException is SqlException { Number: 2601 or 2627 })
{
    throw new ConflictException("Email already exists");
}
```

### Q377. What is a transaction?
A group of DB operations that succeed **all or none** (ACID). Example: money transfer — debit and credit must both happen.

### Q378. How do you create a transaction in EF Core?
`SaveChanges` is already one transaction. For multiple saves:
```csharp
await using var tx = await _db.Database.BeginTransactionAsync();
try
{
    _db.Accounts.Update(from); await _db.SaveChangesAsync();
    _db.Accounts.Update(to);   await _db.SaveChangesAsync();
    await tx.CommitAsync();
}
catch { await tx.RollbackAsync(); throw; }
```

### Q379. Why are transactions important?
Keep data **consistent** — no half-completed operations (order created but payment not saved).

### Q380. What is rollback?
Undoing all changes made in the current transaction.

### Q381. What is commit?
Permanently saving all changes made in the transaction.

### Q382. What is connection pooling?
Reusing a set of open DB connections instead of opening/closing for each request — opening connections is expensive. ADO.NET does it automatically; `AddDbContextPool` pools DbContext instances.

### Q383. How does EF Core manage database connections?
It opens a connection **just before** executing a command and closes it right after `SaveChanges`/query completes (returns it to the pool). Inside an explicit transaction it stays open until commit/rollback.

### Q384. What is SQL injection?
An attack where user input is inserted into SQL text and changes the query.
`' OR 1=1 --` in a login box can bypass authentication if SQL is built by string concatenation.

### Q385. Does LINQ prevent SQL injection?
Yes — LINQ queries are **parameterized** automatically. Danger appears only with raw SQL built by string concatenation.

### Q386. How does parameterized SQL protect against SQL injection?
Input is sent as a **parameter value**, never as SQL code, so the DB treats it as data only.
```sql
SELECT * FROM Users WHERE Email = @p0   -- @p0 = "' OR 1=1 --" is just a harmless string
```

### Q387. Difference between FromSqlRaw() and FromSqlInterpolated()?
- `FromSqlRaw("... {0}", x)` — you must use parameters yourself; string concatenation here is unsafe.
- `FromSqlInterpolated($"... {x}")` — C# interpolation is **converted to parameters** automatically (safe).
```csharp
var u = db.Users.FromSqlInterpolated($"SELECT * FROM Users WHERE Email = {email}").ToList();
// ❌ db.Users.FromSqlRaw("SELECT * FROM Users WHERE Email = '" + email + "'")  — injection risk
```

### Q388. When should raw SQL be used?
For complex/optimized queries LINQ can't express, stored procedures, DB-specific features, bulk operations, reports — always parameterized.

### Q389. What is stored procedure integration with EF Core?
EF Core can execute stored procedures to return entities/DTOs or run commands, mixing them with normal LINQ code.

### Q390. How do you call a stored procedure from EF Core?
```csharp
// returns data
var users = await _db.Users.FromSqlInterpolated($"EXEC GetActiveUsers {minAge}").ToListAsync();
// no result set
await _db.Database.ExecuteSqlInterpolatedAsync($"EXEC DeactivateUser {id}");
```

### Q391. What is database normalization?
Organizing tables to **remove duplicate data** and keep integrity (1NF, 2NF, 3NF). Store customer address once in `Customers`, not in every `Order`.

### Q392. What is denormalization?
Deliberately adding redundancy (copying data) to speed up reads, e.g., storing `CustomerName` in the `Orders` table for reports. Trade-off: harder to keep consistent.

### Q393. What is a database deadlock?
Two transactions each hold a lock the other needs and wait forever; the DB kills one (victim) with error 1205.

### Q394. How can deadlocks be reduced?
Access tables/rows in the **same order**, keep transactions **short**, add proper indexes, use lower isolation levels/RCSI, avoid user interaction inside transactions, retry on deadlock error.

### Q395. What is database timeout?
The max time to wait for a command/connection (default 30s for SqlClient). If exceeded, an error is thrown.

### Q396. How do you handle database timeout exceptions?
Find why it's slow (index, big query, locks), then fix. Optionally increase timeout, add retry (`EnableRetryOnFailure`), paginate, catch and return `503/504`.
```csharp
o.UseSqlServer(cs, sql => { sql.CommandTimeout(60); sql.EnableRetryOnFailure(3); });
```

### Q397. How would you troubleshoot an API that is slow because of database queries?
1. Measure (Application Insights/MiniProfiler/logs).
2. Log generated SQL, find slow ones.
3. Check execution plan & missing indexes.
4. Fix N+1, add `AsNoTracking`, projection, pagination.
5. Cache read-heavy data.
6. Re-measure.

### Q398. How would you identify generated SQL from EF Core?
```csharp
var sql = _db.Users.Where(u => u.IsActive).ToQueryString();   // see SQL
// or logging
o.UseSqlServer(cs).LogTo(Console.WriteLine, LogLevel.Information).EnableSensitiveDataLogging();
```
Also SQL Profiler / Extended Events.

### Q399. How would you optimize an API returning 100,000 database records?
Never return all. Use **pagination** (`Skip/Take`), filtering/search, projection to DTO, `AsNoTracking`, indexes, enforce max page size (e.g., 100), maybe streaming (`IAsyncEnumerable`) or export-to-file/background job for huge exports, and caching/compression.

### Q400. How would you implement pagination using EF Core?
```csharp
[HttpGet]
public async Task<IActionResult> Get(int page = 1, int pageSize = 10)
{
    pageSize = Math.Clamp(pageSize, 1, 100);
    var query = _db.Users.AsNoTracking().OrderBy(u => u.Id);   // stable ordering is required
    var total = await query.CountAsync();
    var items = await query.Skip((page - 1) * pageSize).Take(pageSize)
                           .Select(u => new UserDto(u.Id, u.Name, u.Email)).ToListAsync();
    return Ok(new { page, pageSize, total, totalPages = (int)Math.Ceiling(total / (double)pageSize), items });
}
```
For huge tables prefer **keyset (cursor) pagination**: `Where(u => u.Id > lastId).Take(n)`.

# 🔴 Part 9 — Middleware, Authentication & Authorization (Q401–450)

### Q401. What is middleware in ASP.NET Core?
A small component in the request pipeline that can inspect/modify the request, call the next component, and inspect/modify the response. Examples: HTTPS redirection, CORS, authentication, exception handling, logging.

### Q402. How does middleware work?
Each middleware receives `HttpContext` and a `next` delegate. It does work **before** `next()`, calls `next()` to pass control forward, and does work **after** `next()` on the way back.
```csharp
app.Use(async (ctx, next) =>
{
    Console.WriteLine("Before");
    await next();
    Console.WriteLine("After");
});
```

### Q403. What is the middleware pipeline?
The ordered chain of middleware. The request goes through them top → bottom; the response returns bottom → top.
`Request → Exception → HTTPS → CORS → Auth → Authorization → Endpoint → Response`

### Q404. What is Use()?
Adds middleware that **can call the next** middleware.

### Q405. What is Run()?
Adds **terminal** middleware — it ends the pipeline and doesn't call `next`.
```csharp
app.Run(async ctx => await ctx.Response.WriteAsync("End of pipeline"));
```

### Q406. What is Map()?
Branches the pipeline based on the **request path**.
```csharp
app.Map("/health-check", b => b.Run(async c => await c.Response.WriteAsync("OK")));
```

### Q407. Difference between Use, Run, and Map?
| Method | Purpose |
|---|---|
| Use | Middleware that may call next |
| Run | Terminal, no next |
| Map | Branch pipeline by path |

### Q408. Why does middleware order matter?
They execute in registration order. Wrong order breaks features, e.g., authorization before authentication, or CORS after endpoint.
Typical order: ExceptionHandler → HTTPS → StaticFiles → Routing → CORS → Authentication → Authorization → Endpoints.

### Q409. What happens if authentication middleware is placed incorrectly?
`[Authorize]` endpoints always return **401/403** because `User` was never populated; or authentication runs after endpoints so it never executes. `UseAuthentication()` must come **before** `UseAuthorization()` and before `MapControllers()`.

### Q410. What is exception-handling middleware?
Middleware that catches unhandled exceptions from later components and returns a controlled response (`UseExceptionHandler`, `UseDeveloperExceptionPage`, or custom). Place it **first** in the pipeline.

### Q411. How do you create custom middleware?
```csharp
public class RequestTimingMiddleware
{
    private readonly RequestDelegate _next;
    public RequestTimingMiddleware(RequestDelegate next) => _next = next;

    public async Task InvokeAsync(HttpContext ctx)
    {
        var sw = Stopwatch.StartNew();
        await _next(ctx);
        sw.Stop();
        ctx.Response.Headers["X-Elapsed-Ms"] = sw.ElapsedMilliseconds.ToString();
    }
}
app.UseMiddleware<RequestTimingMiddleware>();
```

### Q412. How do you log requests using middleware?
```csharp
public class RequestLoggingMiddleware(RequestDelegate next, ILogger<RequestLoggingMiddleware> logger)
{
    public async Task InvokeAsync(HttpContext ctx)
    {
        logger.LogInformation("→ {Method} {Path}", ctx.Request.Method, ctx.Request.Path);
        await next(ctx);
        logger.LogInformation("← {Status}", ctx.Response.StatusCode);
    }
}
```
(Built-in alternative: `app.UseHttpLogging()`.) Never log passwords/tokens.

### Q413. How do you implement global exception handling?
```csharp
public class ExceptionMiddleware(RequestDelegate next, ILogger<ExceptionMiddleware> log)
{
    public async Task InvokeAsync(HttpContext ctx)
    {
        try { await next(ctx); }
        catch (NotFoundException ex)  { await Write(ctx, 404, ex.Message); }
        catch (ConflictException ex)  { await Write(ctx, 409, ex.Message); }
        catch (Exception ex)
        {
            log.LogError(ex, "Unhandled exception");
            await Write(ctx, 500, "An unexpected error occurred");
        }
    }
    private static Task Write(HttpContext c, int code, string msg)
    {
        c.Response.StatusCode = code; c.Response.ContentType = "application/json";
        return c.Response.WriteAsJsonAsync(new { status = code, message = msg });
    }
}
// .NET 8 alternative: IExceptionHandler + builder.Services.AddExceptionHandler<GlobalExceptionHandler>(); app.UseExceptionHandler();
```

### Q414. What is authentication?
Verifying **who you are** (login with username/password, token).

### Q415. What is authorization?
Deciding **what you are allowed to do** after you are authenticated (roles, permissions).

### Q416. Difference between authentication and authorization?
Authentication = identity ("Who are you?" → 401). Authorization = permission ("Can you do this?" → 403). Example: airport — passport check vs boarding-pass/lounge access.

### Q417. What is JWT?
**JSON Web Token** — a compact, signed token that carries user information (claims). The server verifies the signature without looking up a session.

### Q418. Why is JWT commonly used in REST APIs?
APIs are stateless; JWT lets each request prove identity with no server session. Works across web, mobile, microservices; self-contained and scalable.

### Q419. What are the parts of a JWT?
`header.payload.signature` — three Base64Url parts separated by dots.

### Q420. What is JWT Header?
Metadata: algorithm and type. `{ "alg": "HS256", "typ": "JWT" }`

### Q421. What is JWT Payload?
The claims (data): user id, role, expiry. `{ "sub": "5", "role": "Admin", "exp": 1767225600 }`
It is **encoded, not encrypted** — never put passwords/secrets inside.

### Q422. What is JWT Signature?
`HMACSHA256(base64(header) + "." + base64(payload), secret)`. Proves the token was not modified and was issued by someone with the key.

### Q423. What are JWT claims?
Statements about the user: registered ones (`iss, sub, aud, exp, nbf, iat`) and custom ones (`role`, `email`, `tenantId`).

### Q424. What is an access token?
A short-lived token (5–30 minutes) sent with every API request in `Authorization: Bearer <token>`.

### Q425. What is a refresh token?
A long-lived random token (days) stored securely and used **only** to get a new access token after the old one expires — without logging in again.

### Q426. Difference between access token and refresh token?
| Access | Refresh |
|---|---|
| Short life | Long life |
| Sent to every API | Sent only to the refresh endpoint |
| JWT, stateless | Opaque, stored in DB, revocable |
| If stolen, limited damage | Must be protected strongly |

### Q427. How does JWT authentication work?
1. User sends credentials to `POST /api/auth/login`.
2. Server validates, creates a signed JWT, returns it.
3. Client stores it and sends `Authorization: Bearer <jwt>` on each request.
4. JWT middleware validates signature, issuer, audience, expiry.
5. If valid, `HttpContext.User` is set with claims; `[Authorize]` allows access.

### Q428. How do you configure JWT authentication in ASP.NET Core?
```csharp
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(o =>
    {
        o.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true, ValidIssuer = builder.Configuration["Jwt:Issuer"],
            ValidateAudience = true, ValidAudience = builder.Configuration["Jwt:Audience"],
            ValidateLifetime = true, ValidateIssuerSigningKey = true,
            IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(builder.Configuration["Jwt:Key"]!)),
            ClockSkew = TimeSpan.FromSeconds(30)
        };
    });
builder.Services.AddAuthorization();
// pipeline
app.UseAuthentication();
app.UseAuthorization();

// creating token
var claims = new[] { new Claim(ClaimTypes.NameIdentifier, user.Id.ToString()), new Claim(ClaimTypes.Role, "Admin") };
var creds = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);
var token = new JwtSecurityToken(issuer, audience, claims, expires: DateTime.UtcNow.AddMinutes(30), signingCredentials: creds);
var jwt = new JwtSecurityTokenHandler().WriteToken(token);
```

### Q429. What is [Authorize]?
Requires an authenticated user (optionally with role/policy) to access a controller/action. Otherwise 401/403.

### Q430. What is [AllowAnonymous]?
Overrides `[Authorize]` so a specific action is public (login, register).
```csharp
[Authorize] public class UsersController : ControllerBase { [AllowAnonymous] [HttpGet("public")] public IActionResult P() => Ok(); }
```

### Q431. How do you protect a controller using JWT?
Put `[Authorize]` on the controller class — all actions require a valid token.

### Q432. How do you protect a specific API endpoint?
Put `[Authorize]` on that action only (others remain public).

### Q433. What is role-based authorization?
Access is decided by the user's **role** (Admin, Manager, User). `[Authorize(Roles = "Admin")]`.

### Q434. What is policy-based authorization?
Access decided by custom **rules** (claims, age, permission, custom handlers), more flexible than roles.
```csharp
builder.Services.AddAuthorization(o => o.AddPolicy("CanDeleteUsers", p => p.RequireClaim("permission", "users.delete")));
[Authorize(Policy = "CanDeleteUsers")]
```

### Q435. Difference between role-based and policy-based authorization?
Role-based: simple, coarse (`Admin`). Policy-based: fine-grained, combines roles, claims, and custom logic; recommended for complex apps (roles are just a simple policy).

### Q436. How do you authorize only Admin users?
```csharp
[Authorize(Roles = "Admin")]
[HttpDelete("{id}")]
public IActionResult Delete(int id) => NoContent();
```

### Q437. How do you authorize multiple roles?
- **OR**: `[Authorize(Roles = "Admin,Manager")]`
- **AND**: stack attributes: `[Authorize(Roles = "Admin")] [Authorize(Roles = "Manager")]`

### Q438. What are claims?
Key-value facts about an authenticated user stored in `ClaimsPrincipal` (id, email, role). Form the basis of authorization.

### Q439. How do you retrieve the current user's ID from JWT claims?
```csharp
var userId = int.Parse(User.FindFirstValue(ClaimTypes.NameIdentifier)!);
```

### Q440. How do you retrieve the current user's role?
```csharp
var role = User.FindFirstValue(ClaimTypes.Role);
var roles = User.FindAll(ClaimTypes.Role).Select(c => c.Value);
bool isAdmin = User.IsInRole("Admin");
```

### Q441. What happens when an expired JWT is sent?
Validation fails (`ValidateLifetime`), API returns **401 Unauthorized** with header `WWW-Authenticate: Bearer error="invalid_token", error_description="The token expired"`. Client should use the refresh token.

### Q442. What happens when an invalid JWT is sent?
Wrong signature, wrong issuer/audience, or malformed token → **401 Unauthorized** (`invalid_token`).

### Q443. How should JWT secrets be stored?
Never in code/Git. Use **User Secrets** (dev), **environment variables**, **Azure Key Vault / AWS Secrets Manager** (prod). Use a long random key (≥ 32 bytes), rotate it, or use asymmetric keys (RS256) with a public key for validation.

### Q444. What is HTTPS?
HTTP over TLS — traffic is **encrypted**, the server is **authenticated**, and data cannot be altered in transit.

### Q445. Why should APIs use HTTPS?
Protects passwords, JWTs and data from sniffing/man-in-the-middle; required by browsers/app stores; mandatory for secure cookies and many security standards.
```csharp
app.UseHttpsRedirection(); app.UseHsts();
```

### Q446. What is CORS?
**Cross-Origin Resource Sharing** — a browser security rule: a page from one origin (`http://localhost:3000`) can call an API on a different origin (`https://localhost:7001`) only if the API allows it via response headers. An origin = scheme + host + port.

### Q447. Why does CORS occur when React calls ASP.NET Core API?
React (port 3000) and API (port 7001) are **different origins**. The browser blocks the response unless the API sends `Access-Control-Allow-Origin`. The server received the request fine — the **browser** blocks reading the result. Postman has no CORS because it's not a browser.

### Q448. How do you configure CORS in ASP.NET Core?
```csharp
builder.Services.AddCors(o => o.AddPolicy("ReactApp", p =>
    p.WithOrigins("http://localhost:3000", "https://myapp.com")
     .WithMethods("GET", "POST", "PUT", "DELETE")
     .WithHeaders("Authorization", "Content-Type")
     .AllowCredentials()));

app.UseRouting();
app.UseCors("ReactApp");     // before UseAuthentication/UseAuthorization
app.UseAuthentication();
app.UseAuthorization();
```

### Q449. Does CORS require an external NuGet package in ASP.NET Core?
No. It is built into the framework (`Microsoft.AspNetCore.Cors` is part of the shared framework).

### Q450. What security risks should be considered when configuring CORS?
- `AllowAnyOrigin()` in production exposes your API to any website.
- `AllowAnyOrigin` + `AllowCredentials` is blocked (and unsafe) — list exact origins.
- Don't reflect the `Origin` header blindly.
- Avoid wildcard headers/methods you don't need.
- CORS is **not** authentication — still use `[Authorize]`.
- Use different policies for dev/prod.

# 🔴 Part 10 — Advanced REST API, Testing, Security & Real Interview Scenarios (Q451–500)

### Q451. How would you design a production-ready REST API?
Checklist:
1. **Architecture**: Controller → Service → Repository, DI everywhere.
2. **DTOs + validation**, never expose entities.
3. **Consistent responses** + global exception handling (ProblemDetails).
4. **Auth**: JWT, roles/policies, HTTPS, CORS with exact origins.
5. **EF Core**: async, `AsNoTracking`, pagination, indexes, migrations.
6. **Observability**: structured logging (Serilog), health checks, metrics.
7. **Docs**: Swagger/OpenAPI; **versioning**.
8. **Quality**: unit + integration tests, CI/CD.
9. **Security**: rate limiting, secrets in Key Vault, input validation, no stack traces.
10. **Performance**: caching, compression, async all the way.

### Q452. How would you structure folders in a large ASP.NET Core Web API project?
Preferred: separate projects (Clean Architecture).
```
MyApp.sln
├── MyApp.Domain          (Entities, Enums, Exceptions)
├── MyApp.Application     (DTOs, Interfaces, Services, Validators, Mappings)
├── MyApp.Infrastructure  (DbContext, Migrations, Repositories, Email, JWT)
├── MyApp.Api             (Controllers, Middleware, Program.cs, Filters)
└── MyApp.Tests           (Unit + Integration)
```
Single-project option: `Controllers/ Services/ Repositories/ Models/ DTOs/ Data/ Middleware/ Extensions/`.

### Q453. What is a typical Controller → Service → Repository architecture?
- **Controller**: HTTP only (bind, call service, return status).
- **Service**: business rules, mapping, transactions.
- **Repository**: data access (EF Core queries).
Each layer talks to the next through **interfaces** registered in DI.

### Q454. Should controllers contain business logic?
No. Keep controllers thin: ~5–10 lines per action. Logic in services makes it testable, reusable (from jobs, other APIs) and keeps responsibilities clean.

### Q455. How would you implement global exception handling?
Use `IExceptionHandler` (.NET 8) or custom middleware (see Q413) mapping custom exceptions to status codes and returning `ProblemDetails`; log the real exception, show a safe message.
```csharp
public class GlobalExceptionHandler(ILogger<GlobalExceptionHandler> log) : IExceptionHandler
{
    public async ValueTask<bool> TryHandleAsync(HttpContext ctx, Exception ex, CancellationToken ct)
    {
        log.LogError(ex, "Unhandled");
        var (code, title) = ex switch { NotFoundException => (404, "Not found"), ConflictException => (409, "Conflict"), _ => (500, "Server error") };
        ctx.Response.StatusCode = code;
        await ctx.Response.WriteAsJsonAsync(new ProblemDetails { Status = code, Title = title }, ct);
        return true;
    }
}
builder.Services.AddExceptionHandler<GlobalExceptionHandler>(); builder.Services.AddProblemDetails(); app.UseExceptionHandler();
```

### Q456. How would you create a standard API response format?
Return the same shape for every response so clients can parse it easily.
```json
{ "success": true, "message": "User created", "data": { "id": 5 }, "errors": null, "traceId": "00-abc..." }
```

### Q457. What is a common API response wrapper?
```csharp
public class ApiResponse<T>
{
    public bool Success { get; set; }
    public string? Message { get; set; }
    public T? Data { get; set; }
    public IEnumerable<string>? Errors { get; set; }
    public static ApiResponse<T> Ok(T data, string? msg = null) => new() { Success = true, Data = data, Message = msg };
    public static ApiResponse<T> Fail(params string[] errors) => new() { Success = false, Errors = errors };
}
return Ok(ApiResponse<UserDto>.Ok(dto));
```
Note: many teams use the standard `ProblemDetails` (RFC 7807) for errors instead.

### Q458. How would you return validation errors consistently?
Customize `InvalidModelStateResponseFactory` (see Q243) so every validation failure returns the same JSON, and have FluentValidation/custom exceptions go through the global handler too.
```json
{ "success": false, "errors": { "email": ["Email is invalid"], "name": ["Name is required"] } }
```

### Q459. How would you implement API pagination?
Accept `page` and `pageSize`, order consistently, return metadata.
```csharp
public class PagedResult<T> { public List<T> Items { get; set; } = new(); public int Page { get; set; } public int PageSize { get; set; } public int TotalCount { get; set; } public int TotalPages => (int)Math.Ceiling(TotalCount / (double)PageSize); }
```
(Query code: see Q400.)

### Q460. How would you implement sorting?
Whitelist sortable fields (never trust raw column names).
```csharp
query = (sortBy?.ToLower(), desc) switch
{
    ("name", false)  => query.OrderBy(u => u.Name),
    ("name", true)   => query.OrderByDescending(u => u.Name),
    ("created", true)=> query.OrderByDescending(u => u.CreatedAt),
    _                => query.OrderBy(u => u.Id)
};
```

### Q461. How would you implement filtering?
Apply conditions only if the parameter is provided.
```csharp
if (!string.IsNullOrWhiteSpace(role))  query = query.Where(u => u.UserRoles.Any(r => r.Role.Name == role));
if (isActive.HasValue)                 query = query.Where(u => u.IsActive == isActive);
if (createdFrom.HasValue)              query = query.Where(u => u.CreatedAt >= createdFrom);
```

### Q462. How would you implement searching?
```csharp
if (!string.IsNullOrWhiteSpace(search))
    query = query.Where(u => EF.Functions.Like(u.Name, $"%{search}%") || EF.Functions.Like(u.Email, $"%{search}%"));
```
For big data use Full-Text Search or Elasticsearch (leading `%` can't use a normal index).

### Q463. How would you combine filtering, sorting, searching, and pagination?
Order of operations: **filter/search → count → sort → paginate → project**.
```csharp
public class UserQuery { public string? Search { get; set; } public string? Role { get; set; } public string? SortBy { get; set; } public bool Desc { get; set; } public int Page { get; set; } = 1; public int PageSize { get; set; } = 10; }

public async Task<PagedResult<UserDto>> GetUsersAsync(UserQuery q)
{
    q.PageSize = Math.Clamp(q.PageSize, 1, 100);
    var query = _db.Users.AsNoTracking().AsQueryable();
    if (!string.IsNullOrWhiteSpace(q.Search)) query = query.Where(u => u.Name.Contains(q.Search) || u.Email.Contains(q.Search));
    if (!string.IsNullOrWhiteSpace(q.Role))   query = query.Where(u => u.UserRoles.Any(r => r.Role.Name == q.Role));
    var total = await query.CountAsync();
    query = q.SortBy?.ToLower() switch { "name" => q.Desc ? query.OrderByDescending(u => u.Name) : query.OrderBy(u => u.Name), _ => query.OrderBy(u => u.Id) };
    var items = await query.Skip((q.Page - 1) * q.PageSize).Take(q.PageSize).Select(u => new UserDto(u.Id, u.Name, u.Email)).ToListAsync();
    return new PagedResult<UserDto> { Items = items, Page = q.Page, PageSize = q.PageSize, TotalCount = total };
}
// Controller: public Task<IActionResult> Get([FromQuery] UserQuery q)
```

### Q464. How would you prevent clients from requesting unlimited records?
Enforce a **maximum page size** (`Math.Clamp`), default page size, require pagination on list endpoints, add **rate limiting**, and reject huge exports (move to background job).

### Q465. How would you implement API versioning?
```csharp
builder.Services.AddApiVersioning(o =>
{
    o.DefaultApiVersion = new ApiVersion(1, 0);
    o.AssumeDefaultVersionWhenUnspecified = true;
    o.ReportApiVersions = true;

[ApiVersion("1.0")] [Route("api/v{version:apiVersion}/users")] public class UsersV1Controller : ControllerBase { }
[ApiVersion("2.0")] [Route("api/v{version:apiVersion}/users")] public class UsersV2Controller : ControllerBase { }
```

### Q466. How would you maintain backward compatibility between API versions?
Never remove/rename fields in an existing version; only **add optional** fields; mark old versions `[Obsolete]`/`deprecated` and announce a sunset date; share business logic in services so V1 and V2 differ only in DTO/controllers; keep contract tests for old versions.

### Q467. How would you document a REST API?
Use **Swagger/OpenAPI** generated from code (Swashbuckle or built-in OpenAPI in .NET 9) with XML comments, `[ProducesResponseType]`, examples, and auth configuration.
```csharp
builder.Services.AddEndpointsApiExplorer(); builder.Services.AddSwaggerGen();
app.UseSwagger(); app.UseSwaggerUI();
```

### Q468. What is Swagger/OpenAPI?
**OpenAPI** is the standard specification (JSON/YAML) describing an API. **Swagger** is the tooling (Swagger UI) that displays it as an interactive page where you can try endpoints.

### Q469. What information should API documentation contain?
Base URL & versions, authentication method, every endpoint (method, URL), request parameters/body schema, response schemas, status codes and error formats, examples, pagination/filter/sort rules, rate limits, changelog.

### Q470. How would you test an API using Swagger?
Run the app → open `/swagger` → click **Authorize**, paste `Bearer <token>` → expand an endpoint → **Try it out** → fill parameters/body → **Execute** → check response code/body.

### Q471. How would you test an API using Postman?
Create a collection; set environment variables (`baseUrl`, `token`); call login and save the token via a test script; add `Authorization: Bearer {{token}}`; write assertions.
```javascript
pm.test("Status 200", () => pm.response.to.have.status(200));
pm.environment.set("token", pm.response.json().data.token);
```
Run with the Collection Runner or Newman in CI.

### Q472. What is unit testing?
Testing the **smallest piece** of code (a method/class) in isolation, with dependencies mocked. Fast, no DB or network.

### Q473. What is integration testing?
Testing **several components together** (API + DB + middleware) like a real request.

### Q474. Difference between unit testing and integration testing?
| Unit | Integration |
|---|---|
| One class, mocks | Multiple real components |
| Very fast | Slower |
| Finds logic bugs | Finds wiring/config/SQL bugs |
| xUnit + Moq | `WebApplicationFactory` + test DB |

### Q475. How would you unit test a controller?
Mock the service, call the action, assert the result type.
```csharp
[Fact]
public async Task GetById_ReturnsNotFound_WhenUserMissing()
{
    var svc = new Mock<IUserService>();
    svc.Setup(s => s.GetAsync(99)).ReturnsAsync((UserDto?)null);
    var controller = new UsersController(svc.Object);
    var result = await controller.GetById(99);

}
```

### Q476. How would you unit test a service?
Mock the repository, call the service method, assert behavior and verify calls.
```csharp
[Fact]
public async Task Create_Throws_WhenEmailExists()
{
    var repo = new Mock<IUserRepository>();
    repo.Setup(r => r.EmailExistsAsync("a@x.com")).ReturnsAsync(true);
    var svc = new UserService(repo.Object);
    await Assert.ThrowsAsync<ConflictException>(() => svc.CreateAsync(new CreateUserDto { Email = "a@x.com" }));

}
```

### Q477. How would you test a database-dependent API?
- **Unit level**: mock repository.
- **Integration level**: `WebApplicationFactory<Program>` with a **real test DB** (SQLite in-memory, or SQL Server/PostgreSQL in Docker via **Testcontainers**), reset data between tests.
- Avoid the EF InMemory provider for relational behavior (no FK/transactions/constraints).

### Q478. What is mocking?
Replacing real dependencies with controlled fake objects in tests (see Q291).

### Q482. What is logging?
Recording application events (info, warnings, errors) so you can monitor and debug production issues.

### Q483. What is ILogger<T>?
Built-in logging interface; `T` = the class category so logs show where they came from.
```csharp
public class UserService(ILogger<UserService> logger)
{
    public void Do(int id) => logger.LogInformation("Fetching user {UserId}", id);   // structured logging
}
```

### Q484. What are log levels in ASP.NET Core?
`Trace (0) < Debug < Information < Warning < Error < Critical < None`. Configure in `appsettings.json` under `Logging:LogLevel`.

### Q485. Difference between Information, Warning, Error, and Critical logs?
- **Information**: normal flow ("User 5 logged in").
- **Warning**: unexpected but app continues ("Retrying payment", "slow query").
- **Error**: an operation failed (exception caught, request failed).
- **Critical**: app/system is in serious trouble (DB down, out of memory) — needs immediate action.

### Q486. How would you troubleshoot an API returning HTTP 500?
1. Check logs / `traceId` for the exception and stack trace.
2. Reproduce locally with same input/config.
3. Common causes: null reference, DI service not registered, DB connection/migration missing, bad config/secret, unhandled DB constraint.
4. Fix, add a unit/integration test, add proper exception handling & logging.

### Q487. How would you troubleshoot an API returning HTTP 401?
Check: token sent? Format `Authorization: Bearer <token>`? Token expired? Issuer/audience/key mismatch between login and validation? `UseAuthentication()` present and before `UseAuthorization()`? Clock skew? Decode the token at jwt.io to inspect claims/exp.

### Q488. How would you troubleshoot an API returning HTTP 403?
User is authenticated but lacks permission: check role/claim names in the token vs `[Authorize(Roles=...)]` or policy; claim type mismatch (`role` vs `ClaimTypes.Role`); token issued before role change; policy handler logic; resource-ownership rules.

### Q489. How would you troubleshoot an API returning HTTP 404?
Wrong URL/version/route template, wrong HTTP verb, missing `[Route]`/`MapControllers()`, route constraint mismatch (`{id:int}` with "abc"), reverse-proxy path base, or the resource truly doesn't exist (service returned null).

### Q490. How would you troubleshoot a CORS error between React and ASP.NET Core?
1. Confirm in browser dev tools it's CORS (preflight `OPTIONS` failing or missing `Access-Control-Allow-Origin`).
2. Origin in policy must match **exactly** (scheme+host+port, no trailing slash).
3. `app.UseCors()` must be after `UseRouting()` and before `UseAuthentication/UseAuthorization`.
4. Allow required headers (`Authorization`, `Content-Type`) and methods.
5. With cookies, add `AllowCredentials()` + explicit origins.
6. Check a 500/401 isn't hiding CORS headers; check HTTP vs HTTPS and proxies.

### Q491. How would you troubleshoot a slow API?
Measure first (APM, logs, `Stopwatch`). Find the slow layer: DB (most common — N+1, missing index, big payloads), external calls (add timeouts/Polly), sync-over-async blocking, serialization of huge objects, no caching, thread-pool starvation. Fix the biggest bottleneck, retest.

### Q492. How would you troubleshoot high CPU usage in an ASP.NET Core API?
Use `dotnet-counters` and `dotnet-trace`/Visual Studio profiler/Application Insights Profiler; look for hot loops, heavy LINQ in memory, regex backtracking, excessive JSON serialization, tight retry loops, too much logging, GC pressure; capture a dump (`dotnet-dump`) and inspect top threads.

### Q493. How would you troubleshoot high memory usage?
Use `dotnet-counters` (GC heap size), `dotnet-gcdump` / `dotnet-dump`, profilers. Common causes: loading huge lists into memory, static collections/caches that never expire, undisposed `HttpClient`/streams/DbContext, event handlers not unsubscribed, captive scoped dependencies in singletons, large object heap allocations. Fix with pagination, streaming, `IMemoryCache` size limits, `IHttpClientFactory`, `using`.

### Q494. How would you secure sensitive configuration values?
User Secrets locally; environment variables or **Key Vault/Secrets Manager** in production; managed identities instead of passwords; never commit secrets; separate configs per environment; rotate keys; restrict access (RBAC); scan repos for leaked secrets; don't log secrets.

### Q495. How would you prevent SQL injection in an API?
Use EF Core/LINQ (parameterized), `FromSqlInterpolated`/parameters for raw SQL, never concatenate user input into SQL, validate input, least-privilege DB account, whitelist sort columns, hide DB errors from responses.

### Q496. How would you prevent over-posting/mass assignment?
Bind to **DTOs** that have only allowed fields, never bind directly to entities, set sensitive fields (`IsAdmin`, `Role`, `Balance`) on the server, use `[BindNever]`, and map explicitly.

### Q498. If an Admin deletes a Role, how would you delete its UserRole records without deleting Users?
Configure FK delete behavior so deleting a Role cascades **only to the join table**, and never touches Users:
```csharp
mb.Entity<UserRole>().HasKey(x => new { x.UserId, x.RoleId });
mb.Entity<UserRole>().HasOne(x => x.Role).WithMany(r => r.UserRoles).HasForeignKey(x => x.RoleId).OnDelete(DeleteBehavior.Cascade);
mb.Entity<UserRole>().HasOne(x => x.User).WithMany(u => u.UserRoles).HasForeignKey(x => x.UserId).OnDelete(DeleteBehavior.Cascade);
```
Service with explicit safety (optional business rule: block deleting a role in use, or remove assignments in a transaction):
```csharp
public async Task DeleteRoleAsync(int roleId)
{
    var role = await _db.Roles.FindAsync(roleId) ?? throw new NotFoundException("Role not found");
    await using var tx = await _db.Database.BeginTransactionAsync();
    await _db.UserRoles.Where(ur => ur.RoleId == roleId).ExecuteDeleteAsync(); // only join rows
    _db.Roles.Remove(role);
    await _db.SaveChangesAsync();
    await tx.CommitAsync();
}
```
Users table is untouched because `User` is the **principal** side — deleting a dependent (`UserRole`) never deletes the principal.

### Q499. Design a complete CRUD REST API for Users using DTOs, validation, EF Core, DI, authentication, authorization, exception handling, and pagination.
**Entity**
```csharp
public class User { public int Id {get;set;} public string Name {get;set;} = ""; public string Email {get;set;} = ""; public string PasswordHash {get;set;} = ""; public bool IsActive {get;set;} = true; public DateTime CreatedAt {get;set;} = DateTime.UtcNow; }
```
**DTOs + validation**
```csharp
public class CreateUserDto { [Required, StringLength(100, MinimumLength = 2)] public string Name {get;set;} = ""; [Required, EmailAddress] public string Email {get;set;} = ""; [Required, MinLength(8)] public string Password {get;set;} = ""; }
public class UpdateUserDto { [Required, StringLength(100)] public string Name {get;set;} = ""; public bool IsActive {get;set;} }
public record UserDto(int Id, string Name, string Email, bool IsActive);
```
**DbContext**
```csharp
public class AppDbContext(DbContextOptions<AppDbContext> o) : DbContext(o)
{
    public DbSet<User> Users => Set<User>();
    protected override void OnModelCreating(ModelBuilder mb) => mb.Entity<User>().HasIndex(u => u.Email).IsUnique();
}
```
**Service interface + implementation**
```csharp
public interface IUserService
{
    Task<PagedResult<UserDto>> GetAllAsync(int page, int pageSize, string? search);
    Task<UserDto> GetByIdAsync(int id);
    Task<UserDto> CreateAsync(CreateUserDto dto);
    Task UpdateAsync(int id, UpdateUserDto dto);
    Task DeleteAsync(int id);
}
public class UserService(AppDbContext db) : IUserService
{
    public async Task<PagedResult<UserDto>> GetAllAsync(int page, int pageSize, string? search)
    {
        pageSize = Math.Clamp(pageSize, 1, 100);
        var q = db.Users.AsNoTracking();
        if (!string.IsNullOrWhiteSpace(search)) q = q.Where(u => u.Name.Contains(search) || u.Email.Contains(search));
        var total = await q.CountAsync();
        var items = await q.OrderBy(u => u.Id).Skip((page - 1) * pageSize).Take(pageSize)
                           .Select(u => new UserDto(u.Id, u.Name, u.Email, u.IsActive)).ToListAsync();
        return new PagedResult<UserDto> { Items = items, Page = page, PageSize = pageSize, TotalCount = total };
    }
    public async Task<UserDto> GetByIdAsync(int id)
    {
        var u = await db.Users.AsNoTracking().FirstOrDefaultAsync(x => x.Id == id) ?? throw new NotFoundException($"User {id} not found");
        return new UserDto(u.Id, u.Name, u.Email, u.IsActive);
    }
    public async Task<UserDto> CreateAsync(CreateUserDto dto)
    {
        if (await db.Users.AnyAsync(u => u.Email == dto.Email)) throw new ConflictException("Email already exists");
        var u = new User { Name = dto.Name, Email = dto.Email, PasswordHash = BCrypt.Net.BCrypt.HashPassword(dto.Password) };
        db.Users.Add(u); await db.SaveChangesAsync();
        return new UserDto(u.Id, u.Name, u.Email, u.IsActive);
    }
    public async Task UpdateAsync(int id, UpdateUserDto dto)
    {
        var u = await db.Users.FindAsync(id) ?? throw new NotFoundException($"User {id} not found");
        u.Name = dto.Name; u.IsActive = dto.IsActive; await db.SaveChangesAsync();
    }
    public async Task DeleteAsync(int id)
    {
        var u = await db.Users.FindAsync(id) ?? throw new NotFoundException($"User {id} not found");
        db.Users.Remove(u); await db.SaveChangesAsync();
    }
}
```
**Controller** (thin, secured)
```csharp
[ApiController, Route("api/v1/[controller]"), Authorize]
public class UsersController(IUserService svc) : ControllerBase
{
    [HttpGet] public async Task<ActionResult<PagedResult<UserDto>>> GetAll(int page = 1, int pageSize = 10, string? search = null) => Ok(await svc.GetAllAsync(page, pageSize, search));
    [HttpGet("{id:int}")] public async Task<ActionResult<UserDto>> Get(int id) => Ok(await svc.GetByIdAsync(id));
    [HttpPost, Authorize(Roles = "Admin")] public async Task<ActionResult<UserDto>> Create(CreateUserDto dto) { var u = await svc.CreateAsync(dto); return CreatedAtAction(nameof(Get), new { id = u.Id }, u); }
    [HttpPut("{id:int}"), Authorize(Roles = "Admin")] public async Task<IActionResult> Update(int id, UpdateUserDto dto) { await svc.UpdateAsync(id, dto); return NoContent(); }
    [HttpDelete("{id:int}"), Authorize(Roles = "Admin")] public async Task<IActionResult> Delete(int id) { await svc.DeleteAsync(id); return NoContent(); }
}
```
**Program.cs wiring**

### Q500. You are given a production ASP.NET Core REST API that has slow database queries, inconsistent error responses, CORS errors, missing authorization, duplicated business logic, and poor controller structure. Explain step-by-step how you would diagnose and redesign the application.

**Phase 0 — Don't break production**
Set up a safety net first: source control + CI, a staging environment, backups, a few **characterization/integration tests** on key endpoints, logging and monitoring so you can measure before/after.

**Phase 1 — Diagnose (measure, don't guess)**
1. Add structured logging (Serilog) with `traceId`, enable Application Insights/OpenTelemetry.
2. Find top slow endpoints (p95 latency), log EF SQL (`ToQueryString`, `LogTo`), review execution plans.
3. Inspect browser dev-tools for CORS failures and the pipeline order in `Program.cs`.
4. Audit every endpoint: which have `[Authorize]`? Build a spreadsheet of endpoint → required role.
5. Scan for duplicate logic (code search/SonarQube) and fat controllers.
6. Capture a list of error response shapes returned today.

**Phase 2 — Quick wins (high impact, low risk)**
1. **Security first**: add default `[Authorize]` (fallback policy `RequireAuthenticatedUser`) and `[AllowAnonymous]` only on login/health; add role/policy checks on sensitive endpoints; check ownership (user can only access own data).
```csharp
builder.Services.AddAuthorization(o => o.FallbackPolicy = new AuthorizationPolicyBuilder().RequireAuthenticatedUser().Build());
```
2. **CORS**: one named policy with exact origins; correct middleware order (`UseRouting → UseCors → UseAuthentication → UseAuthorization`).
3. **Global exception handling** + `ProblemDetails` so every error has the same shape and no stack traces leak.
4. **Database quick wins**: add missing indexes, `AsNoTracking` on reads, `Select` projections, `Include` to kill N+1, mandatory pagination with max page size, move `ToList()` calls to the end of the query, make everything `async`.

**Phase 3 — Redesign structure**
1. Introduce layers: Controller → Service → Repository (or direct DbContext in service) using interfaces + DI.
2. **Move logic out of controllers** into services; **merge duplicated logic** into one service method / domain helper used by all callers.
3. Introduce **DTOs** (request/response) and validation (annotations/FluentValidation); stop returning entities (fixes over-posting and circular references).
4. Standardize responses, status codes (201/204/404/409) and validation errors.
5. Add API versioning and Swagger documentation for the new contract.
```csharp
// Before: fat controller
[HttpPost] public IActionResult Create(User u) { if (_db.Users.Any(x=>x.Email==u.Email)) return BadRequest("dup"); u.IsAdmin = u.IsAdmin; _db.Add(u); _db.SaveChanges(); return Ok(u); }
// After: thin controller
[HttpPost] public async Task<ActionResult<UserDto>> Create(CreateUserDto dto) { var u = await _svc.CreateAsync(dto); return CreatedAtAction(nameof(Get), new { id = u.Id }, u); }
```

**Phase 4 — Harden & prove**
1. Add unit tests (services) and integration tests (`WebApplicationFactory` + test DB) for each fixed area; add authorization tests (401/403 cases).
2. Move secrets to Key Vault; rotate JWT key; enforce HTTPS/HSTS; add rate limiting.
3. Add health checks, dashboards, alerts.
4. Load test (k6/JMeter) to confirm performance gains.

**Phase 5 — Roll out safely**
Deploy to staging, run regression tests, release gradually (feature flags / blue-green / canary), keep old API version running while clients migrate, monitor errors & latency, and document everything (README, ADRs, Swagger).

**Interview closing line:** *"I'd measure first, fix security and error handling quickly, then fix the database hot spots, then refactor to thin controllers and services with DTOs, and protect every change with tests and monitoring."*
