# .NET Developer & RESTful API Complete Interview Guide (Questions 1–500)

---

## 🟢 Part 1 — C# Fundamentals — Questions 1–50

### 1. What is C#?
**Simple Explanation:** C# (pronounced C-Sharp) is an object-oriented, type-safe, high-level programming language developed by Microsoft. It runs on the .NET platform and is designed to build desktop, web, cloud, and mobile applications.

**Real-World Example:**
```csharp
public class Program
{
    public static void Main()
    {
        string devName = "Alex";
        Console.WriteLine($"Welcome to C# Development, {devName}!");
    }
}
```

**Interview Tip:** Always highlight that C# is strongly typed and garbage-collected, which prevents memory leaks and type-mismatch bugs at compile time.

---

### 2. What is .NET?
**Simple Explanation:** .NET is a developer platform created by Microsoft containing libraries, compilers, tools, and a runtime engine (CLR) used to build and execute cross-platform software.

**Real-World Example:**
Think of .NET as a construction site equipped with tools, prefabricated materials, and rules (libraries), while C# is the specific language spoken by the workers to build the structure.

---

### 3. What is the difference between C# and .NET?
- **C#:** The programming language used to write source code syntax.
- **.NET:** The runtime execution engine and standard library framework that executes C# code.

```csharp
// C# provides language syntax (e.g., class, public, string)
public class OrderProcessor 
{
    // System.DateTime comes from the .NET Framework / Runtime library
    public DateTime ProcessedAt { get; set; } = DateTime.UtcNow;
}
```

---

### 4. What is CLR?
**Simple Explanation:** CLR (Common Language Runtime) is the virtual machine component of .NET. It manages execution of code, memory allocation, garbage collection, thread management, and security checks.

```csharp
// When you instantiate an object, CLR handles memory allocation on the heap 
// and reclaims it via Garbage Collection when no longer referenced.
var customer = new Customer { Name = "John Doe" };
```

---

### 5. What is CTS?
**Simple Explanation:** CTS (Common Type System) defines how types are declared, used, and managed in .NET across all supported languages (C#, VB.NET, F#) to ensure seamless interop.

```csharp
// C# keyword 'int' maps directly to the CTS type 'System.Int32'
int age = 30; 
System.Int32 sameAge = 30; // Identical in .NET CTS
```

---

### 6. What is CLS?
**Simple Explanation:** CLS (Common Language Specification) is a set of rules and guidelines that all .NET languages must follow so code written in one language (e.g., C#) can be called directly by another (e.g., VB.NET).

```csharp
// CLS-compliant code avoids features like unsigned integers in public APIs
[assembly: System.CLSCompliant(true)]
public class SharedLibrary
{
    public int CalculateTotal(int price) => price; // CLS-compliant
    // public uint UnsignedTotal(uint price) => price; // Non-CLS compliant
}
```

---

### 7. What is managed code?
**Simple Explanation:** Managed code is C# code that compiles into Intermediate Language (IL) and is executed entirely under the supervision and environment management of the CLR.

```csharp
public class ManagedExample
{
    public void Work()
    {
        // Allocation and cleanup managed by CLR Garbage Collector
        List<string> items = new List<string> { "Item1", "Item2" };
    }
}
```

---

### 8. What is unmanaged code?
**Simple Explanation:** Unmanaged code executes outside the CLR (e.g., C/C++ DLLs, Win32 APIs). The developer must directly handle memory management and pointers.

```csharp
using System.Runtime.InteropServices;

public class UnmanagedExample
{
    // Calling C++ DLL function directly via P/Invoke
    [DllImport("user32.dll", CharSet = CharSet.Auto)]
    public static extern int MessageBox(IntPtr hWnd, String text, String caption, uint type);
}
```

---

### 9. What is an assembly in .NET?
**Simple Explanation:** An assembly is a compiled unit of code (`.dll` or `.exe`) containing Intermediate Language (IL), metadata, and manifest information. It is the basic unit of deployment and security in .NET.

---

### 10. What is the difference between .dll and .exe?
- **`.exe` (Executable):** Contains an entry point (`Main` method) and can run directly as an independent application.
- **`.dll` (Dynamic Link Library):** Cannot run on its own; contains reusable library code invoked by `.exe` files or other DLLs.

---

### 11. What are value types in C#?
**Simple Explanation:** Value types store their actual data directly where the variable is declared (typically on the Stack). Examples include `int`, `double`, `bool`, `struct`, and `enum`.

```csharp
int x = 10;
int y = x; // Copy of value 10 is made
y = 20;    // x remains 10
```

---

### 12. What are reference types in C#?
**Simple Explanation:** Reference types store a pointer (reference) to the memory address on the Heap where the actual data resides. Examples include `class`, `interface`, `delegate`, `string`, and `array`.

```csharp
public class User { public string Name { get; set; } }

User user1 = new User { Name = "Alice" };
User user2 = user1; // Both reference the SAME heap object
user2.Name = "Bob";  // user1.Name is now also "Bob"
```

---

### 13. What is the difference between value type and reference type?

| Feature | Value Type | Reference Type |
| :--- | :--- | :--- |
| **Storage** | Stack | Heap (Reference stored on Stack) |
| **Assignment** | Copies actual value | Copies reference pointer |
| **Nullability** | Non-nullable by default | Nullable by default |
| **Base Type** | `System.ValueType` | `System.Object` |

---

### 14. What is boxing?
**Simple Explanation:** Converting a value type into a reference type (`object`) by wrapping it inside an allocation on the managed Heap.

```csharp
int accountId = 1001;     // Value Type (Stack)
object boxedId = accountId; // Boxing (Heap Allocation - performance cost)
```

---

### 15. What is unboxing?
**Simple Explanation:** Explicitly extracting the original value type out of a boxed reference type.

```csharp
object boxedId = 1001;        // Boxed Object
int unboxedId = (int)boxedId;  // Unboxing (Explicit Cast back to Value Type)
```

---

### 16. What is implicit conversion?
**Simple Explanation:** Automatic conversion performed by the compiler when converting a smaller type to a larger type without data loss risk.

```csharp
int smallNumber = 50;
double bigNumber = smallNumber; // Implicit conversion from int to double
```

---

### 17. What is explicit conversion?
**Simple Explanation:** Manual type casting required when there is a risk of data loss or casting incompatible reference types.

```csharp
double price = 99.99;
int roundedPrice = (int)price; // Explicit cast: truncates decimal to 99
```

---

### 18. What is the difference between Parse() and TryParse()?
- **`Parse()`:** Throws a `FormatException` or `ArgumentNullException` if conversion fails.
- **`TryParse()`:** Returns `bool` (`true` if successful, `false` if failed) without throwing exceptions, making it high-performance.

```csharp
string input = "123a";

// Throws Exception (Bad Practice for unvalidated input)
// int num1 = int.Parse(input);

// Safe parsing (Recommended)
if (int.TryParse(input, out int result))
{
    Console.WriteLine($"Parsed: {result}");
}
else
{
    Console.WriteLine("Invalid integer input.");
}
```

---

### 19. What is the difference between Convert.ToInt32() and int.Parse()?
- `Convert.ToInt32(null)` returns `0`.
- `int.Parse(null)` throws `ArgumentNullException`.

```csharp
string nullStr = null;
int val1 = Convert.ToInt32(nullStr); // Returns 0
// int val2 = int.Parse(nullStr);     // Throws ArgumentNullException
```

---

### 20. What is a nullable value type?
**Simple Explanation:** Allows a normal value type (like `int`, `bool`, `DateTime`) to accept `null` values.

```csharp
int? nullableAge = null; // Equivalent to Nullable<int>
if (nullableAge.HasValue)
{
    Console.WriteLine(nullableAge.Value);
}
```

---

### 21. What is Nullable<T>?
**Simple Explanation:** A generic underlying struct (`System.Nullable<T>`) where `T` must be a value type (`struct`).

```csharp
Nullable<DateTime> lastLoginDate = null;
lastLoginDate = DateTime.Now;
```

---

### 22. What is the difference between null, 0, and string.Empty?
- **`null`:** No object memory allocated. Pointer points to nothing.
- **`0`:** A valid numerical value of zero.
- **`string.Empty`:** An actual allocated string instance with zero length `""`.

---

### 23. What is var in C#?
**Simple Explanation:** Statically typed implicit declaration. The compiler infers the exact type at compile time. Type cannot change afterwards.

```csharp
var customerName = "John"; // Compiler infers string
// customerName = 123;     // Compile Error!
```

---

### 24. What is dynamic?
**Simple Explanation:** Dynamically typed declaration. Bypasses compile-time type checking; type resolution occurs completely at runtime.

```csharp
dynamic data = "Hello";
Console.WriteLine(data.Length); // OK at runtime
data = 100;                     // Valid: Type changes to int at runtime
```

---

### 25. Difference between var and dynamic?

| Feature | `var` | `dynamic` |
| :--- | :--- | :--- |
| **Type Checking** | Compile-time | Runtime |
| **Performance** | High (No overhead) | Slower (Dynamic reflection overhead) |
| **IntelliSense** | Fully supported | Not supported |

---

### 26. What is const?
**Simple Explanation:** Compile-time constant. Must be initialized at declaration and can never be altered. Implicitly `static`.

```csharp
public class ApplicationConfig
{
    public const string ApiVersion = "v1.0"; // Evaluation at compile-time
}
```

---

### 27. What is readonly?
**Simple Explanation:** Runtime constant. Value can be assigned at declaration or inside the class constructor.

```csharp
public class SystemService
{
    public readonly string ConnectionString;

    public SystemService(string connStr)
    {
        ConnectionString = connStr; // Set at runtime initialization
    }
}
```

---

### 28. Difference between const and readonly?
- **`const`:** Evaluated at compile-time; value hardcoded in consumer assembly.
- **`readonly`:** Evaluated at runtime; allows different values depending on constructor inputs.

---

### 29. What are access modifiers in C#?
Keywords used to specify the scope and visibility of members and types across classes and assemblies.

---

### 30. Difference between public, private, protected, and internal?
- **`public`:** Accessible everywhere.
- **`private`:** Accessible only inside the declaring class.
- **`protected`:** Accessible inside declaring class and derived subclasses.
- **`internal`:** Accessible anywhere within the same assembly (`.dll`).

---

### 31. What is a class?
**Simple Explanation:** A blueprint or template defining properties, methods, and behavior for objects.

```csharp
public class BankAccount
{
    public string AccountNumber { get; set; }
    public decimal Balance { get; set; }
}
```

---

### 32. What is an object?
**Simple Explanation:** A real instance of a class loaded in memory.

```csharp
BankAccount myAccount = new BankAccount { AccountNumber = "ACC-01", Balance = 1500.00m };
```

---

### 33. What is a constructor?
**Simple Explanation:** A special method in a class that executes automatically when an object is instantiated to initialize its state.

---

### 34. What is a default constructor?
A parameterless constructor created automatically by C# if no explicit constructors are defined.

---

### 35. What is a parameterized constructor?
A constructor that accepts input parameters to assign custom initial values upon instantiation.

```csharp
public class Product
{
    public string Name { get; set; }
    public decimal Price { get; set; }

    public Product(string name, decimal price)
    {
        Name = name;
        Price = price;
    }
}
```

---

### 36. Can a class have multiple constructors?
**Yes.** This is achieved through constructor overloading.

---

### 37. What is constructor overloading?
Defining multiple constructors with different parameters within the same class.

```csharp
public class LogService
{
    public LogService() : this("System.log") { } // Constructor chaining
    public LogService(string filePath)
    {
        // Setup file path
    }
}
```

---

### 38. What is inheritance?
**Simple Explanation:** An OOP concept where a child class inherits properties and methods from a parent class.

```csharp
public class Vehicle // Parent Class
{
    public string Brand { get; set; }
}

public class Car : Vehicle // Child Class inheriting Vehicle
{
    public int DoorCount { get; set; }
}
```

---

### 39. What is encapsulation?
**Simple Explanation:** Hiding internal class data using private access modifiers and providing controlled access via public properties or methods.

```csharp
public class UserAccount
{
    private string _passwordHash; // Hidden internal state

    public bool VerifyPassword(string inputPassword)
    {
        return ComputeHash(inputPassword) == _passwordHash;
    }

    private string ComputeHash(string pass) => pass; // Implementation hidden
}
```

---

### 40. What is abstraction?
**Simple Explanation:** Displaying only essential feature definitions to users while hiding the underlying execution complexity.

---

### 41. What is polymorphism?
**Simple Explanation:** Ability for derived classes to provide their own specific execution implementation for shared base class methods ("Many forms").

---

### 42. What is method overloading?
Creating multiple methods with the same name within a single class but with different signatures (parameter types or counts).

```csharp
public class Calculator
{
    public int Add(int a, int b) => a + b;
    public double Add(double a, double b) => a + b; // Overloaded
}
```

---

### 43. What is method overriding?
Providing a custom implementation in a child class for a method defined as `virtual` or `abstract` in its parent class.

---

### 44. Difference between overload and override?
- **Overload:** Same class, same name, different parameters (Compile-time polymorphism).
- **Override:** Derived class, same name and exact signature (Runtime polymorphism).

---

### 45. What is the virtual keyword?
Allows a parent class method to be overridden in derived subclasses.

```csharp
public class PaymentGateway
{
    public virtual void ProcessPayment()
    {
        Console.WriteLine("Standard Payment Processing");
    }
}
```

---

### 46. What is the override keyword?
Used in a child class to extend or replace the base class `virtual` implementation.

```csharp
public class PayPalGateway : PaymentGateway
{
    public override void ProcessPayment()
    {
        Console.WriteLine("Processing via PayPal API");
    }
}
```

---

### 47. What is the abstract keyword?
Defines an incomplete class or method that MUST be implemented by non-abstract child classes.

```csharp
public abstract class Notification
{
    public abstract void Send(string message); // Signature only
}
```

---

### 48. What is an interface?
A contract defining properties, methods, and events without default storage state. Implementing classes must fulfill the contract.

```csharp
public interface IEmailSender
{
    Task SendEmailAsync(string to, string subject, string body);
}
```

---

### 49. Difference between abstract class and interface?
- **Abstract Class:** Can contain state fields, non-abstract implementations, and constructor logic. Single inheritance.
- **Interface:** Cannot store state fields; ideal for pure capability contracts. Supports multiple inheritance.

---

### 50. Can a class implement multiple interfaces?
**Yes.** C# supports multiple interface inheritance.

```csharp
public class AuditLogger : IEmailSender, IDatabaseWriter
{
    // Implements contract methods from both interfaces
}
```

## 🟢 Part 2 — C# OOP, Collections & Advanced Basics — Questions 51–100

### 51. What is the difference between composition and inheritance?
- **Inheritance:** "Is-a" relationship (`Car` is a `Vehicle`). Strong coupling.
- **Composition:** "Has-a" relationship (`Car` has an `Engine`). Flexible, reusable, and easier to modify.

```csharp
public class Engine { public void Start() {} }

public class Car
{
    private readonly Engine _engine = new Engine(); // Composition
    public void StartCar() => _engine.Start();
}
```

---

### 52. What is method hiding?
Re-defining a base class method in a child class without overriding it, hiding the parent method using the `new` keyword.

---

### 53. What is the new keyword in method hiding?
Explicitly indicates to the compiler that a child class method intentionally hides a base class member.

```csharp
public class Parent { public void Display() => Console.WriteLine("Parent"); }
public class Child : Parent { public new void Display() => Console.WriteLine("Child"); }
```

---

### 54. What is a sealed class?
A class that cannot be inherited by any other class.

```csharp
public sealed class SecurityTokenProvider
{
    // Cannot be subclassed
}
```

---

### 55. What is a sealed method?
A method in a child class that overrides a base method and prevents any subsequent derived subclasses from overriding it further.

```csharp
public class BaseClass { public virtual void Log() {} }
public class DerivedClass : BaseClass 
{ 
    public sealed override void Log() {} // Cannot be overridden further
}
```

---

### 56. Can an abstract class have a constructor?
**Yes.** Used to initialize base class fields when instantiated by child classes.

---

### 57. Can an interface contain properties?
**Yes.** Interfaces can declare property contracts without backing fields.

```csharp
public interface IUser
{
    string Username { get; set; }
}
```

---

### 58. Can an interface contain method implementations?
**Yes.** Since C# 8, default interface methods allow default implementations inside interfaces.

---

### 59. What are properties in C#?
Class members that provide flexible mechanisms to read, write, or compute values of private fields using accessors (`get`, `set`).

---

### 60. Difference between field and property?
- **Field:** Direct variable storage in a class (`private decimal _amount;`).
- **Property:** Accessor wrapper providing encapsulation (`public decimal Amount { get; set; }`).

---

### 61. What is an auto-implemented property?
A concise syntax where the compiler generates the hidden backing field automatically.

```csharp
public string OrderId { get; set; } // Auto-property
```

---

### 62. What is an init-only property?
Properties introduced in C# 9 that can only be assigned during object construction/initialization.

```csharp
public class OrderDto
{
    public string Id { get; init; } // Immutable after object initialization
}

var dto = new OrderDto { Id = "ORD-123" };
// dto.Id = "NEW-ID"; // Compile Error!
```

---

### 63. What is a static class?
A class that cannot be instantiated using `new` and contains only `static` members.

---

### 64. What is a static method?
A method belongs to the class type itself rather than a specific object instance.

```csharp
public static class MathUtils
{
    public static int Square(int number) => number * number;
}
```

---

### 65. Can a static class be inherited?
**No.** Static classes are sealed by default.

---

### 66. What is a namespace?
A organizational unit used to group related classes, interfaces, and types to prevent name collisions.

```csharp
namespace Application.Services
{
    public class CustomerService {}
}
```

---

### 67. What is exception handling?
A process of handling runtime application errors gracefully using `try`, `catch`, `finally`, and `throw`.

---

### 68. Difference between throw and throw ex?
- **`throw;`:** Preserves the original exception call stack trace (Best Practice).
- **`throw ex;`:** Resets the call stack trace to the current catch block, losing previous error context.

```csharp
try 
{ 
    // Logic 
}
catch (Exception ex)
{
    // Re-throw preserving stack trace
    throw; 
}
```

---

### 69. What is try-catch-finally?
- **`try`:** Encloses code that might throw an exception.
- **`catch`:** Handles thrown errors.
- **`finally`:** Always executes regardless of success or exception (ideal for cleanup operations).

---

### 70. Can finally execute if an exception occurs?
**Yes.** The `finally` block executes even if an unhandled exception occurs or a return statement is reached inside `try` or `catch`.

---

### 71. What is a custom exception?
A user-defined exception class inheriting from `System.Exception` used for handling business domain-specific failure scenarios.

```csharp
public class InsufficientFundsException : Exception
{
    public InsufficientFundsException(string message) : base(message) { }
}
```

---

### 72. What is Exception base class?
The root class for all standard runtime and custom exceptions in .NET (`System.Exception`).

---

### 73. What is IEnumerable<T>?
A read-only interface supporting simple iteration over a collection in memory or deferred execution query streams.

---

### 74. What is ICollection<T>?
Extends `IEnumerable<T>` to provide mutating features such as `Add()`, `Remove()`, `Clear()`, and count inspection (`Count`).

---

### 75. What is IList<T>?
Extends `ICollection<T>` to support index-based array element access (`list[0]`).

---

### 76. Difference between IEnumerable, ICollection, and IList?
- **`IEnumerable<T>`:** Forward-only reading (deferred queries).
- **`ICollection<T>`:** Size awareness + item modifications.
- **`IList<T>`:** Index access + element insertion/removal at dynamic index positions.

---

### 77. What is List<T>?
A dynamic, indexed array implementation supporting fast lookups and resizing capabilities.

---

### 78. What is Dictionary<TKey,TValue>?
A collection storing key/value pairs providing $O(1)$ constant time performance for lookups using key hashing algorithms.

```csharp
var users = new Dictionary<int, string>
{
    { 1, "Alice" },
    { 2, "Bob" }
};
string name = users[1]; // Fast lookup by Key
```

---

### 79. Difference between List and Dictionary?
- **`List<T>`:** Sequential access by integer index ($O(N)$ searches).
- **`Dictionary<TKey, TValue>`:** Lookup via unique hashed keys ($O(1)$ fast lookups).

---

### 80. What is HashSet?
An unordered collection containing unique elements with no duplicates.

```csharp
var uniqueIds = new HashSet<int> { 1, 2, 2, 3 }; // Contains 1, 2, 3
```

---

### 81. Difference between HashSet and List?
- **`List`:** Allows duplicates and maintains defined index positions.
- **`HashSet`:** Enforces distinct unique items and performs fast existence checks (`Contains`).

---

### 82. What is Queue?
A First-In-First-Out (FIFO) collection (`Enqueue`, `Dequeue`).

---

### 83. What is Stack?
A Last-In-First-Out (LIFO) collection (`Push`, `Pop`).

---

### 84. What is LinkedList<T>?
A doubly linked list where each element references both next and previous nodes.

---

### 85. What is IQueryable<T>?
Extends `IEnumerable<T>`. Constructs expression trees translated into native database scripts (e.g., SQL queries) executed on remote servers.

---

### 86. Difference between IEnumerable and IQueryable?
- **`IEnumerable<T>`:** Executes filter queries in memory on the local server.
- **`IQueryable<T>`:** Translates filter queries directly to SQL running inside the database engine server.

---

### 87. What is LINQ?
Language Integrated Query: C# declarative syntax used to filter, project, and transform data from diverse collection providers.

---

### 88. What are LINQ extension methods?
Methods like `.Where()`, `.Select()`, `.OrderBy()` operating on `IEnumerable<T>` or `IQueryable<T>`.

---

### 89. Difference between Where() and Select()?
- **`Where()`:** Filters elements based on a boolean predicate condition.
- **`Select()`:** Projects/transforms elements into new structural object shapes.

---

### 90. Difference between First() and FirstOrDefault()?
- **`First()`:** Returns first element; throws `InvalidOperationException` if empty.
- **`FirstOrDefault()`:** Returns default value (`null` or `0`) if empty.

---

### 91. Difference between Single() and SingleOrDefault()?
- **`Single()`:** Expects exactly one element; throws exception if zero or multiple exist.
- **`SingleOrDefault()`:** Returns default if empty, but throws exception if more than one item exists.

---

### 92. Difference between Any() and Count()?
- **`Any()`:** Checks if at least one matching item exists (stops evaluation on first match - faster).
- **`Count()`:** Iterates and counts all elements in the collection.

---

### 93. What is deferred execution in LINQ?
Execution of the query expression is delayed until the data is actively iterated (`foreach` or `.ToList()`).

---

### 94. What is immediate execution in LINQ?
Forces query execution immediately to evaluate results (`.ToList()`, `.ToArray()`, `.Count()`).

---

### 95. What does ToList() do in LINQ?
Executes the LINQ query immediately and stores the output elements into an in-memory `List<T>`.

---

### 96. What is SelectMany()?
Flattens nested list hierarchies into a single flat collection sequence.

```csharp
var studentGrades = classes.SelectMany(c => c.Students);
```

---

### 97. What is OrderBy()?
Sorts sequence elements in ascending order based on a specified key selector.

---

### 98. What is GroupBy()?
Groups sequence elements sharing a common specified key into grouped buckets.

---

### 99. What is Join() in LINQ?
Correlates two sequences based on matching key values (similar to SQL INNER JOIN).

---

### 100. Write a LINQ query to find duplicate records.

```csharp
var list = new List<string> { "Apple", "Banana", "Apple", "Orange", "Banana" };

var duplicates = list.GroupBy(x => x)
                     .Where(g => g.Count() > 1)
                     .Select(g => g.Key)
                     .ToList();
// Result: "Apple", "Banana"
```

## 🟡 Part 3 — ASP.NET Core Fundamentals — Questions 101–150

### 101. What is ASP.NET Core?
An open-source, high-performance, cross-platform framework for building modern, cloud-based web applications, REST APIs, and microservices.

---

### 102. What are the advantages of ASP.NET Core?
Cross-platform capabilities, high performance (Kestrel web server), built-in Dependency Injection, unified Web API/MVC controllers, and lightweight modular middleware pipeline architecture.

---

### 103. Difference between ASP.NET Framework and ASP.NET Core?
- **ASP.NET Framework:** Windows-only, monolithic structure, tied to IIS.
- **ASP.NET Core:** Cross-platform (Linux, Windows, macOS), modular, decoupled server capabilities, optimized for cloud container environments.

---

### 104. Is ASP.NET Core cross-platform?
**Yes.** It runs seamlessly on Windows, Linux, and macOS platforms.

---

### 105. What is Kestrel?
A lightweight, fast, cross-platform HTTP web server built directly into ASP.NET Core applications.

---

### 106. What is the role of Kestrel in ASP.NET Core?
It listens for incoming HTTP requests and routes them directly through the internal middleware pipeline of the application process.

---

### 107. What is Program.cs?
The application entry point containing configuration logic, service injection setup, and middleware pipeline initialization.

---

### 108. What is Startup.cs?
Historically used in older ASP.NET Core versions to handle `ConfigureServices()` and `Configure()`. In .NET 6+, its logic was consolidated directly into `Program.cs`.

---

### 109. Why is Startup.cs not required in newer ASP.NET Core versions?
Minimal APIs and top-level statements introduced in .NET 6 combined configuration startup routines directly inside `Program.cs`.

---

### 110. What is WebApplicationBuilder?
A helper builder object initialized in `Program.cs` used to configure logging, services (DI container), configuration files, and hosting options.

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();
```

---

### 111. What is WebApplication?
The constructed application instance created by calling `builder.Build()`. Configures middleware execution routes and starts the web server host.

---

### 112. What is the purpose of appsettings.json?
A central JSON configuration file storing application environment settings, API keys, and connection strings.

---

### 113. What is appsettings.Development.json?
Environment-specific setting overrides applied exclusively when running the application under the `Development` host environment.

---

### 114. How do you read configuration values in ASP.NET Core?
By injecting `IConfiguration` into controllers or services.

```csharp
public class HomeController
{
    private readonly string _connectionString;

    public HomeController(IConfiguration config)
    {
        _connectionString = config.GetConnectionString("DefaultConnection");
    }
```

## 🟡 Part 4 — RESTful API Concepts — Questions 151–200

### 151. What is REST?
REpresentational State Transfer: An architectural style for building distributed system API services using standard stateless HTTP operations.

---

### 152. What does REST stand for?
**RE**presentational **S**tate **T**ransfer.

---

### 153. What are REST architectural principles?
1. Client-Server separation.
2. Statelessness.
3. Cacheability.
4. Uniform Interface.
5. Layered System.
6. Code-On-Demand (Optional).

---

### 154. What is a RESTful API?
A web API system constructed in full alignment with REST architectural principles.

---

### 155. Difference between REST API and Web API?
- **Web API:** Any service endpoint exposing data over HTTP (can include SOAP, RPC, or XML APIs).
- **REST API:** A specific Web API strictly adhering to REST constraints and resource URI naming semantics.

---

### 156. What is a resource in REST?
Any identifiable data entity or domain noun exposed by an API system (e.g., `Users`, `Orders`, `Products`).

---

### 157. What is statelessness in REST?
Every incoming request must contain all necessary token authentication and parameter state required for completion. The server stores no client session context state between calls.

---

### 158. Why should REST APIs be stateless?
Statelessness enhances horizontal scalability. Any load-balanced app server can handle any incoming request independently.

---

### 159. What is an HTTP request?
A standardized message sent by a client to a server containing an HTTP verb method, URI target path, headers, and payload body.

---

### 160. What is an HTTP response?
The response sent back by the server to the client containing an HTTP status code, response headers, and result body.

---

### 161. What is an HTTP method?
Verbs specifying the intended action operation to perform on a resource (`GET`, `POST`, `PUT`, `DELETE`, `PATCH`).

---

### 162. Explain GET.
Retrieves resources from the server without modifying resource state (Safe & Idempotent).

---

### 163. Explain POST.
Submits new payload data to the server to create a new resource (Non-Idempotent).

---

### 164. Explain PUT.
Replaces an existing resource entirely or creates it if non-existent (Idempotent).

---

### 165. Explain PATCH.
Applies partial modifications to an existing resource target without sending full object structures (Non-Idempotent in some contexts, but used for partial updates).

---

### 166. Explain DELETE.
Removes a specified target resource from the system (Idempotent).

---

### 167. Explain HEAD.
Identical to GET requests, but returns only response headers without payload body content.

---

### 168. Explain OPTIONS.
Retrieves supported HTTP methods and capabilities exposed by the target resource endpoint (commonly used in CORS preflight checks).

---

### 169. Which HTTP method is idempotent?
An operation is idempotent if executing it multiple identical times produces the same server state outcome (`GET`, `PUT`, `DELETE`, `HEAD`, `OPTIONS`).

---

### 170. Is POST idempotent?
**No.** Executing multiple POST requests will create multiple duplicate records.

---

### 171. Is PUT idempotent?
**Yes.** Replacing a resource multiple times with identical data results in the same final state.

---

### 172. Is DELETE idempotent?
**Yes.** Deleting a resource record once or multiple times leaves the system in the same target state (the resource is gone).

---

### 173. What is an HTTP status code?
A 3-digit numerical response code returned by the server indicating the outcome of an HTTP request.

---

### 174. Explain status code 200.
**200 OK:** Request completed successfully, returning request payload data.

---

### 175. Explain status code 201.
**201 Created:** Resource successfully created. Returns a `Location` header pointing to the new resource.

---

### 176. Explain status code 202.
**202 Accepted:** Request accepted for background processing, but execution is not yet complete.

---

### 177. Explain status code 204.
**204 No Content:** Request completed successfully, but there is no response body content to return (common for DELETE/PUT).

---

### 178. Explain status code 400.
**400 Bad Request:** Malformed request payload, syntax error, or invalid input validation rules.

---

### 179. Explain status code 401.
**401 Unauthorized:** Client lacks valid authentication credentials.

---

### 180. Explain status code 403.
**403 Forbidden:** Client is authenticated, but lacks explicit authorization permissions for the resource.

---

### 181. Explain status code 404.
**404 Not Found:** Target resource URI does not exist on the server.

---

### 182. Explain status code 405.
**405 Method Not Allowed:** HTTP verb used is not supported for the endpoint.

---

### 183. Explain status code 409.
**409 Conflict:** Request conflict with current server resource state (e.g., creating a record with a duplicate unique key).

---

### 184. Explain status code 422.
**422 Unprocessable Entity:** Well-formed request syntax, but contains semantic validation errors.

---

### 185. Explain status code 429.
**429 Too Many Requests:** Client exceeded rate limiting threshold quotas.

---

### 186. Explain status code 500.
**500 Internal Server Error:** Unhandled internal application error on the server side.

---

### 187. Difference between 401 and 403?
- **401 Unauthorized:** Missing or invalid authentication token identity (Who are you?).
- **403 Forbidden:** User identity validated, but missing permission roles (You are not allowed here).

---

### 188. Difference between 400 and 422?
- **400 Bad Request:** Malformed payload structure parsing failure.
- **422 Unprocessable Entity:** Valid payload structure, but failing business domain validation parameters.

---

### 189. When should an API return 201?
When a POST request successfully creates a new database record entity.

---

### 190. When should an API return 204?
When an update or delete operation completes successfully and no payload body needs to be returned.

---

### 191. What is content negotiation?
The process where client and server negotiate response payload formats (e.g., JSON vs XML) using HTTP headers (`Accept`, `Content-Type`).

---

### 192. What is JSON?
JavaScript Object Notation: A lightweight, human-readable data interchange format.

---

### 193. Why is JSON commonly used in REST APIs?
Lightweight string footprint, fast parsing efficiency, language independence, and native compatibility with front-end web client frameworks.

---

### 194. What are HTTP headers?
Key-value pair metadata sent with HTTP requests and responses specifying content types, tokens, and server rules.

---

### 195. What is the Content-Type header?
Informs the recipient about the media type format of the enclosed message body payload (`application/json`).

---

### 196. What is the Accept header?
Informs the server about the specific media types the client can parse in response (`application/json`).

---

### 197. Difference between Content-Type and Accept?
- **Content-Type:** Describes what format the sent payload body contains.
- **Accept:** Describes what format the client expects back in response.

---

### 198. What is API versioning?
Managing breaking change updates to API contracts without disrupting existing integrated clients.

---

### 199. Why is API versioning required?
Prevents unexpected breaking client failures when domain API structure attributes change over time.

---

### 200. What are different API versioning strategies?
1. **URI Path:** `/api/v1/users`
2. **Query Parameter:** `/api/users?api-version=1.0`
3. **Custom Headers:** `X-Version: 1.0`
4. **Accept Header Content Negotiation:** `Accept: application/vnd.company.v1+json`

## 🟠 Part 6 — Dependency Injection & Services — Questions 251–300

### 251. What is Dependency Injection?
A design pattern used to achieve Inversion of Control (IoC) between classes and their dependencies by injecting objects rather than instantiating them directly.

---

### 252. Why is Dependency Injection used in ASP.NET Core?
Promotes loose coupling, simplifies automated unit testing using mocks, and improves application maintainability and testability.

---

### 253. What is IoC?
Inversion of Control: A software architecture principle transferring control of object creation and lifecycle management from custom caller code to an external framework or container.

---

### 254. Difference between IoC and DI?
- **IoC:** The overall design principle (inverting control).
- **DI:** The specific implementation technique used to realize IoC by passing dependencies into constructors.

---

### 255. What are the benefits of DI?
Decoupled class architectures, easy component mocking for unit testing, streamlined lifetime management, and modular codebase maintainability.

---

### 256. What is constructor injection?
Injecting dependencies explicitly via class constructor parameters (Recommended Best Practice).

```csharp
public class OrderService

    public OrderService(IPaymentProcessor processor)
    {
        _processor = processor;
    }
}
```

---

### 257. What is property injection?
Passing dependencies into public properties of a class (Not natively supported by default ASP.NET Core DI container).

---

### 258. What is method injection?
Passing dependencies directly as arguments into a specific method invocation (e.g., using `[FromServices]` in action methods).

---

### 259. Which DI approach is recommended in ASP.NET Core?
**Constructor Injection.**

---

### 260. What is IServiceCollection?
The standard service descriptor collection container used to register application dependencies inside `Program.cs`.

---

### 261. What is IServiceProvider?
The engine interface responsible for resolving and retrieving service instance objects from the DI container.

---

### 262. What is AddTransient()?
Registers services with a **Transient** lifetime. A new object instance is created every single time it is requested.

---

### 263. What is AddScoped()?
Registers services with a **Scoped** lifetime. A single instance is created once per incoming HTTP request cycle.

---

### 264. What is AddSingleton()?
Registers services with a **Singleton** lifetime. A single instance is created once when first requested and shared across the entire application lifecycle.

---

### 265. Difference between Transient, Scoped, and Singleton?

| Lifetime | Instance Creation | Usage Scenario |
| :--- | :--- | :--- |
| **Transient** | Every time requested | Lightweight, stateless utilities |
| **Scoped** | Once per HTTP request | Database contexts (`DbContext`), Unit of Work |
| **Singleton** | Once across entire application execution | Caching services, system configurations |

---

### 266. Which lifetime is normally used for DbContext?
**Scoped.**

---

### 267. Why is DbContext usually scoped?
Ensures isolated database query tracking states per client HTTP request while safely disposing connection resources at the request end.

---

### 268. What happens if a Singleton depends on a Scoped service?
Captive Dependency bug! The Scoped service remains locked inside memory as long as the Singleton lives, causing resource leakage and concurrency bugs across requests.

---

### 269. What is service registration?
Mapping an abstraction interface to its concrete class implementation inside the IoC container.

---

### 270. How do you register an interface and implementation?


---

### 271. How do you inject a service into a controller?

---

### 272. Why should business logic not be written directly inside controllers?
Controllers should strictly handle HTTP routing and response orchestrations. Placing complex domain logic in controllers breaks Separation of Concerns, prevents reusable domain execution, and complicates unit testing.

---

### 273. What is the Service Layer?
An intermediate architectural layer containing core business application logic, detached from HTTP controllers and persistence databases.

---

### 274. What is Repository Pattern?
A software design pattern encapsulating database querying logic behind generic collection-like abstraction methods.

---

### 275. What is Unit of Work?
A design pattern grouping multiple repository database persistence operations into a single transaction boundary to ensure atomic execution.

---

### 276. Is Repository Pattern mandatory with EF Core?
**No.** `DbContext` itself acts as a combination of Repository and Unit of Work patterns natively. Adding another abstraction layer can sometimes cause unnecessary overhead unless specifically required by application architecture.

---

### 277. What is a generic repository?
A single repository template implementation handling shared CRUD persistence queries across all entity models.

```csharp

{
    Task<IEnumerable<T>> GetAllAsync();
    Task AddAsync(T entity);

```

---

### 278. What are disadvantages of generic repository?
Exposes over-generalized data operations that may bypass domain safety rules and can restrict access to optimized EF Core-specific features like native complex projections.

---

### 279. What is Clean Architecture?
An architectural style organizing software applications into concentric circular layers, enforcing that dependencies strictly point inward toward core domain models.

---

### 280. What is separation of concerns?
A core design principle dividing software into distinct functional sections where each handles an isolated responsibility (e.g., Web API vs Business Logic vs Database Persistence).

---

### 281. What is SOLID?
An acronym representing five fundamental object-oriented software architectural design principles for creating maintainable, testable, and flexible codebases.

---

### 282. Explain Single Responsibility Principle.
**S:** A class should have one, and only one, reason to change.

```csharp
// Bad: Invoice handles printing AND database persistence
// Good: Split into InvoiceRepository and InvoicePrinter classes
```

---

### 283. Explain Open/Closed Principle.
**O:** Software entities should be open for extension, but closed for modification.

---

### 284. Explain Liskov Substitution Principle.
**L:** Derived classes must be completely substitutable for their parent base classes without altering correct application behaviors.

---

### 285. Explain Interface Segregation Principle.
**I:** Clients should not be forced to depend on massive interface contracts containing methods they do not use. Prefer smaller, focused interfaces.

---

### 286. Explain Dependency Inversion Principle.
**D:** High-level software modules should not depend directly on low-level concrete modules; both should depend strictly on abstractions.

---

### 287. How does DI support SOLID?
Enables complete compliance with the **Dependency Inversion Principle** by allowing high-level components to reference injected interface abstractions rather than direct concrete instantiations.

---

### 288. What is tight coupling?
When software components depend directly on concrete implementations, making modifications and unit testing difficult.

---

### 289. What is loose coupling?
When software components interact exclusively through abstract interface contracts, allowing component implementations to be swapped safely.

---

### 290. How do you unit test a service using DI?
By providing mocked interface dependencies directly into the service constructor during testing setup.

---

### 291. What is mocking?
Creating simulated dummy implementations of real objects to verify unit test behaviors under controlled isolation conditions.

---

### 292. What is Moq?
A popular .NET mocking framework used to mock interfaces and setup expected return values during unit testing execution.

```csharp

```

---

### 293. What is an abstraction?
An interface or abstract parent contract defining structural capabilities without locking caller code to underlying concrete implementations.

---

### 294. Why should controllers depend on interfaces?
Allows dependencies to be swapped transparently and simplifies mock injection during controller unit testing.

---

### 295. What happens when a dependency is not registered?
The application runtime throws an `InvalidOperationException` when resolving the service endpoint from the DI container.

---

### 296. What exception occurs when DI cannot resolve a service?
`System.InvalidOperationException` (e.g., "Unable to resolve service for type '...' while attempting to activate '...'").

---

### 297. How do you register multiple implementations of one interface?

```csharp
builder.Services.AddScoped<INotificationService, SmsNotificationService>();
```

### 298. How do you select a specific implementation?

---

### 299. What is keyed service registration?
A feature introduced in .NET 8 allowing service registrations to be registered and retrieved using unique key names.


---

### 300. Explain the complete request flow through Controller → Service → Repository → Database.
1. **HTTP Request:** Hits Kestrel server host and enters application Middleware pipeline.
2. **Controller:** Route matches endpoint controller action; dependencies are resolved via DI.
3. **Service Layer:** Controller passes Request DTO to Service, which validates business rules.
4. **Repository Layer:** Service invokes Repository functions to handle database persistence.
5. **Database:** Entity Framework Core maps queries to standard SQL statements and executes them against the database database engine.
6. **Response Flow:** Data entity results map back into Response DTOs and travel up through Service $\rightarrow$ Controller $\rightarrow$ Middleware $\rightarrow$ HTTP JSON Response to Client.

### 303. Why use EF Core?
Eliminates repetitive data access boilerplates, provides strong-typed LINQ queries, tracks entity changes automatically, and supports cross-database platforms.

### 304. What is DbContext?
The core class in EF Core representing an active session instance with the database, managing entity query mappings and change tracking state.

### 305. What is DbSet?

### 310. What is Code First?

### 312. Difference between Code First and Database First?

### 314. Why are migrations used?

### 318. What is EnsureCreated()?
An EF Core method creating the database schema directly if it does not exist, bypassing migration history tracking.

### 319. Difference between EnsureCreated() and migrations?

### 320. What is entity configuration?
Defining table column data types, key constraints, and foreign key relationships using Data Annotations or Fluent API.

### 321. What is Fluent API?
An advanced configuration approach overriding `OnModelCreating()` inside `DbContext` to explicitly configure entity mappings using C# method chaining.

```csharp
        .Property(c => c.Email)
        .IsRequired()
        .HasMaxLength(200);
```

### 322. What are data annotations?
Attributes placed directly above C# entity properties defining table column constraints (`[Key]`, `[Required]`, `[MaxLength]`).

---

### 323. Difference between Fluent API and Data Annotations?
- **Data Annotations:** Attribute annotations applied directly inside entity class files (Clutters entity clean models).
- **Fluent API:** Centralized configuration inside `DbContext` keeping domain entities clean and supporting complex composite keys and relationship rules.

---

### 324. What is a primary key?
A unique identifier column constraint uniquely identifying every row record in a database table.

---

### 325. What is a foreign key?
A key constraint linking a record column in one database table directly to the Primary Key column of another table.

---

### 326. What is a composite primary key?
A primary key constraint formed by combining two or more entity columns together.

---

### 327. What is a navigation property?
An entity property pointing directly to related entity object instances (e.g., `public Order Order { get; set; }`).

---

### 328. What is one-to-one relationship?
A relationship where one record entity connects directly to exactly one matching record in another table (e.g., `User` $\leftrightarrow$ `UserProfile`).

---

### 329. What is one-to-many relationship?
A relationship where one parent record connects to multiple child entity records (e.g., `Customer` $\leftrightarrow$ `Orders`).

---

### 330. What is many-to-many relationship?
A relationship where multiple parent entities link to multiple child entity records through a target join table (e.g., `Students` $\leftrightarrow$ `Courses`).

---

### 331. How do you configure relationships in EF Core?
Using Fluent API relationships methods like `HasOne()`, `WithMany()`, `HasMany()`, and `WithOne()`.

---

### 332. What is cascade delete?
A database rule where deleting a parent entity record automatically deletes all related child entities bound to it.

---

### 333. What is DeleteBehavior.Cascade?
EF Core delete behavior configuration ensuring derived dependent entities are removed automatically when a principal entity is deleted.

---

### 334. What is DeleteBehavior.Restrict?
Prevents deletion of parent entities if any related child entities exist, throwing a database exception instead.

---

### 335. What is DeleteBehavior.NoAction?
Applies no cascade delete operation; leaves database foreign key execution behavior entirely to underlying target database setup.

---

### 336. When should cascade delete be avoided?
Avoid in critical system entities (e.g., Users, Transactions) where accidental parent record deletions could destroy historical data records.

---

### 337. How do you prevent deleting Users when deleting a Role?
Configure foreign key behavior on `UserRole` relationships using `DeleteBehavior.Restrict` or `DeleteBehavior.NoAction`.

---

### 338. How do you delete related UserRole records when a Role is deleted?
Configure explicit cascade delete behavior (`DeleteBehavior.Cascade`) on the `Role` $\rightarrow$ `UserRole` entity relationship model.

---

### 339. What is eager loading?
Loading related entity data simultaneously during the initial database query execution using `.Include()`.

```csharp
var usersWithOrders = await context.Users.Include(u => u.Orders).ToListAsync();
```

---

### 340. What is lazy loading?
Automatically fetching related entity data from the database dynamically only when the navigation property is accessed for the first time.

---

### 341. What is explicit loading?
Manually fetching related entity navigation data for an already loaded entity instance using `context.Entry(entity).Collection(...).LoadAsync()`.

---

### 342. Difference between Include and ThenInclude?
- **`Include()`:** Loads first-level navigation properties (e.g., `User.Orders`).
- **`ThenInclude()`:** Loads nested secondary navigation properties (e.g., `User.Orders.OrderItems`).

---

### 343. What is tracking in EF Core?
Mechanism where `DbContext` monitors changes made to loaded entity properties to automatically persist updates when `SaveChangesAsync()` is called.

---

### 344. What is AsNoTracking()?
Instructs EF Core to disable entity change tracking monitoring, significantly improving performance for read-only queries.

```csharp
var users = await context.Users.AsNoTracking().ToListAsync();
```

---

### 345. When should AsNoTracking() be used?
Use in read-only API query endpoints where entities are retrieved purely for display responses without modifications.

---

### 346. What is SaveChanges()?
Synchronously persists tracked entity insertions, modifications, and deletions into the target relational database.

---

### 347. What is SaveChangesAsync()?
Asynchronously persists entity modifications to the database without blocking execution threads under high load operations.

---

### 348. Difference between synchronous and asynchronous database operations?
- **Synchronous:** Blocks execution threads while waiting for network/database disk execution, limiting application scalability.
- **Asynchronous:** Releases execution threads back to the system thread pool during database operations, supporting higher concurrent user capacity.

---

### 349. What is concurrency in EF Core?
Handling scenarios where multiple users attempt to update the exact same database record concurrently.

---

### 350. What is optimistic concurrency?
Concurrency control pattern assuming conflicts are rare. Checks a version token or timestamp column during updates; if changed, it throws a `DbUpdateConcurrencyException` to prevent accidental overwrites.

```csharp
public class Product
{
    public int Id { get; set; }
    
    [Timestamp]
    public byte[] RowVersion { get; set; } // Managed automatically by database for optimistic locking
}
```

When LINQ expressions cannot be translated to SQL, forcing EF Core to pull entire table dataset records into server memory for local evaluation (throws exceptions in modern EF Core versions if unsupported).

Translating the entire LINQ expression into native optimized SQL executed completely within the database engine.

### 384. What is SQL injection?

## 🔴 Part 9 — Middleware, Authentication & Authorization — Questions 401–450

### 401. What is middleware in ASP.NET Core?
Software components assembled into an application processing pipeline that handle incoming HTTP requests and outgoing responses.

---

### 402. How does middleware work?
Request pipeline components are invoked sequentially. Each middleware component can process the request, pass control to the next delegate using `next()`, or short-circuit execution.

---

### 403. What is the middleware pipeline?
A chain of middleware software delegates through which every incoming HTTP request flows in sequence.

---

### 404. What is Use()?
Middleware method used to execute custom code and pass execution down to the next pipeline delegate.

```csharp
app.Use(async (context, next) => {
    // Before request
    await next();
    // After request
});
```

---

### 405. What is Run()?
Terminating middleware method that short-circuits execution and stops execution from passing to subsequent pipeline delegates.

---

### 406. What is Map()?
Middleware method used to branch execution paths based on matching HTTP request URL paths.

---

### 407. Difference between Use, Run, and Map?
- **`Use()`:** Executes code and invokes the next pipeline component.
- **`Run()`:** Executes code and terminates the pipeline execution.
- **`Map()`:** Branches the middleware execution pipeline based on matching route paths.

---

### 408. Why does middleware order matter?
Middleware components execute sequentially in the exact order they are registered inside `Program.cs`. Incorrect ordering causes bugs (e.g., registering authorization before authentication will evaluate empty identity claims).

---

### 409. What happens if authentication middleware is placed incorrectly?
If `UseAuthorization()` is placed *before* `UseAuthentication()`, authorization checks will fail because user identity claims have not been populated yet.

---

### 410. What is exception-handling middleware?
Middleware positioned at the top of the processing pipeline that catches unhandled exceptions across subsequent components, returning standardized error responses.

---

### 411. How do you create custom middleware?

```csharp
public class CustomLoggingMiddleware

    public CustomLoggingMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        Console.WriteLine($"Request: {context.Request.Path}");
        await _next(context);
    }
}
```

---

### 412. How do you log requests using middleware?
Inspect request method paths and execution times within custom middleware before and after calling `_next(context)`.

---

### 413. How do you implement global exception handling?
Use `app.UseExceptionHandler()` or implement the custom `IExceptionHandler` interface available in modern .NET versions.

---

### 414. What is authentication?
The security process of validating **who** a client user is (identity verification).

---

### 415. What is authorization?
The security process determining **what** resources or actions an authenticated user is allowed to access (permission verification).

---

### 416. Difference between authentication and authorization?
- **Authentication:** Verifying user identity credentials (e.g., logging in with email and password).
- **Authorization:** Checking permission rights for a user (e.g., verifying if the user has an Admin role).

---

### 417. What is JWT?
JSON Web Token: An open standard (RFC 7519) defining a compact, self-contained method for securely transmitting claims between parties as a digitally signed JSON object.

---

### 418. Why is JWT commonly used in REST APIs?
Stateless, compact, portable across domain servers, self-contained, and easily validated without requiring server-side session lookups.

---

### 419. What are the parts of a JWT?
A encoded string containing 3 base64-url string segments separated by dots (`.`): **Header**, **Payload**, and **Signature**.

---

### 420. What is JWT Header?
Contains metadata specifying the signing algorithm (e.g., HS256) and token format type (JWT).

---

### 421. What is JWT Payload?
Contains user identity claims, role details, and token expiration timestamps (`exp`).

---

### 422. What is JWT Signature?
A cryptographic hash produced by signing the header and payload using a secret key, protecting the token from tampering.

---

### 423. What are JWT claims?
Key-value pair data statements stored inside the JWT payload body asserting identity details (e.g., `sub`, `email`, `role`).

---

### 424. What is an access token?
A short-lived JWT token presented by clients in the `Authorization: Bearer <token>` HTTP header to access protected endpoints.

---

### 425. What is a refresh token?
A long-lived, securely stored secret token presented to refresh endpoints to issue new short-lived access tokens without requiring re-authentication.

---

### 426. Difference between access token and refresh token?
- **Access Token:** Short lifespan (e.g., 15 mins), sent with every request, contains permission claims.
- **Refresh Token:** Long lifespan (e.g., 7 days), securely stored server-side/HTTP-only cookie, used exclusively to request new access tokens.

---

### 427. How does JWT authentication work?
1. User posts valid credentials to `/login`.
2. Server validates credentials and returns a signed JWT access token.
3. Client stores token and sends it in the HTTP `Authorization: Bearer <token>` header for subsequent requests.
4. Server validates signature using the secret key and processes the request.

---

```csharp
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,
            ValidIssuer = "my-api",
```

### 429. What is [Authorize]?
An attribute enforcing authentication and authorization permission checks on controller actions or classes.

### 444. What is HTTPS?

### 499. Design a complete CRUD REST API for Users using DTOs, validation, EF Core, DI, authentication, authorization, exception handling, and pagination.

```csharp
// --- DTO Contracts ---
public record CreateUserRequest([Required][EmailAddress] string Email, [Required] string Name);
public record UserResponse(int Id, string Email, string Name);

// --- Interface Abstraction ---
public interface IUserService
{
    Task<IEnumerable<UserResponse>> GetUsersAsync(int pageNumber, int pageSize);
    Task<UserResponse> CreateUserAsync(CreateUserRequest request);
}

// --- Service Implementation ---
public class UserService : IUserService
{
    private readonly ApplicationDbContext _db;
    public UserService(ApplicationDbContext db) => _db = db;

    public async Task<IEnumerable<UserResponse>> GetUsersAsync(int pageNumber, int pageSize)
    {
        return await _db.Users.AsNoTracking()
            .OrderBy(u => u.Id)
            .Skip((pageNumber - 1) * pageSize)
            .Take(pageSize)
            .Select(u => new UserResponse(u.Id, u.Email, u.Name))
            .ToListAsync();
    }

    public async Task<UserResponse> CreateUserAsync(CreateUserRequest request)
    {
        var user = new User { Email = request.Email, Name = request.Name };
        await _db.Users.AddAsync(user);
        await _db.SaveChangesAsync();
        return new UserResponse(user.Id, user.Email, user.Name);
    }
}

// --- REST Controller ---
[ApiController]
[Route("api/[controller]")]
[Authorize]
public class UsersController : ControllerBase
{
    private readonly IUserService _userService;
    public UsersController(IUserService userService) => _userService = userService;

    [HttpGet]
    public async Task<IActionResult> GetAll([FromQuery] int page = 1, [FromQuery] int size = 10)
    {
        var result = await _userService.GetUsersAsync(page, size);
        return Ok(result);
    }

    [HttpPost]
    [Authorize(Roles = "Admin")]
    public async Task<IActionResult> Create([FromBody] CreateUserRequest request)
    {
        var response = await _userService.CreateUserAsync(request);
        return CreatedAtAction(nameof(GetAll), new { id = response.Id }, response);
    }
}
```
