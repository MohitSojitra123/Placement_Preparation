# 🟢 PART 1: BASIC LEVEL (Q1-50)

## REST & HTTP Fundamentals

### 1. What is REST, and what are its key architectural constraints?
REST (Representational State Transfer) is a style for designing web APIs where everything is a **resource** (product, order) reached by a URL, and you act on it with standard HTTP methods.

**The 6 constraints:**
1. **Client-Server**: UI and backend are separate and evolve independently.
2. **Stateless**: each request carries everything the server needs; the server keeps no session memory.
3. **Cacheable**: responses say whether they can be cached.
4. **Uniform Interface**: same rules everywhere (resource URLs, standard methods, representations like JSON, links).
5. **Layered System**: client doesn't know if it talks to the real server, a proxy, or a gateway.
6. **Code on Demand** (optional): server may send executable code (e.g., JavaScript).

```
GET /api/products/10   → returns product 10 as JSON
```

### 2. Explain the standard HTTP methods
| Method | Purpose | Example |
|---|---|---|
| GET | Read a resource | `GET /products/10` |
| POST | Create a resource / run an action | `POST /products` |
| PUT | Replace a resource fully | `PUT /products/10` |
| PATCH | Partially update | `PATCH /products/10` |
| DELETE | Remove | `DELETE /products/10` |
| HEAD | Same as GET but **headers only** (check if exists, size) | `HEAD /files/report.pdf` |
| OPTIONS | Ask what the server allows (used by CORS preflight) | `OPTIONS /products` |

### 3. Safe vs Idempotent HTTP methods
- **Safe**: doesn't change server data (GET, HEAD, OPTIONS).
- **Idempotent**: calling it many times gives the same final state as calling it once (GET, PUT, DELETE, HEAD, OPTIONS).

| Method | Safe | Idempotent |
|---|---|---|
| GET | ✅ | ✅ |
| PUT | ❌ | ✅ |
| DELETE | ❌ | ✅ |
| POST | ❌ | ❌ |
| PATCH | ❌ | ❌ (usually) |

Why it matters: clients/proxies can safely **retry** idempotent calls after a network failure. Retrying POST may create duplicates.

### 4. PUT vs PATCH
```http
# Product: { "name":"Pen", "price":10, "stock":50 }

PUT /products/1        { "name":"Pen", "price":12, "stock":50 }   ← must send ALL fields
PATCH /products/1      { "price":12 }                             ← send only what changes
```
PUT replaces the whole resource (missing fields become null/default). PATCH changes only the sent fields. In .NET PATCH is often done with a DTO of nullable fields or `JsonPatchDocument<T>`.

### 5. HTTP status code categories
- **1xx** Informational (100 Continue)
- **2xx** Success (200 OK, 201 Created, 204 No Content)
- **3xx** Redirection (301 Moved, 304 Not Modified)
- **4xx** Client error (400, 401, 403, 404, 409, 429)
- **5xx** Server error (500, 502, 503, 504)

### 6. 401 vs 403
- **401 Unauthorized**: "I don't know who you are": missing/invalid/expired token (authentication failed).
- **403 Forbidden**: "I know who you are, but you're not allowed" (authorization failed).

Example: calling `DELETE /products/1` without a token → 401. With a valid *Customer* token but the endpoint needs *Admin* → 403.

### 7. Content Negotiation (Accept and Content-Type)
The client and server agree on a data format.
- `Content-Type`: format of the **body being sent**.
- `Accept`: format the client **wants back**.

```http
POST /products
Content-Type: application/json      ← I'm sending JSON
Accept: application/xml             ← please reply in XML
```
If the server can't produce that format → `406 Not Acceptable`; if it can't read the sent format → `415 Unsupported Media Type`.
```csharp
builder.Services.AddControllers().AddXmlSerializerFormatters();
```

### 8. URI, URL, URN
- **URI** (Identifier): any string that identifies a resource. Umbrella term.
- **URL** (Locator): URI that says **where** and how to get it: `https://shop.com/api/products/10`.
- **URN** (Name): URI that gives a permanent **name**, not location: `urn:isbn:9780131103627`.

Every URL and URN is a URI.

### 9. Why nouns, not verbs?
The HTTP method is already the verb. URL should name the **thing**.
```
❌ POST /createProduct   GET /getProductById?id=5   POST /deleteProduct
✅ POST /products        GET /products/5            DELETE /products/5
```
Benefits: consistent, predictable, less endpoints to remember, cacheable, easy to document.

### 10. CORS and why browsers enforce it
Browsers use the **Same-Origin Policy**: JavaScript from `https://app.com` may not read responses from `https://api.com` (different origin = scheme + host + port). This protects users from malicious sites reading their data with their cookies. CORS is how the **API tells the browser** which other origins are allowed.
```csharp
builder.Services.AddCors(o => o.AddPolicy("web", p =>
    p.WithOrigins("https://app.com").AllowAnyHeader().AllowAnyMethod()));
app.UseCors("web");
```
Important: CORS is enforced by **browsers only**; Postman/servers aren't blocked. It's not a security replacement for authentication.

## C# & .NET Core Basics

### 11. .NET Framework vs .NET Core vs modern .NET
- **.NET Framework (≤ 4.8)**: Windows-only, legacy, no new features.
- **.NET Core (1.0-3.1)**: cross-platform, open source, fast, rewrite.
- **.NET 5+ (6, 7, 8, 9...)**: the unified successor ("Core" dropped from the name). Even versions (6, 8, 10) are LTS.
Choose modern .NET for new work.

### 12. CLR and managed execution
The **Common Language Runtime** runs your code. Steps:
1. C# → compiled to **IL** (Intermediate Language) in a `.dll`.
2. At run time the **JIT** compiles IL → machine code.
3. CLR provides **garbage collection**, type safety, exception handling, and security.
"Managed code" = code controlled by the CLR (no manual memory freeing).

### 13. Value types vs Reference types
- **Value types** (`int`, `bool`, `struct`, `enum`) hold the data itself; assignment **copies**.
- **Reference types** (`class`, `string`, arrays, delegates) hold an address to an object on the heap; assignment copies the **address**.
```csharp
var p1 = new Product { Price = 10 }; var p2 = p1; p2.Price = 99;
Console.WriteLine(p1.Price);   // 99, same object
int a = 1; int b = a; b = 2;   // a is still 1
```

### 14. Boxing and unboxing
Boxing: value type → `object` (allocated on heap). Unboxing: back (type check + copy).
```csharp
int n = 5;
object o = n;      // boxing: heap allocation
int m = (int)o;    // unboxing
```
**Performance:** extra allocations → more GC work. In loops (e.g., old `ArrayList`, `string.Format` with ints) it adds up. Avoid with generics (`List<int>`).

### 15. string vs String vs StringBuilder
- `string` is the C# keyword alias for `System.String`. Identical.
- Both are **immutable**: every change creates a new string.
- `StringBuilder` is a mutable buffer for many appends.
```csharp
var sb = new StringBuilder();
foreach (var p in products) sb.AppendLine($"{p.Id},{p.Name}");   // no new string per iteration
var csv = sb.ToString();
```

### 16. const vs readonly
- `const`: value fixed at **compile time**, implicitly static, only primitives/strings; changing it needs recompiling dependent assemblies.
- `readonly`: assigned at declaration or **in constructor** (run time), can differ per instance.
```csharp
public const int MaxItems = 100;
public readonly DateTime CreatedAt = DateTime.UtcNow;
```

### 17. Extension methods
Add methods to an existing type without modifying it: static method in a static class with `this` on the first parameter.
```csharp
public static class StringExtensions {
    public static string ToSlug(this string s) => s.Trim().ToLower().Replace(" ", "-");
}
var slug = "Red Shoes".ToSlug();   // "red-shoes"
```
LINQ (`Where`, `Select`) and `services.AddMyFeature()` are extension methods.

### 18. ref, out, in
- `ref`: pass by reference; variable must be **initialized**; method may read & modify.
- `out`: method **must assign** it; caller needn't initialize. Used for extra return values.
- `in`: pass by reference but **read-only** (avoids copying large structs).
```csharp
void Increase(ref int x) => x++;
bool TryGetPrice(int id, out decimal price) { price = 9.99m; return true; }
decimal Total(in LargeStruct s) => s.A + s.B;
```

### 19. Nullable types and `??`, `??=`, `?.`
```csharp
int? age = null;                       // value type that can be null
string name = user?.Name ?? "Guest";   // ?. safe access, ?? default if null
cache ??= new Dictionary<int,string>();// assign only if null
int len = text?.Length ?? 0;
```
With nullable reference types enabled, `string?` means "may be null" and the compiler warns on risky use.

### 20. Delegates, events, anonymous functions
- **Delegate**: a type-safe pointer to a method. Built-ins: `Func<>`, `Action<>`.
- **Event**: delegate-based notification; outside code can only subscribe/unsubscribe.
- **Anonymous function / lambda**: inline method without a name.
```csharp
public class OrderService {
    public event Action<int>? OrderPlaced;
    public void Place(int id) { /* save */ OrderPlaced?.Invoke(id); }
}
var svc = new OrderService();
svc.OrderPlaced += id => Console.WriteLine($"Email for order {id}");   // lambda
Func<int,int,int> add = (a, b) => a + b;
```

## ASP.NET Core Web API Basics

### 21. Role of Program.cs
The single entry point: **register services** (DI), **build** the app, **configure the middleware pipeline**, **map endpoints**, **run**.
```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();
builder.Services.AddDbContext<StoreDb>(o => o.UseSqlServer(builder.Configuration.GetConnectionString("Default")));
var app = builder.Build();
app.UseHttpsRedirection();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
app.Run();
```
(Older apps had `Startup.cs` with `ConfigureServices`/`Configure`; .NET 6+ merged this.)

### 22. ControllerBase vs Controller
`ControllerBase` = API features (`Ok()`, `NotFound()`, `ModelState`). `Controller` = ControllerBase + **View support** for MVC pages (`View()`, `ViewBag`). For Web APIs inherit `ControllerBase`.

### 23. Purpose of [ApiController]
Turns on API-friendly behavior:
- Automatic **400** response when ModelState is invalid.
- **Binding source inference** (complex types → `[FromBody]`, simple → route/query).
- **ProblemDetails** for error status codes.
- Requires attribute routing.
- `multipart/form-data` inference for `IFormFile`.

### 24. Routing: attribute vs conventional
- **Attribute routing** (API standard): route written on controller/action.
- **Conventional routing** (MVC pages): one global pattern `{controller=Home}/{action=Index}/{id?}`.
```csharp
[ApiController, Route("api/[controller]")]
public class ProductsController : ControllerBase {
    [HttpGet("{id:int}")] public IActionResult Get(int id) => Ok();
    [HttpGet("category/{name}")] public IActionResult ByCategory(string name) => Ok();
}
```

### 25. Parameter binding sources
| Attribute | Reads from | Example |
|---|---|---|
| `[FromBody]` | JSON body | `Create([FromBody] ProductDto dto)` |
| `[FromQuery]` | `?x=1` | `List([FromQuery] int page)` |
| `[FromRoute]` | `/products/5` | `Get([FromRoute] int id)` |
| `[FromHeader]` | header | `[FromHeader(Name="X-Api-Key")] string key` |
| `[FromForm]` | form / file upload | `Upload([FromForm] IFormFile file)` |
| `[FromServices]` | DI container | `[FromServices] IMailer mailer` |

### 26. Dependency Injection and why it's built in
DI = classes receive their dependencies (usually via constructor) from a container instead of using `new`. ASP.NET Core builds it in because the framework itself (controllers, middleware, logging, config, EF) is made of services and needs lifetime management, testability, and loose coupling.
```csharp
public class OrderService(IPaymentGateway pay, ILogger<OrderService> log) { }
builder.Services.AddScoped<IPaymentGateway, StripeGateway>();
```

### 27. Service lifetimes
| Lifetime | Instance | Use for |
|---|---|---|
| **Transient** | new each time | lightweight stateless helpers |
| **Scoped** | one per HTTP request | `DbContext`, business services |
| **Singleton** | one for whole app | caches, config, `HttpClient` factory |
Pitfall: injecting **Scoped into Singleton** (captive dependency).

### 28. Kestrel
Default, cross-platform, high-performance **web server** built into ASP.NET Core. It can face the internet directly, but is commonly put behind a **reverse proxy** (Nginx, IIS, YARP, cloud load balancer) for TLS, load balancing, and extra security.
```json
"Kestrel": { "Endpoints": { "Https": { "Url": "https://*:5001" } } }
```

### 29. appsettings.json and IConfiguration
```json
{ "ConnectionStrings": { "Default": "Server=...;Database=Store" },
  "Payment": { "Provider": "Stripe", "TimeoutSeconds": 10 } }
```
```csharp
var conn = builder.Configuration.GetConnectionString("Default");
var provider = builder.Configuration["Payment:Provider"];
```
Sources layered (later wins): appsettings.json → appsettings.{Environment}.json → user-secrets → environment variables → command line.

### 30. IOptions<T> pattern
Bind a config section to a strongly-typed class (no magic strings).
```csharp
public class PaymentOptions { public string Provider { get; set; } = ""; public int TimeoutSeconds { get; set; } }
builder.Services.Configure<PaymentOptions>(builder.Configuration.GetSection("Payment"));

public class PaymentService(IOptions<PaymentOptions> opt) { int t = opt.Value.TimeoutSeconds; }
```
`IOptions` (singleton, read once), `IOptionsSnapshot` (scoped, reloads per request), `IOptionsMonitor` (singleton + change notifications). Add `.ValidateDataAnnotations().ValidateOnStart()` to fail fast.

## Entity Framework Core (EF Core) Basics

### 31. ORM and EF Core
ORM maps database tables to C# classes so you use objects and LINQ instead of hand-written SQL. **EF Core** is Microsoft's cross-platform ORM supporting SQL Server, PostgreSQL, MySQL, SQLite, Cosmos DB, etc.
```csharp
var cheap = await db.Products.Where(p => p.Price < 100).ToListAsync();
```

### 32. Code-First vs Database-First
- **Code-First**: write C# entities → create migrations → EF builds the DB. Best for new projects.
- **Database-First**: database already exists → generate classes with `dotnet ef dbcontext scaffold "conn" Microsoft.EntityFrameworkCore.SqlServer`. Best for legacy DBs.

### 33. DbContext as Unit of Work and Repository
- **Repository** role: `DbSet<T>` gives query/add/remove for an entity.
- **Unit of Work** role: the context tracks all changes and `SaveChanges()` commits them together in one transaction.
```csharp
db.Orders.Add(order);
db.Products.Update(product);
await db.SaveChangesAsync();   // both saved atomically
```

### 34. Migrations
Versioned scripts of schema changes.
```bash
dotnet ef migrations add AddProductTable     # create
dotnet ef database update                    # apply
dotnet ef migrations remove                  # undo last (unapplied)
dotnet ef migrations script                  # generate SQL (use in production)
```

### 35. DbSet<T>
Represents the table/collection for entity `T` in the context. Query it with LINQ and modify with `Add/Remove/Update`.
`public DbSet<Product> Products => Set<Product>();`

### 36. IQueryable<T> vs IEnumerable<T>
- `IQueryable`: builds an **expression tree** → translated to SQL; filtering happens **in the database**.
- `IEnumerable`: runs **in memory** after data is loaded.
```csharp
var good = db.Products.Where(p => p.Price > 50).ToList();                // WHERE in SQL ✅
var bad  = db.Products.AsEnumerable().Where(p => p.Price > 50).ToList(); // loads ALL rows ❌
```

### 37. Data Annotations vs Fluent API
```csharp
// Data annotations
public class Product { [Key] public int Id { get; set; } [Required, MaxLength(100)] public string Name { get; set; } }
// Fluent API (in OnModelCreating)
modelBuilder.Entity<Product>(b => {
    b.HasKey(p => p.Id);
    b.Property(p => p.Name).IsRequired().HasMaxLength(100);
    b.Property(p => p.Price).HasPrecision(18, 2);
    b.HasIndex(p => p.Sku).IsUnique();
});
```
Annotations: simple, but mix DB concerns into entities and cover less. Fluent: complete (composite keys, indexes, relationships, conversions) and wins on conflict.

### 38. Primary Key and Foreign Key configuration
By convention `Id` or `<Class>Id` is the PK and `<Nav>Id` the FK.
```csharp
public class Order { public int Id { get; set; } public int CustomerId { get; set; } public Customer Customer { get; set; } = null!; }
modelBuilder.Entity<Order>().HasOne(o => o.Customer).WithMany(c => c.Orders)
            .HasForeignKey(o => o.CustomerId).OnDelete(DeleteBehavior.Restrict);
// composite PK
modelBuilder.Entity<OrderItem>().HasKey(i => new { i.OrderId, i.ProductId });
```

### 39. Shadow property
A column that exists in the model/DB but **not as a property** on the class (e.g., audit columns).
```csharp
modelBuilder.Entity<Product>().Property<DateTime>("LastModified");
db.Entry(product).Property("LastModified").CurrentValue = DateTime.UtcNow;
var recent = db.Products.Where(p => EF.Property<DateTime>(p, "LastModified") > cutoff);
```

### 40. AsNoTracking()
Skips change tracking → faster and less memory for read-only queries.
```csharp
var list = await db.Products.AsNoTracking().Where(p => p.IsActive).ToListAsync();
```
Don't use when you plan to modify and save the returned entities. Can set globally: `UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking)`.

## Async Programming & Data Models

### 41. async and await
`async` marks a method that can pause; `await` waits for an operation **without blocking the thread**. The thread returns to the pool to serve other requests, then the method resumes when the operation completes.
```csharp
public async Task<Product?> GetAsync(int id) => await db.Products.FindAsync(id);
```
Rule: use async for I/O (DB, HTTP, files); don't wrap CPU work in `Task.Run` in controllers.

### 42. Task vs ValueTask
`Task<T>` is a reference type (allocates). `ValueTask<T>` is a struct: no allocation when the result is already available (cache hit). Use `Task` by default; `ValueTask` for hot paths that often finish synchronously. Never await a ValueTask twice or call `.Result` before completion.
```csharp
public ValueTask<Product?> GetCachedAsync(int id) =>
    _cache.TryGetValue(id, out var p) ? ValueTask.FromResult<Product?>(p) : new(LoadAsync(id));
```

### 43. DTO and why not expose entities
A DTO is a lightweight class shaped for the API contract.
```csharp
public record ProductResponse(int Id, string Name, decimal Price);
```
Entities shouldn't be returned because: they leak internal/sensitive fields (`CostPrice`, `PasswordHash`), couple clients to the DB schema, cause circular JSON references, enable **over-posting** (client sets `IsAdmin`), and load unnecessary data.

### 44. ModelState validation
`ModelState` collects binding and validation errors. With `[ApiController]` invalid input automatically returns 400.
```csharp
public class CreateProduct { [Required] public string Name { get; set; } [Range(0.01, 100000)] public decimal Price { get; set; } }
// manual (without [ApiController])
if (!ModelState.IsValid) return ValidationProblem(ModelState);
```

### 45. Serialize/deserialize with System.Text.Json
```csharp
string json = JsonSerializer.Serialize(product);
Product? p = JsonSerializer.Deserialize<Product>(json);
var opts = new JsonSerializerOptions { PropertyNamingPolicy = JsonNamingPolicy.CamelCase, WriteIndented = true };
```
Attributes: `[JsonPropertyName("product_name")]`, `[JsonIgnore]`. ASP.NET Core uses it automatically for request/response bodies.

### 46. System.Text.Json vs Newtonsoft.Json
| | System.Text.Json | Newtonsoft (Json.NET) |
|---|---|---|
| Speed/memory | Faster, less allocation | Slower |
| Features | Fewer by default (improving) | Very rich (JObject, JSONPath, flexible converters, JsonPatch) |
| Defaults | Strict, case-sensitive in options | Lenient |
| Source generators / AOT | ✅ | ❌ |
Use STJ for new code; Newtonsoft when you need advanced features or legacy compatibility (`AddNewtonsoftJson()`).

### 47. Returning custom JSON response structures
Use anonymous types, generic wrappers, or records.
```csharp
public record ApiResponse<T>(bool Success, T? Data, string? Error = null);
[HttpGet("{id}")]
public async Task<ActionResult<ApiResponse<ProductResponse>>> Get(int id) {
    var p = await _svc.GetAsync(id);
    return p is null ? NotFound(new ApiResponse<ProductResponse>(false, null, "Not found"))
                     : Ok(new ApiResponse<ProductResponse>(true, p));
}
```
Tip: prefer standard `ProblemDetails` for errors.

### 48. Swagger / OpenAPI and Swashbuckle
**OpenAPI** is a standard JSON description of your API. **Swagger UI** renders it as interactive docs where you can try endpoints. **Swashbuckle** generates it from your controllers.
```csharp
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();
app.UseSwagger(); app.UseSwaggerUI();   // /swagger
```
Benefits: living documentation, client code generation, contract testing. (.NET 9 also has built-in `Microsoft.AspNetCore.OpenApi`.)

### 49. Logging and ILogger<T>
`ILogger<T>` is the built-in logging abstraction; `T` becomes the category name. Providers (console, file via Serilog, App Insights) plug in behind it.
```csharp
public class OrderService(ILogger<OrderService> log) {
    public void Place(int id) {
        log.LogInformation("Order {OrderId} placed", id);       // structured
        try { } catch (Exception ex) { log.LogError(ex, "Order {OrderId} failed", id); }
    }
}
```
Levels: Trace, Debug, Information, Warning, Error, Critical. Configure in `appsettings.json` → `Logging:LogLevel`.

### 50. Synchronous vs asynchronous endpoint execution
- **Sync**: the request thread is **blocked** while waiting for the DB; under load you run out of threads (thread-pool starvation).
- **Async**: thread is released during the wait, so the same server handles many more concurrent requests.
```csharp
// ❌ blocks a thread
public IActionResult Get() => Ok(db.Products.ToList());
// ✅ frees the thread while waiting for the DB
public async Task<IActionResult> Get(CancellationToken ct) => Ok(await db.Products.ToListAsync(ct));
```
A single async request isn't faster; **throughput and scalability** improve.

## Pipeline, Middleware & Request Lifecycle

### 51. Middleware, and the flow through Use and Run
Middleware = components in the request pipeline; each can handle the request, call the next one, and act on the way back.
- `Use`: can call `next()` and pass control on.
- `Run`: **terminal**, ends the pipeline (no `next`).
```csharp
app.Use(async (ctx, next) => {
    Console.WriteLine("1 before");
    await next();                       // go to next middleware
    Console.WriteLine("1 after");
});
app.Run(async ctx => await ctx.Response.WriteAsync("Hello"));  // end
// Output order: 1 before → Hello → 1 after
```

### 52. Map vs MapWhen vs Use
- `Use`: runs for **every** request.
- `Map("/admin", ...)`: **branches** the pipeline when the path starts with `/admin` (path is trimmed).
- `MapWhen(predicate, ...)`: branches on **any condition** (header, query, host).
```csharp
app.Map("/ping", b => b.Run(c => c.Response.WriteAsync("pong")));
app.MapWhen(c => c.Request.Headers.ContainsKey("X-Beta"), b => b.Use(async (c, n) => { /* beta flow */ await n(); }));
```
Branches don't rejoin the main pipeline (unless `UseWhen` is used).

### 53. Pipeline order
Recommended order:
```
UseExceptionHandler → UseHsts → UseHttpsRedirection → UseStaticFiles
→ UseRouting → UseCors → UseAuthentication → UseAuthorization
→ (rate limiter, response caching) → MapControllers / endpoints
```
Why: errors must be caught by the first middleware; routing must know the endpoint before CORS/auth read its metadata; authentication must run before authorization; wrong order = 401s or missing CORS headers.

### 54. Action, Exception, Resource filters vs Middleware
Filters run **inside MVC**, after routing, and know about actions, model binding, and results. Middleware runs for **all** requests.

| Filter | Runs | Typical use |
|---|---|---|
| Authorization | first | custom auth checks |
| Resource | before model binding, after the rest | caching, short-circuit |
| Action | before/after the action method | logging, argument validation |
| Exception | when action throws | MVC-specific error handling |
| Result | around result execution | modify response |
```csharp
public class LogActionFilter : IAsyncActionFilter {
    public async Task OnActionExecutionAsync(ActionExecutingContext c, ActionExecutionDelegate next) {
        Console.WriteLine($"Calling {c.ActionDescriptor.DisplayName}");
        await next();
    }
}
```

### 55. Custom middleware class
```csharp
public class ApiKeyMiddleware(RequestDelegate next, IConfiguration cfg) {
    public async Task InvokeAsync(HttpContext ctx) {
        if (!ctx.Request.Headers.TryGetValue("X-Api-Key", out var key) || key != cfg["ApiKey"]) {
            ctx.Response.StatusCode = 401;
            await ctx.Response.WriteAsync("Invalid API key");
            return;                          // short-circuit
        }
        await next(ctx);
    }
}
public static class Ext { public static IApplicationBuilder UseApiKey(this IApplicationBuilder a) => a.UseMiddleware<ApiKeyMiddleware>(); }
app.UseApiKey();
```
Scoped services go in `InvokeAsync` parameters, not the constructor.

### 56. Global exception handling (custom middleware / IExceptionHandler)
```csharp
public class GlobalExceptionHandler(ILogger<GlobalExceptionHandler> log) : IExceptionHandler {
    public async ValueTask<bool> TryHandleAsync(HttpContext ctx, Exception ex, CancellationToken ct) {
        log.LogError(ex, "Unhandled exception");
        var (status, title) = ex switch {
            NotFoundException => (404, "Resource not found"),
            ValidationException => (400, "Validation failed"),
            _ => (500, "Server error") };
        ctx.Response.StatusCode = status;
        await ctx.Response.WriteAsJsonAsync(new ProblemDetails { Status = status, Title = title,
            Instance = ctx.Request.Path }, ct);
        return true;   // handled
    }
}
builder.Services.AddExceptionHandler<GlobalExceptionHandler>();
builder.Services.AddProblemDetails();
app.UseExceptionHandler();
```
Never return stack traces to clients in production.

### 57. ProblemDetails (RFC 7807 / 9457)
Standard JSON format for API errors.
```json
{ "type":"https://httpstatuses.com/404", "title":"Product not found", "status":404,
  "detail":"No product with id 99", "instance":"/api/products/99", "traceId":"00-abc..." }
```
Content-Type: `application/problem+json`. Clients can parse every error the same way. Add extra data via `Extensions`.

### 58. IActionResult vs ActionResult<T> vs concrete types
| Return | Pros | Cons |
|---|---|---|
| Concrete (`Product`) | simplest, typed | always 200; can't return 404 |
| `IActionResult` | any status | Swagger doesn't know the body type (needs `[ProducesResponseType]`) |
| `ActionResult<T>` | any status **and** typed for Swagger; `return product;` works | slight verbosity |
```csharp
[HttpGet("{id}")]

    var p = await db.Products.FindAsync(id);
    if (p is null) return NotFound();
    return p;                    // implicit 200
}
```

```csharp
}
```

## Authentication, Security & Validation

### 61. Authentication vs Authorization
Authentication = **who are you** (login, token validation, sets `HttpContext.User`). Authorization = **what may you do** (`[Authorize]`, roles, policies). In the pipeline: `UseAuthentication()` then `UseAuthorization()`.

### 62. How JWT authentication works
1. `POST /auth/login` with email + password.
2. Server verifies and returns a **signed JWT**.
3. Client sends `Authorization: Bearer <jwt>` on every call.
4. Server checks signature, issuer, audience, expiry → builds the user from claims.
5. No server session needed (stateless).
```csharp
builder.Services.AddAuthentication("Bearer").AddJwtBearer(o => o.TokenValidationParameters = new() {
    ValidateIssuer = true, ValidIssuer = "store-api", ValidateAudience = true, ValidAudience = "store-clients",
    ValidateLifetime = true, ValidateIssuerSigningKey = true,
    IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(cfg["Jwt:Key"]!)) });
```

### 63. JWT structure
`xxxxx.yyyyy.zzzzz`
- **Header**: `{"alg":"HS256","typ":"JWT"}`
- **Payload (claims)**: `{"sub":"42","email":"a@b.com","role":"Admin","exp":1767225600}`
- **Signature**: `HMAC(base64(header) + "." + base64(payload), secretKey)`
Payload is only Base64-encoded, **not encrypted**; never put passwords/secrets in it. Signature guarantees it wasn't modified.

### 64. Refresh token
Access tokens are short-lived (5-15 min) for safety. A **refresh token** (long-lived random string) lets the client get a new access token without logging in again.
Flow: login → (access, refresh) → access expires → `POST /auth/refresh {refresh}` → server validates (stored **hashed** in DB, not expired/revoked) → issues new access **and a new refresh token** (rotation), invalidating the old one. Reuse of an old refresh token = theft signal → revoke all that user's tokens.
```csharp
var bytes = RandomNumberGenerator.GetBytes(64);
var refresh = Convert.ToBase64String(bytes);
// store SHA256(refresh), userId, expiresAt in DB
```

### 65. Role-based vs Policy-based authorization
```csharp
// Role-based
[Authorize(Roles = "Admin,Manager")]
// Policy-based
builder.Services.AddAuthorization(o => {
    o.AddPolicy("CanRefund", p => p.RequireClaim("permission", "orders.refund"));
    o.AddPolicy("Over18", p => p.RequireAssertion(c => int.Parse(c.User.FindFirstValue("age") ?? "0") >= 18));
});
[Authorize(Policy = "CanRefund")]
```
Roles are simple but coarse. Policies combine claims/requirements/custom handlers (`IAuthorizationHandler`), support resource-based checks ("owner of this order") and scale better.

### 66. Claims-based identity
- **Claim**: a fact about the user (`email`, `role`, `tenantId`).
- **ClaimsIdentity**: a set of claims from one authentication source (e.g., JWT).
- **ClaimsPrincipal**: the user = one or more identities. Available as `HttpContext.User`.
```csharp
var claims = new[] { new Claim(ClaimTypes.NameIdentifier, "42"), new Claim(ClaimTypes.Role, "Admin") };
var principal = new ClaimsPrincipal(new ClaimsIdentity(claims, "jwt"));
var id = User.FindFirstValue(ClaimTypes.NameIdentifier);
bool admin = User.IsInRole("Admin");
```

### 67. FluentValidation vs DataAnnotations
```csharp
public class CreateOrderValidator : AbstractValidator<CreateOrderRequest> {
    public CreateOrderValidator(IProductRepo repo) {
        RuleFor(x => x.Items).NotEmpty();
        RuleForEach(x => x.Items).ChildRules(i => { i.RuleFor(a => a.Qty).GreaterThan(0); });
        RuleFor(x => x.Email).EmailAddress().When(x => x.NotifyByEmail);
        RuleFor(x => x.CouponCode).MustAsync(async (c, ct) => c is null || await repo.CouponExistsAsync(c, ct));
    }
}
```
| | DataAnnotations | FluentValidation |
|---|---|---|
| Style | attributes | code rules, separate class |
| Conditional/cross-field | awkward | easy |
| Async/DB checks | no | yes |
| DI & unit testing | limited | great |

### 68. Preventing XSS and SQL injection
**SQL injection**: always parameterize.
```csharp
await db.Products.FromSqlInterpolated($"SELECT * FROM Products WHERE Name = {name}").ToListAsync(); // safe
// ❌ $"... WHERE Name = '{name}'" in FromSqlRaw
```
Plus: EF LINQ (auto-parameterized), least-privilege DB user, validate input.
**XSS**: validate/sanitize input, **encode output** (`HtmlEncoder`), return JSON with correct content type, add CSP header, HttpOnly cookies, never inject untrusted data in HTML. APIs that only return JSON are less exposed, but stored malicious text can attack the front end that renders it.

### 69. HTTPS, HSTS, secure headers
```csharp
if (!app.Environment.IsDevelopment()) app.UseHsts();     // tells browsers "HTTPS only" (Strict-Transport-Security)
app.UseHttpsRedirection();
app.Use(async (ctx, next) => {
    var h = ctx.Response.Headers;
    h["X-Content-Type-Options"] = "nosniff";
    h["X-Frame-Options"] = "DENY";
    h["Referrer-Policy"] = "no-referrer";
    h["Content-Security-Policy"] = "default-src 'none'; frame-ancestors 'none'";

});
```
Also configure Kestrel/proxy TLS 1.2+, use `UseForwardedHeaders` behind a proxy, and remove the `Server` header (`AddServerHeader = false`).

### 70. API Key authentication vs JWT
API key = a secret string identifying the **calling application**.
```csharp
public class ApiKeyHandler : AuthenticationHandler<AuthenticationSchemeOptions> { /* read X-Api-Key, look up hashed key, build principal */ }
```
Use API keys for: server-to-server, public developer APIs, webhooks, simple partner integrations, usage tracking/quotas. Use JWT for: **user** identity, short-lived tokens, claims/roles, SSO. Keys are long-lived: store hashed, rotate, scope them, send only over HTTPS.

## EF Core Deep Dive & Performance

### 71. N+1 query problem
1 query loads N orders, then N more queries load each order's items.
```csharp
// ❌ N+1 (lazy loading or loop queries)
foreach (var o in await db.Orders.ToListAsync()) { var items = await db.Items.Where(i => i.OrderId == o.Id).ToListAsync(); }
// ✅ fixes
await db.Orders.Include(o => o.Items).ToListAsync();                      // eager load
await db.Orders.Select(o => new OrderDto(o.Id, o.Items.Count)).ToListAsync(); // projection (best)
```
Detect via SQL logging (`LogTo`), MiniProfiler, or APM query counts.

### 72. Loading strategies
```csharp
// Eager: in the same query
var o = await db.Orders.Include(x => x.Items).ThenInclude(i => i.Product).FirstAsync();
// Explicit: load on demand
await db.Entry(order).Collection(x => x.Items).LoadAsync();
// Lazy: automatic on first access (needs Microsoft.EntityFrameworkCore.Proxies + virtual props)
options.UseLazyLoadingProxies();
```
Use eager/projection for APIs; explicit for conditional loads; avoid lazy in APIs (hidden N+1, serialization surprises).

### 73. First, FirstOrDefault, Single, SingleOrDefault
| Method | 0 rows | 1 row | 2+ rows |
|---|---|---|---|
| `First` | throws | ✅ | ✅ first |
| `FirstOrDefault` | null | ✅ | ✅ first |
| `Single` | throws | ✅ | throws |
| `SingleOrDefault` | null | ✅ | throws |
Use `Single*` when uniqueness is a rule (email); `First*` with an `OrderBy` when many are fine. `FindAsync(id)` checks the tracker first.

### 74. Change tracking and entity states
EF snapshots loaded entities; on `SaveChanges` it detects differences.
| State | Meaning | SQL |
|---|---|---|
| Added | new | INSERT |
| Unchanged | loaded, no changes | none |
| Modified | property changed | UPDATE (only changed columns) |
| Deleted | marked removed | DELETE |
| Detached | not tracked | none |
```csharp
var p = await db.Products.FirstAsync(); p.Price = 20;
Console.WriteLine(db.Entry(p).State);   // Modified
await db.SaveChangesAsync();
```

### 75. Global Query Filters
A `WHERE` clause automatically applied to every query of an entity.
```csharp
modelBuilder.Entity<Product>().HasQueryFilter(p => !p.IsDeleted);                      // soft delete
modelBuilder.Entity<Order>().HasQueryFilter(o => o.TenantId == _tenant.Id);            // multi-tenancy
var all = await db.Products.IgnoreQueryFilters().ToListAsync();                         // bypass
```
Use cases: soft delete, multi-tenancy, "published only", row-level visibility. Watch out for required navigations referencing filtered entities.

### 76. Raw SQL and stored procedures
```csharp
var items = await db.Products.FromSql($"SELECT * FROM Products WHERE Price > {min}").ToListAsync();   // safe, parameterized
var top   = await db.Products.FromSqlInterpolated($"EXEC GetTopProducts {count}").ToListAsync();
int rows  = await db.Database.ExecuteSqlInterpolatedAsync($"UPDATE Products SET Stock = 0 WHERE Id = {id}");
```
`FromSqlRaw` with string concatenation = injection risk; use parameters (`new SqlParameter("@min", min)`). `FromSql*` must return all entity columns and can be composed with LINQ (not with `EXEC`).

### 77. Compiled Queries
Cache the LINQ→SQL translation so repeated hot queries skip compilation.
```csharp
private static readonly Func<StoreDb, int, Task<Product?>> ById =
    EF.CompileAsyncQuery((StoreDb db, int id) => db.Products.FirstOrDefault(p => p.Id == id));
var p = await ById(db, 5);
```
Use for very frequent, simple, stable queries after profiling shows gains. EF already caches query plans, so benefit is modest.

### 78. Database transactions
`SaveChanges` is already one transaction. For multiple steps:
```csharp
await using IDbContextTransaction tx = await db.Database.BeginTransactionAsync();
try {
    db.Orders.Add(order); await db.SaveChangesAsync();
    await db.Products.Where(p => p.Id == pid).ExecuteUpdateAsync(s => s.SetProperty(p => p.Stock, p => p.Stock - 1));
    await tx.CommitAsync();
} catch { await tx.RollbackAsync(); throw; }
```
`TransactionScope` (with `TransactionScopeAsyncFlowOption.Enabled`) wraps multiple contexts/resources but may escalate to distributed transactions (MSDTC on Windows); prefer `IDbContextTransaction`. Use `CreateExecutionStrategy()` with retrying providers.

### 79. EF Core Interceptors
Hooks into EF operations.
```csharp
public class SlowQueryInterceptor : DbCommandInterceptor {
    public override ValueTask<DbDataReader> ReaderExecutedAsync(DbCommand c, CommandExecutedEventData e, DbDataReader r, CancellationToken ct = default) {
        if (e.Duration.TotalMilliseconds > 500) Console.WriteLine($"SLOW: {c.CommandText}");
        return base.ReaderExecutedAsync(c, e, r, ct);
    }
}
options.AddInterceptors(new SlowQueryInterceptor(), new AuditSaveChangesInterceptor());
```
Types: `DbCommandInterceptor` (SQL commands), `SaveChangesInterceptor` (audit/soft delete), `DbConnectionInterceptor` (e.g., add auth token), `DbTransactionInterceptor`.

### 80. Concurrency conflicts with RowVersion
```csharp
public class Product { public int Id { get; set; } public int Stock { get; set; } [Timestamp] public byte[] RowVersion { get; set; } = []; }
try { await db.SaveChangesAsync(); }
catch (DbUpdateConcurrencyException ex) {
    var entry = ex.Entries.Single();
```

## API Performance, Caching & Best Practices

### 81. Response Caching vs Output Caching
- **Response caching**: sets HTTP headers (`Cache-Control`) so **clients/proxies** cache; server doesn't store. Honors client headers; limited control.
- **Output caching (.NET 7+)**: **server-side** cache of whole responses with policies, tags, vary-by, invalidation; client headers don't control it.
```csharp
builder.Services.AddOutputCache(o => o.AddPolicy("Products", b => b.Expire(TimeSpan.FromMinutes(1)).Tag("products")));
app.UseOutputCache();
app.MapGet("/products", GetProducts).CacheOutput("Products");
await cache.EvictByTagAsync("products", ct);     // after updates
```

### 82. IMemoryCache vs IDistributedCache (Redis)
| | IMemoryCache | IDistributedCache (Redis) |
|---|---|---|
| Location | app process | external shared server |
| Speed | fastest | network hop |
| Multi-instance | each has its own copy | shared, consistent |
| Survives restart | no | yes |
```csharp
var product = await _mem.GetOrCreateAsync($"p:{id}", async e => { e.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5); return await repo.GetAsync(id); });

builder.Services.AddStackExchangeRedisCache(o => o.Configuration = "localhost:6379");
await _dist.SetStringAsync("p:1", json, new DistributedCacheEntryOptions { SlidingExpiration = TimeSpan.FromMinutes(10) });
```
.NET 9 `HybridCache` combines both with stampede protection.

### 83. Rate limiting (.NET 7+)

### 84. Pagination, sorting, filtering
```csharp
public record ProductQuery(string? Search, string? Category, string? Sort = "name", bool Desc = false, int Page = 1, int PageSize = 20);
[HttpGet] public async Task<ActionResult<PagedResult<ProductDto>>> Get([FromQuery] ProductQuery q) {
    var pageSize = Math.Clamp(q.PageSize, 1, 100);
    IQueryable<Product> query = db.Products.AsNoTracking();
    if (!string.IsNullOrWhiteSpace(q.Search)) query = query.Where(p => p.Name.Contains(q.Search));
    if (q.Category is not null) query = query.Where(p => p.Category == q.Category);
    query = (q.Sort, q.Desc) switch {
        ("price", false) => query.OrderBy(p => p.Price), ("price", true) => query.OrderByDescending(p => p.Price),
        (_, true) => query.OrderByDescending(p => p.Name), _ => query.OrderBy(p => p.Name) };   // whitelist sort fields
    var total = await query.CountAsync();
    var items = await query.Skip((q.Page - 1) * pageSize).Take(pageSize).Select(p => new ProductDto(p.Id, p.Name, p.Price)).ToListAsync();
    return new PagedResult<ProductDto>(items, total, q.Page, pageSize);
}
```
Always apply a stable `OrderBy` before `Skip/Take`.

### 85. Offset vs Cursor (Keyset) pagination
- **Offset**: `?page=500&pageSize=20` → `OFFSET 9980`. Simple, supports "jump to page", but slow for deep pages (DB scans skipped rows) and can duplicate/skip rows if data changes.
- **Cursor/Keyset**: `?after=1042&limit=20` → `WHERE Id > 1042 ORDER BY Id LIMIT 20`. Uses the index, constant speed, stable; no page jumping.
```csharp
var items = await db.Orders.Where(o => o.Id > after).OrderBy(o => o.Id).Take(limit + 1).ToListAsync();
var next = items.Count > limit ? items[limit - 1].Id : (int?)null;
```
Use cursor for infinite scroll, feeds, huge tables.

### 89. Background tasks and hosted services

## C# Language Features & Memory Basics

### 91. Records
Concise types with **value-based equality**, `with` expressions, and built-in `ToString`.
```csharp
public record ProductDto(int Id, string Name);              // record class (reference type), immutable by default
public readonly record struct Money(decimal Amount, string Currency);   // value type
var a = new ProductDto(1, "Pen"); var b = a with { Name = "Pencil" };
Console.WriteLine(a == new ProductDto(1, "Pen"));  // True
```
Class: reference equality. Struct: value type, no built-in value equality for fields by default beyond reflection-based. Record: compiler-generated equality. Records are ideal for DTOs and messages.

### 92. Pattern matching
```csharp
decimal Discount(object o) => o switch {
    Order { Total: > 1000, Customer.IsVip: true } => 0.20m,   // property pattern
    Order { Total: > 1000 }                        => 0.10m,
    Order                                          => 0m,
    null                                           => throw new ArgumentNullException(nameof(o)),
    _                                              => 0m };
var (x, y) = point; var area = shape switch { Circle(var r) => Math.PI*r*r, Rect(var w, var h) => w*h, _ => 0 };  // positional
string size = qty switch { < 10 => "small", >= 10 and < 100 => "medium", _ => "large" };  // relational + logical
```

### 93. Span<T> and Memory<T>
`Span<T>` is a stack-only, zero-allocation **view** over contiguous memory (array, string, stackalloc). `Memory<T>` is the heap-friendly version usable in async methods/fields.
```csharp
ReadOnlySpan<char> year = "2025-06-01".AsSpan(0, 4);      // no new string allocated
int n = int.Parse(year);
Span<byte> buffer = stackalloc byte[256];
```
Benefits: slicing/parsing without allocations → less GC. Limitations: `Span` can't be a field of a class, captured in lambdas, or used across `await`.

### 94. Garbage Collection: generations and LOH
GC frees unreachable objects automatically.
- **Gen 0**: new, short-lived objects (collected very often, cheap).
- **Gen 1**: survivors of Gen 0 (buffer).
- **Gen 2**: long-lived objects (collected rarely, expensive: "full GC").
- **LOH (Large Object Heap)**: objects ≥ 85 KB, collected with Gen 2, historically not compacted → fragmentation/memory growth.
Tips: avoid large short-lived allocations (use `ArrayPool`), avoid holding references longer than needed, prefer `Span`, and don't call `GC.Collect()`.

### 95. IDisposable vs the Garbage Collector
GC frees **managed memory** at an unpredictable time. It doesn't know about **unmanaged resources** (file handles, DB connections, sockets). `IDisposable.Dispose()` releases them **immediately and deterministically**. Finalizers are only a last-resort safety net and are slow.
```csharp
public class Report : IDisposable {
    private readonly FileStream _fs = File.OpenRead("r.dat");
    public void Dispose() { _fs.Dispose(); GC.SuppressFinalize(this); }
}
```

### 96. using statement / declaration
Guarantees `Dispose()` is called, even on exceptions (compiles to try/finally).
```csharp
using (var conn = new SqlConnection(cs)) { await conn.OpenAsync(); }   // classic: disposed at }
using var stream = File.OpenRead("a.txt");                              // declaration: disposed at end of scope
await using var tx = await db.Database.BeginTransactionAsync();         // IAsyncDisposable
```
Don't dispose services injected by DI (the container owns them).

### 97. CancellationToken in async actions and EF Core
When a client disconnects or times out, ASP.NET Core signals `HttpContext.RequestAborted`. Passing the token down cancels the **database query** and other work instead of wasting CPU/DB on results nobody will read.
```csharp
[HttpGet] public async Task<IActionResult> Get(CancellationToken ct)
    => Ok(await db.Products.AsNoTracking().ToListAsync(ct));    // query is cancelled if client leaves
```
Handle `OperationCanceledException` (the framework treats it as normal; don't log it as error). Pass the token through services, `HttpClient` calls, and `Task.Delay`.

### 98. Task.WhenAll vs Task.WhenAny
```csharp
var t1 = http.GetStringAsync(urlA); var t2 = http.GetStringAsync(urlB);
string[] all = await Task.WhenAll(t1, t2);          // waits for ALL; throws first exception (others in task.Exception)

var winner = await Task.WhenAny(t1, Task.Delay(2000));   // first to finish → timeout pattern
if (winner != t1) throw new TimeoutException();
```
`WhenAll` = fan-out/fan-in for independent calls. `WhenAny` = timeout, redundancy ("fastest mirror wins"), processing as they complete. Don't run parallel queries on one `DbContext`.

### 99. ValueTask: when to prefer it over Task
Prefer when the method **often completes synchronously** and is called very frequently (cache lookups, buffered reads), avoiding a `Task` allocation each call.
Rules: await it **once**, don't use `.Result` until done, don't store/await concurrently; convert with `.AsTask()` if you need those. For most business code `Task` is fine; measure first.

### 100. Thread pool starvation and how async prevents it
The thread pool has limited threads. If requests **block** threads (`.Result`, `.Wait()`, `Thread.Sleep`, sync DB calls) while waiting on I/O, all threads become busy doing nothing → new requests queue → latency spikes/timeouts even though CPU is low. The pool injects threads slowly (~1-2/second), so it recovers slowly.
`async/await` releases the thread during the wait, so a few threads can serve thousands of in-flight requests.
```csharp
// ❌ starvation risk
var result = service.GetAsync().Result;
// ✅
var result = await service.GetAsync();
```
Diagnose with `dotnet-counters` (ThreadPool Queue Length, Thread Count).

## Architecture, CQRS & Design Patterns

### 101. Clean / Onion Architecture
Layers with dependencies pointing **inward only**:
```
API (Controllers) ─┐
Infrastructure (EF Core, Email, Redis) ─┤→ Application (use cases, interfaces, DTOs) → Domain (entities, rules)
```
- **Domain**: entities, value objects, business rules. No dependencies.
- **Application**: use cases (commands/queries), interfaces like `IOrderRepository`, `IPaymentGateway`.
- **Infrastructure**: implements those interfaces (EF Core, SMTP, Stripe).
- **API**: thin controllers, DI wiring.
Decoupling comes from **Dependency Inversion**: the Application layer defines the interface; Infrastructure implements it; DI connects them at startup. Result: swap the DB or gateway without touching business logic, and test business rules without a DB.

### 102. Repository & Unit of Work; is EF Core already one?
- **Repository**: collection-like abstraction for data access (`IProductRepository`).
- **Unit of Work**: groups changes into one transaction and one `Commit`.
Yes, `DbSet<T>` ≈ repository, `DbContext` ≈ unit of work. Wrapping them again is often redundant, but still useful when you want to: hide EF from the domain (strict Clean Architecture), centralize complex queries (Specification pattern), or ease mocking.
```csharp
public interface IUnitOfWork { Task<int> SaveChangesAsync(CancellationToken ct = default); }
public class StoreDb : DbContext, IUnitOfWork { }
```
Avoid generic `IRepository<T>` that just forwards to `DbSet<T>`; it adds noise and leaks `IQueryable`.

### 103. CQRS
Split the model into **Commands** (change state, return little) and **Queries** (read, change nothing).
```csharp
public record PlaceOrderCommand(int CustomerId, List<OrderLine> Lines) : IRequest<int>;
public record GetOrderQuery(int Id) : IRequest<OrderDto?>;
```
Why used: reads and writes have different needs (scale, caching, optimized read models/Dapper vs rich domain model for writes), clearer code, easier to apply validation/transactions to commands only. Levels: same DB (simple) → separate read DB with eventual consistency (advanced). Not worth it for simple CRUD.

### 104. Mediator pattern with MediatR
Components talk to a **mediator** instead of each other. Controllers send a request; MediatR finds its single handler; **pipeline behaviors** add cross-cutting concerns.
```csharp
public class PlaceOrderHandler(StoreDb db) : IRequestHandler<PlaceOrderCommand, int> {
    public async Task<int> Handle(PlaceOrderCommand c, CancellationToken ct) {
        var order = Order.Create(c.CustomerId, c.Lines); db.Orders.Add(order); await db.SaveChangesAsync(ct); return order.Id;
    }
}
public class ValidationBehavior<TReq, TRes>(IEnumerable<IValidator<TReq>> vs) : IPipelineBehavior<TReq, TRes> where TReq : notnull {
    public async Task<TRes> Handle(TReq r, RequestHandlerDelegate<TRes> next, CancellationToken ct) {
        var fails = vs.Select(v => v.Validate(r)).SelectMany(x => x.Errors).ToList();
        if (fails.Count > 0) throw new ValidationException(fails);
        return await next();
    }
}
[HttpPost] public async Task<IActionResult> Place(PlaceOrderCommand cmd) => Ok(await mediator.Send(cmd));
```
Notifications (`INotification`) publish to many handlers (domain events). Note: MediatR v12+ is under a commercial license for some uses; alternatives exist (Wolverine, Mediator source-gen).

### 105. Domain-Driven Design (DDD)
Model software around the business domain using its language ("Ubiquitous Language").
- **Entity**: has identity, can change (`Order` Id=5).
- **Value Object**: no identity, compared by value, immutable (`Money`, `Address`).
- **Aggregate**: cluster of entities with a **root** that enforces invariants; only the root is accessed from outside; one transaction per aggregate.
- **Domain Event**: something that happened (`OrderPlaced`).
```csharp
public record Money(decimal Amount, string Currency);
public class Order {                         // aggregate root
    private readonly List<OrderLine> _lines = new();
    public IReadOnlyList<OrderLine> Lines => _lines;
    public void AddLine(int productId, int qty, Money price) {
        if (qty <= 0) throw new DomainException("Qty must be positive");   // invariant
        _lines.Add(new OrderLine(productId, qty, price));
    }
    public void Place() { /* ... */ AddDomainEvent(new OrderPlaced(Id)); }
}
```

### 106. Event Sourcing and its pairing with CQRS
Store **events** (facts) instead of current state: `ProductCreated`, `StockAdded(10)`, `StockRemoved(3)`. Current state = replay events (snapshots speed up). 
With CQRS: the **write side** appends events to an event store; **projections** build optimized **read models** (SQL/Elasticsearch) from the events → easy scaling and multiple read views.
Pros: full audit history, time travel, rebuild read models. Cons: complexity, event schema versioning, eventual consistency, learning curve. Tools: Marten, EventStoreDB.

### 107. Minimal APIs vs Controllers
```csharp
app.MapGet("/products/{id}", async (int id, StoreDb db) => await db.Products.FindAsync(id) is { } p ? Results.Ok(p) : Results.NotFound());
```
| | Minimal API | Controllers |
|---|---|---|
| Pipeline | lighter: routing → endpoint filters → handler | MVC filters, model binding, formatters |
| Startup/overhead | less (reflection reduced), AOT-friendly | more features, a bit more overhead |
| Features | filters, groups, OpenAPI; fewer built-ins (validation added in .NET 10) | filters, conventions, `[ApiController]`, versioning, rich ecosystem |
| Best for | microservices, small APIs, performance-sensitive | large structured APIs, teams used to MVC |
Benchmarks show Minimal APIs slightly faster, but DB/network time usually dominates, so choose by structure and team preference.

### 108. Idempotency and Idempotency Keys
Idempotent = repeating the request has no extra effect. POST isn't naturally, so clients send an **Idempotency-Key** (UUID) for operations like payments.
```csharp
[HttpPost("payments")]
public async Task<IActionResult> Pay([FromHeader(Name = "Idempotency-Key")] Guid key, PayRequest r) {
    var saved = await db.IdempotencyRecords.FindAsync(key);
    if (saved is not null) return StatusCode(saved.StatusCode, JsonDocument.Parse(saved.Body).RootElement);   // replay
    try {
        db.IdempotencyRecords.Add(new IdempotencyRecord { Key = key, Status = "InProgress" });
        await db.SaveChangesAsync();                   // PK on Key → duplicates fail here
    } catch (DbUpdateException) { return Conflict("Request in progress"); }
    var result = await gateway.ChargeAsync(r, key.ToString());   // pass key to the gateway too
    await SaveResponseAsync(key, 201, result);
    return Created($"/payments/{result.Id}", result);
}
```
Also: expire keys after ~24h, hash the request body to detect same key + different payload (422).

### 109. HATEOAS
Responses include **links to next possible actions**, so clients follow links instead of hard-coding URLs.
```json
{ "id": 5, "status": "Pending", "total": 99.5,
  "_links": { "self": {"href":"/orders/5"}, "pay": {"href":"/orders/5/pay","method":"POST"}, "cancel": {"href":"/orders/5","method":"DELETE"} } }
```
Links change with state (a shipped order has no `cancel`). In .NET build them with `LinkGenerator` or libraries (Hateoas, HAL). Adds discoverability and decoupling, but more payload/complexity; this is "Level 3" of the Richardson model and is rare in practice.

### 110. Outbox Pattern
Problem: you save an order in the DB **and** publish `OrderPlaced` to a broker; if one succeeds and the other fails, systems become inconsistent (dual-write problem).
Solution: in **one DB transaction**, save the order **and** an `OutboxMessage` row. A separate publisher reads unsent rows, publishes to the broker, then marks them sent (at-least-once delivery).
```csharp
db.Orders.Add(order);
db.OutboxMessages.Add(new OutboxMessage { Type = nameof(OrderPlaced), Payload = JsonSerializer.Serialize(new OrderPlaced(order.Id)) });
await db.SaveChangesAsync();                                   // atomic

// BackgroundService
var batch = await db.OutboxMessages.Where(m => m.SentAt == null).OrderBy(m => m.Id).Take(50).ToListAsync(ct);
foreach (var m in batch) { await bus.PublishAsync(m, ct); m.SentAt = DateTime.UtcNow; }
await db.SaveChangesAsync(ct);
```
Consumers must be **idempotent** (use message IDs; the "inbox" pattern). MassTransit has a built-in EF outbox.

## Microservices, Messaging & Distributed Systems

### 111. Monolith vs Microservices
| | Monolith | Microservices |
|---|---|---|
| Deployment | one unit | many independent |
| Data | one DB | database per service |
| Scaling | whole app | per service |
| Complexity | low | high (network, tracing, consistency) |
| Team fit | small/medium | many autonomous teams |
Recommendation: start with a **modular monolith**, extract services when scale/team boundaries require it. Microservices cost: distributed transactions, latency, DevOps maturity, observability.

### 112. Synchronous (REST/gRPC) vs asynchronous messaging
- **Sync**: caller waits for response; simple; but tight temporal coupling, cascading failures, latency adds up.
- **Async (RabbitMQ, Service Bus, Kafka)**: caller sends a message and moves on; services decoupled, buffered traffic, retries, fan-out; but eventual consistency and harder debugging.
Rule: **queries/real-time answers → sync; commands/events/long workflows → async.**

### 113. MassTransit and NServiceBus
Abstractions over message brokers (RabbitMQ, Azure Service Bus, SQS, Kafka) providing: publish/subscribe, consumers, retries, **outbox/inbox**, **sagas/state machines**, scheduling, observability, and testing harnesses; so you don't write raw broker code.
```csharp
public record OrderPlaced(int OrderId);
public class SendEmailConsumer : IConsumer<OrderPlaced> {
    public Task Consume(ConsumeContext<OrderPlaced> ctx) { /* send email */ return Task.CompletedTask; }
}
builder.Services.AddMassTransit(x => { x.AddConsumer<SendEmailConsumer>(); x.UsingRabbitMq((c, cfg) => { cfg.Host("rabbit"); cfg.ConfigureEndpoints(c); }); });
await publishEndpoint.Publish(new OrderPlaced(5));
```
NServiceBus is commercial with strong tooling (monitoring/ServicePulse); MassTransit has open-source/commercial licensing (v9 commercial).

### 114. gRPC and why it beats REST for internal calls
gRPC uses **Protocol Buffers** (binary, compact) over **HTTP/2** (multiplexed streams on one connection, header compression, bidirectional streaming).
```proto
service Inventory { rpc GetStock (StockRequest) returns (StockReply); }
message StockRequest { int32 product_id = 1; }  message StockReply { int32 quantity = 1; }
```
```csharp
builder.Services.AddGrpc(); app.MapGrpcService<InventoryService>();
var reply = await client.GetStockAsync(new StockRequest { ProductId = 5 });
```
Choose gRPC: internal microservice calls, low latency/high throughput, streaming, strict contracts, polyglot. Choose REST: public APIs, browsers, easy debugging/caching. (Browsers need gRPC-Web.)

### 115. WebSockets and SignalR
**WebSockets** = persistent, full-duplex connection (server can push). **SignalR** wraps it: auto-negotiates the transport (WebSockets → SSE → long polling), provides hubs, groups, user targeting, reconnect, and scale-out via Redis/Azure SignalR.
```csharp
public class OrderHub : Hub { public Task Join(string orderId) => Groups.AddToGroupAsync(Context.ConnectionId, orderId); }
builder.Services.AddSignalR(); app.MapHub<OrderHub>("/hubs/orders");
await hub.Clients.Group(orderId).SendAsync("StatusChanged", "Shipped");   // push from service
```
Use cases: live order tracking, chat, dashboards, notifications.

### 116. API Gateway pattern (YARP / Ocelot)
Single entry point for clients that routes to internal services.
Responsibilities: routing, TLS termination, **authentication**, **rate limiting**, request aggregation (BFF), caching, load balancing, versioning, logging/tracing, resilience.
```json
"ReverseProxy": { "Routes": { "orders": { "ClusterId": "ordersCluster", "Match": { "Path": "/api/orders/{**rest}" } } },
  "Clusters": { "ordersCluster": { "Destinations": { "d1": { "Address": "http://orders-svc:8080/" } } } } }
```
```csharp
builder.Services.AddReverseProxy().LoadFromConfig(builder.Configuration.GetSection("ReverseProxy"));
app.MapReverseProxy();
```
YARP (Microsoft, flexible, code-friendly) vs Ocelot (config-driven, simpler). Keep business logic out of the gateway; avoid it becoming a bottleneck/SPOF (run multiple instances).

### 117. Circuit Breaker with Polly
States: **Closed** (normal) → **Open** (after failures; calls fail fast) → **Half-Open** (trial calls) → Closed if OK.
```csharp
builder.Services.AddHttpClient<PaymentClient>().AddResilienceHandler("pay", b => {
    b.AddRetry(new() { MaxRetryAttempts = 3, BackoffType = DelayBackoffType.Exponential, UseJitter = true, Delay = TimeSpan.FromMilliseconds(200) });
    b.AddCircuitBreaker(new() { FailureRatio = 0.5, MinimumThroughput = 10, SamplingDuration = TimeSpan.FromSeconds(30), BreakDuration = TimeSpan.FromSeconds(15) });
    b.AddTimeout(TimeSpan.FromSeconds(5));
});
// or: .AddStandardResilienceHandler()
```
Prevents hammering a dead service and exhausting your own threads. Combine with timeouts, retries (order: timeout → retry → breaker), fallbacks.

### 118. Distributed tracing: OpenTelemetry and Jaeger/Zipkin
A **trace** = one request's journey; made of **spans** (each operation) sharing a `traceId`. The W3C `traceparent` HTTP header carries it between services. **OpenTelemetry** instruments code and exports to **Jaeger/Zipkin/Tempo/App Insights**, which draw the timeline so you see which service/DB call was slow or failed.
```csharp
builder.Services.AddOpenTelemetry().ConfigureResource(r => r.AddService("orders-api"))
    .WithTracing(t => t.AddAspNetCoreInstrumentation().AddHttpClientInstrumentation().AddEntityFrameworkCoreInstrumentation()
                       .AddSource("Orders").AddOtlpExporter())
    .WithMetrics(m => m.AddAspNetCoreInstrumentation().AddRuntimeInstrumentation().AddOtlpExporter());
```
Add the `traceId` to logs to jump from a log line to its trace.

### 119. Health checks: readiness vs liveness in Kubernetes
```csharp
builder.Services.AddHealthChecks().AddCheck("self", () => HealthCheckResult.Healthy(), tags: ["live"])
    .AddSqlServer(conn, tags: ["ready"]).AddRedis(redisConn, tags: ["ready"]);
app.MapHealthChecks("/health/live",  new() { Predicate = r => r.Tags.Contains("live") });
app.MapHealthChecks("/health/ready", new() { Predicate = r => r.Tags.Contains("ready") });
```
```yaml
livenessProbe:  { httpGet: { path: /health/live,  port: 8080 }, periodSeconds: 10 }
readinessProbe: { httpGet: { path: /health/ready, port: 8080 }, periodSeconds: 5 }
```
**Liveness** fail → K8s **restarts** the pod. **Readiness** fail → pod is **removed from the Service** (no traffic) but not restarted. Keep liveness cheap, no dependency checks (or a DB outage restarts everything). Also `startupProbe` for slow starts.

### 120. Saga Pattern: Choreography vs Orchestration
Distributed workflow as a series of local transactions with **compensations** on failure.
- **Choreography**: no central brain; each service reacts to events.
  `OrderPlaced → Payment charges → PaymentCompleted → Inventory reserves → StockReserved → Shipping`. On `StockFailed` → Payment refunds.
  + simple, decoupled; − hard to see the whole flow, cyclic dependencies risk.
- **Orchestration**: a coordinator (saga state machine) commands each step and handles failures.
  + clear flow, easier to monitor/change; − orchestrator is another component.
```csharp
public class OrderStateMachine : MassTransitStateMachine<OrderState> {
    public OrderStateMachine() {
        InstanceState(x => x.CurrentState);
        Initially(When(OrderSubmitted).Publish(c => new ChargePayment(c.Saga.CorrelationId)).TransitionTo(AwaitingPayment));
        During(AwaitingPayment, When(PaymentFailed).Publish(c => new CancelOrder(c.Saga.CorrelationId)).TransitionTo(Cancelled));
    }
}
```
Compensations must be idempotent; use outbox for reliable event publishing.

## Advanced Security & Identity

### 121. OAuth 2.0 and OpenID Connect vs plain JWT
- **JWT**: just a token **format**.
- **OAuth 2.0**: framework for **delegated authorization** (how an app gets an access token to call an API on a user's behalf; flows: Authorization Code + PKCE, Client Credentials...).
- **OIDC**: identity layer on OAuth 2.0 → adds **authentication** (ID token, `openid` scope, userinfo endpoint, discovery document).
Plain JWT login (you issue your own tokens) is fine for a single app. OAuth/OIDC gives SSO, social login, central identity provider, standard flows, token lifecycle, and third-party integration.

### 122. Integrating IdentityServer or Keycloak
API only **validates** tokens from the identity provider (authority); it doesn't issue them.
```csharp
builder.Services.AddAuthentication("Bearer").AddJwtBearer(o => {
    o.Authority = "https://keycloak.company.com/realms/store";   // discovery + JWKS keys fetched automatically
    o.Audience = "store-api";
    o.TokenValidationParameters.NameClaimType = "preferred_username";
});
builder.Services.AddAuthorization(o => o.AddPolicy("Admin", p => p.RequireClaim("realm_access.roles", "admin")));
```
Keycloak roles live in nested JSON; map them with `IClaimsTransformation` or `OnTokenValidated`. Duende IdentityServer (commercial for many uses) is embedded in your own ASP.NET app (clients, scopes, resources configured in code/DB); Keycloak is a standalone open-source server. For client apps use Authorization Code + PKCE; for service-to-service use Client Credentials.

### 123. Data Protection API (IDataProtectionProvider)
ASP.NET Core's built-in crypto for protecting short-lived/app data (auth cookies, anti-forgery tokens, reset links). Not for long-term storage of data (keys rotate; use real encryption such as AES with KMS).
```csharp
var protector = provider.CreateProtector("Store.PasswordReset");
string token = protector.Protect($"{userId}|{DateTime.UtcNow.AddHours(1):o}");
string plain = protector.Unprotect(token);
```
In **multi-instance/containers** persist and share the key ring or tokens/cookies fail after restart/other node:
```csharp
builder.Services.AddDataProtection().SetApplicationName("store")
    .PersistKeysToStackExchangeRedis(redis, "DataProtection-Keys").ProtectKeysWithCertificate(cert);
```
(DPAPI is the Windows-specific OS API; ASP.NET Core's Data Protection is cross-platform and different.)

### 124. Storing secrets with Azure Key Vault / AWS Secrets Manager
Never put secrets in code or appsettings in Git. Load them at startup as configuration.
```csharp
// Azure
builder.Configuration.AddAzureKeyVault(new Uri("https://store-kv.vault.azure.net/"), new DefaultAzureCredential());
var dbPassword = builder.Configuration["Db--Password"];     // "--" maps to ":" hierarchy
// AWS
var client = new AmazonSecretsManagerClient();
var res = await client.GetSecretValueAsync(new GetSecretValueRequest { SecretId = "store/db" });
```
Best practices: **Managed Identity / IAM role** (no credentials to store), least privilege, rotation, audit logs, cache values, use `user-secrets` locally.

### 125. Mutual TLS (mTLS)
Both sides present certificates: client verifies server **and** server verifies client → strong service-to-service identity.
```csharp
builder.WebHost.ConfigureKestrel(k => k.ConfigureHttpsDefaults(h => {
    h.ClientCertificateMode = ClientCertificateMode.RequireCertificate;
    h.ClientCertificateValidation = (cert, chain, errors) => cert.Issuer == "CN=Internal-CA" && errors == SslPolicyErrors.None;
}));
builder.Services.AddAuthentication(CertificateAuthenticationDefaults.AuthenticationScheme).AddCertificate();
// client
var handler = new HttpClientHandler(); handler.ClientCertificates.Add(clientCert);
```
Behind proxies, forward the cert (`UseCertificateForwarding`). In Kubernetes a service mesh (Istio/Linkerd) can provide mTLS automatically.

### 126. Claims Transformation (IClaimsTransformation)
Adds/changes claims **after authentication** on every request (e.g., load permissions from the DB, map external roles).
```csharp
public class PermissionClaims(IPermissionService perms) : IClaimsTransformation {
    public async Task<ClaimsPrincipal> TransformAsync(ClaimsPrincipal principal) {
        if (principal.HasClaim(c => c.Type == "permission")) return principal;     // runs many times → be idempotent
        var id = new ClaimsIdentity();
        foreach (var p in await perms.GetAsync(principal.FindFirstValue(ClaimTypes.NameIdentifier)!)) id.AddClaim(new Claim("permission", p));
        principal.AddIdentity(id); return principal;
    }
}
builder.Services.AddScoped<IClaimsTransformation, PermissionClaims>();
```
Cache results; it may run multiple times per request.

### 127. Multi-tenancy in EF Core
| Strategy | Isolation | Cost/ops | Notes |
|---|---|---|---|
| **Shared DB, `TenantId` column** | low (logical) | cheapest | global query filter; risk of leaks if a filter is missed |
| **Schema per tenant** | medium | medium | `HasDefaultSchema(tenant)`; migrations per schema |
| **Database per tenant** | highest | most expensive | per-tenant connection string; easy backup/restore, noisy-neighbor safe |
```csharp
public class StoreDb(DbContextOptions<StoreDb> o, ITenantContext tenant) : DbContext(o) {
    protected override void OnModelCreating(ModelBuilder b) { b.Entity<Order>().HasQueryFilter(x => x.TenantId == tenant.Id); }
    public override Task<int> SaveChangesAsync(CancellationToken ct = default) {
        foreach (var e in ChangeTracker.Entries<ITenantEntity>().Where(e => e.State == EntityState.Added)) e.Entity.TenantId = tenant.Id;
        return base.SaveChangesAsync(ct);
    }
}
// DB-per-tenant: optionsBuilder.UseSqlServer(tenantStore.GetConnectionString(tenant.Id));
```
Resolve the tenant from subdomain/header/JWT claim in middleware; never trust a client-sent tenant id without validating it against the user's claims.

### 128. CSRF/XSRF and anti-forgery tokens
Attack: while logged in (cookie auth), you visit `evil.com`, which makes your browser send `POST bank.com/transfer`; the cookie goes along automatically.
Defense: **anti-forgery token**, a random value in a cookie **and** in a header/form field; attacker's site can't read it (same-origin policy), so a forged request lacks the matching header. Also `SameSite=Lax/Strict` cookies.
```csharp
builder.Services.AddAntiforgery(o => o.HeaderName = "X-XSRF-TOKEN");
app.UseAntiforgery();                       // .NET 8+
[ValidateAntiForgeryToken] / [AutoValidateAntiforgeryToken]
```
APIs using **Bearer tokens in the Authorization header** (not cookies) are not CSRF-vulnerable, since browsers don't attach that header automatically.

### 129. Securing Webhooks (HMAC)
Sender signs the **raw body** with a shared secret; receiver recomputes and compares.
```csharp
[HttpPost("webhooks/gateway")]
public async Task<IActionResult> Receive() {
    using var reader = new StreamReader(Request.Body); var body = await reader.ReadToEndAsync();
    var sig = Request.Headers["X-Signature"].ToString(); var ts = Request.Headers["X-Timestamp"].ToString();
    if (Math.Abs(DateTimeOffset.UtcNow.ToUnixTimeSeconds() - long.Parse(ts)) > 300) return Unauthorized();   // replay protection
    using var h = new HMACSHA256(Encoding.UTF8.GetBytes(secret));
    var expected = Convert.ToHexString(h.ComputeHash(Encoding.UTF8.GetBytes($"{ts}.{body}"))).ToLower();
    if (!CryptographicOperations.FixedTimeEquals(Encoding.UTF8.GetBytes(expected), Encoding.UTF8.GetBytes(sig))) return Unauthorized();
    // process idempotently (event id), respond 200 quickly, do heavy work in background
    return Ok();
}
```
Also: HTTPS only, constant-time compare, timestamp check, dedupe by event id, IP allow-list, rotate secrets.

### 130. Rate-limiting algorithms
| Algorithm | How | Pros/Cons |
|---|---|---|
| **Fixed Window** | N requests per window (e.g., 100/min), resets at boundary | simple; burst at boundaries (200 in 2 seconds) |
| **Sliding Window** | window slides in segments | smoother, more accurate; slightly more memory |
| **Token Bucket** | bucket refills tokens at a rate; each request uses one | allows controlled **bursts** + steady rate |
| **Concurrency** | max N requests **in flight** at once | protects slow resources; not a rate |
```csharp
o.AddSlidingWindowLimiter("s", x => { x.PermitLimit = 100; x.Window = TimeSpan.FromMinutes(1); x.SegmentsPerWindow = 6; });
o.AddConcurrencyLimiter("c", x => { x.PermitLimit = 10; x.QueueLimit = 5; });
```

## High-Performance .NET Internals & Tuning

### 131. Native AOT (.NET 8+)
Compiles to a **native executable** at publish time (no JIT, no runtime install).
```xml
<PublishAot>true</PublishAot>
```
**Pros:** very fast startup (ms), lower memory, smaller attack surface, great for containers/serverless/CLI. **Limits:** no runtime code generation, limited reflection (needs source generators: System.Text.Json `JsonSerializerContext`, `CreateSlimBuilder`), no `Assembly.LoadFrom`, many libraries (AutoMapper, some EF Core features, MVC controllers) not fully AOT-ready → **Minimal APIs** recommended; longer publish time; peak throughput can be similar or slightly lower than JIT with PGO.

### 132. ArrayPool<T> and MemoryPool<T>
Rent and return buffers instead of allocating new arrays → fewer allocations, less GC (especially LOH for big buffers).
```csharp
var pool = ArrayPool<byte>.Shared;
byte[] buf = pool.Rent(81920);              // may be larger than requested
try { int read = await stream.ReadAsync(buf.AsMemory(0, 81920), ct); /* use buf[..read] */ }
finally { pool.Return(buf, clearArray: true); }   // clear if it held sensitive data
```
Always return the buffer, never use it after returning, track real length separately. `MemoryPool<T>` returns `IMemoryOwner<T>` (dispose to return).

### 133. System.IO.Pipelines
High-performance I/O API (used by Kestrel). A **PipeWriter** produces data, a **PipeReader** consumes it, with pooled buffers, backpressure, and zero-copy parsing via `ReadOnlySequence<byte>`.
Better than `Stream` because: you don't manage buffers/copies, handles **partial messages** neatly (`AdvanceTo(consumed, examined)`), built-in flow control, fewer allocations.
```csharp
var reader = PipeReader.Create(stream);
while (true) {
    ReadResult r = await reader.ReadAsync(ct); ReadOnlySequence<byte> buf = r.Buffer;
    while (TryReadLine(ref buf, out var line)) Process(line);
    reader.AdvanceTo(buf.Start, buf.End);
    if (r.IsCompleted) break;
}
```
Use for custom protocols, large streaming parsers; not needed for everyday controllers.

### 134. Server GC vs Workstation GC
- **Workstation**: single heap, optimized for latency/UI responsiveness, lower memory.
- **Server**: one heap + dedicated GC thread **per core**, higher throughput, more memory; **default for ASP.NET Core**.
```xml
<ServerGarbageCollector>true</ServerGarbageCollector>
<ConcurrentGarbageCollection>true</ConcurrentGarbageCollection>   <!-- background GC -->
```
Env vars: `DOTNET_gcServer=1`, `DOTNET_GCHeapCount`, `DOTNET_GCHeapHardLimit`. In small containers (1 CPU, low memory) server GC may use more memory; consider `GCHeapAffinitizeMask`/Workstation or `DOTNET_GCConserveMemory`. .NET also has **DATAS** (dynamic adaptation) to size heaps for containers.

### 135. Unsafe code and `fixed`
`unsafe` lets you use pointers and bypass bounds checks; `fixed` **pins** a managed object so the GC can't move it while you hold its address.
```csharp
unsafe { fixed (byte* p = buffer) { /* native interop, p[i] */ } }
```
Justified: native interop/P-Invoke, very hot parsing/crypto/serialization paths proven by benchmarks, custom allocators. Prefer safe alternatives first: `Span<T>`, `stackalloc`, `MemoryMarshal`, `Unsafe` class. Needs `<AllowUnsafeBlocks>true</AllowUnsafeBlocks>`; risks: memory corruption, security bugs, harder code review.

```csharp
[MemoryDiagnoser]
public class JsonBench { [Benchmark] public string Stj() => JsonSerializer.Serialize(_obj); [Benchmark] public string Newtonsoft() => JsonConvert.SerializeObject(_obj); }
BenchmarkRunner.Run<JsonBench>();      // run in Release mode
```
Workflow: measure (counters) → find hot spot (trace/dump) → fix → verify with benchmark/load test.

### 137. Lock contention and mitigation
Contention happens when many threads wait for the same `lock`, so throughput drops and latency rises (and `lock` can't be used across `await`).
```csharp
// ❌ one global lock around everything
lock (_gate) { _cache[key] = value; }
// ✅ concurrent collections
var cache = new ConcurrentDictionary<string, Lazy<Task<Product>>>();
var p = await cache.GetOrAdd(key, k => new Lazy<Task<Product>>(() => LoadAsync(k))).Value;
// ✅ async-friendly throttling / mutual exclusion
private readonly SemaphoreSlim _sem = new(1, 1);
await _sem.WaitAsync(ct); try { /* critical section with await */ } finally { _sem.Release(); }
```
Also: shrink critical sections, partition state (per-key locks, sharding), use `Interlocked`, immutable data, `ReaderWriterLockSlim` for read-heavy, and `System.Threading.Channels` for producer/consumer.

### 138. ConfigureAwait(false)
`await x.ConfigureAwait(false)` says "resume on any thread; don't capture the SynchronizationContext".
- **Class libraries**: recommended because consumers (WinForms/WPF/legacy ASP.NET) have a sync context; capturing it costs performance and can deadlock if callers block with `.Result`.
- **ASP.NET Core**: has **no SynchronizationContext**, so `ConfigureAwait(false)` makes no difference in controllers → not needed (but harmless).
Caveat: after `ConfigureAwait(false)` don't depend on the original context (e.g., UI thread, `HttpContext.Current` in old ASP.NET).

### 139. String interning
The CLR keeps a pool of unique string literals; identical literals share one instance. `string.Intern(s)` adds/looks up runtime strings in that pool.
```csharp
string a = "hello"; string b = "hel" + "lo";      // same literal → same reference
string c = new string(new[] {'h','e','l','l','o'});
Console.WriteLine(ReferenceEquals(a, c));             // False
Console.WriteLine(ReferenceEquals(a, string.Intern(c)));   // True
```
Memory implications: interned strings **live for the whole process lifetime** (never GC'd), so interning user-generated/unbounded strings leaks memory. Saves memory only for a small set of frequently repeated values. Safer alternative: your own bounded cache/dictionary.

### 140. Expression Trees and EF Core
An expression tree is code represented as **data** (`Expression<Func<T,bool>>`) so it can be inspected and translated.
```csharp
Expression<Func<Product, bool>> expr = p => p.Price > 100 && p.Name.StartsWith("A");
// Tree: AndAlso( GreaterThan(p.Price, 100), Call(p.Name.StartsWith, "A") )
```
EF Core pipeline: LINQ on `IQueryable` builds an expression tree → **query translation** visitors convert it to an internal relational expression → provider's **SQL generator** emits SQL (`WHERE [Price] > 100 AND [Name] LIKE N'A%'`) with parameters → results materialized. Methods EF can't translate (custom C# methods) throw or run on the client; keep logic translatable or use `EF.Functions`.

## Automated Testing, CI/CD & DevOps

### 141. Unit vs Integration vs E2E tests
| | Scope | Speed | Dependencies | Example |
|---|---|---|---|---|
| **Unit** | one class/method | ms | mocked | `DiscountCalculator` returns 10% |
| **Integration** | several components + real infra | seconds | real DB/HTTP pipeline | `POST /orders` saves a row |
| **E2E** | whole system as a user | slowest | everything deployed | browser/UI or full API flow in staging |
Follow the **test pyramid**: many unit, fewer integration, few E2E. Tools: xUnit/NUnit, WebApplicationFactory, Testcontainers, Playwright/Selenium.

```csharp
public class ProductTests(ApiFactory f) : IClassFixture<ApiFactory> {
```

### 143. Mocking interfaces vs abstract class members (Moq / NSubstitute)
```csharp
// Moq
var repo = new Mock<IProductRepo>(); repo.Setup(r => r.GetAsync(1)).ReturnsAsync(new Product { Id = 1 });
// NSubstitute
var repo2 = Substitute.For<IProductRepo>(); repo2.GetAsync(1).Returns(new Product { Id = 1 });
```
- **Interfaces**: every member can be mocked.
- **Abstract/concrete classes**: only **abstract or `virtual`** members can be intercepted (proxies subclass the type); non-virtual/`static`/`sealed` can't. With Moq: `new Mock<Base> { CallBase = true }` calls real implementations for non-setup members.
Design for testability: depend on interfaces; don't mock types you don't own (wrap `HttpClient`/`DbContext` boundaries).

### 144. Testcontainers for .NET
Starts **real** Docker containers (SQL Server, Postgres, Redis, RabbitMQ) per test run, giving tests true database behavior (no InMemory differences).
```csharp
public class DbFixture : IAsyncLifetime {
    private readonly MsSqlContainer _db = new MsSqlBuilder().Build();
    public string ConnectionString => _db.GetConnectionString();
    public Task InitializeAsync() => _db.StartAsync();
    public Task DisposeAsync() => _db.DisposeAsync().AsTask();
}
```
Use it with `WebApplicationFactory` (replace the connection string), apply migrations at start, reset data between tests (Respawn). Needs Docker on dev/CI machines.

### 145. EF Core InMemory vs SQLite in-memory
| | InMemory provider | SQLite in-memory |
|---|---|---|
| Relational behavior | ❌ no FK, constraints, transactions, real SQL | ✅ real relational engine |
| Speed | fastest | fast |
| Fidelity | low (not recommended by Microsoft) | medium (SQL dialect differs from SQL Server) |
```csharp
var conn = new SqliteConnection("DataSource=:memory:"); conn.Open();   // keep open or DB vanishes
var opts = new DbContextOptionsBuilder<StoreDb>().UseSqlite(conn).Options;
using var db = new StoreDb(opts); db.Database.EnsureCreated();
```
Best: **Testcontainers with the real DB** for integration tests; SQLite for quick tests; InMemory only for trivial logic. Don't unit test queries against the mocked `DbSet`.

### 146. Dockerizing a .NET API (multi-stage)
```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY *.csproj . 
RUN dotnet restore                       # cached layer
COPY . .
RUN dotnet publish -c Release -o /app --no-restore

FROM mcr.microsoft.com/dotnet/aspnet:8.0-jammy-chiseled AS final   # tiny, no shell, non-root
WORKDIR /app
COPY --from=build /app .
EXPOSE 8080
ENTRYPOINT ["dotnet", "StoreApi.dll"]
```
Multi-stage: build with the big SDK image, ship only the small runtime image. **Alpine** (small, musl libc), **Chiseled/Ubuntu** (distroless-like, minimal attack surface). Add `.dockerignore`, restore before copying source for layer caching, listen on 8080 (non-root can't bind <1024; .NET 8 default port is 8080).

### 147. Non-root practices for containers in Kubernetes
Why: if the app is compromised, root in the container makes escape/damage easier.
```dockerfile
USER $APP_UID          # .NET 8 images provide the 'app' user (UID 1654); chiseled images default to non-root
```
```yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 1654
  allowPrivilegeEscalation: false
  readOnlyRootFilesystem: true
  capabilities: { drop: ["ALL"] }
```
Also: ports above 1024, write only to mounted volumes/`/tmp`, no secrets in image layers, scan images (Trivy), pin image versions/digests, set resource limits, network policies.

### 148. CI/CD for .NET APIs (GitHub Actions / Azure DevOps)
```yaml
name: ci-cd
on: { push: { branches: [main] }, pull_request: {} }
jobs:
  build-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
```

### 150. Structured and centralized logging
**Structured logging** keeps named properties (JSON) instead of plain text, so logs are **searchable and filterable**.
```csharp
builder.Host.UseSerilog((ctx, cfg) => cfg.ReadFrom.Configuration(ctx.Configuration)
    .Enrich.FromLogContext().Enrich.WithProperty("Service", "orders-api")
    .WriteTo.Console(new CompactJsonFormatter()).WriteTo.Seq("http://seq:5341"));
app.UseSerilogRequestLogging();
log.LogInformation("Order {OrderId} paid by {CustomerId} amount {Amount}", id, cid, amt);   // not $"..." interpolation
```
**Centralized logging** ships all instances' logs to one place (ELK/Elastic, Seq, Loki, Application Insights), so you can:
- Query `OrderId = 5 and Level = Error` across 20 pods instantly.
- Correlate by `TraceId`/`CorrelationId` across microservices.
- Build dashboards and alerts (error rate spikes).
- Keep logs after a container dies.
Rules: don't log secrets/PII, use correct levels, include context (user, tenant, trace id), set retention, sample noisy logs.
