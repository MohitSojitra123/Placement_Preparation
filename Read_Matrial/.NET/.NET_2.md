## 🟢 LEVEL 1 — BASIC

### 1. C# Fundamentals

#### 1. What is C# and where is it used?
* **Explanation:** C# (C-Sharp) is a modern, object-oriented, strongly typed programming language developed by Microsoft. It runs on the .NET runtime and provides garbage collection, type safety, and cross-platform compatibility.
* **Where it is used:** Backend REST APIs, microservices, cloud applications (Azure/AWS), enterprise software, game development (Unity), desktop software (WPF, MAUI), and web UI (Blazor).
* **Code Example:**
```csharp
namespace FundamentalDemo
{
    public class Program
    {
        public static void Main()
        {
            Console.WriteLine("Hello, .NET Backend World!");
        }
    }
}
```

---

#### 2. What is .NET?
* **Explanation:** .NET is an open-source, cross-platform developer platform created by Microsoft for building many different types of applications. It provides a runtime (CLR), base libraries, and tools to run C#, F#, or VB.NET apps.
* **Real-World Usecase:** Building high-throughput Web APIs hosted on Linux containers in AWS/Azure.

---

#### 3. What is the difference between .NET Framework, .NET Core, and modern .NET?
* **Explanation:**
  * **.NET Framework (1.0 - 4.8.1):** Legacy, Windows-only, monolithic framework.
  * **.NET Core (1.0 - 3.1):** Cross-platform, high-performance, modular rewrite.
  * **Modern .NET (.NET 5, 6, 7, 8, 9+):** Unified single platform replacing both Core and Framework. Cross-platform, open-source, and extremely fast.

---

#### 4. What is CLR?
* **Explanation:** Common Language Runtime (CLR) is the virtual execution engine of .NET. It converts Intermediate Language (IL) bytecode into native machine instructions via JIT compilation and handles memory management, thread execution, garbage collection, and security checks.

---

#### 5. What is CTS?
* **Explanation:** Common Type System (CTS) defines how types are declared, used, and managed in .NET. It enables language interoperability—ensuring an `int` in C# corresponds directly to `System.Int32` and can be used seamlessly in VB.NET or F#.

---

#### 6. What is CLS?
* **Explanation:** Common Language Specification (CLS) is a set of rules and guidelines that languages targeting .NET must follow to ensure full interoperability with other .NET languages.

---

#### 7. What is managed code and unmanaged code?
* **Managed Code:** Code executed directly by the CLR. CLR handles automatic memory allocation, garbage collection, and boundary safety checks (e.g., standard C# code).
* **Unmanaged Code:** Code executed outside the CLR directly by the operating system. The developer manually manages memory allocation/deallocation (e.g., C/C++ DLLs, Win32 API calls).
* **Code Example:**
```csharp
using System.Runtime.InteropServices;

public class NativeMethods
{
    // Calling unmanaged C++ DLL inside C# managed code
    [DllImport("user32.dll", CharSet = CharSet.Auto)]
    public static extern int MessageBox(IntPtr hWnd, String text, String caption, uint type);
}
```

---

#### 8. What is the difference between value types and reference types?
* **Value Types:** Store actual data directly in memory (typically allocated on the stack or inline inside an object). Examples: `int`, `bool`, `double`, `struct`, `enum`. Passed by value (copied).
* **Reference Types:** Store a reference (memory address pointing to the object on the heap). Examples: `class`, `string`, `object`, `interface`, `array`.
* **Code Example:**
```csharp
int x = 10;
int y = x; // Value copy: y is 10, changing y won't affect x

OrderRef ref1 = new OrderRef { OrderId = 100 };
OrderRef ref2 = ref1; // Reference copy: both point to the same object
ref2.OrderId = 200; // ref1.OrderId is now also 200!
```

---

#### 9. What are boxing and unboxing?
* **Boxing:** Converting a value type to a reference type (`object` or interface). Allocates memory on the heap.
* **Unboxing:** Explicitly extracting the value type from the boxed object back onto the stack.
* **Code Example:**
```csharp
int val = 42;
object boxed = val;   // Boxing (stack -> heap)
int unboxed = (int)boxed; // Unboxing (heap -> stack)
```

---

#### 10. What is a class?
* **Explanation:** A blueprint or template that defines properties, methods, events, and fields for an object. It is a reference type allocated on the heap.
* **Code Example:**
```csharp
public class User
{
    public int Id { get; set; }
    public string Name { get; set; } = string.Empty;
}
```

---

#### 11. What is an object?
* **Explanation:** An instance of a class created in memory at runtime using the `new` keyword (or instantiated via dependency injection/reflection).
* **Code Example:**
```csharp
User user = new User { Id = 1, Name = "Alice" };
```

---

#### 12. What is a constructor?
* **Explanation:** A special member method of a class executed automatically when an instance of the class is created. Used to initialize state or inject dependencies.
* **Code Example:**
```csharp
public class OrderService
{
    private readonly ILogger _logger;
    // Constructor Injection
    public OrderService(ILogger logger)
    {
        _logger = logger;
    }
}
```

---

#### 13. What is a static class?
* **Explanation:** A class that cannot be instantiated (`new` cannot be used) and cannot be inherited (`sealed`). All members inside a static class must also be `static`. Loaded automatically when referenced for the first time.
* **Code Example:**
```csharp
public static class PasswordHasher
{
    public static string Hash(string rawPassword)
    {
        return Convert.ToBase64String(System.Text.Encoding.UTF8.GetBytes(rawPassword));
    }
}
```

---

#### 14. What is the difference between const, readonly, and static readonly?
* **`const`:** Compile-time constant. Value must be assigned at declaration and cannot change. Implicitly static.
* **`readonly`:** Run-time constant. Value can be set at declaration or inside the instance constructor.
* **`static readonly`:** Run-time constant evaluated once for the whole class, set at declaration or in a static constructor.
* **Code Example:**
```csharp
public class AppConfig
{
    public const string AppName = "InventoryAPI"; // Compile time constant
    public readonly string InstanceId;             // Instance-level runtime constant
    public static readonly DateTime StartTime;    // Class-level runtime constant

    static AppConfig()
    {
        StartTime = DateTime.UtcNow;
    }

    public AppConfig(string instanceId)
    {
        InstanceId = instanceId;
    }
}
```

---

#### 15. What are access modifiers in C#?
* **Explanation:** Keywords used to specify the accessibility/visibility of classes, methods, fields, and properties to control encapsulation.

---

#### 16. What is the difference between public, private, protected, and internal?
* **`public`:** Accessible from anywhere.
* **`private`:** Accessible only within the declaring class.
* **`protected`:** Accessible within the class and derived classes.
* **`internal`:** Accessible anywhere within the same assembly (.dll/.exe).
* **`protected internal`:** Accessible within the current assembly or derived classes in other assemblies.
* **`private protected`:** Accessible within the declaring class or derived classes *within the same assembly*.

---

#### 17. What is inheritance?
* **Explanation:** An OOP pillar where a derived class (child) inherits fields, properties, and methods from a base class (parent), enabling code reuse and hierarchical modeling.
* **Code Example:**
```csharp
public class Account
{
    public string AccountNumber { get; set; } = string.Empty;
}

public class SavingsAccount : Account
{
    public decimal InterestRate { get; set; }
}
```

---

#### 18. What is polymorphism?
* **Explanation:** The ability of different classes to respond to the same method call in their own specific way.
  * **Compile-time (Static):** Method Overloading.
  * **Runtime (Dynamic):** Method Overriding via `virtual`/`override`.
* **Code Example:**
```csharp
public class PaymentProcessor
{
    public virtual void Process(decimal amount) => Console.WriteLine($"Processing generic ${amount}");
}

public class CreditCardProcessor : PaymentProcessor
{
    public override void Process(decimal amount) => Console.WriteLine($"Processing Credit Card ${amount}");
}
```

---

#### 19. What is encapsulation?
* **Explanation:** Restricting direct access to an object's internal state/data fields, exposing controlled operations through public methods or properties.
* **Code Example:**
```csharp
public class BankAccount
{
    private decimal _balance; // Private state

    public decimal Balance => _balance;

    public void Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentException("Amount must be positive");
        _balance += amount;
    }
}
```

---

#### 20. What is abstraction?
* **Explanation:** Hiding complex implementation details and exposing only essential features to the consumer. Achieved using interfaces or abstract classes.

---

#### 21. What is an interface?
* **Explanation:** A contract defining a set of properties, methods, and events without concrete implementations (prior to C# 8 default interface implementations). Interfaces support multiple inheritance.
* **Code Example:**
```csharp
public interface INotificationService
{
    Task SendEmailAsync(string recipient, string message);
}
```

---

#### 22. What is an abstract class?
* **Explanation:** A class marked with `abstract` that cannot be instantiated directly. It can contain both abstract methods (without implementation) and non-abstract methods (with implementation).
* **Code Example:**
```csharp
public abstract class BaseRepository<T>
{
    public void LogExecution() => Console.WriteLine("Executing Database Operation...");
    public abstract Task<T?> GetByIdAsync(int id);
}
```

---

#### 23. Interface vs Abstract Class?
| Feature | Interface | Abstract Class |
|---|---|---|
| Multiple Inheritance | Supported | Single inheritance only |
| Fields | Cannot contain state fields | Can contain instance fields |
| Constructors | Cannot have constructors | Can have constructors |
| Default Implementation| C# 8+ allows default implementations | Fully supported |

---

#### 24. Method Overloading vs Method Overriding?
* **Overloading:** Multiple methods in the same class with the same name but different signature parameters (compile-time polymorphism).
* **Overriding:** Redefining a base class `virtual`/`abstract` method inside a derived class using the `override` keyword (runtime polymorphism).

---

#### 25. What is the virtual keyword?
* **Explanation:** Used in a base class to allow a method, property, or indexer to be overridden in derived classes.

---

#### 26. What is the override keyword?
* **Explanation:** Used in a derived class to explicitly extend or modify the virtual/abstract implementation of an inherited method.

---

#### 27. What is the sealed keyword?
* **Explanation:** Prevents a class from being inherited, or prevents a derived method/property from being further overridden in subsequent derived classes.
* **Code Example:**
```csharp
public sealed class SecurityTokenProvider
{
    // Cannot be inherited
}
```

#### 29. What are properties in C#?
* **Explanation:** Members that provide a flexible mechanism to read, write, or compute the value of a private field using `get` and `set` accessors.

---

#### 30. What is an auto-implemented property?


#### 31. What is a nullable type?
* **Explanation:** Enables value types (like `int`, `bool`, `DateTime`) to represent `null`. Declared using `T?` or `Nullable<T>`.
* **Code Example:**
```csharp
int? optionalAge = null;
if (optionalAge.HasValue)
{

```

---

#### 32. What is the difference between var, dynamic, and object?
* **`var`:** Statically typed at compile time. Compiler infers the type based on assignment.
* **`object`:** Ultimate base class for all types in .NET. Requires explicit casting (type checks at runtime).
* **`dynamic`:** Bypasses compile-time type checking. Types are resolved dynamically at runtime.
* **Code Example:**
```csharp
var text = "Hello";      // Type string inferred at compile-time
object obj = "Hello";    // Requires string s = (string)obj;
dynamic dyn = "Hello";  // Late-bound, dyn.ToUpper() evaluated at runtime
```

---

#### 33. What are enums?
* **Explanation:** A distinct value type that defines a set of named integral constants, improving code readability and domain safety.
* **Code Example:**
```csharp
public enum OrderStatus
{
    Pending = 1,
    Processing = 2,
    Shipped = 3,
    Delivered = 4
}
```

---

#### 34. What are structs?
* **Explanation:** Lightweight value types allocated on the stack (or inline inside containing reference types). Best suited for small, immutable data structures.
* **Code Example:**
```csharp
public readonly struct GeoPoint
{
    public double Latitude { get; }
    public double Longitude { get; }

    public GeoPoint(double lat, double lon)
    {
        Latitude = lat;
        Longitude = lon;
    }
}
```

---

#### 35. Class vs Struct?
| Feature | Class | Struct |
|---|---|---|
| Memory | Heap allocated | Stack/Inline allocated |
| Type | Reference type | Value type |
| Inheritance | Supported | Inheritance not supported (except interfaces) |
| Size | Large, complex objects | Small (< 16 bytes recommended) |

---

#### 36. What is a record in C#?
* **Explanation:** Introduced in C# 9, `record` is a reference type (or value type via `record struct`) with built-in value-based equality, non-destructive mutation (`with` expressions), and clean positional syntax.
* **Code Example:**
```csharp
public record CustomerResponseDto(int Id, string Name, string Email);

// Usage
var c1 = new CustomerResponseDto(1, "Alice", "alice@test.com");
var c2 = new CustomerResponseDto(1, "Alice", "alice@test.com");
Console.WriteLine(c1 == c2); // True! Value-based equality comparison
```

---

#### 37. What is pattern matching?
* **Explanation:** Expression mechanism in C# allowing concise checking, extracting, and testing of shapes and types of objects.
* **Code Example:**
```csharp
public decimal GetDiscount(object customer) => customer switch
{
    CustomerResponseDto { Id: < 100 } => 0.20m,
    CustomerResponseDto => 0.05m,
    null => throw new ArgumentNullException(nameof(customer)),
    _ => 0.00m
};
```

---

#### 38. What are nullable reference types?
* **Explanation:** Compiler feature enabled via `<Nullable>enable</Nullable>` in `.csproj` to prevent `NullReferenceException`. Warns developers if a reference type could be null unless marked with `?`.
* **Code Example:**
```csharp
string name = "John"; // Non-nullable, compiler warns if null is assigned
string? middleName = null; // Expressly allowed to be null
```

---

#### 39. What is string immutability?
* **Explanation:** Once created on the heap, a `System.String` object cannot be altered. Modifying a string creates a completely new string object on the heap, abandoning the original object to garbage collection.

---

#### 40. String vs StringBuilder?
* **`string`:** Immutable. Every concatenation (`s += "a"`) creates a new memory object. High memory allocation for repeated string modifications.
* **`StringBuilder`:** Mutable character buffer. Allows appending, replacing, and dynamic string construction without creating intermediate heap objects.
* **Code Example:**
```csharp
var sb = new System.Text.StringBuilder();
for (int i = 0; i < 100; i++)
{
    sb.Append("Line ").AppendLine(i.ToString());
}
string finalLog = sb.ToString();
```

### 2. Collections & LINQ

#### 41. What is an array?
* **Explanation:** A contiguous memory block storing a fixed-size, strongly typed sequence of elements indexed by an integer starting at zero.
* **Code Example:**
```csharp
int[] scores = new int[3] { 90, 85, 95 };
```

---

#### 42. Array vs List<T>?
* **`Array`:** Fixed size defined at creation, non-resizable, highly optimized memory contiguous allocation.
* **`List<T>`:** Dynamic size built over an internal array that doubles capacity when full. Offers helpful collection operations (`Add`, `Remove`, `Find`).

---

#### 43. What is Dictionary<TKey, TValue>?
* **Explanation:** A hash-table-based collection mapping unique keys to values, providing $O(1)$ average time complexity for lookup, insertion, and deletion operations.
* **Code Example:**
```csharp
var cache = new Dictionary<int, string>();
cache.Add(101, "Product A");
if (cache.TryGetValue(101, out var productName))
{
    Console.WriteLine(productName);
}
```

---

#### 44. IEnumerable vs ICollection vs IList?
* **`IEnumerable<T>`:** Forward-only read iteration (`foreach`). Supports LINQ deferred execution.
* **`ICollection<T>`:** Extends `IEnumerable<T>`. Adds size tracking (`Count`) and modification operations (`Add`, `Remove`, `Contains`).
* **`IList<T>`:** Extends `ICollection<T>`. Adds positional index-based access (`list[0]`) and positional insertion/deletion.

---

#### 45. IEnumerable<T> vs IQueryable<T>?
* **`IEnumerable<T>`:** Memory-based querying (LINQ to Objects). Filtering happens in .NET memory after reading data.
* **`IQueryable<T>`:** Remote store querying (LINQ to Entities). Builds Expression Trees translated directly to SQL queries executed on the database engine.
* **Code Example:**
```csharp
// Runs fully in-memory
IEnumerable<User> inMemoryUsers = dbContext.Users.ToList().Where(u => u.IsActive);

// Translates directly to SELECT ... FROM Users WHERE IsActive = 1
IQueryable<User> dbQuery = dbContext.Users.Where(u => u.IsActive);
```

---

#### 46. What is LINQ?
* **Explanation:** Language Integrated Query (LINQ) brings native query capability directly into C# syntax to operate seamlessly over databases, arrays, XML, JSON, and objects.

---

#### 47. Why is LINQ useful?
* Eliminates boilerplate `for`/`foreach` filtering logic.
* Provides compile-time type checking for database and object queries.
* Standardizes data access across disparate data providers.

---

#### 48. What is deferred execution?
* **Explanation:** LINQ query evaluation is delayed until the variable is actually enumerated over (e.g., inside a `foreach` loop, or calling `.ToList()`, `.ToArray()`, `.First()`).
* **Code Example:**
```csharp
var query = dbContext.Products.Where(p => p.Price > 50); // Query NOT executed yet
// Query executes on database HERE:
foreach (var item in query) { }
```

---

#### 49. What is immediate execution?
* **Explanation:** Force-executing a LINQ query and returning concrete in-memory results immediately using materialization operators like `.ToList()`, `.ToArray()`, `.Count()`, or `.FirstOrDefault()`.

---

#### 50. Difference between Where() and Select()?
* **`Where()`:** Filters elements based on a boolean predicate condition (reduces record count).
* **`Select()`:** Projects or transforms elements from one shape into another shape (transforms structure).
* **Code Example:**
```csharp
var activeUserNames = users
    .Where(u => u.IsActive)       // Filter
    .Select(u => u.UserName);    // Project
```

---

#### 51. Difference between First() and FirstOrDefault()?
* **`First()`:** Returns the first element. Throws `InvalidOperationException` if the source collection is empty or no element satisfies the predicate.
* **`FirstOrDefault()`:** Returns the first element or a default value (`null` for reference types, `0` for numeric types) if no element is found.

---

#### 52. Difference between Single() and SingleOrDefault()?
* **`Single()`:** Expects **exactly one** element. Throws an exception if 0 elements or > 1 elements exist.
* **`SingleOrDefault()`:** Expects **0 or 1** element. Throws an exception if > 1 elements exist; returns default if 0 elements exist.

---

#### 53. Any() vs Count()?
* **`Any()`:** Checks if at least one element satisfies the condition ($O(1)$ short-circuit evaluation).
* **`Count() > 0`:** Evaluates or iterates over the full set/query ($O(N)$ overhead if unoptimized). Always use `Any()` for existential checks.

---

#### 54. OrderBy() vs OrderByDescending()?
* **`OrderBy()`:** Sorts collection elements in ascending order.
* **`OrderByDescending()`:** Sorts collection elements in descending order.

---

#### 55. What is GroupBy()?
* **Explanation:** Groups collection elements based on a specified key expression, returning a sequence of `IGrouping<TKey, TElement>`.
* **Code Example:**
```csharp
var ordersByCustomer = orders.GroupBy(o => o.CustomerId);
```

---

#### 56. What is Join() in LINQ?
* **Explanation:** Correlates two sequences based on matching key values (inner join concept).
* **Code Example:**
```csharp
var innerJoin = orders.Join(
    customers,
    order => order.CustomerId,
    customer => customer.Id,
    (order, customer) => new { order.OrderId, customer.Name }
);
```

---

#### 57. What is SelectMany()?
* **Explanation:** Projects each element of a sequence to an `IEnumerable<T>` and flattens the resulting sequences into a single sequence (1-to-many flattening).
* **Code Example:**
```csharp
List<Order> orders = GetOrders();
// Flatten all line items from all orders into a single list
var allItems = orders.SelectMany(o => o.LineItems);
```

---

#### 58. What is ToList() doing internally?
* **Explanation:** Evaluates the query expression immediately, instantiates a new `List<T>`, iterates through the enumerable sequence, and appends every element into the underlying list buffer in memory.

---

#### 59. What happens when you enumerate an IEnumerable multiple times?
* **Explanation:** Triggers the underlying execution multiple times (known as multiple enumeration). For database `IQueryable` queries, this results in sending duplicate SQL queries to the database server.
* **Fix:** Materialize the result using `.ToList()` or `.ToArray()` prior to multiple operations.

---

#### 60. What is the difference between LINQ-to-Objects and LINQ-to-Entities?
* **LINQ-to-Objects:** Operates on in-memory collections using delegate predicates directly within CLR.
* **LINQ-to-Entities:** Translates LINQ expression trees into SQL queries executed on target relational database engines via Entity Framework Core.

---

### 3. Exception Handling

#### 61. What is an exception?
* **Explanation:** An unexpected event or condition occurring during execution that disrupts normal instruction execution flow.

---

#### 62. How does try-catch-finally work?
* **`try`:** Wraps code that might throw an exception.
* **`catch`:** Intercepts, handles, or logs specified exceptions.
* **`finally`:** Guarantees execution of cleanup code regardless of whether an exception occurred or not.
* **Code Example:**
```csharp
FileStream? file = null;
try
{
    file = File.Open("log.txt", FileMode.Open);
}
catch (FileNotFoundException ex)
{
    Console.WriteLine($"File missing: {ex.Message}");
}
finally
{
    file?.Dispose();
}
```

---

#### 63. What is the difference between throw and throw ex?
* **`throw;`:** Preserves the original stack trace of the exception completely.
* **`throw ex;`:** Resets/overwrites the stack trace starting from the current line, destroying diagnostic information about where the error originally occurred. Always use `throw;`.

---

#### 64. Can we have multiple catch blocks?
* **Explanation:** Yes. Catch blocks are evaluated sequentially from top to bottom. Specific derived exceptions **must** appear before general base exceptions (`System.Exception`).
* **Code Example:**
```csharp
try { /* code */ }
catch (ArgumentNullException ex) { /* handle null */ }
catch (InvalidOperationException ex) { /* handle state */ }
catch (Exception ex) { /* fallback handler */ }
```

---

#### 65. What is a custom exception?
* **Explanation:** A domain-specific exception class inheriting from `System.Exception` used to signal domain logic assertion failures cleanly.
* **Code Example:**
```csharp
public class InsufficientFundsException : Exception
{
    public InsufficientFundsException(string message) : base(message) { }
}
```

---

#### 66. Should exceptions be used for normal business logic?
* **Explanation:** **No.** Exceptions are costly due to stack unwinding and memory overhead. Use explicit conditional validation or patterns like Result Object (`OneOf` / `Result<T>`) for control flow instead.

---

#### 67. What happens if an exception is not handled?
* **Explanation:** The exception propagates up the execution call stack. If no catch block is reached, the host runtime terminates the thread or returns a generic HTTP 500 error in Web APIs.

---

#### 68. What is global exception handling?
* **Explanation:** A centralized exception interceptor operating at application boundaries to capture unhandled exceptions, log detailed diagnostics, and return standardized error HTTP responses.

---

#### 69. How do you implement global exception handling in ASP.NET Core?
* **Explanation:** Implement `IExceptionHandler` (ASP.NET Core 8+) or use custom Middleware.
* **Code Example:**
```csharp
public class GlobalExceptionHandler : Microsoft.AspNetCore.Diagnostics.IExceptionHandler
{
    public async ValueTask<bool> TryHandleAsync(
        HttpContext httpContext, Exception exception, CancellationToken cancellationToken)
    {
        var response = new { Status = 500, Title = "An unexpected server error occurred." };
        httpContext.Response.StatusCode = 500;
        await httpContext.Response.WriteAsJsonAsync(response, cancellationToken);
        return true;
    }
}
```

---

#### 70. What is ProblemDetails?
* **Explanation:** An RFC 7807 standardized machine-readable HTTP response format for specifying API error context cleanly.
* **Code Example:**
```json
{
  "type": "https://tools.ietf.org/html/rfc7231#section-6.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "Email": ["The Email field is required."]
  }
}
```

### 4. ASP.NET Core Fundamentals

#### 71. What is ASP.NET Core?
* **Explanation:** A modern, cross-platform, high-performance, open-source framework built by Microsoft for developing cloud-ready RESTful web services, APIs, and microservices.

---

#### 72. Why use ASP.NET Core for backend development?
* **Performance:** TechEmpower benchmarks confirm ASP.NET Core is among the fastest web frameworks.
* **Cross-Platform:** Runs natively on Docker containers, Linux, macOS, and Windows.
* **Built-in DI:** Native Dependency Injection runtime engine.
* **Unified Pipeline:** Single pipeline model for APIs, Minimal APIs, and Razor applications.

---

#### 73. What is middleware?
* **Explanation:** Software components assembled sequentially into an application request pipeline to handle incoming HTTP requests and outgoing HTTP responses.
* **Code Example:**
```csharp
app.Use(async (context, next) =>
{
    // Pre-processing
    await next(); // Pass to next middleware
    // Post-processing
});
```

---

#### 74. How does the ASP.NET Core request pipeline work?
* **Explanation:** Incoming HTTP requests pass through a sequence of chained middleware components (`RequestDelegate`). Each middleware component can either inspect/transform the request, invoke the next middleware, or short-circuit the pipeline completely.

---

#### 75. What is Program.cs?
* **Explanation:** The application entry point where WebApplicationBuilder configures services (DI), logging, configuration settings, and builds the request processing middleware pipeline.

---

#### 76. What is dependency injection?
* **Explanation:** A design pattern enforcing Inversion of Control (IoC), where object dependencies are injected into constructors rather than being directly instantiated within classes using `new`.

---

#### 77. Why is dependency injection important?
* Decouples caller code from underlying implementation details.
* Facilitates seamless unit testing via object mocking (`Moq`, `NSubstitute`).
* Centralizes lifetime management of application objects.

---

#### 78. What are the three DI lifetimes?
1. **Transient**
2. **Scoped**
3. **Singleton**

---

#### 79. What is Singleton?
* **Explanation:** Created the first time it is requested and persists for the entire lifecycle of the host application process.

---

#### 80. What is Scoped?
* **Explanation:** Created once per client HTTP Request lifecycle scope. Shared across all operations executing within that specific HTTP request context.

---

#### 81. What is Transient?
* **Explanation:** Created every single time it is requested from the dependency injection container. Ideal for lightweight, stateless services.

---

#### 82. Singleton vs Scoped vs Transient?
```csharp
builder.Services.AddSingleton<ICacheService, MemoryCacheService>(); // 1 instance forever
builder.Services.AddScoped<IOrderService, OrderService>();         // 1 instance per HTTP Request
builder.Services.AddTransient<ITokenGenerator, TokenGenerator>();   // New instance every inject
```

#### 83. What is configuration in ASP.NET Core?
* **Explanation:** A key-value based multi-provider abstraction mechanism aggregating settings from JSON files, Environment Variables, Command Line args, and Azure Key Vault.

#### 84. What is appsettings.json?

---

#### 85. What is appsettings.Development.json?
* **Explanation:** Environment-specific configuration file that overrides default settings defined in `appsettings.json` when running locally under the `Development` environment.

---

#### 86. What is IConfiguration?
* **Explanation:** Service interface injected into components to access key-value pairs across active configuration providers.

---

#### 87. What is the Options pattern?
* **Explanation:** Strongly-typed binding mechanism mapping configuration sections directly into plain C# classes (POCOs) via `IOptions<T>`, `IOptionsSnapshot<T>`, or `IOptionsMonitor<T>`.

```csharp
builder.Services.Configure<SmtpSettings>(builder.Configuration.GetSection("SmtpSettings"));
```

#### 88. What are environment variables?
* **Explanation:** OS-level key-value variables used to pass sensitive infrastructure configuration settings into containers at runtime without storing secrets in source code files.

---

#### 89. How do you store database connection strings?
* **Local Dev:** Secret Manager (`dotnet user-secrets`) or `appsettings.Development.json`.
* **Production:** Managed Identity with Azure Key Vault, AWS Secrets Manager, or Environment Variables in Kubernetes/Docker.

#### 90. What is Kestrel?

### 5. REST API Fundamentals

#### 91. What is an API?
* **Explanation:** Application Programming Interface — a software contract that defines defined rules and protocols allowing two software systems to communicate and exchange data.

---

#### 92. What is REST?
* **Explanation:** Representational State Transfer — an architectural style for distributed hypermedia systems introduced by Roy Fielding relying on standard HTTP protocols and stateless communication.

---

#### 93. What is a RESTful API?
* **Explanation:** An HTTP Web API adhering to standard REST constraints including statelessness, explicit resource modeling via URIs, standard HTTP verb usage, and standard response codes.

---

#### 94. What are REST principles?
* **Client-Server Separation:** Loose coupling between UI and data logic.
* **Statelessness:** No client context stored on server across requests.
* **Cacheability:** Implicit or explicit response caching.
* **Uniform Interface:** Standard URIs, HTTP verbs, and data representations.
* **Layered System:** Support for proxies, load balancers, and security layers.

---

#### 95. What is a resource in REST?
* **Explanation:** An object or concept exposed by the API (e.g., `User`, `Order`, `Invoice`), identified cleanly using nouns in URIs (e.g., `/api/v1/orders`).

---

#### 96. What is an endpoint?
* **Explanation:** A specific URL/URI path exposed by an API where clients send requests to access or modify resources (e.g., `POST https://api.store.com/v1/payments`).

---

#### 97. What is HTTP?
* **Explanation:** Hypertext Transfer Protocol — an application-layer network protocol used to request and transmit web content and structured API payloads across the web over TCP/IP or HTTP/3.

---

#### 98. What are HTTP methods?
* **Explanation:** Standardized verbs indicating the desired CRUD action to be performed on an endpoint resource.

---

#### 99. What is GET?
* **Explanation:** Retrieves a representation of a resource without altering server state (Safe & Idempotent).

---

#### 100. What is POST?
* **Explanation:** Submits payload data to create a new resource (Non-Idempotent).

---

#### 101. What is PUT?
* **Explanation:** Completely replaces/overwrites an existing resource with the request body, or creates it if non-existent (Idempotent).

---

#### 102. What is PATCH?
* **Explanation:** Performs a partial update/modification to a specific resource (Non-Idempotent by default).

---

#### 103. What is DELETE?
* **Explanation:** Removes a specific resource from the system (Idempotent).

---

#### 104. GET vs POST?
| Attribute | GET | POST |
|---|---|---|
| Purpose | Retrieve data | Create data |
| Body | No payload body | Contains JSON payload |
| Idempotent | Yes | No |
| Caching | Highly cacheable | Non-cacheable by default |

---

#### 105. PUT vs PATCH?
* **PUT:** Replaces the entire resource entity payload. Unsent properties revert to defaults.
* **PATCH:** Modifies **only** specified fields within the payload. Untouched properties remain unchanged.

---

#### 106. PUT vs POST?
* **POST:** Creates a resource. Server assigns ID (`/api/orders`). Calling 5 times creates 5 separate records.
* **PUT:** Creates or replaces a resource at a client-known location (`/api/orders/101`). Calling 5 times yields the exact same state.

---

#### 107. What is an HTTP status code?
* **Explanation:** A 3-digit numeric status returned by the server indicating the execution result of an HTTP request.
  * **2xx:** Success
  * **3xx:** Redirection
  * **4xx:** Client Errors
  * **5xx:** Server Errors

---

#### 108. What does 200 OK mean?
* Request successfully executed and returning data in the response body.

---

#### 109. What does 201 Created mean?
* Request succeeded and a new resource was successfully created. Includes a `Location` header pointing to the new resource.

---

#### 110. What does 204 No Content mean?
* Request succeeded, but there is no payload body to return (common for `DELETE` or `PUT` operations).

---

#### 111. What does 400 Bad Request mean?
* Client sent invalid syntax, malformed JSON payload, or failed domain schema validation.

---

#### 112. What does 401 Unauthorized mean?
* Client lacks valid authentication credentials (e.g., missing or invalid JWT Bearer token).

---

#### 113. What does 403 Forbidden mean?
* Client is authenticated, but lacks sufficient role or policy permissions to access the requested resource.

---

#### 114. What does 404 Not Found mean?
* The requested resource URI path does not exist on the server.

---

#### 115. What does 409 Conflict mean?
* Request conflicts with current state on server (e.g., duplicate unique email register request).

---

#### 116. What does 500 Internal Server Error mean?
* An unhandled exception or crash occurred on the server while executing the request.

---

#### 117. What is idempotency?
* **Explanation:** A property of an HTTP method where executing identical requests multiple times produces the exact same server state as making a single request.

---

#### 118. Which HTTP methods are idempotent?
* **Idempotent:** `GET`, `PUT`, `DELETE`, `HEAD`, `OPTIONS`.
* **Non-Idempotent:** `POST`, `PATCH`.

---

#### 119. What is statelessness in REST?
* **Explanation:** Every incoming HTTP request must contain all contextual information (tokens, payload) required to process it. The server stores no client session context in memory between requests.

---

#### 120. What is content negotiation?
* **Explanation:** Process where client and server negotiate response payload formats (e.g., `application/json`, `application/xml`) via request `Accept` HTTP headers.

---

### 6. ASP.NET Core Web API

#### 121. What is a Controller?
* **Explanation:** A C# class that groups API endpoints together to process incoming HTTP requests and construct responses.

---

#### 122. What is ControllerBase?
* **Explanation:** Base class for ASP.NET Core API Controllers providing core controller features (`User`, `Response`, `ModelState`, `Ok()`, `BadRequest()`) without overhead views support.

---

#### 123. Controller vs ControllerBase?
* **`ControllerBase`:** Used for RESTful Web APIs (No views).
* **`Controller`:** Inherits from `ControllerBase`, adds MVC View support (`View()`, `ViewBag`).

---

#### 124. What is [ApiController]?
* **Explanation:** Class attribute enabling API-specific behaviors: automatic HTTP 400 responses for validation failures, automatic parameter source inference (`[FromBody]`, `[FromRoute]`), and multipart request handling.

---

#### 125. What is routing?
* **Explanation:** The engine that matches an incoming HTTP request URI path to an endpoint action inside a controller.

---

#### 126. Attribute Routing vs Conventional Routing?
* **Attribute Routing:** Routes explicitly defined directly on endpoints using attributes (`[Route("api/[controller]")]`). Standard for APIs.
* **Conventional Routing:** Global route templates defined centralized in `Program.cs` (`{controller=Home}/{action=Index}/{id?}`). Standard for MVC.

---

#### 127. What is [Route]?
* **Explanation:** Attribute specifying the URL pattern path for an API Controller or endpoint action.

---

#### 128. What is [HttpGet]?
* **Explanation:** Maps an endpoint specifically to handle incoming `GET` HTTP method requests.

---

#### 129. What is [HttpPost]?
* **Explanation:** Maps an endpoint specifically to handle incoming `POST` HTTP method requests.

---

#### 130. What is [HttpPut]?
* **Explanation:** Maps an endpoint specifically to handle incoming `PUT` HTTP method requests.

---

#### 131. What is [HttpPatch]?
* **Explanation:** Maps an endpoint specifically to handle incoming `PATCH` HTTP method requests.

---

#### 132. What is [HttpDelete]?
* **Explanation:** Maps an endpoint specifically to handle incoming `DELETE` HTTP method requests.

---

#### 133. What is route parameter?
* **Explanation:** A variable bound directly within the URL path segment (e.g., `/api/products/{id}`).

---

#### 134. What is query parameter?
* **Explanation:** Key-value parameters passed at the end of a URL after a `?` symbol (e.g., `/api/products?category=tech&page=2`).

---

#### 135. Route parameter vs query parameter?
* **Route Parameter:** Required segment used to identify a specific single resource (`/orders/42`).
* **Query Parameter:** Optional parameter used to filter, sort, or paginate collections (`/orders?status=active`).

---

#### 136. What is [FromBody]?
* **Explanation:** Parameter binding attribute specifying that an argument value must be deserialized from the incoming HTTP request payload body.

---

#### 137. What is [FromRoute]?
* **Explanation:** Parameter binding attribute forcing a parameter to bind explicitly from URL route path parameters.

---

#### 138. What is [FromQuery]?
* **Explanation:** Parameter binding attribute forcing a parameter to bind explicitly from URL query string parameters.

---

#### 139. What is [FromHeader]?
* **Explanation:** Parameter binding attribute forcing a parameter to bind directly from an incoming HTTP header key.

---

#### 140. What is model binding?
* **Explanation:** The automatic ASP.NET Core process of converting HTTP request data (strings, JSON, headers, route values) into strongly-typed C# method parameters.

---

#### 141. What is model validation?
* **Explanation:** Validating incoming mapped parameters against defined validation rules before processing business logic.

---

#### 142. What is ModelState?
* **Explanation:** A dictionary containing model binding and validation state evaluation flag (`ModelState.IsValid`) and error messages.

---

#### 143. What is ActionResult<T>?
* **Explanation:** Return type supporting either a specific domain response model `T` or an `IActionResult` (e.g., `Ok(T)`, `NotFound()`). Improves OpenAPI documentation typing.

---

#### 144. IActionResult vs ActionResult<T>?
* **`IActionResult`:** Untyped interface return. Requires generic response annotations (`[ProducesResponseType]`) for Swagger tools.
* **`ActionResult<T>`:** Strongly typed result wrapper explicitly exposing domain contracts to Swagger schema tools.

---

#### 145. How do you return different HTTP status codes?
* **Code Example:**
```csharp
[HttpGet("{id}")]
public async Task<ActionResult<ProductDto>> GetProduct(int id)
{
    var product = await _service.GetByIdAsync(id);
    if (product == null) return NotFound($"Product {id} not found.");
    return Ok(product);
}
```

---

#### 146. How do you return JSON from an API?
* **Explanation:** Web APIs automatically serialize C# return objects into JSON strings by default when endpoints return `Ok(object)` or `ActionResult<T>`.

---

#### 147. What is JSON serialization?
* **Explanation:** The process of converting in-memory C# objects into JSON formatted text strings for HTTP network response transfer.

---

#### 148. What is System.Text.Json?
* **Explanation:** Built-in high-performance, low-memory, zero-allocation JSON library native to modern .NET replacing legacy `Newtonsoft.Json`.

---

#### 149. What is DTO?
* **Explanation:** Data Transfer Object — an object design pattern defining simple data containers without behavior used to transfer data between system layers over network endpoints.

---

#### 150. Why should DTOs be used instead of exposing entities directly?
* **Security:** Prevents over-posting/mass-assignment attacks and hides internal database structures.
* **Decoupling:** Decouples internal database persistence models from external API contracts.
* **Performance:** Reduces payload sizes by serializing only required client fields.

### 7. Entity Framework Core

#### 151. What is Entity Framework Core?
* **Explanation:** An open-source, lightweight, cross-platform Object-Relational Mapper (ORM) for .NET that enables developers to interact with databases using strongly typed LINQ C# queries.

---

#### 152. EF Core vs ADO.NET?
* **ADO.NET:** Low-level database access library requiring manual SQL queries, commands, and `SqlDataReader` mapping. Extremely fast, but verbose.
* **EF Core:** High-level ORM abstracting SQL logic. Handles change tracking, relationships, and model generation automatically.

---

#### 153. What is ORM?
* **Explanation:** Object-Relational Mapping — a software technique mapping tabular relational database structures (tables, foreign keys) directly into Object-Oriented representations (C# classes, properties).

---

#### 154. What is DbContext?
* **Explanation:** Primary EF Core session component acting as a combination of Repository and Unit of Work patterns to query and save entity instances into a database.
* **Code Example:**
```csharp
public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options) { }
    public DbSet<Order> Orders => Set<Order>();
}
```

---

#### 155. What is DbSet<T>?
* **Explanation:** Represents a typed collection entity set used to perform LINQ read, create, update, and delete queries against a specific target table in the database.

---

#### 156. What is an entity?
* **Explanation:** A domain model C# class mapped directly to a relational database table record containing a distinct identity key.

---

#### 157. What is a primary key?
* **Explanation:** A unique database column identifier for an entity table record. In EF Core, properties named `Id` or `<EntityName>Id` are assigned as primary keys automatically by convention.

---

#### 158. What is a foreign key?
* **Explanation:** A database column creating a explicit relationship linking a record in one table to the primary key of another table.

---

#### 159. What is a navigation property?
* **Explanation:** Property on an EF Core entity referencing associated related entities (e.g., `order.Customer` or `customer.Orders`).

---

#### 160. What is a migration?
* **Explanation:** Tooling feature tracking entity configuration changes over time to update database schemas safely without losing existing production data.

---

#### 161. How do you create a migration?
```bash
dotnet ef migrations add InitialCreate
```

---

#### 162. How do you apply a migration?
```bash
dotnet ef database update
```

---

#### 163. What happens when SaveChangesAsync() is called?
* **Explanation:** EF Core Change Tracker inspects tracked entities for mutations, generates optimized SQL statements (`INSERT`, `UPDATE`, `DELETE`), executes them inside an automatic database transaction, and updates entity states to `Unchanged`.

---

#### 164. What is change tracking?
* **Explanation:** The internal process where `DbContext` monitors entity instance property changes to generate correct update SQL operations during `SaveChangesAsync()`.

---

#### 165. What is AsNoTracking()?
* **Explanation:** Disables change tracking evaluation for read-only queries. Significantly reduces memory usage and execution overhead.
* **Code Example:**
```csharp
var products = await _context.Products
    .AsNoTracking()
    .ToListAsync();
```

---

#### 166. When should you use AsNoTracking()?
* **Usage:** On **all** read-only API query operations where returned entity results will not be modified or saved back to the database.

---

#### 167. What is eager loading?
* **Explanation:** Loading related child entities immediately in the primary SQL query execution using `.Include()`.

---

#### 168. What is lazy loading?
* **Explanation:** Deferring loading of child entities until the navigation property is accessed at runtime (requires `UseLazyLoadingProxies()` and `virtual` properties). Discouraged in APIs due to hidden N+1 query execution.

---

#### 169. What is explicit loading?
* **Explanation:** Intentionally loading child entities for an already fetched base entity on demand using `Entry().Reference()` or `Entry().Collection()`.

---

#### 170. Include() vs ThenInclude()?
* **`Include()`:** Specifies first-level child entity relationship loading.
* **`ThenInclude()`:** Specifies multi-level nested child entity relationship loading.
* **Code Example:**
```csharp
var orders = await _context.Orders
    .Include(o => o.Customer)
    .Include(o => o.OrderItems)
        .ThenInclude(item => item.Product)
    .ToListAsync();
```

---

#### 171. What is a shadow property?
* **Explanation:** Properties defined directly in the EF Core database model context that do not exist explicitly inside the standard C# entity class (e.g., `LastUpdated`).

---

#### 172. What is Fluent API?
* **Explanation:** Configuration mechanism overriding conventions by building database mappings inside `OnModelCreating` via `ModelBuilder` builder calls.

---

#### 173. Data Annotations vs Fluent API?
* **Data Annotations:** Attribute decorations directly on C# model properties (`[Required]`, `[MaxLength(50)]`). Simple, but pollutes domain entities.
* **Fluent API:** Clean separation of entity configuration logic inside dedicated configuration mapping classes (`IEntityTypeConfiguration<T>`). Recommended for clean architecture.

---

#### 174. What is entity configuration?
* **Explanation:** Cleanly organizing database model metadata logic into isolated classes using `IEntityTypeConfiguration<T>`.
* **Code Example:**
```csharp
public class OrderConfiguration : IEntityTypeConfiguration<Order>
{
    public void Configure(EntityTypeBuilder<Order> builder)
    {
        builder.HasKey(o => o.Id);
        builder.Property(o => o.TotalAmount).HasPrecision(18, 2);
    }
}
```

---

#### 175. What is a composite key?
* **Explanation:** A table primary key composed of two or more columns combined together to form a unique identity. Configured via Fluent API: `builder.HasKey(x => new { x.OrderId, x.ProductId });`.

---

#### 176. What is optimistic concurrency?
* **Explanation:** Concurrency check preventing data overwrite conflicts without locking database rows. Uses a version token or `[Timestamp]` byte array column.

---

#### 177. What is a transaction?
* **Explanation:** A sequence of database operations executed as a single logical unit of work. Guarantees that either **all** operations succeed or **all** are rolled back completely.

---

#### 178. How do you implement a transaction in EF Core?
* **Code Example:**
```csharp
using var transaction = await _context.Database.BeginTransactionAsync();
try
{
    _context.Orders.Add(newOrder);
    await _context.SaveChangesAsync();

    _context.Logs.Add(new AuditLog());
    await _context.SaveChangesAsync();

    await transaction.CommitAsync();
}
catch
{
    await transaction.RollbackAsync();
    throw;
}
```

---

#### 179. What is the N+1 query problem?
* **Explanation:** Performance anti-pattern where an application executes 1 primary SQL query to fetch parent rows, followed by N separate secondary SQL queries to fetch child data for each row individually inside a loop.

---

#### 180. How can you prevent N+1 queries?
* Explicitly use Eager Loading (`Include()`).
* Use Query Projection (`Select()`) to fetch only required fields directly into a DTO in a single SQL query execution.

---

### 8. Database & SQL

#### 181. What is normalization?
* **Explanation:** Process of organizing relational database schema structures to eliminate data redundancy, prevent update anomalies, and enforce data integrity (1NF, 2NF, 3NF).

---

#### 182. What is denormalization?
* **Explanation:** Optimization strategy intentionally introducing redundant data into normalized schemas to reduce complex join overhead and speed up read query performance.

---

#### 183. What is an index?
* **Explanation:** B-tree data structure created on database table columns to drastically speed up table record filtering and sorting operations.

---

#### 184. Clustered vs Non-Clustered Index?
* **Clustered Index:** Defines the physical table row storage order on disk. Exactly one clustered index permitted per table (typically Primary Key).
* **Non-Clustered Index:** Separate index lookup structure storing key values pointing to physical table rows. Multiple permitted per table.

---

#### 185. What is a unique constraint?
* **Explanation:** Database rule ensuring that all values inserted across a targeted table column remain distinct and unique.

---

#### 186. Primary Key vs Unique Key?
* **Primary Key:** Uniquely identifies a record. Cannot accept `NULL` values. Single per table.
* **Unique Key:** Guarantees uniqueness. Accepts one `NULL` value (in SQL Server). Multiple allowed per table.

---

#### 187. What is a foreign key constraint?
* **Explanation:** Referential integrity enforcement preventing insertion of orphan child records referencing invalid primary key IDs.

---

#### 188. What is a transaction?
* **Explanation:** Logical unit of database execution guaranteeing atomic state modifications.

---

#### 189. What are ACID properties?
* **Atomicity:** All operations complete successfully or all roll back.
* **Consistency:** Transaction transitions data validly across integrity constraints.
* **Isolation:** Concurrent transactions execute without mutual interference.
* **Durability:** Committed state changes persist permanently across system crashes.

---

#### 190. What is a deadlock?
* **Explanation:** Concurrency state where Process A locks Resource 1 and requests Resource 2, while Process B locks Resource 2 and requests Resource 1. Neither can proceed.

---

#### 191. What is SQL Injection?
* **Explanation:** Security vulnerability occurring when unvalidated client dynamic input strings are concatenated directly into SQL execution strings.

---

#### 192. How do you prevent SQL injection in .NET?
* Use EF Core or parameterized queries (`FromSqlInterpolated`).
* Never concatenate raw user input strings directly into SQL command strings.

---

#### 193. What is a stored procedure?
* **Explanation:** Precompiled set of SQL statements stored directly on the relational database server engine.

---

#### 194. Stored Procedure vs EF Core LINQ?
* **Stored Procedure:** Managed on database server. Fast execution, but lacks C# type safety and version control tracking.
* **EF Core LINQ:** Managed in source control. Strongly-typed, cross-database compatible, easy to refactor.

---

#### 195. What is a view?
* **Explanation:** Virtual database table derived from executing an underlying saved SQL query expression.

---

#### 196. What is a database transaction isolation level?
* **Explanation:** Controls degree of isolation preventing concurrency anomalies (Read Uncommitted, Read Committed, Repeatable Read, Serializable, Snapshot).

---

#### 197. Optimistic vs Pessimistic Locking?
* **Optimistic:** Assumes conflicts are rare. Verifies row versions upon update using tokens (`ConcurrencyCheck`).
* **Pessimistic:** Assumes conflicts are frequent. Locks target database rows explicitly (`UPDLOCK`) until transaction completion.

---

#### 198. How do you optimize a slow SQL query?
* Analyze query execution plans for full table scans.
* Add appropriate non-clustered indexes covering query predicate columns (`WHERE`, `JOIN`).
* Remove unnecessary column selects (`SELECT *` -> `SELECT col1`).
* Replace scalar subqueries or cursors with set-based join operations.

---

#### 199. What causes database performance problems in APIs?
* Missing indexes on foreign keys and search query columns.
* Unbounded query fetching (missing pagination).
* N+1 query execution loops.
* Over-fetching entity graphs without projection.

---

#### 200. How would you troubleshoot a slow API caused by the database?
1. Capture target execution metrics using APM logging tools (Serilog, OpenTelemetry, Application Insights).
2. Inspect exact raw executed SQL using EF Core logging or SQL Server Profiler.
3. Review Execution Plan for missing index recommendations or high-cost table scans.
4. Implement database query indexes or query projections.

---

### 9. Dependency Injection & Architecture

#### 201. Explain Dependency Injection with a real example.
* **Explanation:** Passing dependent objects into a class rather than allowing the class to instantiate dependencies internally.
* **Code Example:**
```csharp
public interface IEmailSender
{
    Task SendAsync(string to, string body);
}

public class OrderController : ControllerBase
{
    private readonly IEmailSender _emailSender;
    // Injected via constructor by ASP.NET Core DI Container
    public OrderController(IEmailSender emailSender)
    {
        _emailSender = emailSender;
    }
}
```

---

#### 202. Why shouldn't we instantiate dependencies directly using `new`?
* Tightly couples classes directly to concrete implementations.
* Makes unit testing impossible because dependencies cannot be mocked or stubbed.
* Violates Dependency Inversion Principle (DIP).

---

#### 203. What is constructor injection?
* **Explanation:** Supplying required service dependencies directly through public class constructors. The standard and recommended DI pattern in .NET.

---

#### 204. What is service registration?
* **Explanation:** Telling the ASP.NET Core DI framework which concrete class implementation to construct when a interface service type is requested.

---

#### 205. What is IServiceCollection?
* **Explanation:** The contract container used in `Program.cs` to register service dependencies and their configured lifetimes before building the application.

---

#### 206. What is IServiceProvider?
* **Explanation:** The built-in IoC service locator engine responsible for instantiating and resolving service instances at runtime.

---

#### 207. What is the Service Layer?
* **Explanation:** Architectural layer isolating business domain rules and orchestration logic away from presentation API Controllers and database persistence entities.

---

#### 208. What is Repository Pattern?
* **Explanation:** Abstraction layer mediating between domain logic and data mapping layers to isolate raw data access querying behind generic collection-like interfaces.

---

#### 209. Is Repository Pattern always required with EF Core?
* **Explanation:** **No.** `DbContext` is already an implementation of the Repository and Unit of Work patterns. Adding generic repositories over EF Core often introduces redundant code unless multi-database abstraction is required.

---

#### 210. What is Unit of Work?
* **Explanation:** Pattern tracking and aggregating multiple database insert/update operations so they commit in a single atomic transaction.

---

#### 211. Repository Pattern vs Unit of Work?
* **Repository:** Handles data access operations for a single specific entity type (`IProductRepository`).
* **Unit of Work:** Coordinates transaction completion across multiple combined repositories (`IUnitOfWork.SaveChangesAsync()`).

---

#### 212. What is separation of concerns?
* **Explanation:** Design rule partitioning application code into distinct structural modules, where each module handles one single responsibility (e.g., UI API Controller vs Business Logic vs Database).

---

#### 213. What is Clean Architecture?
* **Explanation:** Domain-centric architecture organizing applications into concentric layers. Inner layers (Domain, UseCases) contain zero references to external layers (Infrastructure, Web APIs, Databases).

---

#### 214. What is Layered Architecture?
* **Explanation:** Traditional N-Tier architectural layout where dependencies flow downward sequentially: Presentation -> Business Logic -> Data Access -> Database.

---

#### 215. What is Onion Architecture?
* **Explanation:** Architectural approach structuring domain entities and core interface abstractions strictly at the center, surrounded by Application Services, and placing Infrastructure/UI drivers at the outermost layer.

---

#### 216. Clean Architecture vs traditional 3-layer architecture?
* **Traditional 3-Layer:** Database is at the core. Everything depends directly on Data Access Layer components.
* **Clean Architecture:** Domain Core is at the center. Databases and External Frameworks are outward plugins depending inward on Domain abstractions.

---

#### 217. What is the Dependency Rule?
* **Explanation:** Primary Clean Architecture constraint specifying that source code dependencies can only point **inward** toward domain entities. Inner core layers must never know anything about outer UI or database layers.

---

#### 218. What is SOLID?
* **Explanation:** Five fundamental object-oriented design principles guiding developers toward readable, maintainable, scalable software codebases.

---

#### 219. Explain Single Responsibility Principle (SRP).
* **Explanation:** A class should have one, and only one, reason to change.
* **Example:** `InvoiceCalculator` computes values; `InvoicePdfExporter` exports PDF documents.

---

#### 220. Explain Open/Closed Principle (OCP).
* **Explanation:** Software entities should be open for extension, but closed for modification.
* **Example:** Implement new payment processors via new interface implementations (`CryptoPaymentProcessor`) without modifying existing code.

---

#### 221. Explain Liskov Substitution Principle (LSP).
* **Explanation:** Subtypes must be completely substitutable for their base types without breaking application behavior or throwing unexpected errors.

---

#### 222. Explain Interface Segregation Principle (ISP).
* **Explanation:** Clients should not be forced to depend upon large interface methods they do not use. Split fat interfaces into focused, role-specific interfaces.

---

#### 223. Explain Dependency Inversion Principle (DIP).
* **Explanation:** High-level modules should not depend on low-level modules. Both should depend on abstractions (interfaces).

---

### 10. Async Programming

#### 224. What is asynchronous programming?
* **Explanation:** Programming pattern allowing long-running I/O operations (database calls, web API HTTP calls, disk reads) to execute without blocking the calling worker thread.

---

#### 225. Why use async and await?
* Prevents thread starvation. Frees up expensive server threads to handle other concurrent incoming HTTP requests while waiting for slow I/O bounds.

---

#### 226. What is a Task?
* **Explanation:** Represents a non-blocking asynchronous operation state in .NET (`System.Threading.Tasks`).

---

#### 227. Task vs Task<T>?
* **`Task`:** Represents an asynchronous operation returning no value (equivalent to async `void`).
* **`Task<T>`:** Represents an asynchronous operation returning a concrete value result of type `T`.

---

#### 228. What happens internally when using await?
* **Explanation:** Compiler transforms the method into a state machine (`IAsyncStateMachine`). The executing thread yields context immediately back to the ThreadPool upon hitting `await`, resuming execution seamlessly when the operation completes.

---

#### 229. Async/await vs synchronous code?
* **Synchronous:** Blocks calling thread completely during I/O wait times. Destroys throughput scalability under load.
* **Async/Await:** Yields threads back to thread pool during I/O wait times. Enables high request concurrency.

---

#### 230. What is Task.WhenAll()?
* **Explanation:** Runs multiple task operations concurrently and waits for all of them to finish execution before proceeding.
* **Code Example:**
```csharp
Task task1 = FetchUsersAsync();
Task task2 = FetchOrdersAsync();
await Task.WhenAll(task1, task2); // Runs parallel
```

---

#### 231. Task.WhenAll() vs Task.WhenAny()?
* **`Task.WhenAll()`:** Completes when **all** tasks in the collection finish.
* **`Task.WhenAny()`:** Completes as soon as **any single** task in the collection finishes.

---

#### 232. What is cancellation token?
* **Explanation:** `CancellationToken` propagates notification signals across threads indicating that an operation should be cancelled before completion.

---

#### 233. How do you cancel an API request?
* **Explanation:** Pass the framework-provided `CancellationToken` parameter from the ASP.NET Core endpoint down into database/async service calls.
* **Code Example:**
```csharp
[HttpGet]
public async Task<IActionResult> GetData(CancellationToken cancellationToken)
{
    var data = await _repository.GetSlowDataAsync(cancellationToken);
    return Ok(data);
}
```

---

#### 234. What is CancellationTokenSource?
* **Explanation:** The signaling object that creates, manages, and issues cancellation requests to associated `CancellationToken` instances.

---

#### 235. Why should database calls use asynchronous methods?
* Relieves thread pool starvation. Database I/O involves waiting on external network/disk responses; running asynchronously allows threads to handle incoming web traffic instead of idling.

---

#### 236. What happens if you use .Result or .Wait() inside async code?
* Performs synchronous blocking over an asynchronous method (Sync-over-Async anti-pattern). Leads to thread starvation and potential severe thread deadlocks.

---

#### 237. What is async deadlock?
* **Explanation:** Blocked execution state occurring when synchronous code blocks a thread (`.Result`) waiting on an async task that requires the original synchronization context to resume execution.

---

#### 238. Can an async method run on a new thread?
* **Explanation:** Not inherently. An async I/O method runs on the calling thread until an `await` point yields execution. `Task.Run()` must be explicitly invoked to offload execution onto a new ThreadPool thread.

---

#### 239. What is ValueTask?
* **Explanation:** A value-type (`struct`) representation of an asynchronous task return designed to prevent heap object allocations when operations complete synchronously.

---

#### 240. Task vs ValueTask?
* **`Task`:** Reference type allocation on heap. Use as default return type for general async operations.
* **`ValueTask`:** Stack-allocated struct. Use in ultra-high performance paths where results are frequently available synchronously from in-memory caches.

---

### 11. Authentication & Authorization

#### 241. Authentication vs Authorization?
* **Authentication:** Identifying who a user is (Identity check - "Who are you?").
* **Authorization:** Determining what permissions an authenticated user has (Permissions check - "What are you allowed to do?").

---

#### 242. What is JWT?
* **Explanation:** JSON Web Token — an open standard (RFC 7519) compact, URL-safe self-contained token format used to transmit securely verifiable JSON identity claims across networks.

---

#### 243. How does JWT authentication work?
1. Client POSTs login credentials to `/api/auth/login`.
2. Server validates credentials and returns a signed JWT.
3. Client attaches token to subsequent HTTP requests header: `Authorization: Bearer <JWT>`.
4. Server validates signature cryptographically without querying database on every request.

---

#### 244. What are the three parts of a JWT?
1. **Header** (Algorithm & Token Type)
2. **Payload** (Claims data)
3. **Signature** (Cryptographic verification signature)

---

#### 245. What is the JWT header?
* JSON containing metadata specifying the signing algorithm (e.g., `HS256`, `RS256`) and token type (`JWT`).

---

#### 246. What is the JWT payload?
* JSON containing claim key-value pairs representing entity details and metadata (e.g., `sub`, `email`, `role`, `exp`).

---

#### 247. What is the JWT signature?
* Hash generated by signing the base64-encoded Header and Payload using a secret key, ensuring token tampering detection.

---

#### 248. What is a claim?
* **Explanation:** A statement key-value piece of information asserted about an identity user (e.g., `email = user@test.com`, `role = Admin`).

---

#### 249. What is a role?
* **Explanation:** A logical grouping assigned to users defining broad operational tiers (e.g., `Admin`, `Manager`, `Customer`).

---

#### 250. Role-based authorization vs Policy-based authorization?
* **Role-Based:** Checks identity roles explicitly (`[Authorize(Roles = "Admin")]`). Simple, but inflexible.
* **Policy-Based:** Decouples permissions into flexible policy handlers (`[Authorize(Policy = "Over21Only")]`). Recommended for enterprise domain logic.

---

#### 251. What is [Authorize]?
* **Explanation:** Controller/Endpoint filter enforcing authentication checks on incoming requests before executing action methods.

---

#### 252. What is [AllowAnonymous]?
* **Explanation:** Bypasses authorization requirements on target action methods within authorized controllers, exposing endpoints publicly (e.g., Login endpoints).

---

#### 253. How do you configure JWT authentication in ASP.NET Core?
* **Code Example:**
```csharp
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateIssuerSigningKey = true,
            ValidIssuer = builder.Configuration["Jwt:Issuer"],
            ValidAudience = builder.Configuration["Jwt:Audience"],
            IssuerSigningKey = new SymmetricSecurityKey(
                Encoding.UTF8.GetBytes(builder.Configuration["Jwt:Key"]!))
        };
    });
```

---

#### 254. Where should JWT tokens be stored?
* **Browser Clients:** In secure, `HttpOnly`, `SameSite=Strict` HTTP cookies to prevent XSS theft.
* **Mobile/Native Clients:** In OS-level secure storage (Keychain, EncryptedSharedPreferences).

---

#### 255. What is an access token?
* Short-lived JWT credential (e.g., 15 mins expiry) used to authorize access directly to protected API endpoints.

---

#### 256. What is a refresh token?
* Long-lived secure token key stored securely on server database used to request new access tokens without requiring users to re-enter login credentials.

---

#### 257. Access Token vs Refresh Token?
| Attribute | Access Token | Refresh Token |
|---|---|---|
| Lifespan | Short (5-15 mins) | Long (7-30 days) |
| Sent with requests | Every API call | Only to token refresh endpoint |
| Revocation | Cannot revoke until expired | Can be revoked on server DB instantly |

---

#### 258. How do you implement refresh-token authentication?
1. Authenticate user -> return short-lived Access Token and long-lived random Refresh Token.
2. Store Refresh Token hash in database mapped to User ID.
3. When Access Token expires, client sends Refresh Token to `/api/auth/refresh`.
4. Validate Refresh Token in database, rotate token, issue new pair.

---

#### 259. What is token expiration?
* Standard JWT payload claim (`exp`) indicating the exact UTC Unix timestamp after which the token is considered invalid and rejected by API security handlers.

---

#### 260. How do you revoke a JWT?
* Since standard JWTs are stateless, instant revocation requires maintaining a short-lived token blacklist in Redis or relying on prompt Refresh Token revocation.

---

#### 261. What is password hashing?
* Passing plain text passwords through strong irreversible one-way cryptographic algorithms (BCrypt, Argon2id, PBKDF2) to convert them into secure hashes before saving to database.

---

#### 262. Why shouldn't passwords be stored directly?
* Storing plain text passwords creates massive security breach vulnerabilities allowing attackers to compromise user accounts across services if database records are stolen.

---

#### 263. What is salting?
* Adding unique, random string sequences to each password prior to hashing to ensure identical plain text passwords generate completely distinct database hashes, mitigating rainbow table attacks.

---

#### 264. JWT vs session-based authentication?
* **JWT:** Stateless. Scalable across microservices. Server stores no session memory state.
* **Session-Based:** Stateful. Server stores session IDs in memory or database. Harder to scale horizontally across server farms.

---

#### 265. OAuth 2.0 vs JWT?
* **OAuth 2.0:** An authorization framework protocol defining workflow delegation rules.
* **JWT:** A token format used to encapsulate user claims and signature data within protocols like OAuth 2.0.

---

#### 266. What is OpenID Connect (OIDC)?
* Identity layer built on top of OAuth 2.0 protocol adding standardized authentication and ID tokens (`id_token`).

---

### 12. REST API Security

#### 267. How do you secure a REST API?
* Use HTTPS exclusively.
* Implement JWT Bearer or OAuth 2.0 authentication.
* Enforce strict Authorization Policies.
* Validate all incoming input models.
* Enable Rate Limiting.
* Apply security headers (HSTS, Content-Security-Policy).

---

#### 268. What is HTTPS?
* Hypertext Transfer Protocol Secure — encrypts network communication between client and server using Transport Layer Security (TLS/SSL).

---

#### 269. Why is HTTPS important?
* Prevents Man-In-The-Middle (MITM) attacks, eavesdropping, and tampering with sensitive request headers and authorization tokens.

---

#### 270. What is CORS?
* Cross-Origin Resource Sharing — browser security mechanism restricting web applications running at one domain origin from requesting API resources on a different domain origin.

---

#### 271. Why does CORS occur?
* Browsers enforce Same-Origin Policy (SOP) by default. If domain `frontend.com` calls `api.com`, browser issues preflight `OPTIONS` check verifying cross-origin server permission.

---

#### 272. How do you configure CORS in ASP.NET Core?
* **Code Example:**
```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowFrontend", policy =>
    {
        policy.WithOrigins("https://myfrontend.com")
              .AllowAnyHeader()
              .AllowAnyMethod();
    });
});
app.UseCors("AllowFrontend");
```

---

#### 273. What is CSRF?
* Cross-Site Request Forgery — attack forcing an authenticated user browser to execute unintended actions against a vulnerable web application using automatically attached cookies.

---

#### 274. Is CSRF relevant for JWT APIs?
* **No, if** JWT tokens are sent using standard `Authorization: Bearer` headers (browsers do not attach custom authorization headers automatically).
* **Yes, if** JWT tokens are stored in standard cookies without `SameSite` flags.

---

#### 275. What is XSS?
* Cross-Site Scripting — attack injecting malicious JavaScript scripts into trusted web application views executed inside victim browser contexts.

---

#### 276. How can an API protect against XSS?
* Sanitize and encode all input/output payload fields.
* Store sensitive JWT tokens in `HttpOnly` cookies.
* Apply strict `Content-Security-Policy` HTTP headers.

---

#### 277. What is SQL Injection?
* Exploitation attack injecting executable SQL syntax directly through raw input parameter fields into backend database queries.

---

#### 278. What is rate limiting?
* Restricting the total number of incoming HTTP requests a client client IP or user identity can execute within a defined time window.

---

#### 279. How do you implement rate limiting in ASP.NET Core?
* **Code Example (ASP.NET Core 7+ Native):**
```csharp
builder.Services.AddRateLimiter(options =>
{
    options.AddFixedWindowLimiter("FixedPolicy", opt =>
    {
        opt.PermitLimit = 100;
        opt.Window = TimeSpan.FromMinutes(1);
    });
});
app.UseRateLimiter();
```

---

#### 280. How do you prevent brute-force attacks?
* Implement rate limiting on authentication routes.
* Apply account lockouts after consecutive invalid login attempts.
* Enforce CAPTCHA mechanisms on suspicious requests.

---

#### 281. What is API key authentication?
* Authentication method requiring clients to supply an assigned secret API key string header (`X-API-KEY`) on every request.

---

#### 282. API Key vs JWT?
* **API Key:** Identifies calling client application/project. Non-expiring static secret.
* **JWT:** Identifies specific authenticated user session identity. Short-lived and signed.

---

#### 283. How should secrets be stored?
* **Never in source code!** Use Secret Manager for local development, and Azure Key Vault, HashiCorp Vault, or AWS Secrets Manager for production environments.

---

#### 284. Why shouldn't JWT signing keys be committed to GitHub?
* Exposed signing keys allow malicious actors to forge arbitrary valid JWT tokens, completely bypassing API authentication and impersonating system administrators.

---

#### 285. What is HTTPS certificate validation?
* Process where client runtime verifies the authenticity, validity, hostname match, and certificate authority trust chain of a web server TLS certificate.

---

#### 286. What are security headers?
* HTTP response headers instructing browser client environments to activate defense mechanisms (`X-Content-Type-Options: nosniff`, `Strict-Transport-Security`, `X-Frame-Options: DENY`).

---

### 13. Middleware

#### 287. What is middleware?
* Software component chained in the ASP.NET Core request pipeline to handle incoming HTTP requests and responses.

---

#### 288. Explain the middleware pipeline.
* A bi-directional chain of components (`RequestDelegate`). Requests enter top-down through each middleware step to the endpoint, and responses flow back bottom-up through the chain.

---

#### 289. What is the difference between Use, Run, and Map?
* **`app.Use()`:** Executes logic and calls `next()` to pass control down the pipeline.
* **`app.Run()`:** Terminal middleware. Processes response and short-circuits pipeline (does not call `next()`).
* **`app.Map()`:** Branches the pipeline path based on target HTTP URL path matching.

---

#### 290. How do you create custom middleware?
* **Code Example:**
```csharp
public class HeaderCheckMiddleware
{
    private readonly RequestDelegate _next;
    public HeaderCheckMiddleware(RequestDelegate next) => _next = next;

    public async Task InvokeAsync(HttpContext context)
    {
        if (!context.Request.Headers.ContainsKey("X-Custom-Header"))
        {
            context.Response.StatusCode = 400;
            await context.Response.WriteAsync("Missing custom header");
            return; // Short circuit pipeline
        }
        await _next(context); // Pass to next
    }
}
```

---

#### 291. Where should exception-handling middleware be placed?
* **At the very beginning of the pipeline** (`app.UseExceptionHandler()`), so it can capture unhandled exceptions thrown by any downstream middleware or controllers.

---

#### 292. Where should authentication middleware be placed?
* **After Routing (`UseRouting`) and before Authorization (`UseAuthorization`)**.

---

#### 293. Where should authorization middleware be placed?
* **After Authentication (`UseAuthentication`)**. Must verify who the user is before evaluating permissions.

---

#### 294. What happens if middleware calls next()?
* Processing control passes forward to the next registered middleware in the request pipeline chain.

---

#### 295. What happens if middleware doesn't call next()?
* Pipeline is **short-circuited**. Downstream middleware and API Controllers are bypassed completely, and execution immediately reverses back up the pipeline chain.

---

#### 296. Can middleware have dependencies?
* **Yes.** Singleton dependencies can be injected via constructor. Scoped dependencies **must** be passed as parameters directly in `InvokeAsync(HttpContext context, IScopedService service)`.

---

#### 297. Middleware vs Action Filter?
* **Middleware:** Operates globally on raw HTTP requests before MVC controller matching occurs.
* **Action Filter:** Operates inside MVC pipeline context with direct access to action execution arguments, model states, and controller metadata.

---

#### 298. Middleware vs Endpoint Filter?
* **Middleware:** Applied broadly across global application request pipeline paths.
* **Endpoint Filter:** Targeted filter operating strictly around specific Minimal API endpoint handlers.

---

#### 299. How would you implement request logging middleware?
* **Code Example:**
```csharp
public class RequestLoggingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<RequestLoggingMiddleware> _logger;

    public RequestLoggingMiddleware(RequestDelegate next, ILogger<RequestLoggingMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        _logger.LogInformation("HTTP {Method} {Path}", context.Request.Method, context.Request.Path);
        await _next(context);
        _logger.LogInformation("HTTP Response {StatusCode}", context.Response.StatusCode);
    }
}
```

---

#### 300. How would you implement global exception middleware?
* **Code Example:**
```csharp
public class GlobalExceptionMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<GlobalExceptionMiddleware> _logger;

    public GlobalExceptionMiddleware(RequestDelegate next, ILogger<GlobalExceptionMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        try { await _next(context); }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Unhandled Exception");
            context.Response.StatusCode = 500;
            context.Response.ContentType = "application/json";
            await context.Response.WriteAsJsonAsync(new { Error = "Server Error" });
        }
    }
}
```

### 14. API Design

#### 301. How should REST API URLs be designed?
* Use clean, lowercase, hyphen-separated plural nouns representing domain resources (e.g., `/api/v1/purchase-orders/42`). Avoid verbs in URI paths.

---

#### 302. Why should nouns generally be used instead of verbs in REST URLs?
* REST models URIs as **resources**, while HTTP verbs (`GET`, `POST`, `PUT`, `DELETE`) define actions performed on those resources. Avoid verb URLs like `/api/getOrders`.

---

#### 303. What is API versioning?
* Practice of managing breaking changes in API contracts by maintaining multiple active versions (e.g., `/v1/users`, `/v2/users`) concurrently.

---

#### 304. Why is API versioning required?
* Prevents breaking existing client applications when adding mandatory fields, changing schema models, or altering business behavior in newer releases.

---

#### 305. URL Versioning vs Header Versioning?
* **URL Versioning:** `/api/v1/products`. Explicit, simple, easily cacheable in CDNs.
* **Header Versioning:** `X-API-Version: 1.0`. Clean URLs, but harder to test directly in standard web browsers.

---

#### 306. What is backward compatibility?
* Designing API updates such that older clients continue functioning smoothly without code modifications (e.g., adding optional parameters).

---

#### 307. What is breaking change?
* An API update that alters contract behavior or payload requirements in a way that breaks existing client integrations (e.g., renaming fields, removing endpoints, adding mandatory headers).

---

#### 308. How do you design pagination?
* Pass page parameters in query string parameters (`pageNumber`, `pageSize`) and return metadata envelope properties (`pageNumber`, `pageSize`, `totalPages`, `totalCount`, `data`).

---

#### 309. What are offset and cursor pagination?
* **Offset:** Skips N records using SQL `OFFSET x FETCH y`. Simple, but slow for huge table sizes ($O(N)$ execution cost).
* **Cursor:** Uses unique pointer index sorting (`WHERE Id > lastSeenId LIMIT 20`). Extremely fast and consistent for real-time data feeds.

---

#### 310. Offset Pagination vs Cursor Pagination?
| Metric | Offset Pagination | Cursor Pagination |
|---|---|---|
| Large Dataset Performance | Poor (Slow SQL skips) | Excellent ($O(1)$ index lookups) |
| Random Page Navigation | Easy (Jump to Page 10) | Difficult (Sequential only) |
| Data Drift (New items inserted) | May result in duplicate results | Completely immune |

---

#### 311. How do you implement filtering?
* Pass query parameters representing target properties (e.g., `/api/products?category=tech&minPrice=100`).

---

#### 312. How do you implement sorting?
* Pass a `sortBy` query parameter supporting direction indicators (e.g., `/api/products?sortBy=price_desc`).

---

#### 313. How do you implement searching?
* Pass search term query parameters (e.g., `/api/products?searchTerm=wireless`) applied via string match predicates (`Contains`, `EF.Functions.Like`).

---

#### 314. How do you implement pagination + filtering + sorting together?
* Consolidate input parameters inside a reusable query request DTO evaluated dynamically on EF Core `IQueryable`.
* **Code Example:**
```csharp
public record QueryParameters(string? SearchTerm, string? SortBy, int Page = 1, int PageSize = 10);
```

---

#### 315. What is HATEOAS?
* Hypermedia As The Engine Of Application State — REST principle (Richardson Level 3) where API responses include dynamic hypermedia links informing clients of allowable next operations.

---

#### 316. What is API discoverability?
* Extent to which an API self-documents its capabilities through OpenAPI/Swagger schemas or hypermedia links without external documentation.

---

#### 317. What is an idempotency key?
* A unique header value (`Idempotency-Key: <UUID>`) attached by clients to POST requests, allowing servers to detect duplicate network requests and prevent duplicate execution.

---

#### 318. When would you use an idempotency key?
* Critical financial transactions, payment processing endpoints, or order placement operations to prevent accidental duplicate charges.

---

#### 319. What is request/response contract?
* Formally defined JSON schema agreement specifying mandatory fields, types, and error formats exchanged between API clients and backend services.

---

#### 320. What is backward-compatible API evolution?
* Evolving API capabilities safely over time by preferring non-breaking additive updates (adding optional properties, preserving existing routes) over breaking changes.

---

### 15. DTOs & Mapping

#### 321. What is DTO?
* Data Transfer Object — plain object designed strictly to carry data across boundaries without containing business behavior.

---

#### 322. Why shouldn't EF entities be directly returned from APIs?
* Exposes database schema details directly to clients.
* Leads to cyclic JSON serialization crashes with relational navigation properties.
* Exposes APIs to mass-assignment security vulnerabilities.

---

#### 323. Entity vs DTO?
* **Entity:** Database persistence object containing identity key and database mappings.
* **DTO:** API interface contract payload object optimized for network data transfer.

---

#### 324. Request DTO vs Response DTO?
* **Request DTO:** Input payload model sent by clients containing creation/update validation rules.
* **Response DTO:** Output payload model sent by servers optimized for client display.

---

#### 325. What is AutoMapper?
* Mapping library copying property values between objects automatically based on property name match conventions.

---

#### 326. AutoMapper vs Manual Mapping?
* **AutoMapper:** Reduces boilerplate code, but hides mapping behavior and can cause subtle runtime bugs or hidden query performance hits.
* **Manual Mapping / Mapster / Source Generators:** Fast, fully explicit, compile-time verifiable, and simple to debug.

---

#### 327. What problems can AutoMapper cause?
* Hidden $O(N)$ execution memory bugs when mapping EF Core entities without `ProjectTo<T>()`.
* Complex configuration mapping rules become difficult to maintain and debug.

---

#### 328. How do you prevent sensitive properties from being returned?
* Omit sensitive database properties (e.g., `PasswordHash`, `SecurityStamp`) entirely from Response DTO models.

---

#### 329. How do you handle nested DTOs?
* Map nested entity relationships to corresponding nested DTO models cleanly within projection expressions.

---

#### 330. How do you map collections?
* Use LINQ projection `.Select(x => new Dto { ... })` or register mapped list configurations (`Mapper.Map<List<ProductDto>>(entities)`).

---

### 16. Validation

#### 331. What is data validation?
* Process verifying that incoming request payload fields conform to target types, non-null rules, field lengths, and acceptable domain boundaries.

---

#### 332. What is Data Annotation validation?
* Attribute-based validation attached directly onto C# class properties (`[Required]`, `[EmailAddress]`, `[StringLength(50)]`).

---

#### 333. What is FluentValidation?
* External .NET library defining validation rules completely isolated from model classes using clean, strongly-typed fluent builder syntax.

---

#### 334. FluentValidation vs Data Annotations?
* **Data Annotations:** Simple, but pollutes DTO models and lacks support for complex conditional validation rules.
* **FluentValidation:** Highly customizable, supports complex conditional logic, easy to unit test, keeps DTOs completely clean.
* **Code Example:**
```csharp
public class CreateProductDtoValidator : AbstractValidator<CreateProductDto>
{
    public CreateProductDtoValidator()
    {
        RuleFor(x => x.Name).NotEmpty().MaximumLength(100);
        RuleFor(x => x.Price).GreaterThan(0);
    }
}
```

---

#### 335. How does [ApiController] handle validation?
* Automatically intercepts incoming model validation state checks (`ModelState.IsValid`). If validation fails, it short-circuits execution and returns an HTTP 400 `ProblemDetails` response immediately.

---

#### 336. How do you return validation errors?
* Return HTTP 400 Bad Request containing a formatted dictionary mapping property names to validation failure details.

---

#### 337. What is custom validation?
* Writing dedicated domain-specific validation logic (e.g., verifying if a promo code is active against a database).

---

#### 338. What is business validation?
* Validation enforcing complex domain rules (e.g., "User cannot transfer funds exceeding daily limits").

---

#### 339. Data Validation vs Business Validation?
* **Data Validation:** Structural verification checks (e.g., Is Email formatted correctly? Is Price > 0?).
* **Business Validation:** State-dependent domain rule checks (e.g., Does user have sufficient wallet balance?).

---

#### 340. How would you validate a complex nested request?
* Use `FluentValidation` to bind child validators cleanly to child collections using `RuleFor(x => x.Items).SetValidator(new ItemValidator())`.

---

### 17. Logging & Monitoring

#### 341. What is logging?
* Process of recording application execution context, events, operational metrics, and error stack traces for operational monitoring and debugging.

---

#### 342. What is ILogger<T>?
* The built-in .NET logging abstraction interface injected into classes to output categorized, structured log messages.

---

#### 343. Log levels in .NET?
* `Trace` -> `Debug` -> `Information` -> `Warning` -> `Error` -> `Critical` -> `None`.

---

#### 344. Trace vs Debug vs Information vs Warning vs Error vs Critical?
* **Trace:** Extremely detailed internal diagnostics.
* **Debug:** Development debugging context.
* **Information:** General application flow milestones.
* **Warning:** Non-fatal abnormal system conditions.
* **Error:** System exceptions impacting specific operations.
* **Critical:** Application crashes requiring immediate emergency attention.

---

#### 345. Why should structured logging be used?
* Emits logs as queryable JSON property structures rather than plain text strings, enabling fast filtering across log aggregators (ElasticSearch, Seq, Datadog).
* **Code Example:**
```csharp
// Structured Logging Syntax
_logger.LogInformation("Order {OrderId} processed for amount {Amount}", order.Id, order.Amount);
```

---

#### 346. What information should never be logged?
* PII (Personally Identifiable Information), raw passwords, secret keys, credit card numbers, JWT tokens, and medical data.

---

#### 347. What is correlation ID?
* A unique UUID generated per HTTP request and attached to all log messages across microservice calls to trace a request end-to-end.

---

#### 348. Why is correlation ID useful?
* Allows developers to isolate and debug every distributed log trace associated with a single client request across multiple microservices.

---

#### 349. How do you trace one request across multiple services?
* Pass the generated correlation ID string in HTTP headers (`X-Correlation-ID`) across inter-service calls, logging it in every downstream service.

---

#### 350. What is health checking?
* Middleware endpoints (`/healthz`) exposing diagnostic status indicators verifying server and infrastructure readiness.

---

#### 351. What is a liveness check?
* Diagnostic probe verifying if the application process is running cleanly. Reboots container if unresponsive.

---

#### 352. What is a readiness check?
* Diagnostic probe verifying if the application is ready to accept user traffic (e.g., database and Redis caches are reachable).

---

#### 353. How do you implement health checks in ASP.NET Core?
* **Code Example:**
```csharp
builder.Services.AddHealthChecks()
    .AddSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")!);
app.MapHealthChecks("/healthz");
```

### 18. Testing

#### 354. What is unit testing?
* Process of testing individual isolation units of code (methods, services) in complete isolation by mocking external dependencies.

---

#### 355. What is integration testing?
* Testing multiple integrated components together (Web API, Middleware, Database, Cache) to verify system integration functionality.

---

#### 356. Unit Testing vs Integration Testing?
| Attribute | Unit Testing | Integration Testing |
|---|---|---|
| Execution Speed | Fast (Milliseconds) | Slower (Seconds) |

### 19. Advanced ASP.NET Core

#### 371. Explain the complete lifecycle of an HTTP request in ASP.NET Core.
1. Request arrives at Kestrel web server.
2. HttpContext is initialized.
3. Request enters Middleware Pipeline.
4. Endpoint Routing matches URI path to Endpoint.
5. Authentication/Authorization middlewares validate user tokens.
6. Execution enters Model Binding & Model Validation filters.
7. Action Method executes and calls business logic services.
8. Response Formatter serializes return model into HTTP response stream.
9. Pipeline unwinds back up through middlewares to client.

---

#### 372. Explain the ASP.NET Core middleware pipeline internally.
* Middeare items are linked function references (`Func<RequestDelegate, RequestDelegate>`). When built, they assemble into a nested recursive function chain executed asynchronously.

---

#### 373. How does dependency injection resolve services?
* Maintains internal lookup dictionaries mapping Service Types to Service Descriptors. When requested, the engine inspects constructors recursively, constructs dependency graphs, and caches scoped/singleton instances appropriately.

---

#### 374. What happens when a scoped service is injected into a singleton?
* Creates a **Captive Dependency bug**. The scoped service becomes permanently tied to the singleton lifetime and is never disposed, causing stale state and potential memory leaks across HTTP requests.

---

#### 375. What is a captive dependency?
* A service with a short lifetime (e.g., Scoped/Transient) incorrectly captured and kept alive inside a service with a longer lifetime (e.g., Singleton).

---

#### 376. How can captive dependencies cause problems?
* Causes concurrency race conditions (since Scoped DbContext is not thread-safe) and memory leaks from holding onto objects long past their intended request lifecycle.

---

#### 377. How does ASP.NET Core manage application lifetime?
* Managed using `IHostApplicationLifetime` exposing events: `ApplicationStarted`, `ApplicationStopping`, and `ApplicationStopped`.

---

#### 378. What are hosted services?
* Background tasks running long-running processes alongside the primary Web Application process lifecycle (`IHostedService`).

---

#### 379. What is BackgroundService?
* Base class implementing `IHostedService` providing an abstract `ExecuteAsync(CancellationToken)` method for background task processing.

---

#### 380. IHostedService vs BackgroundService?
* **`IHostedService`:** Raw interface requiring explicit management of `StartAsync` and `StopAsync` methods.
* **`BackgroundService`:** Convenience abstract class handling thread looping logic and clean cancellation tokens automatically.

---

#### 381. How would you implement a background job?
* Inherit from `BackgroundService`, implement `ExecuteAsync` containing process loops, and register as `AddHostedService<T>()`.
* **Code Example:**
```csharp
public class QueueProcessor : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            // Process queue messages
            await Task.Delay(5000, stoppingToken);
        }
    }
}
```

---

#### 382. How do you gracefully shut down an ASP.NET Core application?
* Host signals application stopping state, stops accepting incoming HTTP requests, allows active inflight requests to complete within a configured timeout window, and triggers background task cancellation tokens.

---

#### 383. What happens to active requests during shutdown?
* Server waits for active HTTP requests to complete within `HostOptions.ShutdownTimeout` window before closing worker threads.

---

#### 384. What is endpoint routing?
* Routing architecture splitting URL matching away from action execution, allowing middlewares to inspect target endpoint metadata early in the request pipeline.

---

#### 385. How does endpoint routing work internally?
* Matches request paths using high-performance prefix-tree matching algorithms, attaching target `Endpoint` metadata objects directly to `HttpContext`.

---

#### 386. What are endpoint filters?
* Interceptors attached directly onto individual Minimal API endpoints to run code before or after action execution.

---

#### 387. Endpoint Filters vs Middleware vs Action Filters?
* **Middleware:** Runs globally across the raw HTTP pipeline.
* **Action Filters:** Dedicated interceptors for MVC Controller actions.
* **Endpoint Filters:** Lightweight interceptors specifically designed for Minimal APIs.

---

#### 388. What is minimal API?
* Feature introduced in .NET 6 enabling lightweight REST API construction directly in `Program.cs` with minimal ceremony and high performance.

---

#### 389. Minimal API vs Controller-based API?
* **Minimal API:** Zero boilerplate setup, lower memory consumption, faster execution startup times. Excellent for microservices.
* **Controller API:** Highly structured, convention-based, traditional enterprise setup for large applications.

---

#### 390. When would you choose Minimal APIs?
* Building lightweight microservices, high-performance edge endpoints, serverless functions, or small API tools.

### 20. Advanced EF Core

#### 391. Explain EF Core change tracking internally.
* Maintain internal `EntityEntry` objects mapping tracked entity instances to states (`Unchanged`, `Added`, `Modified`, `Deleted`). Tracks original vs current values.

---

#### 392. What is the difference between tracked and untracked queries?
* **Tracked:** Standard EF Core queries. Saves object references in memory to detect modifications.
* **Untracked (`AsNoTracking`):** Read-only queries. Skips tracking overhead completely, freeing memory.

---

#### 393. How does EF Core detect entity changes?
* Uses Snapshot Change Tracking by default, comparing current property values against original snapshots captured when loaded.

---

#### 394. What is identity resolution?
* Ensures that multiple references to the same database row within a single `DbContext` instance resolve to the exact same C# object instance in memory.

---

#### 395. What is AsNoTrackingWithIdentityResolution()?
* Performs untracked read-only queries while maintaining identity resolution across duplicate child entities in query results.

---

#### 396. What is query projection?
* Using LINQ `.Select()` to map entity data directly into DTO shapes inside the database SQL generation layer.

---

#### 397. Why is projection better than loading complete entities?
* Generates SQL selecting **only** required columns instead of all table columns (`SELECT Name FROM Users` vs `SELECT * FROM Users`). Saves database I/O, network bandwidth, and memory.

---

#### 398. How can you optimize EF Core queries?
* Use `AsNoTracking()` for read queries.
* Project directly to DTOs via `Select()`.
* Avoid N+1 query patterns using `Include()`.
* Use Split Queries (`AsSplitQuery()`) for heavy nested includes.
* Add database indexes on search columns.

---

#### 399. What is compiled query?
* Pre-compiles LINQ expressions into raw SQL execution delegates (`EF.CompileAsyncQuery`), bypassing LINQ parsing overhead for hot execution paths.

---

#### 400. What is split query?
* Splitting complex entity join queries into multiple single relational SQL queries (`.AsSplitQuery()`) to avoid Cartesian product duplication explosion.

---

#### 401. Single Query vs Split Query?
* **Single Query:** Executes a single massive JOIN SQL query. Can cause Cartesian data explosion performance hits.
* **Split Query:** Executes multiple clean SQL queries per included collection. Eliminates data duplication, but requires multiple network database roundtrips.

---

#### 402. How can Include() cause performance problems?
* Including multiple 1-to-many collections generates massive cross-product joins, returning redundant duplicate row data over the network.

---

#### 403. What is Cartesian explosion?
* Exponential growth of duplicate dataset row counts caused by joining multiple 1-to-many navigation properties in a single SQL query.

---

#### 404. How can you prevent Cartesian explosion?
* Use `.AsSplitQuery()` or perform explicit projection using `.Select()`.

---

#### 405. What is optimistic concurrency in EF Core?
* Mechanism detecting concurrent update conflicts using concurrency tokens (`[Timestamp]` byte array `xmin` or `Version`).

---

#### 406. How do you handle concurrency conflicts?
* Catch `DbUpdateConcurrencyException`, resolve conflicts by reloading latest values from database, and retry update.
* **Code Example:**
```csharp
try { await _context.SaveChangesAsync(); }
catch (DbUpdateConcurrencyException ex)
{
    var entry = ex.Entries.Single();
    entry.OriginalValues.SetValues(await entry.GetDatabaseValuesAsync());
}
```

---

#### 407. How do you implement soft delete?
* Add an `IsDeleted` property on entities and enforce a Global Query Filter in `OnModelCreating`.
* **Code Example:**
```csharp
builder.Entity<User>().HasQueryFilter(u => !u.IsDeleted);
```

---

#### 408. What are global query filters?
* LINQ query predicates applied automatically to all database queries executed for a target entity type across the entire `DbContext`.

---

#### 409. What are interceptors in EF Core?
* Components (`SaveChangesInterceptor`, `DbCommandInterceptor`) allowing custom code execution before/after EF Core executes commands or commits changes.

---

#### 410. How do you audit database changes using EF Core?
* Intercept `SaveChangesAsync()`, iterate through `ChangeTracker.Entries()`, and log entity modifications to an `AuditLogs` table.

---

#### 411. How do you execute raw SQL safely?
* Use parameterized raw SQL methods (`FromSqlInterpolated` or `FromSqlRaw` with explicit `SqlParameter` objects) to prevent SQL injection.

---

#### 412. What is ExecuteUpdate()?
* EF Core 7+ bulk operation updating target database rows directly on the database server without loading entities into memory or change tracking.
* **Code Example:**
```csharp
await _context.Products
    .Where(p => p.CategoryId == 1)
    .ExecuteUpdateAsync(s => s.SetProperty(p => p.Price, p => p.Price * 1.10m));
```

---

#### 413. What is ExecuteDelete()?
* EF Core 7+ bulk operation deleting target database rows directly on the server without loading entities into tracking memory.

---

#### 414. How do bulk operations affect change tracking?
* `ExecuteUpdate()` and `ExecuteDelete()` bypass the Change Tracker completely. Tracked entity instances in memory do not update automatically.

---

#### 415. How would you handle a transaction involving multiple repositories?
* Coordinate repository execution under a single shared `DbContext` instance, wrapped explicitly inside `_context.Database.BeginTransactionAsync()`.

### 21. Advanced REST API

#### 416. What makes an API truly RESTful?
* Complete compliance with REST constraints, resource-oriented URIs, proper HTTP verbs, statelessness, cacheability, and dynamic HATEOAS discovery mechanisms.

---

#### 417. Explain REST constraints.
* Uniform Interface, Client-Server, Statelessness, Cacheability, Layered System, and Code on Demand (optional).

---

#### 418. What is Richardson Maturity Model?
* A scale categorizing Web API compliance into 4 distinct levels of REST maturity (Level 0 through Level 3).

---

#### 419. Level 0 vs Level 1 vs Level 2 vs Level 3 REST?
* **Level 0:** Single URI and method (e.g., RPC/SOAP over HTTP POST).
* **Level 1:** Multiple distinct Resource URIs (`/api/orders`).
* **Level 2:** Resource URIs + Explicit HTTP Verbs & Status Codes (`GET`, `POST`, 201, 404).
* **Level 3:** Hypermedia Controls (HATEOAS dynamic discovery links).

---

#### 420. What is resource-oriented API design?
* Designing API endpoints around core business entity resources (e.g., `/users`, `/orders`) rather than functional remote operations (`/getUsers`, `/processOrder`).

---

#### 421. How do you design nested resources?
* Express hierarchical parent-child relationships cleanly in URLs (e.g., `/api/v1/authors/10/books/4`).

---

#### 422. When should nested resources be avoided?
* Avoid deep nesting exceeding 2 levels (e.g., `/authors/1/books/2/chapters/3/paragraphs/4`). Use direct top-level resource endpoints instead (`/api/v1/chapters/3`).

---

#### 423. How do you design APIs for very large datasets?
* Enforce mandatory pagination, require filter criteria, support asynchronous processing via long-running job IDs, and stream responses.

---

#### 424. How would you design a high-volume POST API?
* Accept payload, push event immediately to a message broker queue (RabbitMQ/Kafka), return `202 Accepted` with a tracking URL immediately, and process asynchronously via background workers.

---

#### 425. How would you make POST operations idempotent?
* Require clients to supply an `Idempotency-Key` HTTP header. Cache key execution results in Redis to detect duplicate submissions.

---

#### 426. How do you handle duplicate requests?
* Intercept incoming requests via middleware checking `Idempotency-Key` in distributed cache. If present, return cached response directly.

---

#### 427. How would you design an API supporting millions of users?
* Ensure complete statelessness, place reverse proxies (Nginx/Cloudflare) and API Gateways in front, implement distributed caching (Redis), scale horizontally across Kubernetes clusters, and utilize database read replicas.

---

#### 428. How do you prevent API abuse?
* Enforce IP and user-based Rate Limiting, enforce API Key/JWT authentication, deploy Web Application Firewalls (WAF), and enforce strict payload schema validation limits.

---

#### 429. How would you handle API backward compatibility?
* Never change or remove existing fields. Introduce optional properties for new features, and use explicit API versioning when introducing breaking structural updates.

---

#### 430. How do you safely deprecate an API version?
* Attach `Sunset` and `Deprecation` HTTP headers, log warning metrics for calling clients, notify client teams, and maintain deprecated routes for a planned sunset period before shutdown.

---

#### 431. What is optimistic concurrency at API level?
* Protecting resource update endpoints using `ETag` and `If-Match` headers to prevent concurrent modification lost updates.

---

#### 432. How would you prevent lost updates?
* Return an `ETag` hash header on resource reads (`GET`). Require clients to pass `If-Match: "etag-value"` on updates (`PUT`/`PATCH`). Fail request with `412 Precondition Failed` if modified concurrently.

---

#### 433. What are ETags?
* HTTP header entity tag representing a unique hash snapshot of a resource version at a specific point in time.

---

#### 434. How do ETag and If-Match work?
* Client reads resource -> Server returns `ETag: "v1"`. Client updates resource passing `If-Match: "v1"`. Server checks if current resource version matches `"v1"`; if changed, update fails.

---

#### 435. How would you implement conditional requests?
* Evaluate `If-None-Match` on GET calls. Return `304 Not Modified` without payload body if content has not changed since last request.

---

#### 436. What is HTTP caching?
* Storing API response payloads in browser or CDN caches based on `Cache-Control` headers to speed up subsequent requests.

---

#### 437. Cache-Control vs ETag?
* **`Cache-Control`:** Defines duration and validity of client payload caching (`max-age=3600`).
* **`ETag`:** Validation identifier used to check with server if cached payload content remains up-to-date.

---

#### 438. What is cache invalidation?
* Process of purging or updating cached data when underlying source data modifies.

---

#### 439. What is content negotiation?
* Client requests specific content format using `Accept` header (`Accept: application/json` or `application/xml`); server responds in requested format.

---

#### 440. How would you support multiple response formats?
* Configure output formatters in ASP.NET Core: `builder.Services.AddControllers().AddXmlSerializerFormatters();`.

### 22. Advanced Authentication & Security

#### 441. Explain the complete JWT authentication flow.
1. Client POSTs credentials to `/login`.
2. Server validates credentials, queries user claims/roles, creates signed Access Token + Refresh Token.
3. Client stores Access Token, attaches header `Authorization: Bearer <token>` to requests.
4. `JwtBearerHandler` middleware intercepts request, validates signature key, issuer, audience, and expiration.
5. ClaimsPrincipal is created and attached to `HttpContext.User`.

---

#### 442. How does ASP.NET Core validate a JWT?
* Decodes header/payload, recalculates signature using secret key, checks current time against `nbf` and `exp` claims, validates `iss` and `aud`.

---

#### 443. What happens if the JWT signature is invalid?
* `JwtBearerHandler` fails validation, rejects the request, and returns an HTTP 401 Unauthorized response immediately.

---

#### 444. What happens if the JWT is expired?
* Validation fails on `exp` check, returning an HTTP 401 Unauthorized response (with `WWW-Authenticate` header indicating token expiration).

---

#### 445. How do you implement refresh-token rotation?
* Every time a Refresh Token is used to generate a new Access Token, invalidate the old Refresh Token immediately and issue a brand-new Refresh Token pair.

---

#### 446. How do you detect refresh-token reuse?
* Store token lineage chains. If an already invalidated/revoked Refresh Token is presented, assume a compromise, revoke the entire token family, and force the user to log in again.

---

#### 447. How do you revoke refresh tokens?
* Set `IsRevoked = true` or delete the token record in the database/Redis cache.

---

#### 448. How would you secure JWT against token theft?
* Shorten access token expiration (e.g., 5-15 mins), enforce HTTPS everywhere, store tokens in `HttpOnly` `SameSite` cookies, and implement IP/User-Agent verification.

---

#### 449. Where should refresh tokens be stored?
* Server side: Encrypted in database/Redis.
* Client side: In secure `HttpOnly`, `Secure`, `SameSite=Strict` HTTP cookies.

---

#### 450. What is token rotation?
* Generating fresh token credentials upon every use and revoking old credentials immediately, reducing token theft misuse windows.

---

#### 451. What is OAuth 2.0 Authorization Code Flow?
* Standard secure authorization workflow where public applications redirect users to an authorization server, receive a temporary single-use code, and exchange code for tokens over a secure backchannel.

---

#### 452. What is PKCE?
* Proof Key for Code Exchange — extension to OAuth 2.0 preventing code interception attacks on public or mobile client applications.

---

#### 453. Why is PKCE important?
* Eliminates need for client secrets on native/mobile/SPA clients by dynamic cryptographic key pairing (`code_verifier` and `code_challenge`).

---

#### 454. OAuth 2.0 vs OpenID Connect?
* **OAuth 2.0:** Framework for **Authorization** (Access tokens for API resources).
* **OpenID Connect:** Layer on top of OAuth 2.0 for **Authentication** (ID tokens containing identity assertions).

---

#### 455. What is IdentityServer / OpenIddict used for?
* Open-source frameworks used to turn ASP.NET Core applications into compliant OAuth 2.0 / OpenID Connect Identity Providers (IdP).

---

#### 456. Authentication vs Authorization at middleware level?
* **Authentication Middleware (`UseAuthentication`):** Identifies caller and constructs `ClaimsPrincipal`.
* **Authorization Middleware (`UseAuthorization`):** Evaluates permissions against `ClaimsPrincipal` to grant or deny access.

---

#### 457. Policy-Based Authorization vs Role-Based Authorization?
* **Role-Based:** Rigid static checks (`[Authorize(Roles="Admin")]`).
* **Policy-Based:** Flexible requirements-driven logic evaluating multiple rules, claims, dynamic business logic (`[Authorize(Policy="CanModifyOrder")]`).

---

#### 458. How do custom authorization handlers work?
* Inherit from `AuthorizationHandler<TRequirement>`, evaluate `context.User` claims or resource conditions, and call `context.Succeed(requirement)` if valid.

---

#### 459. How would you implement permission-based authorization?
* Assign explicit permission strings (e.g., `orders.read`, `orders.delete`) to roles/users. Build dynamic Authorization Requirements matching permission claims.

---

#### 460. How would you secure service-to-service communication?
* Use OAuth 2.0 Client Credentials Grant Flow, mTLS (Mutual TLS) certificate verification, or internal network VPC mesh policies.

---

### 23. Performance & Scalability

#### 461. How do you improve ASP.NET Core API performance?
* Use `AsNoTracking()` on read queries.
* Implement Caching (Redis).
* Use Async/Await throughout the stack.
* Enable Response Compression.
* Utilize DTO query projections.
* Prevent N+1 queries.

---

#### 462. How do you identify a slow endpoint?
* Monitor request duration metrics using APM tools (Application Insights, Datadog, Prometheus/Grafana) and inspect distributed traces.

---

#### 463. What causes high API latency?
* Unoptimized slow database queries, missing database indexes, blocking synchronous calls (`.Result`), network bottlenecks, or unmanaged external API dependencies.

---

#### 464. How do you reduce database round trips?
* Batch multiple operations in single transactions, execute projection queries, use bulk EF Core operations (`ExecuteUpdate`), or utilize Redis caches.

---

#### 465. What is response caching?
* Caching entire HTTP responses using `[ResponseCache]` attributes, serving responses directly from server or proxy memory without re-executing action logic.

---

#### 466. What is distributed caching?
* External centralized cache store (e.g., Redis) shared across all instances of a horizontally scaled web application farm.

---

#### 467. In-Memory Cache vs Distributed Cache?
* **In-Memory:** Extremely fast local process memory cache. Not shared across instances; lost when application restarts.
* **Distributed Cache:** External network store (Redis). Shared across all server instances; persists through individual web app restarts.

---

#### 468. What is Redis?
* Ultra-fast in-memory key-value data structure store heavily used as a distributed cache, pub/sub broker, and session store.

---

#### 469. When should Redis be used?
* Caching frequently accessed read data, managing user session state, distributed rate limiting, or cross-service pub/sub event broadcasting.

---

#### 470. What is cache-aside pattern?
1. App reads request from Cache.
2. If Cache Hit -> return data immediately.
3. If Cache Miss -> query Database, write fetched data into Cache, return data.

---

#### 471. What is cache stampede?
* High-concurrency failure where cache expiration causes thousands of simultaneous incoming requests to miss the cache at once, overloading the database server.

---

#### 472. How do you prevent cache stampede?
* Implement distributed locking, or use mutex mechanisms like `LazyCache` or `FusionCache` to serialize cache repopulation logic.

---

#### 473. What is connection pooling?
* Maintenance of a reusable pool of warm database connection instances, avoiding the high latency overhead of opening and closing physical network connections repeatedly.

---

#### 474. How does database connection pooling work?
* Framework reuses existing open pool connections when `.Open()` is requested, returning connection references back to the warm pool upon `.Close()` or `.Dispose()`.

---

#### 475. What is horizontal scaling?
* Adding more server instances/nodes to distribute network traffic load (Scaling Out).

---

#### 476. What is vertical scaling?
* Adding more CPU, RAM, or SSD resources to an existing single server node (Scaling Up).

---

#### 477. Horizontal vs Vertical Scaling?
* **Vertical:** Simple, but constrained by hardware limits and expensive. Represents single point of failure.
* **Horizontal:** Infinite expansion potential, high availability, highly cost-efficient; requires stateless architecture.

---

#### 478. How does load balancing work?
* Load balancers (Nginx, AWS ALB) distribute incoming network traffic across multiple backend application instances using routing algorithms (Round Robin, Least Connections).

---

#### 479. What is stateless architecture?
* Server instances preserve zero client state locally in process memory between HTTP requests, treating every incoming request identically.

---

#### 480. Why are stateless APIs easier to scale?
* Any arbitrary server instance behind a load balancer can handle any client request seamlessly without needing sticky sessions or synchronized memory state.

---

#### 481. What is a reverse proxy?
* Intermediate server (Nginx, YARP, HAProxy) placed in front of backend servers to handle SSL termination, load balancing, compression, and request routing.

---

#### 482. What is a CDN?
* Content Delivery Network — globally distributed network of edge proxy servers caching static files and API responses physically close to end users.

---

#### 483. How can a CDN improve API performance?
* Offloads static and cacheable GET response traffic away from primary backend origin servers, reducing response latency worldwide.

---

#### 484. What is asynchronous I/O?
* Non-blocking network and disk execution model releasing worker threads while waiting for external hardware responses.

---

#### 485. Why can async I/O improve scalability?
* Frees thread pool threads from idling during disk/network wait times, enabling a server to handle thousands of concurrent incoming requests with minimal threads.

---

### 24. Distributed Systems & Microservices

#### 486. What is a monolith?
* Architecture style building an entire software application as a single unified deployable unit.

---

#### 487. What is a microservice?
* Architecture style decomposing an application into small, loosely coupled, independently deployable services organized around specific business capabilities.

---

#### 488. Monolith vs Microservices?
* **Monolith:** Simple to build, test, and deploy initially. Hard to scale independently and maintain as codebases grow huge.
* **Microservices:** Independently deployable and scalable. Introduces significant network complexity, operational overhead, and data consistency challenges.

---

#### 489. What are the disadvantages of microservices?
* Distributed system complexity, network latency overhead, complex data consistency management, difficult debugging, and high infrastructure orchestration costs.

---

#### 490. What is service-to-service communication?
* Mechanisms used by microservices to exchange data with each other:
  * **Synchronous:** REST, gRPC.
  * **Asynchronous:** Message Queues (RabbitMQ, Kafka).

---

#### 491. REST vs gRPC?
* **REST:** HTTP/1.1, JSON payload. Human-readable, universal web compatibility, but slower/larger payload footprint.
* **gRPC:** HTTP/2, Protobuf binary payload. Ultra-fast, strongly-typed, low bandwidth; ideal for internal inter-service calls.

---

#### 492. When would you choose gRPC over REST?
* High-performance internal service-to-service communication, real-time streaming, low latency microservice meshes.

---

#### 493. What is message-based communication?
* Asynchronous inter-service communication model where services communicate by publishing events/messages through an intermediate broker.

---

#### 494. What is a message broker?
* Middleware infrastructure platform (RabbitMQ, Apache Kafka, Service Bus) routing and persisting messages between producers and consumers.

---

#### 495. RabbitMQ vs Kafka?
* **RabbitMQ:** Traditional smart broker / dumb consumer message queue. Outstanding for complex routing patterns and individual message tasks.
* **Kafka:** High-throughput append-only distributed event stream platform. Outstanding for log streaming, replayability, and massive event processing.

---

#### 496. What is event-driven architecture?
* System design paradigm where decoupled services react asynchronously to state change domain events published across the system.

---

#### 497. What is eventual consistency?
* Consistency model in distributed systems where data replicas across decoupled databases become consistent over time rather than instantaneously.

---

#### 498. What is a distributed transaction?
* A single logical transaction spanning across multiple independent databases or microservices.

---

#### 499. Why are distributed transactions difficult?
* Traditional 2-Phase Commit (2PC) locks network resources across independent systems, introducing severe latency, coupling, and single points of failure.

---

#### 500. What is the Saga Pattern?
* Architectural pattern managing distributed transactions through a sequence of local transactions per service. If a step fails, executing compensating transactions roll back previous state changes sequentially.

---

#### 501. What is the Outbox Pattern?
* Architectural pattern guaranteeing reliable event publishing by atomically saving events to a local database `Outbox` table within the same business transaction, before an asynchronous worker publishes them to a message broker.

---

#### 502. What is CQRS?
* Command Query Responsibility Segregation — pattern separating state mutation operations (**Commands**) from data read queries (**Queries**) into distinct models and data stores.

---

#### 503. CQRS advantages and disadvantages?
* **Advantages:** Independent scaling of reads vs writes, optimized query projections, cleaner domain models.
* **Disadvantages:** Increased code complexity, potential eventual consistency delays.

---

#### 504. What is event sourcing?
* Pattern persisting application state as a sequence of immutable append-only state events over time, rather than storing just the current state record.

---

#### 505. What is service discovery?
* Mechanism (Consul, Eureka, Kubernetes DNS) allowing microservices to locate network IP addresses of dependent services dynamically.

---

#### 506. What is an API Gateway?
* Central entry point server (YARP, Ocelot, Kong) routing client requests to appropriate downstream microservices.

---

#### 507. What problems does an API Gateway solve?
* Centralizes cross-cutting concerns: Request Routing, Authentication, Rate Limiting, SSL Termination, CORS policies, and Protocol Translation.

---

#### 508. What is circuit breaker pattern?
* Design pattern preventing continuous failure cascades by intercepting calls to an unstable downstream service, tripping open, and returning immediate fallback errors until the target service recovers.

---

#### 509. What is retry pattern?
* Automatically re-executing failed operations under the assumption that the underlying failure is caused by a transient network blip.

---

#### 510. Why can retries make a system worse?
* Retrying failing calls repeatedly against an already overloaded downstream service creates a retry storm, driving the system into complete collapse.

---

#### 511. What is exponential backoff?
* Retry strategy progressively increasing delay intervals between retries (e.g., 1s -> 2s -> 4s -> 8s) with added random jitter to prevent request collisions.

---

#### 512. What is timeout pattern?
* Setting strict upper duration limits on calls to external dependencies to prevent resource exhaustion from hanging network calls.

---

#### 513. What is bulkhead pattern?
* Isolating system resource pools (e.g., thread pools, connection limits) per service client so that a failure in one service does not consume all system resources and bring down the entire application.

---

#### 514. What is resilience?
* The capability of an application framework to gracefully withstand, recover from, and self-heal during infrastructure or dependency failures.

---

#### 515. What is Polly used for in .NET?
* Popular .NET resilience and transient-fault-handling library providing policy implementations for Retries, Circuit Breakers, Timeouts, Rate Limiters, and Fallbacks.
* **Code Example:**
```csharp
var retryPolicy = Policy
    .Handle<HttpRequestException>()
    .WaitAndRetryAsync(3, retryAttempt => TimeSpan.FromSeconds(Math.Pow(2, retryAttempt)));
```

### 25. Advanced C# / .NET

#### 516. What is garbage collection?
* Automatic memory management feature in CLR that tracks, allocates, and reclaims memory allocated to objects no longer referenced by the application.

---

#### 517. Explain .NET GC generations.
* GC optimizes performance by categorizing heap objects into 3 generational tiers based on their survival age:
  * **Gen 0:** Short-lived temporary objects (e.g., local method variables). Frequently collected.
  * **Gen 1:** Medium-lived buffer generation between short and long-lived objects.
  * **Gen 2:** Long-lived objects (e.g., static data, singletons). Collected infrequently.

---

#### 518. What are Gen 0, Gen 1, and Gen 2?
* **Gen 0:** Fast, highly frequent allocations/collections.
* **Gen 1:** Short-lived objects surviving Gen 0 collection promoted here.
* **Gen 2:** Long-lived objects surviving Gen 1 collections. Expensive to collect.

---

#### 519. What is the Large Object Heap (LOH)?
* Separate heap segment reserved exclusively for allocations $\ge$ 85,000 bytes. Collected during Gen 2 GC sweeps to avoid moving large memory blocks.

---

#### 520. What causes memory leaks in .NET?
* Static references keeping objects alive indefinitely, unubscribed C# events, lingering captive dependencies, and failing to dispose unmanaged resources.

---

#### 521. How do you diagnose memory leaks?
* Analyze memory dumps using `dotnet-dump`, `dotMemory`, Visual Studio Memory Profiler, or PerfView to identify rooted object reference paths.

---

#### 522. What is IDisposable?
* Interface defining a deterministic `Dispose()` method used to release unmanaged resources (file handles, sockets, DB connections) manually.

---

#### 523. What is the using statement?
* Syntactic sugar ensuring `Dispose()` is invoked reliably on an `IDisposable` object upon exiting scope, even if exceptions occur.
* **Code Example:**
```csharp
using var stream = new FileStream("file.txt", FileMode.Open);
// Stream automatically disposed when execution exits containing scope
```

---

#### 524. What is IAsyncDisposable?
* Interface defining `DisposeAsync()`, allowing asynchronous release of unmanaged resources without thread blocking.

---

#### 525. Dispose() vs Finalizer?
* **`Dispose()`:** Explicit, deterministic cleanup invoked manually by developer code or `using` blocks.
* **Finalizer (`~ClassName()`):** Implicit, non-deterministic cleanup executed asynchronously by the GC before object destruction.

---

#### 526. What is dependency disposal?
* Process where DI containers automatically invoke `Dispose()` on created `IDisposable` service dependencies when the matching DI scope ends.

---

#### 527. What is a delegate?
* Strongly-typed function pointer encapsulating references to methods matching a specific signature.

---

#### 528. What is an event?
* Encapsulated publisher-subscriber wrapper built over delegates enabling objects to broadcast notifications to subscribers when state changes.

---

#### 529. Delegate vs Event?
* **Delegate:** Naked function pointer variable. Invokable by any outside caller possessing reference to it.
* **Event:** Restricted delegate wrapper. Can only be invoked or triggered from within the declaring publisher class context.

---

#### 530. What are Func, Action, and Predicate?
* **`Action`:** Built-in delegate returning no value (`void`).
* **`Func<T, TResult>`:** Built-in delegate returning a value of type `TResult`.
* **`Predicate<T>`:** Special `Func<T, bool>` delegate taking type `T` and returning a `bool`.

---

#### 531. What are expression trees?
* Data structures representing executable C# code logic as expression node trees (`Expression<Func<T, bool>>`), allowing libraries like EF Core to parse C# logic directly into SQL strings.

---

#### 532. What are generics?
* C# feature enabling classes, interfaces, and methods to operate over placeholder type parameters (`<T>`) while maintaining compile-time type safety.

---

#### 533. Why are generics useful?
* Eliminates boxing/unboxing overhead, avoids repetitive casting, enforces compile-time type safety, and promotes clean code reuse.

---

#### 534. Generic Class vs Generic Method?
* **Generic Class:** Type parameter applied to entire class definition (`class Repository<T>`).
* **Generic Method:** Type parameter applied strictly to a specific method (`T Transform<T>(T input)`).

---

#### 535. What are covariance and contravariance?
* **Covariance (`out T`):** Allows using a more derived type than original generic specification (Preserves assignment compatibility).
* **Contravariance (`in T`):** Allows using a more generic (base) type parameter than originally specified.

---

#### 536. What is reflection?
* Runtime capability to inspect assembly metadata, discover types, extract attributes, and dynamically invoke methods or construct instances.

---

#### 537. What are attributes?
* Declarative metadata markers attached to classes, methods, or properties (`[HttpGet]`, `[Authorize]`) queried at runtime using reflection.

---

#### 538. What are source generators?
* C# compiler feature analyzing code during compilation to dynamically inject additional generated C# code files into the compilation pipeline, bypassing runtime reflection overhead.

---

#### 539. What is Span<T>?
* Stack-allocated, zero-allocation representation of contiguous memory regions (array slices, strings) providing ultra-fast memory manipulation.

---

#### 540. What is Memory<T>?
* Heap-compatible counterpart to `Span<T>` that can be passed across asynchronous `await` method boundaries safely.

---

#### 541. When should Span<T> be used?
* High-performance code paths, parsing string buffers, or processing memory data streams without allocating temporary heap objects.

---

#### 542. What is boxing performance overhead?
* Converting value types to reference types forces a heap memory allocation, memory copying, and later GC pressure, degrading application execution performance.

---

#### 543. What is JIT compilation?
* Just-In-Time compilation converting Intermediate Language (IL) bytecode into native machine instructions at application runtime.

---

#### 544. What is AOT compilation?
* Ahead-Of-Time compilation converting C# code directly into native platform machine instructions during the build process.

---

#### 545. JIT vs Native AOT?
* **JIT:** Higher startup latency, runtime memory footprint, but allows dynamic reflection and runtime code generation.
* **Native AOT:** Instant startup times, tiny memory footprint, zero JIT overhead; ideal for containers and serverless functions (restricts reflection usage).

```csharp
    }
}
```

#### 555. How would you upload a 1 GB file without exhausting server memory?
* Stream the file payload directly from `HttpRequest.Body` directly to disk/blob storage using `MultipartReader` without buffering the entire file into RAM memory.
* **Code Example:**
```csharp
[HttpPost("upload-stream")]
[DisableModelBinding]
public async Task<IActionResult> UploadStream()
{
    var boundary = HeaderUtilities.RemoveQuotes(MediaTypeHeaderValue.Parse(Request.ContentType).Boundary).Value;
    var reader = new MultipartReader(boundary!, Request.Body);
    var section = await reader.ReadNextSectionAsync();

    while (section != null)
    {
        if (ContentDispositionHeaderValue.TryParse(section.ContentDisposition, out var cd) && cd.DisposeType.Equals("form-data"))
        {
            using var targetStream = System.IO.File.Create("destination_path");
            await section.Body.CopyToAsync(targetStream); // Streaming directly!
        }
        section = await reader.ReadNextSectionAsync();
    }
    return Ok();
}
```
