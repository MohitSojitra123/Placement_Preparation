# 1. Create a CRUD Web API

**1.1 What is CRUD in a Web API?**
Create, Read, Update, Delete — the four basic data operations. In a Web API they map to HTTP methods: POST, GET, PUT/PATCH, DELETE. Example: a student portal needs to add, view, edit and remove students.

**1.2 How do you create a CRUD API in ASP.NET Core?**
1) Create an entity + DbContext. 2) Create a controller marked `[ApiController]`. 3) Add actions for GetAll, GetById, Add, Update, Delete. 4) Register DbContext in `Program.cs`. 5) Return correct status codes. (Full example in 1.17.)

**1.3 What are the HTTP methods used for CRUD operations?**
Create → `POST`, Read → `GET`, Update → `PUT` (full) / `PATCH` (partial), Delete → `DELETE`.

**1.4 What is the difference between GET, POST, PUT, and DELETE?**
| Method | Purpose | Body | Idempotent | Success code |
|---|---|---|---|---|
| GET | read | no | yes | 200 |
| POST | create | yes | no | 201 |
| PUT | replace/update | yes | yes | 204/200 |
| DELETE | remove | no | yes | 204 |

**1.5 How do you create a controller in ASP.NET Core?**
```csharp
[ApiController]
[Route("api/[controller]")]
public class StudentsController : ControllerBase
{
    private readonly AppDbContext _db;
    public StudentsController(AppDbContext db) => _db = db;
}
```

**1.6 How do you implement GetAll()?**
```csharp
[HttpGet]
public async Task<ActionResult<IEnumerable<Student>>> GetAll()
    => Ok(await _db.Students.AsNoTracking().ToListAsync());
```

**1.7 How do you implement GetById()?**
```csharp
[HttpGet("{id:int}")]
public async Task<ActionResult<Student>> GetById(int id)
{
    var s = await _db.Students.FindAsync(id);
    return s is null ? NotFound() : Ok(s);
}
```

**1.8 How do you implement Add()?**
```csharp
[HttpPost]
public async Task<ActionResult<Student>> Add(Student s)
{
    _db.Students.Add(s);
    await _db.SaveChangesAsync();
    return CreatedAtAction(nameof(GetById), new { id = s.Id }, s);
}
```

**1.9 How do you implement Update()?**
```csharp
[HttpPut("{id:int}")]
public async Task<IActionResult> Update(int id, Student s)
{
    if (id != s.Id) return BadRequest("Id mismatch");
    var existing = await _db.Students.FindAsync(id);
    if (existing is null) return NotFound();
    existing.Name = s.Name; existing.Course = s.Course;
    await _db.SaveChangesAsync();
    return NoContent();
}
```

**1.10 How do you implement Delete()?**
```csharp
[HttpDelete("{id:int}")]
public async Task<IActionResult> Delete(int id)
{
    var s = await _db.Students.FindAsync(id);
    if (s is null) return NotFound();
    _db.Students.Remove(s);
    await _db.SaveChangesAsync();
    return NoContent();
}
```

**1.11 How do you pass an ID through the route?**
Put it in the route template: `[HttpGet("{id}")]` → URL `GET /api/students/5`. The `id` parameter is filled by model binding. Add a constraint `{id:int}` so "abc" gives 404 instead of an error.

**1.12 What is [ApiController]?**
An attribute that turns on API-friendly behavior: automatic 400 for invalid models, automatic `[FromBody]` binding for complex types, ProblemDetails error format, and requires attribute routing.

**1.13 What is [Route("api/[controller]")]?**
Defines the base URL. `[controller]` is replaced by the class name without "Controller": `StudentsController` → `/api/students`.

**1.14 Difference between [HttpGet] and [HttpGet("{id}")]?**
`[HttpGet]` → `GET /api/students` (list). `[HttpGet("{id}")]` → `GET /api/students/5` (one item). Same HTTP verb, different URL template.

**1.15 How do you return a newly created record from a POST API?**
Use `CreatedAtAction` — returns status **201**, a `Location` header (`/api/students/7`) and the created object in the body.
```csharp
return CreatedAtAction(nameof(GetById), new { id = s.Id }, s);
```

**1.16 How would you handle a request when the requested ID does not exist?**
Return **404 Not Found** (optionally with a message).
```csharp
if (student is null) return NotFound(new { message = $"Student {id} not found" });
```

public class Student { public int Id { get; set; } [Required, StringLength(100)] public string Name { get; set; } = ""; [Required] public string Course { get; set; } = ""; }

**1.18 Practical: Create CRUD APIs for Role.**
```csharp
[ApiController, Route("api/[controller]"), Authorize(Roles = "Admin")]
public class RolesController(AppDbContext db) : ControllerBase
{
    [HttpGet] public async Task<IActionResult> GetAll() =>
        Ok(await db.Roles.AsNoTracking().Select(r => new { r.RoleId, r.RoleName }).ToListAsync());

    [HttpGet("{id:int}")] public async Task<IActionResult> Get(int id) =>
        await db.Roles.FindAsync(id) is { } r ? Ok(new { r.RoleId, r.RoleName }) : NotFound();

    [HttpPost] public async Task<IActionResult> Create(RoleCreateDto dto)
    {
        if (await db.Roles.AnyAsync(r => r.RoleName == dto.RoleName)) return Conflict("Role already exists");
        var r = new Role { RoleName = dto.RoleName }; db.Roles.Add(r); await db.SaveChangesAsync();
        return CreatedAtAction(nameof(Get), new { id = r.RoleId }, new { r.RoleId, r.RoleName });
    }

    [HttpPut("{id:int}")] public async Task<IActionResult> Update(int id, RoleCreateDto dto)
    {
        var r = await db.Roles.FindAsync(id); if (r is null) return NotFound();
        r.RoleName = dto.RoleName; await db.SaveChangesAsync(); return NoContent();
    }

    [HttpDelete("{id:int}")] public async Task<IActionResult> Delete(int id)
    {
        var r = await db.Roles.FindAsync(id); if (r is null) return NotFound();
        db.Roles.Remove(r); await db.SaveChangesAsync(); return NoContent();   // UserRoles cascade, Users stay (see topic 27)
    }
}
public class RoleCreateDto { [Required, StringLength(50)] public string RoleName { get; set; } = ""; }
```

**1.19 Debugging: Your POST API returns 400 Bad Request. How would you investigate it?**
1. Read the **response body** — `[ApiController]` lists which fields failed validation.
2. Check `Content-Type: application/json` and that JSON is valid (trailing commas, quotes).
3. Check property names/types match the DTO (`"age": "abc"` for an int fails).
4. Check missing `[Required]` fields, string length, enum values, date formats.
5. Set a breakpoint / log `ModelState` errors (if ApiController is disabled).
6. Check the action parameter isn't expecting a different shape (e.g., two `[FromBody]`, wrapper object).
7. Check a custom validation filter/middleware is not returning 400.

**1.20 Scenario: How would you design CRUD APIs for a Users table?**
| Method | URL | Notes |
|---|---|---|
| GET | `/api/users?pageNumber=1&pageSize=10&search=` | paged, DTO response |
| GET | `/api/users/{id}` | 404 if missing |
| POST | `/api/users` | `UserCreateDto`, hash password, 201, 409 on duplicate email |
| PUT | `/api/users/{id}` | `UserUpdateDto`, 204 |
| DELETE | `/api/users/{id}` | 204 (or soft delete) |

Use DTOs, Controller → Service → Repository, async EF Core, `[Authorize(Roles="Admin")]`, unique index on Email, never return password (details in topics 2, 3, 28).

# 2. CRUD Using DTOs

**2.1 What is a DTO?**
A Data Transfer Object: a simple class that carries only the data needed between client and API. No logic.
```csharp
public record UserResponseDto(int UserId, string FullName, string Email);
```

**2.2 Why should we use DTOs instead of directly exposing EF Core models?**
Security (hide password), control the API contract, avoid over-posting, avoid circular JSON references, send less data, and freedom to change the DB without breaking the frontend.

**2.3 What is the difference between Entity Model and DTO?**
Entity = represents a DB table (all columns, relationships, internal). DTO = represents what the API shows/accepts (selected fields only).

**2.4 What is a Request DTO?**
Data coming **into** the API (create/update body).
```csharp
public class UserCreateDto { [Required] public string FullName { get; set; } = ""; [Required, EmailAddress] public string Email { get; set; } = ""; [Required, MinLength(8)] public string Password { get; set; } = ""; }
```

**2.5 What is a Response DTO?**
Data going **out** of the API — only safe, needed fields.

**2.6 Should password fields be returned in a Response DTO?**
**Never** — neither password nor `PasswordHash`. Passwords are write-only (accepted at registration/login/reset, never returned).

**2.7 How do DTOs improve API security?**
They whitelist exactly which fields can come in or go out: no `PasswordHash` leaks, no client-set `IsAdmin`/`RoleId`/`UserId` (over-posting), no internal columns exposed.

**2.8 How do you map an Entity to a DTO?**
```csharp
var dto = new UserResponseDto(u.UserId, u.FullName, u.Email);
// best for lists: projection in SQL
var list = await _db.Users.Select(u => new UserResponseDto(u.UserId, u.FullName, u.Email)).ToListAsync();
// or AutoMapper: _mapper.Map<UserResponseDto>(u)
```

**2.9 How do you map a DTO back to an Entity?**
```csharp
var user = new User { FullName = dto.FullName, Email = dto.Email.Trim().ToLower(), PasswordHash = BCrypt.Net.BCrypt.HashPassword(dto.Password) };
```
Server sets Id, CreatedAt, IsActive, role — never the client.

**2.10 What problems can occur if you directly return Entity Framework entities?**
Password hash leaked, circular reference error (`User → UserRoles → User…`), over-fetching, lazy-loading surprises, tight coupling DB↔API, over-posting on input, hard versioning.

**2.11 Practical: Create UserCreateDto.**
```csharp
public class UserCreateDto
{
    [Required, StringLength(100, MinimumLength = 2)] public string FullName { get; set; } = "";
    [Required, EmailAddress] public string Email { get; set; } = "";
    [Required, MinLength(8)] public string Password { get; set; } = "";
    [RegularExpression(@"^\d{10}$", ErrorMessage = "Mobile must be 10 digits")] public string? MobileNumber { get; set; }
}
```

**2.12 Practical: Create UserResponseDto.**
```csharp
public class UserResponseDto
{
    public int UserId { get; set; }
    public string FullName { get; set; } = "";
    public string Email { get; set; } = "";
    public string? MobileNumber { get; set; }
    public List<string> Roles { get; set; } = new();
    public DateTime CreatedAt { get; set; }
}
```

**2.13 Practical: Create separate DTOs for POST and PUT.**
```csharp
public class UserCreateDto { /* includes Password, Email */ }
public class UserUpdateDto
{
    [Required, StringLength(100)] public string FullName { get; set; } = "";
    [RegularExpression(@"^\d{10}$")] public string? MobileNumber { get; set; }
    public bool IsActive { get; set; }
    // no Password, no Email change, no UserId — separate flows for those
}
```
Reason: create and update have different rules (password only on create; email maybe immutable).

**2.14 Scenario: Your UsersModel contains Password. How will you prevent it from appearing in API responses?**
Return `UserResponseDto` (no password), project with `Select`, never return entity, add `[JsonIgnore]` on the entity as a second safety net, and rename the column to `PasswordHash`. Add a test asserting JSON has no "password".

**2.15 Scenario: Database has 15 columns but frontend requires only 5. How would you design the API?**
Create a `UserListDto` with the 5 fields and use projection so SQL selects only those 5 columns:
```csharp
_db.Users.AsNoTracking().Select(u => new UserListDto { UserId = u.UserId, FullName = u.FullName, Email = u.Email, MobileNumber = u.MobileNumber, IsActive = u.IsActive })
```
Add a separate `UserDetailsDto` for the detail endpoint if more fields are needed.

# 3. Controller → Service → Repository

**3.1 What is the Repository Pattern?**
A class that hides data-access code behind an interface (`IUserRepository`). The rest of the app asks it for data without knowing about EF Core/SQL.

**3.2 What is the Service Layer?**
The layer that holds business rules (duplicate checks, hashing, calculations, workflows). It uses repositories.

**3.3 Why should business logic not be placed directly inside the controller?**
Not testable without HTTP, not reusable (background jobs/other APIs), duplicated across controllers, controllers become huge ("fat controller"), hard to maintain.

**3.4 What is Separation of Concerns?**
Each layer has one job: Controller = HTTP, Service = business rules, Repository = data. Changing one doesn't break the others.

**3.5 Explain Controller → Service → Repository architecture.**
```
React → Controller (HTTP, status codes)
          → Service (rules, mapping, hashing)
              → Repository (EF Core queries)
                  → SQL Server
```
Each arrow goes through an interface injected by DI.

**3.6 What should a Controller contain?**
Routing, `[Authorize]`, reading request data (DTOs), calling a service, returning `Ok/Created/NotFound/NoContent`. Nothing more.

**3.7 What should a Service contain?**
Business validation, password hashing, orchestration of multiple repositories, transactions, mapping DTO↔Entity, throwing domain exceptions (`ConflictException`).

**3.8 What should a Repository contain?**
Only data access: `GetByIdAsync`, `GetPagedAsync`, `AddAsync`, `Remove`, `EmailExistsAsync`, `SaveChangesAsync`. No business rules, no HTTP.

**3.9 What is Dependency Injection?**
Classes receive their dependencies from outside (constructor) instead of using `new`. ASP.NET Core has a built-in container.

**3.10 Why do we use interfaces such as IUserService?**
Loose coupling, easy mocking in unit tests, swap implementations without changing consumers, follows Dependency Inversion.

**3.11 What is the difference between AddScoped, AddTransient, and AddSingleton?**
Transient = new instance each time. Scoped = one per HTTP request (DbContext, services, repositories). Singleton = one for the whole app (cache, config). Rule: a singleton must not depend on a scoped service.

**3.12 Practical: Create IUserRepository.**
```csharp
public interface IUserRepository
{
    Task<User?> GetByIdAsync(int id);
    Task<User?> GetByEmailAsync(string email);
    Task<bool> EmailExistsAsync(string email);
    Task<(List<User> Items, int Total)> GetPagedAsync(int page, int size, string? search);
    Task AddAsync(User user);
    void Remove(User user);
    Task SaveChangesAsync();
}
```

**3.13 Practical: Create UserRepository.**
```csharp
public class UserRepository(AppDbContext db) : IUserRepository
{
    public Task<User?> GetByIdAsync(int id) => db.Users.Include(u => u.UserRoles).ThenInclude(r => r.Role).FirstOrDefaultAsync(u => u.UserId == id);
    public Task<User?> GetByEmailAsync(string email) => db.Users.Include(u => u.UserRoles).ThenInclude(r => r.Role).FirstOrDefaultAsync(u => u.Email == email);
    public Task<bool> EmailExistsAsync(string email) => db.Users.AnyAsync(u => u.Email == email);
    public async Task<(List<User>, int)> GetPagedAsync(int page, int size, string? search)
    {
        var q = db.Users.AsNoTracking().AsQueryable();
        if (!string.IsNullOrWhiteSpace(search)) q = q.Where(u => u.FullName.Contains(search) || u.Email.Contains(search));
        var total = await q.CountAsync();
        var items = await q.OrderBy(u => u.UserId).Skip((page - 1) * size).Take(size).ToListAsync();
        return (items, total);
    }
    public async Task AddAsync(User user) => await db.Users.AddAsync(user);
    public void Remove(User user) => db.Users.Remove(user);
    public Task SaveChangesAsync() => db.SaveChangesAsync();
}
```

    Task<UserResponseDto> GetByIdAsync(int id);

**3.15 Practical: Create UserService.**
```csharp
public class UserService(IUserRepository repo, ILogger<UserService> log) : IUserService
{
    public async Task<UserResponseDto> CreateAsync(UserCreateDto dto)
    {
        var email = dto.Email.Trim().ToLowerInvariant();
        if (await repo.EmailExistsAsync(email)) throw new ConflictException("Email already registered");
        var user = new User { FullName = dto.FullName, Email = email, MobileNumber = dto.MobileNumber,
                              PasswordHash = BCrypt.Net.BCrypt.HashPassword(dto.Password) };
        await repo.AddAsync(user);
        await repo.SaveChangesAsync();
        log.LogInformation("User {UserId} created", user.UserId);
        return Map(user);
    }
    public async Task<UserResponseDto> GetByIdAsync(int id)
        => Map(await repo.GetByIdAsync(id) ?? throw new NotFoundException($"User {id} not found"));
    public async Task UpdateAsync(int id, UserUpdateDto dto)
    {
        var u = await repo.GetByIdAsync(id) ?? throw new NotFoundException($"User {id} not found");
        u.FullName = dto.FullName; u.MobileNumber = dto.MobileNumber; u.IsActive = dto.IsActive; u.UpdatedAt = DateTime.UtcNow;
        await repo.SaveChangesAsync();
    }
    public async Task DeleteAsync(int id)
    {
        var u = await repo.GetByIdAsync(id) ?? throw new NotFoundException($"User {id} not found");
        repo.Remove(u); await repo.SaveChangesAsync();
    }
    public async Task<PagedResult<UserResponseDto>> GetAllAsync(int page, int size, string? search)
    {
        size = Math.Clamp(size, 1, 100);
        var (items, total) = await repo.GetPagedAsync(page, size, search);
        return new PagedResult<UserResponseDto> { Items = items.Select(Map).ToList(), Page = page, PageSize = size, TotalCount = total };
    }
    private static UserResponseDto Map(User u) => new() { UserId = u.UserId, FullName = u.FullName, Email = u.Email, MobileNumber = u.MobileNumber,
        Roles = u.UserRoles.Select(r => r.Role.RoleName).ToList(), CreatedAt = u.CreatedAt };
}
```

**3.16 Scenario: Where should password hashing logic be placed?**
In the **Service** layer (or a dedicated `IPasswordHasher` injected into the service). Not the controller (HTTP only), not the repository (data only). Use BCrypt/Argon2/ASP.NET `PasswordHasher<T>` — never MD5/SHA1 alone.

**3.17 Scenario: Where should database queries be written?**
In the **Repository** (or `DbContext` used inside services when you skip repositories). Never in controllers.

**3.18 Scenario: Where should business validation be performed?**
In the **Service** (duplicate email, role exists, user is active, order total rules). Simple shape validation (required, length, format) goes on DTOs. A unique DB index is the final safety net.

**3.19 Debugging: Dependency injection throws "Unable to resolve service". How do you fix it?**
Error: `Unable to resolve service for type 'IUserService' while attempting to activate 'UsersController'`.
1. Register it: `builder.Services.AddScoped<IUserService, UserService>();`
2. Check every nested dependency is registered (`IUserRepository`, `AppDbContext`).
3. Check the interface/class names and namespaces match.
4. Register **before** `builder.Build()`.
5. Check lifetimes (singleton can't take scoped).

# 4. Configure EF Core

**4.1 What is Entity Framework Core?**
Microsoft's modern ORM: you work with C# classes and LINQ, EF Core generates SQL and maps rows to objects.

**4.2 Why is EF Core used in ASP.NET Core Web API?**
Productivity, LINQ type-safety, migrations, change tracking, parameterized queries (SQL-injection safe), multi-database support, async support.

**4.3 What is DbContext?**
The class representing a database session: holds `DbSet`s, tracks changes, runs queries and `SaveChanges`.

**4.4 What is DbSet?**
A property of DbContext representing a table/entity collection: `DbSet<User> Users`.

**4.5 How do you configure EF Core?**
Install packages (`Microsoft.EntityFrameworkCore.SqlServer`, `.Tools`, `.Design`), create entities + `AppDbContext`, store the connection string, register DbContext, create migration, update database.

**4.6 How do you register DbContext in Program.cs?**
```csharp
builder.Services.AddDbContext<AppDbContext>(o =>
    o.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));
```

**4.7 What is OnModelCreating()?**
A DbContext method where you configure the model with Fluent API (keys, relationships, indexes, delete behavior).

**4.8 What is Fluent API?**
Code-based model configuration using method chaining inside `OnModelCreating`.

**4.9 What are Data Annotations?**
Attributes on entity properties (`[Key]`, `[Required]`, `[MaxLength]`) used for configuration/validation.

**4.10 Fluent API vs Data Annotations?**
Annotations: quick and simple, on the class. Fluent API: more powerful (composite keys, delete behavior, indexes, relationships), keeps entities clean, **wins when both are used**.

**4.11 How do you configure a primary key?**
```csharp
mb.Entity<User>().HasKey(u => u.UserId);              // Fluent
// or  [Key] public int UserId { get; set; }          // annotation
// composite: mb.Entity<UserRole>().HasKey(x => new { x.UserId, x.RoleId });
```

**4.12 How do you configure required fields?**
```csharp
mb.Entity<User>().Property(u => u.Email).IsRequired();   // or [Required]
```

**4.13 How do you configure maximum string length?**
```csharp
mb.Entity<User>().Property(u => u.FullName).HasMaxLength(100);  // or [MaxLength(100)]
```
Without it, SQL Server column becomes `nvarchar(max)`.

**4.14 How do you configure unique fields?**
```csharp
mb.Entity<User>().HasIndex(u => u.Email).IsUnique();
```

**4.15 Practical: Configure AppDbContext.**
```csharp
public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options) { }
    public DbSet<User> Users => Set<User>();
    public DbSet<Role> Roles => Set<Role>();
    public DbSet<UserRole> UserRoles => Set<UserRole>();

    protected override void OnModelCreating(ModelBuilder mb)
    {
        mb.Entity<User>(e => {
            e.HasKey(x => x.UserId);
            e.Property(x => x.FullName).IsRequired().HasMaxLength(100);
            e.Property(x => x.Email).IsRequired().HasMaxLength(200);
            e.Property(x => x.PasswordHash).IsRequired();
            e.HasIndex(x => x.Email).IsUnique();
        });
        mb.Entity<Role>(e => { e.HasKey(x => x.RoleId); e.Property(x => x.RoleName).IsRequired().HasMaxLength(50); e.HasIndex(x => x.RoleName).IsUnique(); });
        mb.Entity<UserRole>(e => {
            e.HasKey(x => new { x.UserId, x.RoleId });
            e.HasOne(x => x.User).WithMany(u => u.UserRoles).HasForeignKey(x => x.UserId).OnDelete(DeleteBehavior.Cascade);
            e.HasOne(x => x.Role).WithMany(r => r.UserRoles).HasForeignKey(x => x.RoleId).OnDelete(DeleteBehavior.Cascade);
        });
    }
}
```

**4.16 Debugging: EF Core cannot connect to the database. What would you check?**
1. Connection string name in code matches `appsettings.json`.
2. Server name/instance, database name, port, firewall.
3. SQL Server service running / LocalDB started (`sqllocaldb start MSSQLLocalDB`).
4. Credentials / Windows auth permission (see "Login failed").
5. `TrustServerCertificate=True` for local SSL errors.
6. Correct environment file loaded (Development vs Production).
7. Provider package installed; DB exists or migrations applied.
8. Read the inner exception message.

# 5. Create Migrations

**5.1 What is an EF Core migration?**
A versioned C# file describing a database schema change (create table, add column). EF can apply (`Up`) or undo (`Down`) it.

**5.2 Why are migrations required?**
To keep the DB schema in sync with your C# models, track schema history in Git, and deploy changes safely to every environment.

**5.3 What is the command to create a migration?**
Package Manager Console: `Add-Migration InitialCreate`

**5.4 What is the command to update the database?**
`Update-Database`

**5.5 What happens internally when Update-Database runs?**
EF builds the model → connects to DB → creates `__EFMigrationsHistory` table if missing → compares applied migrations with those in the Migrations folder → runs the SQL generated from each pending migration's `Up()` in order → inserts a row into `__EFMigrationsHistory` for each.

**5.6 What is the Migrations folder?**
Contains migration files (`2026..._InitialCreate.cs`, `.Designer.cs`) and `AppDbContextModelSnapshot.cs` (the snapshot of the current model used to compute the next migration's difference).

**5.7 How do you remove the last migration?**
`Remove-Migration` (or `dotnet ef migrations remove`). Only if not applied; otherwise first `Update-Database <PreviousMigrationName>`.

**5.8 How do you create a migration using .NET CLI?**
```bash
dotnet tool install --global dotnet-ef
dotnet ef migrations add InitialCreate
dotnet ef database update
# with separate projects:
dotnet ef migrations add InitialCreate -p MyApp.Infrastructure -s MyApp.Api
```

**5.9 What happens if you modify a model after creating a migration?**
Nothing happens to the database until you create **another** migration. If the migration is not yet applied you can remove and recreate it; if it's applied (or shared), add a new migration. Mismatched model/DB leads to "Invalid column name" runtime errors.

**5.10 Practical: Add UserRole and create a migration.**
1. Add `UserRole` entity + `DbSet<UserRole>` + Fluent config (see 4.15).
2. Run:
```bash
dotnet ef migrations add AddUserRole
dotnet ef database update
```
3. Review the generated `Up()` — it should create table `UserRoles` with composite PK and two FKs plus indexes.

**5.11 Debugging: Migration says "Build failed". What do you check?**
Run `dotnet build` and fix compiler errors first (EF builds the project). Check: correct startup project selected, missing packages (`Microsoft.EntityFrameworkCore.Design`), running app locking DLLs (stop debugging), errors in other projects in the solution, wrong namespace/usings in the DbContext.

**5.12 Debugging: Migration already exists but database is not updated. What could be wrong?**
- Created migration but never ran `Update-Database`.
- Updating the **wrong database** (different connection string/environment).
- `__EFMigrationsHistory` says it's already applied (migration was applied then DB changed manually).
- Empty migration (model snapshot already matched, `Up()` is empty).
- Migration is in another assembly/project not picked up.
- Update failed halfway — read the error and check the history table.
- Using `EnsureCreated()` earlier, which bypasses migrations.

# 6. Configure SQL Server

**6.1 How do you connect ASP.NET Core to SQL Server?**
```csharp
// package: Microsoft.EntityFrameworkCore.SqlServer
builder.Services.AddDbContext<AppDbContext>(o => o.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));
```
```json
"ConnectionStrings": { "DefaultConnection": "Server=(localdb)\\MSSQLLocalDB;Database=StudentProjectDb;Trusted_Connection=True;TrustServerCertificate=True;" }
```

**6.2 What is a connection string?**
A text with key=value pairs telling the app how to reach a database (server, database, authentication, options).

**6.3 Explain this connection string**
`Server=(localdb)\MSSQLLocalDB;Database=StudentProjectDb;Trusted_Connection=True;TrustServerCertificate=True;`
- `Server=(localdb)\MSSQLLocalDB` → connect to the LocalDB instance named MSSQLLocalDB on this machine.
- `Database=StudentProjectDb` → use this database.
- `Trusted_Connection=True` → log in with the current Windows account (no username/password).
- `TrustServerCertificate=True` → accept the server's SSL certificate without validating it (OK for local dev).
(In JSON the backslash must be escaped: `\\`.)

**6.4 What is Trusted_Connection=True?**
Windows Integrated Authentication: SQL Server trusts your Windows identity instead of a SQL username/password. Same as `Integrated Security=True/SSPI`.

**6.5 What is TrustServerCertificate=True?**
Skips certificate-chain validation. Needed because Microsoft.Data.SqlClient 4+ encrypts by default and local servers have self-signed certs. **Avoid in production** — use a valid certificate.

**6.6 What is LocalDB?**
A lightweight, on-demand SQL Server Express mode for developers, installed with Visual Studio. No service to manage; databases are files; runs under your user.

**6.7 SQL Server vs LocalDB?**
| SQL Server (full/Express) | LocalDB |
|---|---|
| Always-running Windows service | Starts on demand |
| Remote connections, production | Local only, dev/test |
| Full management/security | Minimal |

**6.8 Where should connection strings be stored?**
Dev: `appsettings.Development.json` (no secrets) or **User Secrets**. Production: environment variables, Azure Key Vault/AWS Secrets Manager, managed identity. Never commit passwords.

**6.9 Why should passwords not be hardcoded in source code?**
Git history/leaks expose them, everyone with code access gets DB access, can't rotate without redeploy, violates compliance.

**6.10 What is appsettings.json?**
Main configuration file (connection strings, logging, JWT settings) loaded at startup.

**6.11 What is appsettings.Development.json?**
Overrides for the Development environment, loaded after `appsettings.json` when `ASPNETCORE_ENVIRONMENT=Development`.

**6.12 Debugging: "Login failed for user" — how would you troubleshoot?**
1. Check username/password in the connection string (or Windows account when `Trusted_Connection`).
2. Does the SQL login exist and is it mapped to the database (`CREATE USER`)? Permissions (`db_datareader/db_datawriter`, or `db_owner` for migrations)?
3. SQL Server must allow **Mixed Mode** auth for SQL logins.
4. App pool identity (IIS) lacks login when using Windows auth.
5. Login disabled/locked/password expired.
6. Wrong server/instance (connected to a different server where the login doesn't exist).
7. Check SQL Server error log for the state code (e.g., state 38 = DB doesn't exist).

**6.13 Debugging: "Keyword not supported: integrated;database" — what could cause it?**
A **typo/format error in the connection string**: a missing `=` or `;` (e.g. `Integrated Security=True Database=X` merged, or `Integrated;Database=...`), a stray character, or JSON escaping problems. Fix: write each pair as `Key=Value;`, e.g. `Server=.;Database=MyDb;Integrated Security=True;`, and check the string isn't read from a wrong/truncated config value.

# 7. One-to-Many Relationships

**7.1 What is a one-to-many relationship?**
One row in table A relates to many rows in table B, but each B row belongs to one A. Example: one Customer → many Orders.

**7.2 Give an example of one-to-many in a Web API.**
`Department → Employees`: `GET /api/departments/3/employees`. Employee has `DepartmentId` FK.

**7.3 How would you model Role → UserRoles?**
One Role has many UserRole rows: `Role.UserRoles` (collection) and `UserRole.RoleId` (FK) + `UserRole.Role` (navigation).

**7.4 How would you model User → UserRoles?**
One User has many UserRole rows: `User.UserRoles` and `UserRole.UserId` + `UserRole.User`.

**7.5 What is a foreign key?**
A column that references the primary key of another table, enforcing valid links.

**7.6 What is a navigation property?**
A C# property that points to related entities, so you can write `user.UserRoles` or `userRole.Role`.

**7.7 What is a collection navigation property?**
The "many" side property: `List<UserRole> UserRoles`. Initialize it (`= new()`) to avoid null.

**7.8 What does HasOne().WithMany() mean?**
"This entity has one related X, and that X has many of this entity." Example `UserRole.HasOne(Role).WithMany(Role.UserRoles)` = each UserRole has one Role; a Role has many UserRoles.

**7.9 What does HasForeignKey() do?**
Specifies which property holds the FK column (`RoleId`).

**7.10 Practical: Configure Role and UserRole.**
```csharp
mb.Entity<UserRole>()
  .HasOne(ur => ur.Role).WithMany(r => r.UserRoles)
  .HasForeignKey(ur => ur.RoleId)
  .OnDelete(DeleteBehavior.Cascade);
```

**7.11 Practical: Configure User and UserRole.**
```csharp
mb.Entity<UserRole>()
  .HasOne(ur => ur.User).WithMany(u => u.UserRoles)
  .HasForeignKey(ur => ur.UserId)
  .OnDelete(DeleteBehavior.Cascade);
```

**7.12 Scenario: One Role can have many UserRoles. How would you configure it?**
Same as 7.10, plus `Role.UserRoles = new List<UserRole>()` and an index/PK on (UserId, RoleId).

**7.13 Scenario: Can one user have multiple roles? How would you design the database?**
Yes. Use a junction table:
```
Users(UserId PK)   Roles(RoleId PK)   UserRoles(UserId FK, RoleId FK, PK(UserId,RoleId))
```
Rahul → (1,Admin) and (1,Faculty) are two rows in UserRoles.

# 8. Cascade / Restrict Delete

**8.1 What is cascade delete?**
Deleting a parent row automatically deletes its dependent child rows.

**8.2 What is restrict delete?**
Deleting a parent is **blocked** if children exist; you must delete/reassign children first.

**8.3 What is DeleteBehavior.Cascade?**
Dependents are deleted with the principal (default for required relationships).

**8.4 What is DeleteBehavior.Restrict?**
Prevents deletion of the principal when dependents exist; EF throws an exception (tracked dependents) / DB rejects it.

**8.5 What is DeleteBehavior.NoAction?**
EF doesn't do anything; DB FK constraint (NO ACTION) rejects the delete if children exist. Mainly used to avoid SQL Server "multiple cascade paths" errors.

**8.6 When should cascade delete be used?**
When children have no meaning without the parent: Order → OrderItems, User → UserRoles, Post → Comments, Role → UserRoles.

**8.7 When should cascade delete be avoided?**
When children are independent or valuable (don't delete Users when a Role is deleted), financial/audit records, multiple cascade paths, or when you prefer soft delete.

**8.8 What happens if UserRole.UserId uses cascade delete?**
Deleting a **User** deletes that user's UserRole rows (good). It does **not** delete Roles.

**8.9 What happens if UserRole.RoleId uses cascade delete?**
Deleting a **Role** deletes the UserRole rows for that role (good). It does **not** delete Users.

**8.10 Scenario: Delete Role → delete UserRoles, but do NOT delete Users. How would you configure it?**
```csharp
mb.Entity<UserRole>().HasOne(x => x.Role).WithMany(r => r.UserRoles).HasForeignKey(x => x.RoleId).OnDelete(DeleteBehavior.Cascade);
mb.Entity<UserRole>().HasOne(x => x.User).WithMany(u => u.UserRoles).HasForeignKey(x => x.UserId).OnDelete(DeleteBehavior.Cascade);
```
Cascade flows from principal to dependent only (Role → UserRole), never from dependent up to another principal (UserRole → User).

**8.11 Why can incorrect cascade configuration delete unexpected records?**
If you put an FK directly on `User` (e.g., `User.RoleId` required with Cascade), deleting the Role deletes every user in it. Also wrong navigation direction or a copy-pasted `OnDelete(Cascade)` on the wrong relationship causes surprise deletions.

**8.12 Practical: Design the correct delete behavior for Users, Roles, and UserRoles.**
| Action | Result | Config |
|---|---|---|
| Delete Role | UserRoles of that role removed; Users untouched | UserRole→Role: Cascade |
| Delete User | That user's UserRoles removed; Roles untouched | UserRole→User: Cascade |
| Delete UserRole | Only the link removed | — |
Optional business rule: block deleting `Admin` role or a role still in use → return 409.

**8.13 Debugging: Deleting a Role unexpectedly deletes User records. How would you investigate?**
1. Check the model: does `User` have a required `RoleId` FK to Role with `Cascade`? Fix: use the junction table or `Restrict`.
2. Check Fluent API `OnDelete` calls and the model snapshot (`AppDbContextModelSnapshot.cs`).
3. Check the actual DB FK (`SELECT * FROM sys.foreign_keys` — `delete_referential_action_desc`).
4. Enable EF logging / `ToQueryString` / SQL Profiler and see which DELETEs run.
5. Look for triggers or `RemoveRange(role.Users)` in service code.
6. Fix configuration → new migration → test deleting a role in staging.

# 9. JWT Login

**9.1 What is JWT?**
JSON Web Token — a signed token containing claims about the user. The server trusts it if the signature is valid.

**9.2 Why is JWT used in Web APIs?**
APIs are stateless; JWT lets the client prove identity on every call without server sessions. Works for React, mobile and microservices.

**9.3 What are the three parts of a JWT?**
Header (algorithm/type), Payload (claims), Signature (tamper-proof seal).

**9.4 Explain: Header.Payload.Signature**
Three Base64Url strings joined by dots: `eyJhbGci...` . `eyJzdWIi...` . `SflKxwRJ...`.
- Header: `{"alg":"HS256","typ":"JWT"}`
- Payload: `{"sub":"5","role":"Admin","exp":1767225600}`
- Signature: `HMAC(base64(header)+"."+base64(payload), secretKey)`

**9.5 What is an access token?**
Short-lived JWT (e.g., 15–60 min) sent in `Authorization: Bearer <token>` to access protected APIs.

**9.6 What information should be stored in JWT claims?**
Minimal, non-sensitive: user id (`sub`), name/email, roles, token id (`jti`), expiry. Not secrets, not big data.

**9.7 Should a password be stored inside JWT?**
**Never.** The payload is only Base64 encoded — anyone can decode it.

**9.8 What is token expiration?**
The `exp` claim: after this time the token is rejected (401). Limits damage if a token is stolen.

**9.9 What is signing key?**
The secret (HMAC) or private key (RSA) used to create and verify signatures. Anyone with it can forge tokens → keep it in Key Vault, long and random (≥ 32 bytes).

**9.10 What is the difference between authentication and authorization?**
Authentication = who you are (login, 401). Authorization = what you can do (roles/policies, 403).

**9.11 How do you configure JWT authentication?**
```csharp
builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme).AddJwtBearer(o =>
{
    o.TokenValidationParameters = new()
    {
        ValidateIssuer = true, ValidIssuer = cfg["Jwt:Issuer"],
        ValidateAudience = true, ValidAudience = cfg["Jwt:Audience"],
        ValidateLifetime = true, ValidateIssuerSigningKey = true,
        IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(cfg["Jwt:Key"]!)),
        ClockSkew = TimeSpan.FromSeconds(30)
    };
});
builder.Services.AddAuthorization();
app.UseAuthentication(); app.UseAuthorization();
```

**9.12 What is JwtBearer?**
The authentication handler (`Microsoft.AspNetCore.Authentication.JwtBearer`) that reads the `Authorization: Bearer` header, validates the token and builds `HttpContext.User`.

**9.13 What does [Authorize] do?**
Requires an authenticated user (and optionally role/policy). If no/invalid token → 401; if authenticated but not allowed → 403.

**9.14 Practical: Implement login using JWT.**
```csharp
public class LoginDto { [Required, EmailAddress] public string Email { get; set; } = ""; [Required] public string Password { get; set; } = ""; }

[ApiController, Route("api/[controller]")]
public class AuthController(AppDbContext db, ITokenService tokens) : ControllerBase
{
    [AllowAnonymous, HttpPost("login")]
    public async Task<IActionResult> Login(LoginDto dto)
    {
        var user = await db.Users.Include(u => u.UserRoles).ThenInclude(r => r.Role)
                         .FirstOrDefaultAsync(u => u.Email == dto.Email.ToLower());
        if (user is null || !user.IsActive || !BCrypt.Net.BCrypt.Verify(dto.Password, user.PasswordHash))
            return Unauthorized(new { message = "Invalid email or password" });   // same message for both cases
        return Ok(new { token = tokens.CreateToken(user), expiresInMinutes = 30 });
    }
}
```

**9.15 Practical: Generate JWT claims from a database user.**
```csharp
public class TokenService(IConfiguration cfg) : ITokenService
{
    public string CreateToken(User user)
    {
        var claims = new List<Claim>
        {
            new(JwtRegisteredClaimNames.Sub, user.UserId.ToString()),
            new(ClaimTypes.NameIdentifier, user.UserId.ToString()),
            new(ClaimTypes.Name, user.FullName),
            new(ClaimTypes.Email, user.Email),
            new(JwtRegisteredClaimNames.Jti, Guid.NewGuid().ToString())
        };
        claims.AddRange(user.UserRoles.Select(r => new Claim(ClaimTypes.Role, r.Role.RoleName)));  // multiple roles
        var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(cfg["Jwt:Key"]!));
        var token = new JwtSecurityToken(cfg["Jwt:Issuer"], cfg["Jwt:Audience"], claims,
            expires: DateTime.UtcNow.AddMinutes(30), signingCredentials: new SigningCredentials(key, SecurityAlgorithms.HmacSha256));
        return new JwtSecurityTokenHandler().WriteToken(token);
    }
}
```

**9.16 Scenario: User successfully logs in but receives 401. Why?**
Most common causes: token not sent or wrong format (must be `Bearer <token>`, with a space); expired token; issuer/audience/key mismatch between creation and validation; `UseAuthentication()` missing or placed after `UseAuthorization()`/endpoints; missing `AddJwtBearer`; token stored with quotes/newline; clock difference; wrong auth scheme; CORS preflight blocked header.

**9.17 Scenario: JWT token is valid but API returns 403. Why?**
Authentication worked, authorization failed: the role/claim required isn't in the token (token issued before role was assigned, role name mismatch like "admin" vs "Admin", role claim type not `ClaimTypes.Role`), policy requirement not met, resource-ownership rule, or `RoleClaimType` misconfigured.

# 10. Role-Based Authorization

**10.1 What is authorization?**
Deciding what an authenticated user is allowed to do.

**10.2 What is role-based authorization?**
Permissions are granted by role (Admin, Faculty, Student). User → roles → access.

**10.3 How does [Authorize(Roles = "Admin")] work?**
The framework checks `User.IsInRole("Admin")`, which looks for a claim of type `ClaimTypes.Role` (or the configured `RoleClaimType`) with value "Admin" in the validated JWT. Missing → 403.

**10.4 How do you store user roles in a database?**
`Users`, `Roles`, `UserRoles` junction table (see topic 26). Load roles at login and put them in the JWT.

**10.5 How do you add a role to JWT claims?**
```csharp
claims.Add(new Claim(ClaimTypes.Role, "Admin"));   // one claim per role
```

**10.6 What is the difference between Role and Claim?**
A claim is any fact about the user (email, department, permission). A **role** is just a special claim type that groups permissions. Claims are more flexible/fine-grained (`permission: users.delete`).

**10.7 Can one user have multiple roles?**
Yes — add multiple role claims; `[Authorize(Roles="Admin,Faculty")]` passes if the user has either.

**10.8 How would you implement Admin/Faculty/Student authorization?**
Seed three roles; assign via UserRoles; include in JWT; protect endpoints:
- Admin: manage users/roles → `[Authorize(Roles="Admin")]`
- Faculty: marks/attendance → `[Authorize(Roles="Admin,Faculty")]`
- Student: view own data → `[Authorize(Roles="Student")]` + ownership check `userId == currentUserId`.

**10.9 Practical: Create an Admin-only endpoint.**
```csharp
[Authorize(Roles = "Admin")]
[HttpGet("admin-report")]
public IActionResult AdminReport() => Ok("Only admins see this");
```

**10.10 Practical: Allow Admin and Faculty to access an endpoint.**
```csharp
[Authorize(Roles = "Admin,Faculty")]
[HttpPost("marks")]
public IActionResult AddMarks(MarksDto dto) => Ok();
```

**10.11 Scenario: Student calls Admin API and receives 403. Explain.**
The Student's token is valid (so authentication passes), but it has no `Admin` role claim, so the authorization middleware rejects it with **403 Forbidden** — "I know who you are, you're not allowed." (401 would mean no/invalid token.)

**10.12 Debugging: Role exists in database but [Authorize(Roles="Admin")] does not work. Why?**
Role is in DB but **not in the JWT** (not added to claims, or token generated before assignment — re-login); claim type isn't `ClaimTypes.Role` / `RoleClaimType` mismatch; case/spelling mismatch; `UserRoles` not loaded (missing `Include`) so claims list is empty; `UseAuthentication()` order wrong; old token cached in React; policy/roles on both controller and action conflict (both must pass). Decode the token at jwt.io to verify.

# 11. Global Exception Handling

**11.1 What is exception handling?**
Catching runtime errors and responding in a controlled way instead of crashing.

**11.2 Why should we use global exception handling?**
One place handles all unhandled errors: consistent JSON responses, central logging, no duplicate try/catch in every action, no stack traces leaked.

**11.3 What is middleware?**
A component in the request pipeline that can process the request/response and call the next component.

**11.4 How can middleware handle exceptions globally?**
Place exception middleware first in the pipeline; it wraps `await next(ctx)` in try/catch and writes an error response.

**11.5 What is the difference between local and global exception handling?**
Local: `try/catch` inside a method for expected, recoverable cases. Global: catch-all for everything else, at the app boundary.

**11.6 How do you handle unexpected exceptions?**
Log full details (with TraceId), return a generic **500** message to the client, optionally alert.

**11.7 Should stack traces be returned to clients?**
No (security risk — reveals code structure, paths, SQL). Show only in Development; log them server-side.

**11.8 What HTTP status code should be returned for an unexpected server error?**
**500 Internal Server Error.**

**11.9 Practical: Create global exception middleware.**
```csharp
public class ExceptionMiddleware(RequestDelegate next, ILogger<ExceptionMiddleware> log, IHostEnvironment env)
{
    public async Task InvokeAsync(HttpContext ctx)
    {
        try { await next(ctx); }
        catch (Exception ex)
        {
            var (code, msg) = ex switch
            {
                NotFoundException e   => (404, e.Message),
                ConflictException e   => (409, e.Message),
                ValidationException e => (400, e.Message),
                UnauthorizedAccessException => (403, "Access denied"),
                _ => (500, "An unexpected error occurred")
            };
            if (code == 500) log.LogError(ex, "Unhandled exception. TraceId {TraceId}", ctx.TraceIdentifier);
            ctx.Response.StatusCode = code; ctx.Response.ContentType = "application/json";
            await ctx.Response.WriteAsJsonAsync(new { success = false, status = code, message = msg, traceId = ctx.TraceIdentifier,
                                                       detail = env.IsDevelopment() ? ex.ToString() : null });
        }
    }
}
public class NotFoundException(string m) : Exception(m);
public class ConflictException(string m) : Exception(m);
// Program.cs: first middleware
app.UseMiddleware<ExceptionMiddleware>();
```

**11.10 Scenario: Any unhandled exception should return a standard JSON response. How would you implement it?**
Use the middleware above (or `IExceptionHandler` + `AddProblemDetails()`), register it first, define a single response shape `{ success, status, message, traceId }`, and test with a controller that throws.

**11.11 Debugging: API returns HTML error instead of JSON. What could be missing?**
`UseDeveloperExceptionPage` (HTML) is active, or no exception middleware is registered; middleware registered **too late** in the pipeline; response `ContentType` not set to `application/json`; error came from the web server/proxy (IIS 500 page); `UseStatusCodePages` returns HTML; `UseExceptionHandler("/error")` points to a non-API route.

# 12. Validation

**12.1 What is model validation?**
Automatic checking of incoming data against rules (annotations/FluentValidation) before your logic runs.

**12.2 What does [Required] do?**
Value must be present (non-null; for strings non-empty).

**12.3 What does [StringLength] do?**
Sets max (and optional min) text length: `[StringLength(100, MinimumLength = 2)]`.

**12.4 What does [Range] do?**
Restricts a number/date to a range: `[Range(18, 60)]`.

**12.5 What does [EmailAddress] do?**
Validates email format (basic check, not that the mailbox exists).

**12.6 What is custom validation?**
Your own rule via `ValidationAttribute`, `IValidatableObject`, or FluentValidation.
```csharp
public class StrongPasswordAttribute : ValidationAttribute {
    protected override ValidationResult? IsValid(object? v, ValidationContext c)
        => v is string s && s.Length >= 8 && s.Any(char.IsDigit) && s.Any(char.IsUpper) ? ValidationResult.Success : new("Password must be 8+ chars with a digit and uppercase");
}
```

**12.7 What happens when [ApiController] validation fails?**
The framework automatically returns **400 Bad Request** with `ValidationProblemDetails` listing field errors; the action method doesn't run.

**12.8 Where should business validation be performed?**
In the **service layer** (needs DB/rules); DTO annotations only for shape/format.

**12.9 Practical: Validate User email and mobile number.**
```csharp
public class UserCreateDto
{
    [Required(ErrorMessage = "Email is required"), EmailAddress(ErrorMessage = "Invalid email")] public string Email { get; set; } = "";
    [Required, RegularExpression(@"^[6-9]\d{9}$", ErrorMessage = "Enter a valid 10-digit mobile number")] public string MobileNumber { get; set; } = "";
}
```

**12.10 Practical: Prevent duplicate email registration.**
```csharp
if (await _repo.EmailExistsAsync(email)) throw new ConflictException("Email already registered");   // 409
```
plus a unique index (see topic 18).

**12.11 Scenario: Email format is correct but email already exists. Is this model validation or business validation?**
**Business validation** — the format is valid; the rule depends on database state. Return **409 Conflict** (or 400/422 per team convention).

**12.12 How should validation errors be returned to React?**
Consistent JSON with field names so React can show messages beside inputs:
```json
{ "status": 400, "errors": { "email": ["Invalid email"], "mobileNumber": ["Enter a valid 10-digit mobile number"] } }
```
React: `err.response.data.errors.email?.[0]`.

# 13. Pagination

**13.1 What is pagination?**
Returning data in small pages instead of all at once.

**13.2 Why is pagination important?**
Performance, lower memory/bandwidth, faster UI, protects DB and server from huge responses.

**13.3 What are pageNumber and pageSize?**
`pageNumber` = which page (starting at 1). `pageSize` = how many items per page.

**13.4 How do you implement pagination using LINQ?**
```csharp
query.OrderBy(x => x.Id).Skip((pageNumber - 1) * pageSize).Take(pageSize)
```

**13.5 What does Skip() do?**
Skips the first N records (SQL `OFFSET N`).

**13.6 What does Take() do?**
Takes the next N records (SQL `FETCH NEXT N` / `TOP`).

**13.7 How do you calculate total pages?**
`totalPages = (int)Math.Ceiling(totalCount / (double)pageSize);` e.g., 95 records, size 10 → 10 pages.

**13.8 Should total record count be returned?**
Yes — the UI needs it for page numbers. It costs an extra `COUNT(*)` query (cache it or use "has next page" for huge tables).

**13.9 Practical: Create GET /api/users?pageNumber=1&pageSize=10**
```csharp
[HttpGet]
public async Task<IActionResult> Get([FromQuery] int pageNumber = 1, [FromQuery] int pageSize = 10)
{
    pageNumber = Math.Max(1, pageNumber);
    pageSize = Math.Clamp(pageSize, 1, 100);
    var q = _db.Users.AsNoTracking();
    var total = await q.CountAsync();
    var items = await q.OrderBy(u => u.UserId).Skip((pageNumber - 1) * pageSize).Take(pageSize)
        .Select(u => new UserResponseDto { UserId = u.UserId, FullName = u.FullName, Email = u.Email }).ToListAsync();
    return Ok(new { pageNumber, pageSize, totalCount = total, totalPages = (int)Math.Ceiling(total / (double)pageSize), data = items });
}
```

**13.10 Scenario: Database contains 1 million records. Why should you avoid returning all records?**
Huge memory use, slow query and serialization, big network payload, browser freezes, DB locks/timeouts, API crash under load. Always paginate with a max page size.

**13.11 How would you combine pagination with search and sorting?**
Order: **filter/search → count → sort → Skip/Take → project** (see topics 14/15). Always sort before paging with a stable key (add `ThenBy(Id)`).

# 14. Search + Filtering

**14.1 What is filtering?**
Restricting results by exact criteria (role = Admin, status = Active).

**14.2 What is searching?**
Finding records containing text (name/email contains "rahul") — usually partial matching.

**14.3 How do you search users by name?**
```csharp
query = query.Where(u => u.FullName.Contains(search));
```

**14.4 How do you filter users by role?**
```csharp
query = query.Where(u => u.UserRoles.Any(ur => ur.Role.RoleName == role));
```

**14.5 How do you filter by status?**
```csharp
if (isActive.HasValue) query = query.Where(u => u.IsActive == isActive.Value);
```

**14.6 What is Where() in LINQ?**
Filters a sequence by a condition → SQL `WHERE`.

**14.7 What is Contains()?**
String contains → SQL `LIKE '%text%'`. (On a list, `ids.Contains(x.Id)` → SQL `IN (...)`.)

**14.8 What is the difference between Contains(), StartsWith(), and EndsWith()?**
`Contains` → `%x%`, `StartsWith` → `x%` (can use an index — fastest), `EndsWith` → `%x`.

**14.9 Practical: Search users by name and email.**
```csharp
if (!string.IsNullOrWhiteSpace(search))
{
    var s = search.Trim();
    query = query.Where(u => u.FullName.Contains(s) || u.Email.Contains(s));
}
```

**14.10 Practical: Filter users by Role and Status.**
```csharp
if (!string.IsNullOrWhiteSpace(role)) query = query.Where(u => u.UserRoles.Any(r => r.Role.RoleName == role));
if (status is "active" or "inactive")  query = query.Where(u => u.IsActive == (status == "active"));
```

**14.11 Scenario: Implement /api/users?search=rahul&role=Admin**
```csharp
[HttpGet]
public async Task<IActionResult> Get(string? search, string? role)
{
    var q = _db.Users.AsNoTracking().AsQueryable();
    if (!string.IsNullOrWhiteSpace(search)) q = q.Where(u => u.FullName.Contains(search) || u.Email.Contains(search));
    if (!string.IsNullOrWhiteSpace(role))   q = q.Where(u => u.UserRoles.Any(r => r.Role.RoleName == role));
    return Ok(await q.Select(u => new UserResponseDto { UserId = u.UserId, FullName = u.FullName, Email = u.Email }).ToListAsync());
}
```

**14.12 How can dynamic filtering affect database performance?**
`Contains` (`%x%`) can't use indexes → table scans; many optional filters create varied query plans; joins with `Any()` on big tables are costly; no pagination multiplies the problem. Fix: indexes on filtered columns, `StartsWith` where possible, full-text search for big text, limit page size, avoid loading before filtering.

# 15. Sorting

**15.1 What is sorting?**
Ordering results by one or more columns.

**15.2 What is OrderBy()?**
Ascending sort → SQL `ORDER BY col ASC`.

**15.3 What is OrderByDescending()?**
Descending sort → `ORDER BY col DESC`.

**15.4 What is ThenBy()?**
Secondary sort key: `OrderBy(u => u.FullName).ThenBy(u => u.CreatedAt)`.

**15.5 How would you sort users by name?**
`query.OrderBy(u => u.FullName)`.

**15.6 How would you implement dynamic sorting?**
Map the client's `sortBy` text to a **whitelist** of expressions (never build SQL from client text):
```csharp
query = (sortBy?.ToLower(), desc) switch
{
    ("name", false)  => query.OrderBy(u => u.FullName),
    ("name", true)   => query.OrderByDescending(u => u.FullName),
    ("email", false) => query.OrderBy(u => u.Email),
    ("email", true)  => query.OrderByDescending(u => u.Email),
    ("created", true)=> query.OrderByDescending(u => u.CreatedAt),
    _                => query.OrderBy(u => u.UserId)
};
```

**15.7 Practical: /api/users?sortBy=name&sortOrder=desc**
```csharp
[HttpGet]
public async Task<IActionResult> Get(string sortBy = "name", string sortOrder = "asc")
{
    var desc = sortOrder.Equals("desc", StringComparison.OrdinalIgnoreCase);
    IQueryable<User> q = _db.Users.AsNoTracking();
    q = sortBy.ToLower() switch
    {
        "name"    => desc ? q.OrderByDescending(u => u.FullName) : q.OrderBy(u => u.FullName),
        "email"   => desc ? q.OrderByDescending(u => u.Email)    : q.OrderBy(u => u.Email),
        "created" => desc ? q.OrderByDescending(u => u.CreatedAt): q.OrderBy(u => u.CreatedAt),
        _         => q.OrderBy(u => u.UserId)
    };
    return Ok(await q.Select(u => new UserResponseDto { UserId = u.UserId, FullName = u.FullName, Email = u.Email }).ToListAsync());
}
```

**15.8 What happens if the client sends an invalid sortBy value?**
Either ignore it and use the default sort, or return **400** with a message listing allowed fields. Never pass it into raw SQL/dynamic expressions blindly (injection/exception risk).

**15.9 How would you combine sorting with pagination?**
Sort first, then `Skip/Take`. Add a unique tiebreaker (`ThenBy(u => u.UserId)`) so pages don't overlap or skip rows when sort values repeat.

# 16. CORS for React

**16.1 What is CORS?**
Cross-Origin Resource Sharing: a browser rule that blocks a web page from reading responses from a different origin unless that server explicitly allows it with CORS headers.

**16.2 Why does CORS occur?**
Browsers enforce the Same-Origin Policy to protect users from malicious sites reading data from other sites using their cookies/session. When React (origin A) calls the API (origin B), the browser checks whether B allows A.

**16.3 Why does React need CORS permission from ASP.NET Core?**
React runs at `http://localhost:5173`, the API at `https://localhost:7125` — different origins. The API must return `Access-Control-Allow-Origin: http://localhost:5173`, else the browser hides the response from React JavaScript.

**16.4 What is an Origin?**
`scheme + host + port`. `http://localhost:5173` ≠ `https://localhost:5173` ≠ `http://localhost:3000`.

**16.5 What is a preflight request?**
An automatic `OPTIONS` request the browser sends **before** the real request when it's "non-simple" (JSON body, `Authorization` header, PUT/DELETE). It asks "may I send this?"

**16.6 What is an OPTIONS request?**
The HTTP method used for preflight; the server replies with allowed origin/methods/headers (`Access-Control-Allow-*`), usually 204.

**16.7 How do you configure CORS in ASP.NET Core?**
```csharp
builder.Services.AddCors(o => o.AddPolicy("ReactPolicy", p => p
    .WithOrigins("http://localhost:5173")
    .AllowAnyHeader()
    .AllowAnyMethod()));
...
app.UseCors("ReactPolicy");
```

**16.8 Where should UseCors() be placed in the middleware pipeline?**
After `UseRouting()` and **before** `UseAuthentication()` / `UseAuthorization()` and `MapControllers()`:
```csharp
app.UseHttpsRedirection();
app.UseRouting();
app.UseCors("ReactPolicy");
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
```

**16.9 Practical: Allow http://localhost:5173**
```csharp
p.WithOrigins("http://localhost:5173")   // exact: no trailing slash
```
Add `.AllowCredentials()` only if using cookies.

**16.10 Should you use AllowAnyOrigin() in production?**
No. It lets any website call your API from a user's browser. List exact production origins (`https://app.mycompany.com`). `AllowAnyOrigin` can't be combined with `AllowCredentials`.

**16.11 Debugging: React receives "No 'Access-Control-Allow-Origin' header" — how do you fix it?**
1. Add/enable a CORS policy with the exact React origin (scheme, host, port, no trailing slash).
2. Call `app.UseCors("policy")` in the right position (before auth).
3. Allow headers (`Authorization`, `Content-Type`) and methods.
4. Check preflight (`OPTIONS`) returns 2xx — not blocked by auth (`[Authorize]` doesn't apply to preflight when CORS runs first) or by a 500.
5. Restart the API after changes; clear browser cache.
6. Verify in the Network tab that the response includes the header.

**16.12 (Question #217) Scenario: API works in Swagger but fails from React. What would you check?**
Swagger is same-origin, React is cross-origin. Check: CORS policy/origin/port match and middleware order; HTTP vs HTTPS (mixed content, certificate trusted?); base URL and route in React; `Authorization: Bearer` header present (and allowed in CORS); `Content-Type: application/json`; preflight result; request body matches DTO; proxy settings (Vite proxy); 401/500 hiding CORS headers (read the Network tab response).

# 17. Async/Await

**17.1 What is asynchronous programming?**
Starting a slow operation (DB/network/file) and freeing the thread to do other work while waiting, instead of blocking.

**17.2 Why use async/await in Web APIs?**
Threads aren't blocked during I/O, so the server handles many more concurrent requests with the same threads (scalability).

**17.3 What does Task represent?**
An ongoing operation that returns nothing when done (like `void` for async).

**17.4 What is Task<T>?**
An ongoing operation that will produce a value of type `T` (`Task<User>`).

**17.5 What does await do?**
Pauses the method until the task completes **without blocking the thread**, then continues and gives the result.

**17.6 Difference between synchronous and asynchronous database calls?**
Sync (`ToList`) holds the thread while SQL runs. Async (`ToListAsync`) releases the thread during the wait. Same query speed, better throughput.

**17.7 What is ToListAsync()?**
Executes the query asynchronously and returns `List<T>`.

**17.8 What is FirstOrDefaultAsync()?**
Async version of `FirstOrDefault` — returns the first match or `null`.

**17.9 What is SaveChangesAsync()?**
Async commit of tracked changes to the database.

**17.10 Why should database operations generally be asynchronous?**
They're I/O-bound; async avoids thread-pool starvation under load and keeps the API responsive.

**17.11 Practical: Convert synchronous CRUD APIs to async.**
```csharp
// Before
[HttpGet] public IActionResult GetAll() => Ok(_db.Users.ToList());
[HttpPost] public IActionResult Add(User u) { _db.Users.Add(u); _db.SaveChanges(); return Ok(u); }
// After
[HttpGet] public async Task<IActionResult> GetAll() => Ok(await _db.Users.AsNoTracking().ToListAsync());
[HttpPost] public async Task<IActionResult> Add(User u) { _db.Users.Add(u); await _db.SaveChangesAsync(); return Ok(u); }
```
Rules: return `Task<T>`, name methods `...Async`, `await` all the way down.

**17.12 Debugging: What happens if you unnecessarily use .Result or .Wait()?**
It **blocks** the thread; under load → thread-pool starvation, slow API, potential **deadlocks** (in apps with a synchronization context), and exceptions get wrapped in `AggregateException`. Fix: `await` instead ("async all the way").

**17.13 Can async improve database query performance? Explain carefully.**
Not a single query's speed — SQL takes the same time. Async improves **scalability/throughput**: while one request waits for the DB, its thread serves others. Query speed comes from indexes, projection, pagination, etc.

# 18. Duplicate Database Records

**18.1 How do you prevent duplicate users?**
Three layers: normalize input (trim/lowercase email), check in service (`AnyAsync`), and enforce a **unique index** in the database; handle the DB exception.

**18.2 What is a unique constraint?**
A database rule that no two rows may have the same value in the column(s).

**18.3 What is a unique index?**
An index that enforces uniqueness (and speeds lookups). A unique constraint is implemented through a unique index.

**18.4 How do you make Email unique in EF Core?**
```csharp
mb.Entity<User>().HasIndex(u => u.Email).IsUnique();
```
Then `dotnet ef migrations add UniqueEmail` and `database update`.

**18.5 Application validation vs database constraint — what's the difference?**
App validation gives friendly messages but can race. DB constraint is the final guarantee, works for every client and bug. Use both.

**18.6 Why should duplicate prevention exist at the database level?**
Race conditions (two simultaneous requests pass the app check), other apps/scripts writing to the DB, bugs. Only the DB can atomically guarantee uniqueness.

**18.7 What exception can occur when inserting a duplicate unique value?**
`DbUpdateException` wrapping `SqlException` (Number **2601** unique index or **2627** unique constraint).

**18.8 Practical: Prevent duplicate email registration.**
```csharp
public async Task<UserResponseDto> CreateAsync(UserCreateDto dto)
{
    var email = dto.Email.Trim().ToLowerInvariant();
    if (await _repo.EmailExistsAsync(email)) throw new ConflictException("Email already registered");
    var user = new User { Email = email, FullName = dto.FullName, PasswordHash = BCrypt.Net.BCrypt.HashPassword(dto.Password) };
    try { await _repo.AddAsync(user); await _repo.SaveChangesAsync(); }
    catch (DbUpdateException ex) when (ex.InnerException is SqlException { Number: 2601 or 2627 })
    { throw new ConflictException("Email already registered"); }
    return Map(user);
}
```

**18.9 Scenario: Two requests simultaneously register the same email. How do you guarantee consistency?**
Both may pass `AnyAsync`. The **unique index** lets only one INSERT succeed; the other fails with 2601/2627. Catch it and return **409 Conflict**. (Optionally serialize with a transaction/`UPDLOCK` or distributed lock, but the unique index is the real guarantee.)

**18.10 Debugging: Migration fails because IX_Users_Email already exists. What would you investigate?**
- Index already created by an earlier migration or manually in the DB → compare `__EFMigrationsHistory` and actual schema.
- Same index defined twice in the model (annotation + Fluent API with different names).
- Database was changed manually/DB-first drift. Fix: remove the duplicate from the migration, or `DROP INDEX`/script conditionally, or baseline the DB.
- Existing duplicate **data** would cause a different error (clean duplicates before creating a unique index).

# 19. Handle DbUpdateException

**19.1 What is DbUpdateException?**
The exception EF Core throws when saving changes to the database fails (constraint violation, FK error, timeout, etc.). `InnerException` holds the real SQL error.

**19.2 When does SaveChanges() throw DbUpdateException?**
When the generated INSERT/UPDATE/DELETE is rejected by the database: unique/FK/NOT NULL violations, string too long, deadlock victim, etc.

**19.3 What can cause a foreign-key violation?**
Inserting a child referencing a non-existent parent (UserRole with RoleId 99), or deleting a parent that still has children (Restrict/NoAction).

**19.4 What can cause a unique constraint violation?**
Inserting/updating a value that already exists in a unique column (duplicate email, role name, UserRole pair).

**19.5 How do you catch DbUpdateException?**
```csharp
try { await _db.SaveChangesAsync(); }
catch (DbUpdateException ex) { _log.LogError(ex, "DB update failed"); throw; /* or translate */ }
```

**19.6 Should you return raw database exception details to the client?**
No — leaks table/column/index names (security) and is meaningless to users. Log details; return a friendly message with 409/400/500.

**19.7 Practical: Handle duplicate email using DbUpdateException.**
```csharp
catch (DbUpdateException ex) when (ex.InnerException is SqlException sql && (sql.Number == 2601 || sql.Number == 2627))
{
    _log.LogWarning(ex, "Duplicate email {Email}", email);
    return Conflict(new { message = "Email already exists" });
}
```

**19.8 Practical: Handle invalid foreign-key insertion.**
```csharp
catch (DbUpdateException ex) when (ex.InnerException is SqlException { Number: 547 })   // FK/check violation
{
    return BadRequest(new { message = "Invalid RoleId or UserId" });
}
```
Better: validate first with `AnyAsync` in the service and return 400/404.

**19.9 Scenario: UserRole references a non-existing Role. What happens?**
`SaveChangesAsync` → SQL error **547** ("INSERT conflicted with FOREIGN KEY constraint") → `DbUpdateException`. If unhandled → API returns 500. Handle: check `Roles.AnyAsync(r => r.RoleId == id)` → return 404/400.

**19.10 How would you log database exceptions?**
Use `ILogger`, log the exception object (stack trace + inner exception), add context (`UserId`, `Email`, `TraceId`), never log passwords; in global middleware log all unhandled ones once; use Serilog/Application Insights for production.
```csharp
_log.LogError(ex, "DbUpdateException while creating user {Email}. TraceId {TraceId}", email, HttpContext.TraceIdentifier);
```

# 20. LINQ Queries

**20.1 What is LINQ?**
Language Integrated Query: querying collections/databases using C# syntax.

**20.2 Why is LINQ useful with EF Core?**
Type-safe queries with IntelliSense; EF translates them to SQL; automatically parameterized (SQL-injection safe); composable (add filters step by step).

**20.3 Explain Where().**
Filters items: `users.Where(u => u.IsActive)`.

**20.4 Explain Select().**
Transforms/projects each item: `users.Select(u => u.Email)` or into DTOs.

**20.5 Explain FirstOrDefault().**
Returns the first match, or `null`/default if none (no exception).

**20.6 Explain SingleOrDefault().**
Returns the only match, `null` if none, throws if **more than one**.

**20.7 Explain Any().**
`true` if at least one item (matching an optional condition) exists.

**20.8 Explain Count().**
Number of items (matching an optional condition).

**20.9 Explain OrderBy().**
Sorts ascending by a key.

**20.10 Explain GroupBy().**
Groups items by key and lets you aggregate each group.

**20.11 Difference between FirstOrDefault() and SingleOrDefault()?**
`FirstOrDefault` doesn't care about duplicates (returns the first). `SingleOrDefault` asserts uniqueness (throws on 2+). Use Single for unique keys (Id, unique email), First when duplicates are possible.

**20.12 Difference between Any() and Count() > 0?**
`Any()` → SQL `EXISTS` (stops at the first row). `Count() > 0` → counts all matches. `Any()` is faster and clearer.

**20.13 Practical: Find all active users.**
```csharp
var users = await _db.Users.Where(u => u.IsActive).ToListAsync();
```

**20.14 Practical: Find users whose names start with "A".**
```csharp
var users = await _db.Users.Where(u => u.FullName.StartsWith("A")).ToListAsync();
```

**20.15 Practical: Find users who have an Admin role.**
```csharp
var admins = await _db.Users.Where(u => u.UserRoles.Any(ur => ur.Role.RoleName == "Admin")).ToListAsync();
```

**20.16 Practical: Count users by role.**
```csharp
var counts = await _db.UserRoles
    .GroupBy(ur => ur.Role.RoleName)
    .Select(g => new { Role = g.Key, Total = g.Count() })
    .ToListAsync();
```

**20.17 Practical: Find the highest salary using LINQ.**
```csharp
var max = await _db.Employees.MaxAsync(e => e.Salary);                           // value only
var top = await _db.Employees.OrderByDescending(e => e.Salary).FirstOrDefaultAsync(); // whole record
// highest per department
var perDept = await _db.Employees.GroupBy(e => e.Department).Select(g => new { g.Key, Max = g.Max(e => e.Salary) }).ToListAsync();
```

# 21. Include() / ThenInclude()

**21.1 What is eager loading?**
Loading related data in the **same query** as the main entity (via JOIN) using `Include`.

**21.2 What is Include()?**
Tells EF to also load a related navigation property: `.Include(u => u.UserRoles)`.

**21.3 What is ThenInclude()?**
Loads a navigation of the previously included entity (next level): `.Include(u => u.UserRoles).ThenInclude(ur => ur.Role)`.

**21.4 When should you use Include()?**
When you need the full entity graph and will use the related data (e.g., login needs roles), or you will modify related entities. For read-only DTO output, prefer `Select`.

**21.5 What happens if you don't use Include()?**
Navigation properties stay `null`/empty (unless lazy loading is enabled) — e.g., `user.UserRoles.Count` is 0 even though rows exist. Classic bug: roles missing from JWT.

**21.6 What is lazy loading?**
Related data is loaded automatically **when first accessed**, with extra queries (needs proxies + `virtual` navigations).

**21.7 Eager loading vs lazy loading?**
Eager: one planned query, predictable. Lazy: many hidden queries (N+1), convenient but risky in APIs. Prefer eager or projection.

**21.8 Practical: Load User with UserRoles.**
```csharp
var user = await _db.Users.Include(u => u.UserRoles).FirstOrDefaultAsync(u => u.UserId == id);
```

**21.9 Practical: Load User → UserRoles → Role.**
```csharp
var user = await _db.Users
    .Include(u => u.UserRoles).ThenInclude(ur => ur.Role)
    .FirstOrDefaultAsync(u => u.UserId == id);
var roles = user?.UserRoles.Select(ur => ur.Role.RoleName).ToList();
```

**21.10 Write a query using .Include(x => x.UserRoles).ThenInclude(x => x.Role)**
```csharp
var users = await _db.Users
    .Include(x => x.UserRoles)
        .ThenInclude(x => x.Role)
    .AsNoTracking()
    .ToListAsync();
```

**21.11 Can excessive Include() affect performance?**
Yes: big JOINs cause **cartesian explosion** (duplicated rows), large memory/transfer, slow serialization. Fix: `Select` only what you need, `AsSplitQuery()`, filtered includes, pagination.

**21.12 How can DTO projection reduce unnecessary data loading?**
```csharp
var dtos = await _db.Users.Select(u => new UserResponseDto {
    UserId = u.UserId, FullName = u.FullName,
    Roles = u.UserRoles.Select(r => r.Role.RoleName).ToList()
}).ToListAsync();
```
SQL fetches only those columns, no tracking, no password hash, no circular graph.

# 22. AsNoTracking()

**22.1 What is AsNoTracking()?**
A query option telling EF not to track the returned entities in the change tracker.

**22.2 Why is AsNoTracking() useful?**
Faster, less memory/CPU — no snapshots or identity resolution — ideal for read-only data.

**22.3 When should you use AsNoTracking()?**
GET endpoints, lists, reports, dropdowns, search results — anywhere you won't call `SaveChanges` on those entities.

**22.4 When should you NOT use it?**
When you will modify and save the entities you loaded (update/delete flows), or need identity resolution/relationship fix-up across the graph.

**22.5 Can you update an entity retrieved using AsNoTracking()?**
Not automatically: changing properties and calling `SaveChanges` does nothing, because EF doesn't know about it. You'd have to `Attach`/`Update(entity)` (which marks all columns modified) — better to re-query with tracking.

**22.6 How does EF Core change tracking work?**
When tracked, EF keeps the entity plus a snapshot of original values. At `SaveChanges` it compares current vs original, marks entity states (Added/Modified/Deleted/Unchanged) and generates INSERT/UPDATE/DELETE for only changed columns.

**22.7 Practical: Optimize a read-only GetAllUsers() query using AsNoTracking().**
```csharp
public async Task<List<UserResponseDto>> GetAllUsersAsync() =>
    await _db.Users.AsNoTracking()
        .Select(u => new UserResponseDto { UserId = u.UserId, FullName = u.FullName, Email = u.Email })
        .ToListAsync();
```
(Projection to DTOs is already untracked, but `AsNoTracking()` makes the intent explicit and helps when returning entities.)

**22.8 Scenario: Your GET API is slow because thousands of entities are tracked. What can you do?**
`AsNoTracking()`, project to DTOs with `Select`, paginate, add indexes, remove unneeded `Include`s, use `AsNoTrackingWithIdentityResolution` if duplicates matter, or set `UseQueryTrackingBehavior(NoTracking)` as default for a read DbContext.

**22.9 Does AsNoTracking() improve every query automatically?**
No. Tiny result sets see little gain; slow queries caused by missing indexes, N+1, or huge payloads aren't fixed by it. It only removes tracking overhead.

# 23. Correct HTTP Status Codes

**23.1 What does 200 OK mean?** Success with a response body (GET, PUT returning data).
**23.2 What does 201 Created mean?** A new resource was created (POST); include `Location` header.
**23.3 What does 204 No Content mean?** Success, nothing to return (DELETE, PUT).
**23.4 What does 400 Bad Request mean?** Client sent invalid/malformed/invalid-shaped data.
**23.5 What does 401 Unauthorized mean?** Not authenticated — missing/invalid/expired token or bad credentials.
**23.6 What does 403 Forbidden mean?** Authenticated, but not permitted.
**23.7 What does 404 Not Found mean?** Resource/route doesn't exist.
**23.8 What does 409 Conflict mean?** Request conflicts with current state (duplicate email, concurrency).
**23.9 What does 500 Internal Server Error mean?** Unexpected server-side failure (bug/unhandled exception).

**23.10 Difference between 401 and 403?**
401 = "who are you?" (identity missing/invalid). 403 = "you can't do that" (identity known, no permission).

**23.11 Difference between 400 and 422?**
400 = request is malformed or fails basic binding/validation. 422 = syntactically valid but semantically/business-invalid. ASP.NET Core's `[ApiController]` uses 400 by default; some teams use 422 for business rules.

**23.12 Scenario: Login credentials are incorrect. Which status code would you return?**
**401 Unauthorized** with a generic message ("Invalid email or password") — don't reveal which was wrong.

**23.13 Scenario: User is authenticated but doesn't have Admin permission. Which status code?**
**403 Forbidden.**

**23.14 Scenario: Email already exists. Which status code could represent this conflict?**
**409 Conflict** (some teams use 400/422).

**23.15 Scenario: Requested User ID doesn't exist. Which status code?**
**404 Not Found.**

# 24. Swagger / Postman

**24.2 Why is Swagger useful?**

**24.4 Swagger vs Postman?**

# 25. Debug 500 / 401 / 403 / 404 / CORS

**25.1 What does HTTP 500 indicate?** The server hit an unexpected error while processing a valid request.

**25.2 What steps would you take to debug a 500 error?**
1. Get TraceId/time from the response. 2. Read server logs/stack trace + inner exception. 3. Reproduce with the same request (Postman). 4. Common causes: null reference, unregistered service, DB/migration problem, bad connection string, unhandled constraint violation, bad config/secret. 5. Debug with breakpoints/dev exception page locally. 6. Fix, add test, add handling/logging.

**25.3 What does HTTP 401 indicate?** Caller is not authenticated.

**25.4 What causes a 401 error?** Missing token, wrong format, expired token, invalid signature/issuer/audience, wrong credentials, `UseAuthentication` missing/misordered.

**25.5 What does HTTP 403 indicate?** Authenticated but not authorized.

**25.6 What causes a 403 error?** Missing role/claim, role name mismatch, policy failure, token issued before role change, ownership rule, IP/CORS-like gateway rules.

**25.7 What does HTTP 404 indicate?** Route or resource not found.

**25.8 What causes a 404 error?** Wrong URL/version/casing issues in route template, wrong HTTP verb pattern, missing `MapControllers()`/`[Route]`, route constraint mismatch, wrong base path behind proxy, record truly doesn't exist.

**25.9 What causes a CORS error?** Origin not allowed by API policy, `UseCors` missing/misplaced, headers/methods not allowed, preflight failing, credentials misconfigured.

**25.10 Scenario: GET /api/Users/10 returns 404.**
Is it route-404 or data-404? Read the body: empty body usually = route not matched (check `[Route]`, controller name `UsersController` vs `UserController`, `{id}` parameter name matching, `MapControllers()`, API version prefix); a JSON message = user 10 doesn't exist (query DB). **25.11 Scenario: API returns 401 even though JWT exists.**

**25.12 Scenario: API returns 403 for Admin.**

**25.13 Scenario: POST API returns 500.**

**25.15 Practical: Given a broken API, explain your debugging process step-by-step.**

# 26. Design Users, Roles, UserRoles

**26.1 Why separate Users and Roles tables?**
Users and roles are different things with different lifecycles. Roles are reusable definitions ("Admin"); users are people. Storing role text inside Users duplicates data, causes typos ("admin"/"Admin"), and makes renaming/adding roles hard.

**26.2 Why do we need UserRoles?**
To connect users and roles. A user can have many roles and a role can belong to many users — a single column can't represent that.

**26.3 What is a many-to-many relationship?**
Many rows in A relate to many rows in B (Students ↔ Courses, Users ↔ Roles). Relational DBs implement it with a junction table.

**26.4 Can a User have multiple Roles?** Yes (Rahul = Admin + Faculty).

**26.5 Can a Role have multiple Users?** Yes (Admin role assigned to many users).

**26.6 Why is UserRoles used as a junction table?**
It holds one row per (User, Role) pair, splitting many-to-many into two one-to-many relations, and can store extra info (`AssignedAt`, `AssignedBy`).

**26.7 Design: Users, Roles, UserRoles**
```sql
Users     (UserId INT PK IDENTITY, FullName NVARCHAR(100), Email NVARCHAR(200) UNIQUE, PasswordHash NVARCHAR(MAX), IsActive BIT, CreatedAt DATETIME2)
Roles     (RoleId INT PK IDENTITY, RoleName NVARCHAR(50) UNIQUE)
UserRoles (UserId INT FK→Users, RoleId INT FK→Roles, AssignedAt DATETIME2, PRIMARY KEY (UserId, RoleId))
```

**26.8 What should the primary keys be?**
Users: `UserId`. Roles: `RoleId`. UserRoles: **composite** (`UserId`, `RoleId`) (or a surrogate `UserRoleId` plus a unique index on the pair).

**26.9 What should the foreign keys be?**
`UserRoles.UserId → Users.UserId` and `UserRoles.RoleId → Roles.RoleId`.

**26.10 Should UserRoles allow duplicate User/Role combinations?**
No — "Rahul is Admin" twice has no meaning.

**26.11 How would you prevent duplicate UserRole assignments?**
Composite primary key (or unique index) on (UserId, RoleId) **plus** a service check:
```csharp
if (await _db.UserRoles.AnyAsync(x => x.UserId == userId && x.RoleId == roleId)) return Conflict("Role already assigned");
```

**26.12 Practical: Create EF Core models for all three tables.**
See "Shared models" at the top of this file (`User`, `Role`, `UserRole`). Add `AssignedAt` if needed.

**26.13 Practical: Configure relationships using Fluent API.**
```csharp
mb.Entity<UserRole>(e =>
{
    e.HasKey(x => new { x.UserId, x.RoleId });
    e.HasOne(x => x.User).WithMany(u => u.UserRoles).HasForeignKey(x => x.UserId).OnDelete(DeleteBehavior.Cascade);
    e.HasOne(x => x.Role).WithMany(r => r.UserRoles).HasForeignKey(x => x.RoleId).OnDelete(DeleteBehavior.Cascade);
});
```

**26.14 Scenario: Rahul is Admin and Faculty. How will you represent this?**
```
Users:     (1, "Rahul", ...)
Roles:     (1, Admin) (2, Faculty) (3, Student)
UserRoles: (UserId=1, RoleId=1) , (UserId=1, RoleId=2)
```
JWT gets two role claims; `[Authorize(Roles="Admin")]` and `[Authorize(Roles="Faculty")]` both pass.

# 27. Delete Role Without Deleting User

**27.1 What happens when a Role is deleted?**
The role row is removed; every UserRole row pointing to it must be handled (deleted via cascade, or the delete is blocked).

**27.2 What should happen to its UserRoles?**
They should be **deleted** (a link to a non-existing role is meaningless).

**27.3 Should the corresponding User be deleted?**
**No.** Users exist independently; they just lose that role.

**27.4 Why should UserRole → User not cascade when deleting a Role?**
Cascade only travels from a parent to its children. UserRole is a *child* of both User and Role; deleting Role deletes its UserRole children, but a child's deletion never deletes its other parent (User). If instead you modeled `User.RoleId` (User as child of Role) with cascade, deleting a Role would delete Users — that's the mistake to avoid.

**27.5 How would you configure Role → UserRole cascade?**
```csharp
.HasOne(x => x.Role).WithMany(r => r.UserRoles).HasForeignKey(x => x.RoleId).OnDelete(DeleteBehavior.Cascade);
```

**27.6 How would you configure User → UserRole cascade?**
```csharp
.HasOne(x => x.User).WithMany(u => u.UserRoles).HasForeignKey(x => x.UserId).OnDelete(DeleteBehavior.Cascade);
```
(SQL Server allows both because they are two different parents without a cycle.)

**27.7 Explain this configuration**
```csharp
modelBuilder.Entity<UserRoleModel>()
    .HasOne(x => x.Role)
    .WithMany(x => x.UserRoles)
    .HasForeignKey(x => x.RoleId)
    .OnDelete(DeleteBehavior.Cascade);
```
- `Entity<UserRoleModel>()` → configure the UserRole table.
- `.HasOne(x => x.Role)` → each UserRole has exactly one Role.
- `.WithMany(x => x.UserRoles)` → each Role has many UserRoles.
- `.HasForeignKey(x => x.RoleId)` → the FK column is `RoleId`.
- `.OnDelete(Cascade)` → deleting a Role automatically deletes all UserRole rows with that RoleId.

**27.8 What happens when RoleId = 1 is deleted?**
The `Roles` row with id 1 is deleted and all `UserRoles` rows where RoleId = 1 are deleted automatically.

**27.9 What happens to Users?**
Nothing — all Users stay, they just no longer have role 1.

**27.10 What happens to UserRoles?**
Rows for RoleId = 1 are removed; rows for other roles remain.

**27.11 Practical: Implement Delete Role API without deleting users.**
```csharp
[Authorize(Roles = "Admin")]
[HttpDelete("{id:int}")]
public async Task<IActionResult> DeleteRole(int id)
{
    var role = await _db.Roles.FirstOrDefaultAsync(r => r.RoleId == id);
    if (role is null) return NotFound(new { message = "Role not found" });
    if (role.RoleName == "Admin") return Conflict(new { message = "Admin role cannot be deleted" });   // business rule

    _db.Roles.Remove(role);              // cascade removes UserRoles only
    await _db.SaveChangesAsync();
    return NoContent();
}
```
Explicit alternative inside a transaction: `await _db.UserRoles.Where(x => x.RoleId == id).ExecuteDeleteAsync();` then remove role.

**27.12 Debugging: Deleting Role deletes Users. Find the relationship/configuration mistake.**
Look for: `User` has a required `RoleId` FK to Role with `DeleteBehavior.Cascade` (default for required FKs!) — Users became children of Role. Or Fluent API configured `HasOne(x => x.User).WithMany(...)` incorrectly pointing at the wrong principal; or a service doing `RemoveRange(role.Users)`; or a DB trigger. Verify via `sys.foreign_keys` and the model snapshot. Fix: use the junction table (UserRoles), or change User→Role to `Restrict`, create migration and retest.

# 28. Protect Sensitive Fields Using DTOs

**28.1 Which User fields are sensitive?**
Password/PasswordHash, security stamp/refresh tokens, OTPs, reset tokens, mobile/email (PII — expose only when needed), address, IDs like Aadhaar/SSN, internal flags (`IsAdmin`), audit/internal columns.

**28.2 Why shouldn't Password be returned from an API?**
Anyone calling the API (or reading browser dev tools) would see it; leaks lead to account takeover and credential stuffing. Passwords should be stored hashed and never retrievable.

**28.3 Should PasswordHash be returned?**
No. Hashes can be cracked offline; there's no reason for a client to ever have them.

**28.4 How can DTOs hide sensitive database fields?**
The response DTO simply doesn't contain them, and mapping/projection only copies safe fields.

**28.5 What is over-posting?**
A client sends extra JSON fields (`"roleId": 1, "isAdmin": true, "userId": 5`) and model binding sets them on your entity (mass assignment).

**28.6 How can DTOs prevent over-posting?**
Request DTOs only contain allowed fields; sensitive fields are set by the server.

**28.7 Practical: Create UserCreateDto, UserUpdateDto, UserResponseDto**
```csharp
public class UserCreateDto
{
    [Required, StringLength(100)] public string FullName { get; set; } = "";
    [Required, EmailAddress] public string Email { get; set; } = "";
    [Required, MinLength(8)] public string Password { get; set; } = "";
    [RegularExpression(@"^\d{10}$")] public string? MobileNumber { get; set; }
}
public class UserUpdateDto
{
    [Required, StringLength(100)] public string FullName { get; set; } = "";
    [RegularExpression(@"^\d{10}$")] public string? MobileNumber { get; set; }
}
public class UserResponseDto
{
    public int UserId { get; set; }
    public string FullName { get; set; } = "";
    public string Email { get; set; } = "";
    public string? MobileNumber { get; set; }
    public string? ProfilePictureUrl { get; set; }
    public DateTime CreatedAt { get; set; }
}
```

**28.8 Why shouldn't UserId necessarily be accepted from a client during creation?**
It's generated by the DB (identity). Accepting it enables overwriting existing users or creating IDs the client shouldn't control (insecure direct object manipulation). For updates, the id comes from the **route** and is authorized against the current user.

**28.9 Why should password hashing happen before database storage?**
So the DB never contains plain passwords — a DB leak/backup/insider can't reveal them. Use salted slow hashing (BCrypt/Argon2/PBKDF2).
```csharp
user.PasswordHash = BCrypt.Net.BCrypt.HashPassword(dto.Password);
```

**28.10 Scenario: Database has UserId, FullName, Email, Password, MobileNumber, ProfilePicturePath, CreatedAt, UpdatedAt — design a safe API response.**
Table column `Password` should actually be `PasswordHash` and **excluded**. Safe response:
```json
{
  "userId": 12,
  "fullName": "Rahul Sharma",
  "email": "rahul@example.com",
  "mobileNumber": "98xxxxxx10",
  "profilePictureUrl": "https://cdn.app.com/profiles/12.jpg",
  "createdAt": "2026-10-01T10:00:00Z"
}
```
- `ProfilePicturePath` → convert internal file path to a public URL (don't leak server paths).
- `UpdatedAt` optional (audit info, include only if UI needs it).
- Mask mobile for list screens if required.

# 29. Logging

**29.1 What is logging?** Recording events (what happened, when, where) so you can monitor and troubleshoot.

**29.2 Why is logging important in Web APIs?** Production debugging, auditing, security monitoring, performance analysis; you can't attach a debugger to production.

**29.3 What is ILogger<T>?** Built-in generic logging interface; `T` becomes the log category (usually the class name).

**29.4 How do you inject ILogger?**
```csharp
public class UserService
{
    private readonly ILogger<UserService> _logger;
    public UserService(ILogger<UserService> logger) => _logger = logger;
}
```

**29.5 What log levels are available?** Trace, Debug, Information, Warning, Error, Critical (and None).

**29.6 Explain Trace, Debug, Information, Warning, Error, Critical.**
- **Trace**: extremely detailed (may include sensitive data) — dev only.
- **Debug**: diagnostic info for developers.
- **Information**: normal business flow ("User created").
- **Warning**: unexpected but recoverable ("Retry 2/3", slow query).
- **Error**: operation failed (exception caught).
- **Critical**: system down/data loss risk (DB unreachable).

**29.7 When should you use LogInformation()?** Key business events and request milestones: user registered, order placed, job started/finished.

**29.8 When should you use LogError()?** When an operation fails with an exception — pass the exception: `_logger.LogError(ex, "Failed to create user {Email}", email)`.

**29.9 Should passwords be logged?** Never (not even hashed). Also avoid logging full request bodies containing them.

**29.10 Should JWT tokens be logged?** No — anyone with log access could impersonate users. Log `userId`/`jti` instead.

**29.11 Practical: Add logging to User Service.**
```csharp
public async Task<UserResponseDto> CreateAsync(UserCreateDto dto)
{
    _logger.LogInformation("Creating user with email {Email}", dto.Email);
    if (await _repo.EmailExistsAsync(dto.Email))
    {
        _logger.LogWarning("Duplicate registration attempt for {Email}", dto.Email);
        throw new ConflictException("Email already registered");
    }
    var user = ...; await _repo.AddAsync(user); await _repo.SaveChangesAsync();
    _logger.LogInformation("User {UserId} created", user.UserId);
    return Map(user);
}
```
(Use structured placeholders `{Email}`, not string concatenation/interpolation.)

**29.12 Practical: Log DbUpdateException.**
```csharp
catch (DbUpdateException ex)
{
    _logger.LogError(ex, "Database update failed while saving user {Email}. Inner: {Inner}", dto.Email, ex.InnerException?.Message);
    throw;
}
```

**29.13 Scenario: Production API returns 500. What logs would you inspect?**
Application logs (Serilog files/Seq/ELK/App Insights) for the exception at that time and TraceId; web server logs (IIS/Kestrel/Nginx); SQL Server logs/slow-query data; hosting platform logs (Azure App Service, container logs); health-check and deployment history (did a release just happen?).

**29.14 How would you correlate logs with a particular API request?**
Use a **correlation/trace id**: `HttpContext.TraceIdentifier` (or `Activity.TraceId`) or an `X-Correlation-ID` header. Add it to every log via a logging scope/Serilog `LogContext`, and return it in the error response so support can search for it.
```csharp

```

# 30. Complete HTTP Request Lifecycle

**30.1 Explain the complete lifecycle of an HTTP request in ASP.NET Core.**
1. Client sends HTTP request. 2. **Kestrel** accepts it and builds `HttpContext`. 3. Request enters the **middleware pipeline** (exception handler → HTTPS redirect → static files → routing → CORS → authentication → authorization → endpoint). 4. **Routing** selects the controller action. 5. Model binding + validation. 6. Filters → **controller action** runs (calls service → repository → DB). 7. Result (`IActionResult`) is executed/serialized to JSON. 8. Response travels back through middleware in reverse order. 9. Kestrel sends it to the client.

**30.2 What happens when React calls GET https://localhost:7125/api/Role?**
Browser (React/Axios/fetch) sends (maybe a preflight `OPTIONS` first, if headers like `Authorization` are present) → Kestrel on port 7125 (TLS) → middleware: HTTPS ✓, routing matches `RoleController.GetAll`, CORS adds headers, JWT validated, authorization checked → controller → service → EF Core → SQL Server `SELECT` → list serialized as JSON `200 OK` with CORS headers → React receives and renders.

**30.3 What is Kestrel?** Cross-platform built-in web server that listens for HTTP requests and hands them to the ASP.NET Core pipeline.

**30.4 What is middleware?** A pipeline component handling requests/responses and optionally calling the next component.

**30.5 What is the middleware pipeline?** The ordered chain of middleware; order of registration = order of execution; the response travels back in reverse.

**30.6 What does UseHttpsRedirection() do?** Redirects HTTP requests to HTTPS (307/308) so traffic is encrypted.

**30.7 What does UseCors() do?** Applies the CORS policy: adds `Access-Control-Allow-*` headers and answers preflight `OPTIONS` requests.

**30.8 What does UseAuthentication() do?** Reads credentials (JWT in the header), validates them, and sets `HttpContext.User` (who the caller is). Doesn't block by itself.

**30.9 What does UseAuthorization() do?** Evaluates `[Authorize]` roles/policies against `HttpContext.User`; returns 401 (challenge) or 403 (forbid) if not satisfied.

**30.10 What does MapControllers() do?** Registers controller actions as endpoints so routing can match requests to them.

**30.11 When does routing occur?** After `UseRouting()` (implicit in minimal hosting before endpoint execution) — selects the endpoint; middleware after it (CORS, auth) can read endpoint metadata like `[Authorize]`.

**30.12 When does authentication occur?** In `UseAuthentication()`, after routing/CORS and before authorization.

**30.13 When does authorization occur?** In `UseAuthorization()`, right after authentication and before the endpoint executes (resource/action filters can also authorize).

**30.14 When does controller execution occur?** At the end of the pipeline when the endpoint middleware runs the matched action, after model binding and validation.

**30.15 How does the response travel back to React?** The action's result is serialized (JSON), passes back through the middleware in reverse (CORS/headers/exception handling can modify), Kestrel writes status + headers + body over the connection; the browser applies CORS checks and hands the data to React's promise.

**30.16 Explain the request lifecycle with JWT authentication.**
React logs in → gets JWT → sends `Authorization: Bearer <jwt>` → CORS passes → `UseAuthentication` validates signature/issuer/audience/expiry and builds the `ClaimsPrincipal` → `UseAuthorization` checks role/policy → controller runs → 200. Invalid/missing token → 401; valid but not allowed → 403.

**30.17 Explain the request lifecycle when CORS fails.**
React sends a preflight `OPTIONS` → no matching CORS policy → server responds without `Access-Control-Allow-Origin` → browser **blocks** the actual request/response → React sees a network/CORS error (the server may never run your action). Server logs may show only the OPTIONS call.

**30.18 Explain the request lifecycle when authorization returns 403.**
Request reaches `UseAuthentication` → user identified (valid JWT) → `UseAuthorization` evaluates `[Authorize(Roles="Admin")]` → user lacks the role → pipeline short-circuits with **403 Forbidden** → controller is never executed → response goes back through CORS/exception middleware to React, which should show "Access denied".

# ⭐ Scenario-Based Interview Questions

**S1. Your API returns all database columns, including Password. How would you fix it?**
Introduce `UserResponseDto` without password; project with `Select`; stop returning entities; rename column to `PasswordHash`; add `[JsonIgnore]` as backup; add a test; rotate/force-reset passwords if the leak reached production and check logs for exposure.

**S2. A Role is deleted and all Users are also deleted. What is wrong?**
Users are modeled as children of Role with cascade (e.g., `User.RoleId` required + Cascade). Fix by using a `UserRoles` junction table with cascade only on UserRole→Role/User, or use `Restrict` on User→Role (see 27.12).

**S3. Your React application gets CORS error but Swagger works. What would you check?** See 16.12.

**S4. Login succeeds, but the next API request returns 401. Explain your debugging approach.**
Is the token saved and attached (React interceptor/Network tab shows `Authorization` header)? Format `Bearer <token>`? Expired? Same issuer/audience/key? Middleware order? Read `WWW-Authenticate` header. Decode token. Reproduce in Postman with the same token.

**S5. Login succeeds and JWT is valid, but Admin API returns 403. Why?** Role claim missing/mismatched/old token (see 9.17, 25.12).

**S6. Your API returns 500 when inserting a duplicate email. How would you handle it?** Service pre-check → 409; unique index; catch `DbUpdateException` (2601/2627) → 409 (see 18.8).

**S7. Your GET API returns 100,000 records and is slow. How would you optimize it?** Pagination + max page size, `AsNoTracking`, projection to DTOs, filters/search server-side, indexes, remove unneeded `Include`, compress responses, cache, or stream/export in background.

**S8. Your database contains duplicate emails. How would you prevent new duplicates?** First clean existing duplicates (group by email, merge/rename/delete), then add a unique index, add service checks and exception handling:
```sql
SELECT Email, COUNT(*) FROM Users GROUP BY Email HAVING COUNT(*) > 1;
```

**S9. Your Include() query is returning too much data. How would you optimize it?** Use `Select` projection into DTOs, filtered includes (`Include(u => u.Orders.Where(...))`), `AsSplitQuery`, pagination, and only include what the endpoint needs.

**S10. Your API has 20 controllers containing duplicate database logic. How would you redesign it?** Extract shared queries into repositories/services (or query objects/specifications), register by interface via DI, keep controllers thin, add generic helpers (paging/sorting extensions), cover with tests before refactoring, migrate controller by controller.

**S11. A developer puts all business logic inside the Controller. What problems can this cause?** Hard to unit test, duplicated rules, tight coupling to HTTP, bloated unreadable controllers, risk when reusing logic in jobs/other endpoints, harder maintenance and team collaboration.

**S12. A developer directly returns EF Core entities from every endpoint. What problems can this cause?** Sensitive data leaks, circular references, over-fetching, tight coupling to DB schema, breaking changes when schema changes, over-posting on input, lazy-loading performance issues.

**S13. An API accepts UserId, Password, RoleId, and other fields directly from the client. What security concerns do you see?** Mass assignment/privilege escalation (client sets RoleId=Admin), identity spoofing via UserId (IDOR), plain-text password handling, no hashing, overwriting other users' data. Fix: DTOs, server-set roles, take identity from JWT claims, hash passwords, authorization checks.

**S14. Your API works synchronously but becomes slow with many simultaneous users. What would you investigate?** Thread-pool starvation from blocking calls (`.Result`, sync EF), slow queries/missing indexes, DB connection pool exhaustion, N+1, lack of caching, external calls without timeouts. Convert to async, add indexes, cache, measure with load tests/`dotnet-counters`.

**S15. Your migration fails because an index already exists. How would you investigate the database/migration state?** Compare `__EFMigrationsHistory` to the Migrations folder, inspect actual indexes (`sys.indexes`), check for manual changes or duplicate index configuration in the model, generate SQL (`dotnet ef migrations script`) to review, then drop/rename the duplicate or baseline the database and create a corrective migration.

**S16. Your API returns 404 even though the controller exists. What would you check?** Route template/controller name, `MapControllers()`, `[ApiController]`/`[Route]`, HTTP verb attribute, route constraints (`{id:int}`), API version prefix, reverse proxy base path, `app.UseRouting()` order, controller in a different assembly not registered (`AddApplicationPart`), correct port/environment.

**S17. Your API returns 405 Method Not Allowed. What could be wrong?** Route exists but not for that verb: calling POST on a `[HttpGet]` action, missing `[HttpPut]`, IIS WebDAV module blocking PUT/DELETE, CORS preflight with disallowed method, wrong URL matching another action with a different verb, redirect from HTTP→HTTPS turning POST into GET.

**S18. Your POST request returns 415 Unsupported Media Type. What would you check?** `Content-Type` header missing or not `application/json` (e.g., `text/plain` or form-data); body format mismatches an `[FromBody]` expectation; missing JSON formatter/custom `Consumes` attribute; sending JSON to an `[FromForm]` action.

**S19. Your API returns 400 before reaching the controller. Why could this happen?** `[ApiController]` auto-validation failed; invalid JSON syntax or type mismatch (string → int); missing required body; invalid route constraint/binding failure; request body too large; a global filter/middleware returning 400; antiforgery or header validation; malformed query string.

# 🎯 Senior-Level Follow-Up Questions

**Repository Pattern vs direct DbContext — when would you use each?**
EF Core's `DbContext` already implements repository + unit-of-work. Use **direct DbContext** (in services/handlers) for small-to-medium apps — simpler, full EF power. Use **repositories** when you need to swap data sources, strongly isolate domain from persistence, share complex queries, or enable easy mocking (or use integration tests with a real DB instead).

**Why can an unnecessary Repository + Service abstraction become problematic?**
Extra layers with pass-through methods, duplicate code (`GetById` everywhere), leaky abstractions hiding `Include`/projection, harder to optimize queries, more files with no real value ("anemic" layers), slower onboarding.

**What is the difference between Entity tracking and no-tracking queries?**
Tracking: EF stores entities and original values to detect changes (needed for updates). No-tracking: results aren't stored — faster and lighter for reads (see topic 22).

**What is IQueryable vs IEnumerable?**
`IQueryable` builds an expression tree translated to SQL and executed in the DB. `IEnumerable` runs in memory over already-loaded data. Filtering an `IQueryable` filters in SQL; an `IEnumerable` filters after loading everything.

**When does an EF Core LINQ query actually execute?**
When you enumerate or use an immediate operator: `ToList(Async)`, `First*`, `Single*`, `Count`, `Any`, `Sum`, `foreach`, `ToQueryString` (doesn't execute, only shows SQL).

**What is deferred execution?**
Query definition and execution are separate; building `Where/Select/OrderBy` doesn't hit the DB. It runs later on enumeration — so changes to data between definition and execution affect the result.

**Why should filtering happen in the database rather than after ToList()?**
Moves only needed rows over the network, uses indexes, less memory/CPU in the API. Filtering after `ToList()` loads the whole table first.

**What is projection using Select()?**
Choosing exactly which columns/shape to return (usually DTO) — SQL `SELECT` only those columns.

**Why can DTO projection be better than multiple Include() calls?**
One lean query with only needed columns, no tracking overhead, no giant joins/duplicate rows, no sensitive columns, and shape matches the API.

**What is the N+1 query problem?**
One query for the parent list + one extra query per parent for children (lazy loading in a loop) → 1+N queries.

**How can you detect and prevent N+1 queries?**
Detect: EF logging/`ToQueryString`, SQL Profiler, MiniProfiler, Application Insights dependency counts, tests counting queries. Prevent: `Include`, projection with `Select`, disable lazy loading, `AsSplitQuery`, batch by IDs (`Where(x => ids.Contains(x.Id))`).

**What is optimistic concurrency?**
Detect conflicting updates with a concurrency token (`RowVersion`) instead of locking; if the row changed since read, `SaveChanges` throws `DbUpdateConcurrencyException`.

**How would you handle two users updating the same database record?**
Add `[Timestamp] byte[] RowVersion`; client sends the version back with the update; on `DbUpdateConcurrencyException` return **409 Conflict** (or 412 Precondition Failed with ETag/If-Match) and let the user reload/merge, or apply a "last write wins"/merge policy.
```csharp
try { await _db.SaveChangesAsync(); } catch (DbUpdateConcurrencyException) { return Conflict("Record was modified by someone else. Please reload."); }
```

**What is a database transaction?**
A group of operations executed atomically (ACID): all succeed or all are rolled back.

**When would you use BeginTransactionAsync()?**
When you need multiple `SaveChanges` calls, raw SQL plus EF, or multiple operations across several repositories to succeed together (transfer money, create user + assign roles + write audit). A single `SaveChanges` is already transactional.
```csharp
await using var tx = await _db.Database.BeginTransactionAsync();
try { /* steps */ await _db.SaveChangesAsync(); await tx.CommitAsync(); } catch { await tx.RollbackAsync(); throw; }
```

**What is the difference between authentication and authorization?** Authentication verifies identity; authorization verifies permission (see 9.10).

**JWT vs Cookie Authentication?**
| JWT (Bearer) | Cookie |
|---|---|
| Stateless, in `Authorization` header | Session cookie sent automatically |
| Great for SPAs/mobile/microservices | Great for same-site server-rendered apps |
| Must store token safely (XSS risk if localStorage) | httpOnly cookie safer from XSS but needs CSRF protection |
| Harder to revoke (use short expiry + refresh) | Easy server-side revoke |

**Access Token vs Refresh Token?** Access = short-lived, used on every API call. Refresh = long-lived, stored securely, only used to obtain new access tokens, revocable in DB.

**Where should JWT secrets be stored in production?** Azure Key Vault/AWS Secrets Manager/HashiCorp Vault or environment variables injected by the platform — never in Git/appsettings. Rotate regularly; consider asymmetric keys (RS256).

**How would you secure an ASP.NET Core API in production?**
HTTPS + HSTS; JWT with short expiry and refresh tokens; role/policy authorization + ownership checks; DTO + validation; CORS exact origins; rate limiting; secrets in Key Vault; parameterized queries; global exception handler without stack traces; security headers; logging/monitoring/alerts; dependency updates; least-privilege DB user; password hashing (BCrypt/Argon2).

**What is rate limiting?**
Restricting how many requests a client can make in a time window (protects from abuse/DoS/brute force).
```csharp
builder.Services.AddRateLimiter(o => o.AddFixedWindowLimiter("login", x => { x.PermitLimit = 5; x.Window = TimeSpan.FromMinutes(1); }));
app.UseRateLimiter();
[EnableRateLimiting("login")] [HttpPost("login")] public IActionResult Login(...) { }
```

**How would you prevent brute-force login attempts?**
Rate limit login by IP+email, progressive delays, account lockout after N failures (ASP.NET Identity), CAPTCHA after failures, MFA, generic error messages, monitor/alert on failed logins, strong password policy.

**How would you version a Web API?** URL path `/api/v1/...` (most common), query string, header or media type, using `Asp.Versioning`; keep old versions until clients migrate; deprecate with notice.

**What is API versioning and why is it useful?** Running multiple contract versions side by side so you can make breaking changes without breaking existing clients (mobile apps that can't update instantly).

**What is idempotency?** Repeating the same request gives the same server state as sending it once.

**Which HTTP methods are idempotent?** GET, PUT, DELETE, HEAD, OPTIONS (POST and PATCH are not guaranteed).

**Why should PUT generally be idempotent?** Clients/proxies may retry on timeouts; if PUT replaces the full resource, retries are safe. (For POST use an `Idempotency-Key` header, e.g., payments.)

**PUT vs PATCH?** PUT replaces the whole resource; PATCH changes only specific fields. PUT = send full user; PATCH = `{ "mobileNumber": "999" }`.

**How would you implement soft delete?**
Add `IsDeleted` (and `DeletedAt`); delete = set flag; use a global query filter so normal queries hide deleted rows.
```csharp
public bool IsDeleted { get; set; }
mb.Entity<User>().HasQueryFilter(u => !u.IsDeleted);
// delete
user.IsDeleted = true; user.DeletedAt = DateTime.UtcNow; await _db.SaveChangesAsync();
// see deleted: _db.Users.IgnoreQueryFilters()
```
Remember unique indexes (filtered unique index `WHERE IsDeleted = 0`).

**Soft delete vs hard delete?**
Soft: keeps data for audit/restore, safer, but table grows, needs filters, unique-constraint care, privacy (GDPR) issues. Hard: permanently removes, simpler/smaller, but irreversible and may break references.

### F2. Design Users, Roles and UserRoles tables and explain all relationships.

### F8. Implement pagination + search + filtering + sorting in one API endpoint.
```csharp
public class UserQueryParams { public int PageNumber {get;set;}=1; public int PageSize {get;set;}=10; public string? Search {get;set;} public string? Role {get;set;} public bool? IsActive {get;set;} public string? SortBy {get;set;} public string SortOrder {get;set;}="asc"; }

public async Task<PagedResult<UserResponseDto>> GetAllAsync(UserQueryParams p)
{
    p.PageNumber = Math.Max(1, p.PageNumber); p.PageSize = Math.Clamp(p.PageSize, 1, 100);
    var q = _db.Users.AsNoTracking().AsQueryable();
    if (!string.IsNullOrWhiteSpace(p.Search)) q = q.Where(u => u.FullName.Contains(p.Search) || u.Email.Contains(p.Search));
    if (!string.IsNullOrWhiteSpace(p.Role))   q = q.Where(u => u.UserRoles.Any(r => r.Role.RoleName == p.Role));
    if (p.IsActive.HasValue)                  q = q.Where(u => u.IsActive == p.IsActive);
    var total = await q.CountAsync();
    var desc = p.SortOrder.Equals("desc", StringComparison.OrdinalIgnoreCase);
    q = p.SortBy?.ToLower() switch
    {
        "name"    => desc ? q.OrderByDescending(u => u.FullName) : q.OrderBy(u => u.FullName),
        "email"   => desc ? q.OrderByDescending(u => u.Email)    : q.OrderBy(u => u.Email),
        "created" => desc ? q.OrderByDescending(u => u.CreatedAt): q.OrderBy(u => u.CreatedAt),
        _         => q.OrderBy(u => u.UserId)
    };
    var items = await q.Skip((p.PageNumber - 1) * p.PageSize).Take(p.PageSize)
        .Select(u => new UserResponseDto { UserId = u.UserId, FullName = u.FullName, Email = u.Email, MobileNumber = u.MobileNumber, CreatedAt = u.CreatedAt }).ToListAsync();
    return new PagedResult<UserResponseDto> { Items = items, Page = p.PageNumber, PageSize = p.PageSize, TotalCount = total };
}
// GET /api/users?search=rahul&role=Admin&isActive=true&sortBy=name&sortOrder=desc&pageNumber=2&pageSize=20
```

### F12. Explain the difference between 401, 403, 404, 409 and 500 using real API scenarios.
- **401** — calling `GET /api/users` with no token, or a wrong password at login.
- **403** — a Student's valid token calls `DELETE /api/users/5` (Admin only).

### F15. Explain the complete lifecycle of a JWT-authenticated HTTP request from React → ASP.NET Core → Controller → Service → Repository → SQL Server → React.
1. React (Axios) builds `GET /api/users?pageNumber=1` with `Authorization: Bearer <jwt>`. Browser may send a preflight `OPTIONS`.
2. **Kestrel** receives it over TLS, creates `HttpContext`.
3. Pipeline: exception middleware → HTTPS redirect → routing → **CORS** (adds headers) → **Authentication** (validates JWT, sets `User`) → **Authorization** (checks `[Authorize(Roles)]`).
4. Endpoint executes: model binding + validation → `UsersController.GetAll`.
5. Controller calls `IUserService.GetAllAsync`.
6. Service applies rules/mapping → calls `IUserRepository`.
7. Repository builds an EF Core LINQ query → EF translates to SQL → **SQL Server** executes (parameterized) → rows returned.
8. EF materializes entities/DTOs → service maps to `UserResponseDto` → controller returns `Ok(result)`.
9. Result is serialized to JSON (`200 OK`), back through middleware (CORS headers, logging), Kestrel sends it.
10. Browser CORS check passes → Axios resolves → React updates state and renders.
Failures: bad/missing token → 401 at step 3; wrong role → 403 at step 3; no CORS → blocked at the browser; exception anywhere → global handler → 4xx/500 JSON.

### F16. Explain the difference between Include(), ThenInclude(), Select() and AsNoTracking().
| Method | What it does | Use for |
|---|---|---|
| `Include` | Loads a related navigation (JOIN) | Need related entities |
| `ThenInclude` | Loads the next level inside an Include | Deep graph (User→UserRoles→Role) |
| `Select` | Projects chosen columns/shape (DTO) | Read-only API responses (best performance) |
| `AsNoTracking` | Skips change tracking | Read-only queries returning entities |
```csharp
var tracked   = await _db.Users.Include(u => u.UserRoles).ThenInclude(r => r.Role).ToListAsync();      // full graph, tracked
var readOnly  = await _db.Users.AsNoTracking().Include(u => u.UserRoles).ThenInclude(r => r.Role).ToListAsync();
var best      = await _db.Users.Select(u => new { u.FullName, Roles = u.UserRoles.Select(r => r.Role.RoleName) }).ToListAsync();
```

### F17. Your production API suddenly starts returning HTTP 500. Explain how you would investigate it using logs, exception handling and database checks.
1. **Triage**: scope (all endpoints or one?), start time, recent deployment/config/DB change? Use the health endpoint.
2. **Logs**: search by TraceId/time in Serilog/App Insights/Seq; find the exception type, stack trace, inner exception.
3. **Classify the cause**: `SqlException` (timeout, login failed, deadlock, missing column/migration, DB down) → check **database** (connectivity, disk space, long-running queries/blocking via `sp_who2`/Query Store, pending migrations, credentials/password rotation); `InvalidOperationException` DI error → missing registration/config; `NullReferenceException` → data/bug; secrets/Key Vault failure → config.
4. **Mitigate**: rollback release / restart / scale / fix connection string.
5. **Fix root cause**, add try/catch only where recoverable, rely on global handler for the rest.
6. **Prevent**: add a test, alert on 5xx rate, health checks, better logging, retry policy for transient DB errors (`EnableRetryOnFailure`).
