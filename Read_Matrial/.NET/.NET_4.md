### REST & HTTP Fundamentals

#### 1. What is REST, and what are its key architectural constraints?
**Explanation:**  
REST (Representational State Transfer) is an architectural style for designing networked applications. It relies on stateless, client-server, cacheable communications using standard HTTP protocols.

**6 Key Constraints:**
1. **Client-Server Separation:** UI concerns are separate from data storage concerns.
2. **Statelessness:** Every request from client to server must contain all necessary info; no client session state is saved on the server.
3. **Cacheability:** Responses must explicitly define themselves as cacheable or non-cacheable.
4. **Uniform Interface:** Standardized interaction through URIs, standard HTTP methods, and representation metadata.
5. **Layered System:** Clients cannot tell whether they are connected directly to the end server or an intermediary (like a load balancer or API Gateway).
6. **Code on Demand (Optional):** Servers can temporarily extend client functionality by transferring executable code (e.g., JavaScript).

**C# / .NET Code Usecase:**
```csharp
// ASP.NET Core Endpoint implementing Stateless REST principles
[ApiController]
[Route("api/v1/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet("{id}")]
    [ResponseCache(Duration = 60)] // Cacheability constraint
    public IActionResult GetProductById(int id)
    {
        var product = new { Id = id, Name = "Gaming Laptop", Price = 1200.00m };
        return Ok(product); // Uniform HTTP 200 response
    }
}
```

#### 2. Explain the standard HTTP methods: GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS.
**Explanation:**  
- **GET:** Retrieves a resource without altering server state.
- **POST:** Creates a new resource or triggers a processing action.
- **PUT:** Replaces an entire target resource with the request payload.
- **PATCH:** Applies partial modifications to a resource.
- **DELETE:** Removes the specified resource.
- **HEAD:** Same as GET, but returns headers only without the body.
- **OPTIONS:** Returns allowed HTTP methods and capabilities for a target URL (used heavily in CORS preflight).

**C# / .NET Code Usecase:**
```csharp
[ApiController]
[Route("api/orders")]
public class OrdersController : ControllerBase
{
    [HttpGet("{id}")]
    public IActionResult Get(int id) => Ok();

    [HttpPost]
    public IActionResult Create([FromBody] OrderDto dto) => CreatedAtAction(nameof(Get), new { id = 1 }, dto);

    [HttpPut("{id}")]
    public IActionResult Replace(int id, [FromBody] OrderDto dto) => NoContent();

    [HttpPatch("{id}")]
    public IActionResult UpdatePartial(int id, [FromBody] JsonPatchDocument<OrderDto> patch) => NoContent();

    [HttpDelete("{id}")]
    public IActionResult Delete(int id) => NoContent();

    [HttpHead("{id}")]
    public IActionResult CheckExists(int id) => Ok();

    [HttpOptions]
    public IActionResult Options() { Response.Headers.Append("Allow", "GET, POST, OPTIONS"); return Ok(); }
}
```

#### 3. What is the difference between Safe and Idempotent HTTP methods?
**Explanation:**  
- **Safe Methods:** Do not modify server state/resources (Read-only operations). Examples: `GET`, `HEAD`, `OPTIONS`.
- **Idempotent Methods:** Can be executed multiple times consecutively with the exact same side-effect on server state as executing it once. Examples: `GET`, `PUT`, `DELETE`, `HEAD`, `OPTIONS`. (`POST` is generally NOT idempotent; `PATCH` is non-idempotent by default unless designed specifically to be).

| HTTP Method | Safe | Idempotent |
| :--- | :---: | :---: |
| GET | Yes | Yes |
| HEAD | Yes | Yes |
| OPTIONS | Yes | Yes |
| PUT | No | Yes |
| DELETE | No | Yes |
| POST | No | No |
| PATCH | No | No |

#### 4. Explain the difference between PUT and PATCH HTTP operations.
**Explanation:**  
- **PUT:** Whole replacement. You send the entire entity representation. If fields are omitted in the request payload, they are typically set to null or default values in the target resource.
- **PATCH:** Partial update. You send only the fields that need updating, leaving remaining fields untouched on the server.

**C# / .NET Code Usecase:**
```csharp
// PUT: Expects Full Customer Data
[HttpPut("customers/{id}")]
public async Task<IActionResult> UpdateCustomer(int id, [FromBody] CustomerDto dto)
{
    var customer = await _db.Customers.FindAsync(id);
    customer.Name = dto.Name;
    customer.Email = dto.Email; // Replaces entire record properties
    await _db.SaveChangesAsync();
    return NoContent();
}

// PATCH: Expects Partial Changes (e.g., JSON Patch or optional fields)
[HttpPatch("customers/{id}")]
public async Task<IActionResult> PatchCustomer(int id, [FromBody] UpdateEmailDto dto)
{
    var customer = await _db.Customers.FindAsync(id);
    if (dto.Email != null) customer.Email = dto.Email; // Only updates provided field
    await _db.SaveChangesAsync();
    return NoContent();
}
```

#### 5. What are the common HTTP status code categories (1xx, 2xx, 3xx, 4xx, 5xx)?
**Explanation:**  
- **1xx (Informational):** Request received, continuing process. (e.g., 100 Continue, 101 Switching Protocols).
- **2xx (Success):** Action successfully received, understood, and accepted. (e.g., 200 OK, 201 Created, 204 No Content).
- **3xx (Redirection):** Further action needed to complete request. (e.g., 301 Moved Permanently, 304 Not Modified).
- **4xx (Client Error):** Request contains bad syntax or cannot be fulfilled due to client action. (e.g., 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found).
- **5xx (Server Error):** Server failed to fulfill an apparently valid request. (e.g., 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable).

#### 6. What is the difference between HTTP 401 Unauthorized and 403 Forbidden status codes?
**Explanation:**  
- **401 Unauthorized:** The client is **unauthenticated** (identity unknown). The request lacks valid authentication credentials. The client should authenticate and retry.
- **403 Forbidden:** The client is **authenticated**, but **unauthorized** (lacks sufficient permissions/roles) to access the specific resource. Authenticating again will not change the outcome unless user context/permissions change.

**C# / .NET Code Usecase:**
```csharp
[ApiController]
[Route("api/admin")]
public class AdminController : ControllerBase
{
    [HttpGet("reports")]
    [Authorize(Roles = "Admin")] // Returns 401 if token is missing/invalid; Returns 403 if token is valid but user is 'Manager'
    public IActionResult GetAdminReports()
    {
        return Ok("Sensitive Financial Data");
    }
}
```

#### 7. What is Content Negotiation in REST APIs, and how do Accept and Content-Type headers work?
**Explanation:**  
Content Negotiation allows clients and servers to agree on the data format (JSON, XML, CSV) transferred between them.
- **Content-Type (Request/Response Header):** Indicates the media type of the payload sent in the body of the current request/response.
- **Accept (Request Header):** Informs the server about the media formats the client is capable of receiving and understanding in response.

**C# / .NET Code Usecase:**
```csharp

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers()
    .AddXmlSerializerFormatters(); // Enables XML format in Accept/Content-Type headers

var app = builder.Build();
app.MapControllers();
app.Run();
```

#### 8. What is a URI, URL, and URN in the context of web services?
**Explanation:**  
- **URI (Uniform Resource Identifier):** The overarching standard for identifying resources.
- **URL (Uniform Resource Locator):** A type of URI that specifies *where* a resource is located and *how* to access it via protocol (e.g., `https://api.example.com/v1/users/10`).
- **URN (Uniform Resource Name):** A type of URI that identifies a resource by name in a specific namespace, without specifying location or access protocol (e.g., `urn:isbn:978-3-16-148410-0`).

```
          URI
        /     \
      URL     URN
```

#### 9. Why should REST endpoints represent resources as nouns rather than verbs?
**Explanation:**  
REST is resource-oriented. Resources represent core business entities/concepts (data). HTTP methods (`GET`, `POST`, `PUT`, `DELETE`) serve as the verbs defining the action. Using verbs in URLs leads to RPC-style APIs (e.g., `/getUserDetails`, `/deleteOrder`) which breaks uniform interface standards and caching mechanisms.

**Comparison:**
- **RPC Style (Incorrect REST):** `POST /api/createUser`, `POST /api/deleteUser?id=1`
- **RESTful Style (Correct):** `POST /api/users`, `DELETE /api/users/1`

#### 10. What is CORS (Cross-Origin Resource Sharing), and why is it enforced by web browsers?
**Explanation:**  
CORS is a browser security mechanism that restricts HTTP requests initiated from scripts running in a domain/origin (e.g., `https://frontend.com`) to a different domain/origin (e.g., `https://api.backend.com`). It prevents malicious websites from reading sensitive data from another site using existing browser credentials/cookies.

**C# / .NET Code Usecase:**
```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowFrontendApp", policy =>
    {
        policy.WithOrigins("https://myfrontend.com")
              .AllowAnyHeader()
              .AllowAnyMethod();
    });
});

var app = builder.Build();
app.UseCors("AllowFrontendApp"); // CORS middleware MUST be placed before MapControllers
app.MapControllers();
app.Run();
```

#### 12. What is CLR (Common Language Runtime) and how does managed code execution work?
**Explanation:**  
The CLR is the virtual machine execution environment for .NET applications. It handles garbage collection, JIT compilation, thread execution, memory management, and security.

**Execution Flow:**
1. C# Source Code is compiled by `csc` into **Intermediate Language (IL)** and Metadata stored in Assemblies (.dll / .exe).
2. Upon execution, the **Just-In-Time (JIT)** Compiler inside CLR translates IL code into architecture-specific machine code (x64/ARM).
3. Native machine code is executed directly by the CPU under CLR supervision (Managed Code).

#### 13. What is the difference between Value Types and Reference Types in C#?
**Explanation:**  
- **Value Types:** Store actual data directly in memory where the variable is declared (typically on the Stack or inline within an enclosing object). Copied by value. Derived from `System.ValueType` (e.g., `int`, `double`, `bool`, `char`, `struct`, `enum`).
- **Reference Types:** Store a memory address reference pointing to the object allocated on the Heap. Copied by reference address. Inherit from `System.Object` (e.g., `class`, `interface`, `delegate`, `string`, `object`).

```csharp
// Value Type
int x = 10;
int y = x; // Copy of value 10 made. Modifying y does NOT change x.

// Reference Type
Customer c1 = new Customer { Name = "Alice" };
Customer c2 = c1; // Copy of reference pointer made. Modifying c2.Name changes c1.Name!
```

#### 14. Explain Boxing and Unboxing in C# with performance implications.
**Explanation:**  
- **Boxing:** The implicit conversion of a Value Type to a Reference Type (`object` or an interface). Copies value from Stack to a newly allocated wrapper on the Heap.
- **Unboxing:** The explicit extraction of the value type from a boxed reference object back into a Value Type on the Stack.

**Performance Impact:** High GC pressure and allocation overhead due to continuous heap allocations during boxing loops.

```csharp
int val = 42;         // Value type on stack
object boxed = val;   // BOXING: Allocates memory on Heap!

int unboxed = (int)boxed; // UNBOXING: Explicit cast back to stack value

// Performance Anti-pattern:
ArrayList list = new ArrayList();
for(int i = 0; i < 10000; i++)
{
    list.Add(i); // Causes 10,000 Boxing operations! Use List<int> instead!
}
```

#### 15. What are the differences between string, String, and StringBuilder?
**Explanation:**  
- `string` vs `String`: `string` is a C# language keyword; `System.String` is the underlying .NET framework class. They are identical in compiled code.
- `string` (Immutable): Once instantiated on the heap, string objects cannot be modified. Appending strings creates new objects in memory every time.
- `StringBuilder` (Mutable): Designed for continuous dynamic string manipulations without repeated allocations. Modifies an internal array of characters.

```csharp
// Inefficient (Allocates 1000 string objects in heap memory)
string str = "";
for (int i = 0; i < 1000; i++) str += i.ToString();

// Efficient (Allocates internal buffer once or dynamically scales)
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) sb.Append(i);
string result = sb.ToString();
```

#### 16. What is the difference between const and readonly keywords in C#?
**Explanation:**  
- **`const`:** Compile-time constant. Must be initialized at declaration. Value is directly baked into assembly code during compilation. Can only be applied to primitive types/strings. Impliclty static.
- **`readonly`:** Run-time constant. Can be initialized at declaration OR inside the class **constructor**. Value can be resolved dynamically at application startup based on config or runtime state.

```csharp
public class ApplicationConfig
{
    public const string AppVersion = "1.0.0"; // Evaluated at compile time
    public readonly DateTime BootTime;         // Evaluated at runtime

    public ApplicationConfig()
    {
        BootTime = DateTime.UtcNow; // Allowed only in constructor
    }
}
```

#### 17. What are Extension Methods in C# and how do you define one?
**Explanation:**  
Extension methods allow developers to add new methods to existing existing types without modifying the original code, inheriting from it, or recompiling it.

**Rules:** Must be declared inside a `static class` and must use the `this` modifier on the first parameter type.

```csharp
public static class StringExtensions
{
    // Extension method on string type
    public static bool IsValidEmail(this string email)
    {
        if (string.IsNullOrWhiteSpace(email)) return false;
        return email.Contains("@") && email.Contains(".");
    }
}

// Usage
string userEmail = "admin@company.com";
bool isValid = userEmail.IsValidEmail(); // Called as an instance method!
```

#### 18. What is the difference between ref, out, and in parameters in C#?
**Explanation:**  
- **`ref`:** Passes argument by reference. Must be initialized *before* being passed into the method. Method can read or modify it.
- **`out`:** Passes argument by reference. Does NOT need to be initialized before calling, but MUST be assigned a value inside the method before returning.
- **`in`:** Passes argument by reference as a **read-only** parameter. Guarantees memory performance without allowing method modification.

```csharp
public class ParameterDemo
{
    public void ProcessData(ref int val, out int result, in int readOnlyVal)
    {
        val += 10;          // Allowed (ref)
        result = val * 2;   // MUST assign before method ends (out)
        // readOnlyVal = 5; // COMPILE ERROR! Cannot write to 'in' parameter
    }
}
```

#### 19. What are Nullable Types and Null-Coalescing Operators (??, ??=, ?.)?
**Explanation:**  
- **Nullable Value Types (`T?` / `Nullable<T>`):** Allows assigning `null` to value types (e.g., `int? age = null;`).
- **Null-Conditional Operator (`?.`):** Accesses member/method only if target object is not null; returns null otherwise.
- **Null-Coalescing Operator (`??`):** Returns left operand if not null; otherwise returns right operand.
- **Null-Coalescing Assignment (`??=`):** Assigns right-hand value to left-hand variable *only* if left-hand variable is null.

```csharp
string? username = GetNullableUser();

// Null-conditional & Null-coalescing combined
int length = username?.Length ?? 0;

// Null-coalescing assignment
username ??= "Default Guest";
```

#### 20. Explain the concept and usage of C# Delegates, Events, and Anonymous Functions.
**Explanation:**  
- **Delegate:** A type-safe function pointer holding a reference to methods matching a specific signature (`Func<>`, `Action<>`, `Predicate<>`).
- **Event:** A publisher-subscriber mechanism built on delegates that restricts subscribers from invoking or clearing the delegate directly.
- **Anonymous Function / Lambda:** Inline unnamed code blocks used to create delegates on the fly (`(x, y) => x + y`).

```csharp
public class OrderProcessor
{
    // Event declaration using generic EventHandler delegate
    public event Action<int>? OnOrderCompleted;

    public void ProcessOrder(int orderId)
    {
        // Business Logic
        Console.WriteLine($"Order {orderId} processed.");
        
        // Raise Event
        OnOrderCompleted?.Invoke(orderId);
    }
}

// Client Subscription
var processor = new OrderProcessor();
processor.OnOrderCompleted += (id) => Console.WriteLine($"Email confirmation sent for order: {id}");
processor.ProcessOrder(101);
```

### ASP.NET Core Web API Basics

#### 21. What is the role of Program.cs in modern ASP.NET Core applications?
**Explanation:**  
In modern ASP.NET Core (.NET 6+ minimal hosting model), `Program.cs` is the single application entry point. It configures the Dependency Injection (DI) service container, builds the `WebApplication` instance, registers middleware execution pipeline components, and boots up Kestrel server.

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();
builder.Services.AddEndpointsApiExplorer();

var app = builder.Build();

// 2. Configure HTTP Request Pipeline (Middleware)
if (app.Environment.IsDevelopment())
{
    app.UseDeveloperExceptionPage();
}
app.UseHttpsRedirection();
app.UseAuthorization();
app.MapControllers();

// 3. Run application
app.Run();
```

#### 22. What is the difference between ControllerBase and Controller in ASP.NET Core?
**Explanation:**  
- **`ControllerBase`:** Base class for Web APIs. Provides access to HTTP context, routing, user authorization, and standard action helper methods like `Ok()`, `BadRequest()`, `NotFound()`, `CreatedAtAction()`.
- **`Controller`:** Inherits from `ControllerBase` and adds built-in support for **MVC Views** (Razor, `ViewData`, `ViewBag`).
- **Best Practice:** Web APIs should always inherit directly from `ControllerBase` to avoid unused MVC overhead.

#### 23. What is the purpose of the [ApiController] attribute in ASP.NET Core Web API?
**Explanation:**  
`[ApiController]` enhances developer experience by automatically enabling REST-specific API behaviors:
1. **Automatic Model Validation:** Automatically validates request model state and returns `400 Bad Request` with standard RFC errors if validation fails (no manual `ModelState.IsValid` checks needed).
2. **Automatic Parameter Source Inference:** Automatically infers parameters source (`[FromBody]` for complex types, `[FromRoute]` for route parameters, etc.).
3. **Multipart/form-data Requirements:** Automatically infers form binding when `[FromForm]` attributes are present.

#### 24. Explain Routing in ASP.NET Core: Attribute Routing vs. Conventional Routing.
**Explanation:**  
- **Attribute Routing:** Routes are declared directly on Controller classes/Action methods using `[Route("api/[controller]")]` or `[HttpGet("details/{id}")]`. Essential for RESTful APIs.
- **Conventional Routing:** Centralized routes defined in `Program.cs` matching explicit URL pattern templates like `{controller=Home}/{action=Index}/{id?}`. Primary choice for traditional MVC apps.

```csharp
// Attribute Routing Example
[ApiController]
[Route("api/v1/products")]
public class ProductsController : ControllerBase
{
    [HttpGet("{id:int}")] // Attribute Route with constraint
    public IActionResult GetProduct(int id) => Ok();
}
```

#### 25. What are Parameter Binding sources in ASP.NET Core ([FromBody], [FromQuery], [FromRoute], [FromHeader], [FromForm])?
**Explanation:**  
Binding sources dictate *where* in the incoming HTTP request the framework looks for parameter data:
- **`[FromBody]`:** Binds from JSON/XML request body payload.
- **`[FromQuery]`:** Binds from URL query strings (e.g., `?category=electronics&page=1`).
- **`[FromRoute]`:** Binds from URL route pattern parameters (e.g., `/users/{id}`).
- **`[FromHeader]`:** Binds values directly from HTTP Request headers.
- **`[FromForm]`:** Binds form fields from `multipart/form-data` (file uploads or traditional HTML form POSTs).

```csharp
[HttpPost("upload/{categoryId}")]
public IActionResult UploadProductImage(
    [FromRoute] int categoryId,
    [FromQuery] bool overwrite,
    [FromHeader(Name = "X-User-Id")] string userId,
    [FromForm] IFormFile file)
{
    return Ok();
}
```

#### 26. What is Dependency Injection (DI) and why is it built directly into ASP.NET Core?
**Explanation:**  
Dependency Injection (DI) is a technique for achieving Inversion of Control (IoC) between classes and their dependencies. Instead of components creating instances of dependent services directly via `new`, objects are passed into class constructors by an IoC container.

**Benefits in ASP.NET Core:** Loose coupling, high testability (easy mocking), centralized lifetime management, and modular architecture.

```csharp
public interface IEmailService { void Send(string to, string body); }

public class EmailService : IEmailService 
{ 
    public void Send(string to, string body) => Console.WriteLine($"Sent to {to}"); 
}

public class AccountController : ControllerBase
{
    private readonly IEmailService _emailService;

    // Dependency Injected via Constructor
    public AccountController(IEmailService emailService)
    {
        _emailService = emailService;
    }
}
```

#### 27. Explain the three Service Lifetimes in ASP.NET Core DI: Transient, Scoped, and Singleton.
**Explanation:**  
- **Transient (`AddTransient`):** Created *every single time* they are requested from the container. Best for lightweight, stateless services.
- **Scoped (`AddScoped`):** Created *once per HTTP Request lifecycle*. All objects resolved within the same HTTP request share the same instance. Essential for Entity Framework `DbContext`.
- **Singleton (`AddSingleton`):** Created *once* the first time they are requested and live across the entire lifetime of the application.

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddTransient<ITokenGenerator, JwtTokenGenerator>();
builder.Services.AddScoped<IOrderRepository, OrderRepository>();
builder.Services.AddSingleton<ICacheService, InMemoryCacheService>();
```

### Entity Framework Core (EF Core) Basics

#### 31. What is Object-Relational Mapping (ORM) and what is Entity Framework Core?
**Explanation:**  
- **ORM:** A software technique that translates data stored in relational database tables into object-oriented C# models, eliminating manual SQL query generation.
- **EF Core:** Microsoft’s official lightweight, extensible, open-source cross-platform ORM framework for .NET.

#### 32. What is the difference between Code-First and Database-First approaches in EF Core?
**Explanation:**  
- **Code-First:** Developer writes C# entity models and `DbContext` first. EF Core Migrations generate and update database tables automatically. Preferred for modern greenfield development.
- **Database-First:** Existing SQL database schema is reverse-engineered into C# POCO entity models and `DbContext` using the `dotnet ef dbcontext scaffold` command. Preferred for legacy systems.

---

#### 33. What is a DbContext and how does it act as both Unit of Work and Repository?
**Explanation:**  
- **`DbContext`:** Representational session with the database.
- **Repository Pattern Role:** Exposes `DbSet<TEntity>` properties which act as abstraction repositories for executing queries/inserts against specific tables.
- **Unit of Work Role:** Manages change tracking across all entity operations in a single context session. Executing `SaveChangesAsync()` commits all queued state changes atomically in a single SQL transaction.

#### 34. What are EF Core Migrations and what commands are used to create and apply them?
**Explanation:**  
EF Core Migrations provide incremental tracking of database schema changes based on C# model modifications over time.

**CLI Commands:**
```bash

dotnet ef migrations add AddProductsTable

# Apply pending migrations directly to the relational database
dotnet ef database update

# Script SQL statements without directly touching the target DB
dotnet ef migrations script
```

#### 36. What is the difference between IQueryable<T> and IEnumerable<T>?
**Explanation:**  
- **`IQueryable<T>`:** Inherits from `IEnumerable<T>`. Builds expression trees. Queries are executed directly on the **Database Server** side (SQL translates LINQ). Filtering/paging happens in SQL before loading into server RAM.
- **`IEnumerable<T>`:** In-memory collection iteration. Queries run on the **Application Client side** in local RAM. If you fetch table data as `IEnumerable`, the entire database table is loaded across the wire first.

```csharp
// IQueryable: Generates "SELECT TOP 10 * FROM Products WHERE Price > 100" in Database!
IQueryable<Product> query = _db.Products.Where(p => p.Price > 100).Take(10);
var result1 = query.ToList(); 

// IEnumerable Anti-pattern: Generates "SELECT * FROM Products", loads ALL rows, then filters in RAM!
IEnumerable<Product> memoryList = _db.Products.AsEnumerable();
var result2 = memoryList.Where(p => p.Price > 100).Take(10);
```

#### 50. What is the difference between synchronous and asynchronous HTTP endpoint execution?

#### 51. What is ASP.NET Core Middleware, and how does request execution flow through Use and Run methods?
**Explanation:**  
Middleware components form a processing pipeline chained together sequentially. Requests pass down through each middleware component until reaching the endpoint, and responses flow back up in reverse.
- **`app.Use()`:** Chains middleware; calls `next()` to pass control to the subsequent component.
- **`app.Run()`:** Terminal middleware; handles request and returns immediately without calling further downstream components.

```csharp
app.Use(async (context, next) =>
{
    // Request Logic (Incoming)
    await next.Invoke(); // Pass to next component
    // Response Logic (Outgoing)
});

app.Run(async context =>
{
    await context.Response.WriteAsync("Terminal Middleware Reached.");
});
```


#### 62. How does JWT (JSON Web Token) authentication work in RESTful APIs?
**Explanation:**  
1. Client sends credentials (`username`/`password`) to `/api/login`.
2. Server validates credentials and signs a stateless JWT token using a secret key.
3. Server sends JWT back to client.
4. Client attaches token in subsequent HTTP headers: `Authorization: Bearer <TOKEN>`.
5. Server validates token signature and claims statelessly without querying the DB on every request.

---

#### 63. Explain the structure of a JWT (Header, Payload, Signature).
**Explanation:**  
A JWT string consists of three Base64Url-encoded parts separated by dots (`.`): `header.payload.signature`

1. **Header:** Algorithm (`HS256`, `RS256`) and Token Type (`JWT`).
2. **Payload:** Claims containing data statements about the user (`sub`, `email`, `role`, `exp`).
3. **Signature:** Cryptographic verification hash calculated using `Base64(Header) + "." + Base64(Payload)` signed with the server's Secret Key.

#### 64. What is a Refresh Token and how is it used to maintain user sessions securely?
**Explanation:**  
Access Tokens have short lifetimes (e.g., 15 minutes) for security. When an Access Token expires, instead of forcing the user to re-type their password, the client submits a long-lived, securely stored **Refresh Token** to a `/api/refresh` endpoint to issue a brand new Access Token.

### EF Core Deep Dive & Performance

#### 71. What is the "N+1 Query Problem" in EF Core, and how do you resolve it?
**Explanation:**  
The N+1 Query Problem occurs when an initial query fetches $1$ parent record set, and subsequent code loops through each record triggering $N$ additional independent SQL queries to fetch child dependencies.

**Resolution:** Use `Include()` (Eager Loading) to fetch parent and child records together in a single optimized `JOIN` SQL query.

```csharp
// Bad Code (Triggers 1 Query for Orders + N Queries for Customers inside loop!)
var orders = _db.Orders.ToList();
foreach(var order in orders)
{
    Console.WriteLine(order.Customer.Name); 
}

// Good Code (Triggers 1 Single SQL JOIN Query)
var orders = _db.Orders.Include(o => o.Customer).ToList();
```

#### 72. Explain the three loading strategies in EF Core: Eager Loading (Include), Explicit Loading (Entry), and Lazy Loading.
**Explanation:**  
- **Eager Loading:** Loads related data as part of the initial database query using `.Include()`.
- **Explicit Loading:** Related data is loaded manually at a later stage from the DB for an already fetched entity using `_db.Entry(entity).Reference(...).LoadAsync()`.
- **Lazy Loading:** Related data is automatically fetched dynamically from the database the moment navigation properties are accessed (Requires virtual navigation properties and `UseLazyLoadingProxies`). *Warning: High N+1 danger.*

#### 74. How does Change Tracking work in EF Core, and what are entity states (Added, Modified, Unchanged, Deleted, Detached)?

### API Performance, Caching & Best Practices

#### 81. What is Response Caching vs. Output Caching in ASP.NET Core (.NET 7+)?
**Explanation:**  
- **Response Caching (`UseResponseCaching`):** Relies on standard HTTP cache headers (`Cache-Control`). Relies heavily on clients or upstream proxies/CDNs to store cached copies.
- **Output Caching (`UseOutputCache`):** Server-side caching engine (.NET 7+). Fully controlled on the backend server. Caches full HTTP responses, supports tag invalidation, resource eviction rules, and locking across concurrent identical requests.

#### 82. What is In-Memory Caching (IMemoryCache) vs. Distributed Caching (IDistributedCache) using Redis?

**Explanation:**

```csharp

{
    var query = _db.Products.AsNoTracking();

    if (!string.IsNullOrEmpty(p.SearchTerm))
        query = query.Where(x => x.Name.Contains(p.SearchTerm)); // Filtering

    query = p.SortBy == "price" ? query.OrderBy(x => x.Price) : query.OrderBy(x => x.Id); // Sorting

    var items = await query.Skip((p.PageNumber - 1) * p.PageSize)
                           .Take(p.PageSize)
                           .ToListAsync(); // Pagination

    return Ok(items);
}
```

#### 85. What is the difference between Offset-based Pagination and Cursor-based (Keyset) Pagination?

#### 94. Explain Garbage Collection (GC) in .NET: Generations 0, 1, 2, and the Large Object Heap (LOH).
**Explanation:**  
The .NET GC automatically manages memory allocations across generational heap regions:
- **Generation 0:** Short-lived small objects (local variables, temporary loop objects). Collected frequently.
- **Generation 1:** Buffer zone for objects surviving Gen 0 collections.
- **Generation 2:** Long-lived objects (Singletons, static references, DbContext caches). Collected infrequently.
- **Large Object Heap (LOH):** Dedicated heap region for objects larger than $85,000$ bytes. GC does not compact LOH by default to avoid huge memory copy overheads.

#### 110. What is the Outbox Pattern and how does it guarantee data consistency between a database and a message broker?

#### 132. How do ArrayPool<T> and MemoryPool<T> reduce GC pressure in high-throughput APIs?

```csharp
}

}
```

- **ASP.NET Core (.NET Core+):** ASP.NET Core does NOT have a `SynchronizationContext`! Therefore, calling `ConfigureAwait(false)` inside Web API controllers is redundant and unnecessary.

#### 139. How does String Interning work in C# and what are its memory implications?
**Explanation:**  
String Interning maintains a single system table (Intern Pool) containing a single reference copy of exact literal strings. Multiple identical string literals refer to the exact same heap memory address, saving memory footprint.

```csharp
string s1 = "Hello";
string s2 = "Hello";
bool sameAddress = object.ReferenceEquals(s1, s2); // True! String interning active.
```

#### 140. What is Expression Trees in C# and how are they converted into SQL strings by EF Core query providers?
**Explanation:**  
An Expression Tree (`Expression<Func<T, bool>>`) represents C# code as a tree data structure composed of node objects (binary operations, member accesses) rather than compiled IL instructions. EF Core query providers inspect node trees at runtime, translating C# nodes directly into relational SQL query strings (`Where` node becomes `WHERE` SQL clause).

### Automated Testing, CI/CD & DevOps

#### 141. What is the difference between Unit Testing, Integration Testing, and End-to-End (E2E) Testing in .NET?
**Explanation:**  
- **Unit Testing:** Tests individual C# methods/classes in complete isolation by mocking all external dependencies (xUnit, Moq). Fast and lightweight.
- **Integration Testing:** Tests real interaction between multiple application components, HTTP endpoints, middleware pipelines, and real database integrations.
- **E2E Testing:** Simulates full user workflows from UI web client frontends down through backend APIs and databases (Playwright, Selenium).

#### 143. How do mocking frameworks (Moq, NSubstitute) mock interfaces vs. abstract class members?

#### 145. How do you implement In-Memory Database provider vs. SQLite In-Memory for unit testing EF Core DbContext?
**Explanation:**  
- **EF Core In-Memory Provider:** Fast, but does **not** behave like a relational database (lacks dynamic SQL key constraints, transaction semantics, and relational data checks).
- **SQLite In-Memory (`Filename=:memory:`):** Real relational SQL database running entirely in RAM. Supports foreign key constraints and transactional integrity, making it far superior for testing EF Core mappings.

#### 146. How do you containerize a .NET Web API using Docker (Multi-stage builds, Alpine/Chiseled images)?
**Explanation:**  
Multi-stage Docker builds separate the heavy SDK build environment from the minimal runtime execution image, keeping production image sizes tiny.

```dockerfile
# Stage 1: Build & Publish
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY ["MyApi.csproj", "./"]
RUN dotnet restore
COPY . .
RUN dotnet publish -c Release -o /app/publish

# Stage 2: Minimal Runtime (Chiseled base image for maximum security)
FROM mcr.microsoft.com/dotnet/aspnet:8.0-chiseled AS final
WORKDIR /app
COPY --from=build /app/publish .
ENTRYPOINT ["dotnet", "MyApi.dll"]
```

#### 147. What are non-root user execution practices for containerized .NET applications in Kubernetes?
**Explanation:**  
Running containers as `root` inside Kubernetes cluster environments introduces container breakout security vulnerabilities. Modern .NET 8 runtime images execute by default as a unprivileged non-root user (`APP_UID 1654`), listening on port `8080` instead of privileged port `80`.

#### 150. How do Structured Logging (Serilog/NLog) and Centralized Logging (ELK Stack, Seq, Application Insights) aid in API debugging?
**Explanation:**  
- **Structured Logging (Serilog):** Formats log event properties into structured JSON payloads (`{ "UserId": 42, "Action": "Checkout" }`) instead of unstructured static strings.
